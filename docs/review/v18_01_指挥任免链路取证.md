## 0. 一句话裁决（先回答第一个问题）

> **问：战役模式（`tacticalState.mode === 'campaign'`）有没有"指挥官任命"逻辑？**

**分三层回答，务必分清「有 / 没有 / 断在哪」：**

| 子问题 | 裁决 | 一句话依据 |
|---|---|---|
| 战役模式是否有**总指挥判定**（谁说了算 / 谁能直接下令）？ | **有，且是自动选举，非玩家任命** | `computeSupremeCommander` 的 `else`（campaign）分支从**参战舰队**按「职位→军衔→功绩」自动选出（`BattleScene.ts` :1832-1840 + `TacticalCommandSystem.ts` `pickSupremeCommander` :49）。玩家**没有**入口去指定/更改。 |
| 战役模式是否消费「派遣名单第一格 = 指挥官」这套 `dispatchAdmirals`？ | **完全没有（0 处读取）** | `dispatchAdmirals` 唯一写入点是 **演习轨** `launchSimBattle`（`gameStore.ts:751`）；全部 3 处读取（`BattleScene.ts` :1829 / :2258 / :3030）**要么只在非战役分支、要么只在演习轨**（见 §3）。 |
| 战役模式是否有**玩家可操作的人事任免**（晋升 / 调职 / 任命防卫官 / 议会人事令）？ | **几乎全断** | 「晋升」通（挂 `AdminPanel.vue:506`）、「任命防卫官」通（挂 `StrategicScene.ts:2104`），但**调职 / 解任是死函数**、**议会「人事任免令」是空操作**、**`AppointmentRecord` 是死数据结构**（见 §2、§6）。 |

**一句话总览**：**"总指挥"在战役里是**自动按资序选举**的（玩家不能选）；"人事任免"只有**军事层级的两三个开关**（晋升 / 防卫官）真的接了玩法，**绝大多数任免入口是断线或空操作**。**

## 1. 总指挥判定的完整链路（item ①）

### 1.1 唯一入口与总开关

| 环节 | 位置（内容锚点） | 说明 |
|---|---|---|
| 判定入口 | `BattleScene.create()` → `this.computeSupremeCommander();`（`BattleScene.ts` :407，锚点 `computeSupremeCommander()`） | **每场战斗只算一次** |
| 硬开关 | `computeSupremeCommander` 首行 `if (this.mapStyle !== 'command') return;`（`BattleScene.ts` :1824，锚点 `this.mapStyle !== 'command'`） | **仅「指挥制」(`command`) 启用**；`hex`/`crt`/`3d` 直接返回，`supremeCommanderId` 保持 `null` = 不拦截，**玩家全控** |
| 镜像到 store | `(this.store as any).supremeCommanderId = supremeId;`（:1847） | 供军议面板 `CouncilWarRoom.vue` / 3D overlay 读 |

> **判定函数体**（`BattleScene.ts` :1821-1850）：先无条件清空 → `mapStyle` 守卫 → 按 `isCampaign` 两分支 → 兜底 → 镜像 + toast。

### 1.2 两条分支（这是"演习 vs 战役"口径分歧的根源）

```
const isCampaign = state && state.mode === 'campaign';   // :1826

if (!isCampaign) {                     // 演习 / 对战轨
    const first = (this.store.dispatchAdmirals || [])[0];   // :1829  ← 第一格 = 总指挥
    if (first !== undefined && first !== null) supremeId = first;
} else {                               // 战役轨
    const cands = [];
    this.globalFleets.forEach(fl => {                        // :1833
        const fac = this.factionMap.get(fl.factionId);
        if (!fac || fac.team !== 1 || fl.commanderId == null) return;
        const adm = (this.store.allAdmirals).find(a => a.id === fl.commanderId);
        if (adm) cands.push(adm);
    });
    const supreme = pickSupremeCommander(cands);             // :1839  ← 资序自动选举
    if (supreme) supremeId = supreme.id;
}
if (supremeId == null) {               // :1842 兜底
    const pFac = this.store.factions.find(f => f.type === 'player');
    if (pFac) supremeId = pFac.id;
}
```

> ⤷ **content-anchor**：`!isCampaign` / `(this.store.dispatchAdmirals || [])[0]` / `pickSupremeCommander(cands)` / `f.type === 'player'`。

**口径对比（直接回答用户"对比演习第一格"）：**

| | 演习 / 对战轨（`mode !== 'campaign'`） | 战役轨（`mode === 'campaign'`） |
|---|---|---|
| 总指挥来源 | **玩家手选的 `dispatchAdmirals[0]`**（"第一格"） | **系统自动**：参赛舰队指挥官按「职位→军衔→功绩」取最高 |
| 玩家能否指定 | **能**（就是在编成面板排第一格） | **不能**（无任何入口） |
| 兜底 | `null` → 落到 player 阵营 id | 同 |

### 1.3 资序键（`pickSupremeCommander`）

`TacticalCommandSystem.ts`：

| 元素 | 位置 | 内容 |
|---|---|---|
| `ROLE_WEIGHT` 职位权重表 | :19-34 | `emperor:100 > prime_minister/council:95 > military_minister:90 > high_command_chief/joint_ops_chief:88 > space_fleet_commander:85 > … > defense_commander:60 > fleet_commander:50 > fleet_staff:30 > none:0` |
| `admiralSeniority` 三元键 | :37-43 | 返回 `[ROLE_WEIGHT[role], rank, stats.tactics]`（**职位 → 数字军衔(1-13) → 功绩近似**） |
| `pickSupremeCommander` | :49-63 | 线性扫描取三元键最大者；**完全平手取数组首位（确定性，不打平加随机）** |

### 1.4 指挥继任（总指挥阵亡 / 覆灭）

| 环节 | 位置 | 逻辑 |
|---|---|---|
| 函数 | `checkSupremeSuccession()`（`BattleScene.ts` :1860-1890） | 守卫 `if (mapStyle!=='command' || supremeCommanderId==null) return;` |
| 调用点 | `BattleScene.ts` :3692（`update` 尾部，锚点 `checkSupremeSuccession()`） | 每帧调用，但现任存活即早退（成本 = 几支舰队的一次 `find`） |

### 1.5 v6「唯一舰队自愈」

| 位置 | `BattleScene.ts` :2174-2187（锚点 `DIRECT_COMMAND_TYPES.includes(type) && !isDirectCommandAllowed`） |
|---|---|
| 触发 | 玩家对某舰队下 `stance`/`attack` 直接命令，但该舰队不是总指挥 → 被拦截 |
| 自愈 | 若「我方**恰好只有 1 支存活舰队**且就是当前这支」→ 强制 `this.supremeCommanderId = fleet.commanderId` 并**放行**（修正 `dispatchAdmirals` 首位与实际 `commanderId` 口径偏差，无需重开战斗） |
| 否则 | toast「⛔ 扮演提督：你只能直接指挥总指挥旗舰…」 |

### 1.6 直接命令判定（拦截边界）

| 元素 | 位置 | 内容 |
|---|---|---|
| `DIRECT_COMMAND_TYPES` | `TacticalCommandSystem.ts` :112 | `['stance', 'attack']` —— **只有这 2 类实时操控被拦截** |
| `isDirectCommandAllowed` | :115-118 | `supremeCommanderId == null → true`（非指挥制/未判定不拦截）；否则 `fleet.commanderId === supremeCommanderId` |
| 消费点 | `BattleScene.ts` :2174（拦截）；`Battle3DOverlay.ts` :3815/3905（3D 姿态按钮只给总指挥旗舰；`supremeMark='◆'`） | — |

> **重要边界**：**军议面板的"任务指令"（`fleet.mission`）不受此拦截**——非总指挥舰队仍可被"间接指挥"（任务 5 类）。见 `TacticalCommandSystem.ts` §B（`MissionType` :69）。

### 1.7 总指挥链路 —— 小结

- ✅ **战役有总指挥逻辑**，且是**玩法相关**的（决定玩家"能直接操作哪支舰队"）。
- ❌ 但它是**自动选举**，**玩家零参与**——用户问的"指挥官任命"在此**不存在玩家入口**。
- ⚠ 演习/对战走另一套（`dispatchAdmirals[0]`），**两套口径并列**（详见 §3 与 §6-G4/G5）。

## 3. 战役编成对 `dispatchAdmirals` 的消费链（item ③ · 核心问题）

### 3.2 决定性证据：`create()` 的双轨分流

### 3.4 ⚠ 一个易误判的坑：`BattleSetupPanel` 的「非演习」不是战役

`BattleSetupPanel.vue` `launchBattle`（:460）：

```
if (isSimMode.value) { store.launchSimBattle(mapStyle); }   // :466 演习
else { store.startMatchLaunch(); }                          // :468 对战（match）
```

- `startMatchLaunch`（`gameStore.ts` :4153）只做：`autoSave()` + `gameState='game'` + 触发 `triggerPhaserMatchLaunch()`。
- 它**不写 `tacticalState`**（保持上一次的 `skirmish` 或初始值），仍走 **轨道 B（`initFactions`）**。
- ⇒ **`BattleSetupPanel` 的两条路（演习 / 对战）都是轨道 B；战役根本不经此面板。** 这是"以为战役消费了 `dispatchAdmirals`"最容易踩的误判点。

### 3.5 核心问题 —— 最终裁决

> **`tacticalState.mode === 'campaign'` 时，`dispatchAdmirals` 被消费的次数 = `0`。**
>
> **"第一格 = 指挥官"仅在演习 / 对战轨成立；战役轨的总指挥完全由 §1.2 的自动选举决定。**
>
> 证据链：写入端（`gameStore.ts:751` 仅演习） + 读取端（`BattleScene.ts:1829/2258/3030` 全在非战役分支） + 建阵营分流（`create()` :293/:299）三处闭合。

## 4. 参战舰队 `commanderId` 的来源（item ④）

### 4.1 战役两处入口（`triggerTacticalBattle`）

### 4.2 序列化链（`commanderId` 的产生）

```
serializeTacticalFleet(strategicFleetId)                    // gameStore.ts :3534
  ├─ const fleet = strategicFleets.value.find(...);         // :3535

serializeOne(fleetId)                                       // :3613

        fleetId: fleet.id, factionId: fleet.factionId,

        flagshipName, commanderName, imageId, formation, slots
     }

launchTacticalBattle → tacticalState = { mode:'campaign', attackers, defenders, … }  // :3704
```

**战役建阵营消费：** `spawnStrategicFleets`（`BattleScene.ts` :840）→ `commanderId: fleetData.commanderId ?? null`（**:866**）。
**总指挥判定消费：** `computeSupremeCommander` campaign 分支读 `fl.commanderId`（`BattleScene.ts` :1835）。
⇒ **战役"谁是提督"的唯一真源 = `strategicFleet.commanderId`。**

### 4.3 `strategicFleet.commanderId` 的上游（战略层从哪来）

| 来源 | 位置 | 值 |

## 5. AI 侧指挥结构（item ⑤）

| 观察 | 位置 | 结论 |
|---|---|---|
| AI 战略 Tick | `aiEngine.ts` :247 `runAIStrategicTurn(state, factionId, onWarpAI, excludeCommanderId?)` | **逐舰队**循环（`for (const fleet of aiFleets)` :277），**无"总指挥/指挥链"概念** |
| 排除玩家亲率舰队 | :269 `excludeCommanderId === undefined \|\| f.commanderId !== excludeCommanderId` | 唯一与"指挥官"相关的逻辑 = **不越权调动玩家舰队** |
| 提督性格驱动 | :328 `getPersonality(state.admirals, fleet.commanderId)` → `getAttackThreshold` | AI 每舰队按其 `commanderId` 取性格/进攻阈值 —— **是"逐提督"，不是"指挥链"** |
| AI 侧任免 | 无 | AI 不会 `promote`/`transfer`/`appoint`（`adminStore` 人事函数只服务玩家） |
| 防御方 AI | `gameStore.ts` :2777 `runAIStrategicTurn`、`runPlayerDefensiveAI`、`aiIssueWarpOrder` | 同上，均逐舰队 |
| 规划/协调层 | — | **无**（详见 `v17_01` §3/§5：无黑板、无跨舰队协调器、无规划层） |

**结论**：**AI 侧没有"指挥结构"这一层**。AI =「N 支各自带一个提督性格参数的舰队，各自跑反应式决策」，**没有总指挥、没有指挥链、没有任免**。玩家侧独有的 `supremeCommanderId` 机制 AI 完全不参与（AI 也走不到 `isDirectCommandAllowed` 的拦截路径——那只是玩家输入守卫）。
