## 1. TL;DR

1. **「横移」不是模型朝向装错了，而是"位移方向瞬时跳变 + 舰首角被限速成 30°/s 慢追"造成的过渡期错位**。2D 运动层把 `fAngle`/位移方向**一帧内**打到新方位（`BattleScene.ts:4067/4068/4074`），3D 呈现层却让舰首以 `SHIP_TURN_RATE = π/6 = 30°/s` 逼近（`Battle3DOverlay.ts:650/3414`）⇒ **转向 90° 时舰首与位移的角差峰值 = 90°（完全侧向），要 2.5s 才降到 15° 以下，期间纯横移 ≈ 34.5px ≈ 1.4 个舰长**。掉头 180° 更甚：峰值 180°、持续 5.5s、横移 68.8px。**"像残骸一样边转边漂"= 这个限速差**。
2. **「模型朝向」这条链是干净的**：加载管线把最长轴归一到 Z + 默认 `rotateY(180°)`（`shipModels.ts:401-423`）；GLB 探针实测 **34 个非 LOD 模型中 33 个原始最长轴 = Z**（唯一例外的 `flagship_BirdofPrey.glb` 已被 `SHIP_MODEL_YAW_FIX=90` 显式修正）。3D 的 `targetYaw = atan2(-cos fa, sin fa)`（`:3407`）在「舰首局部 -Z」约定下**数学正确**。⇒ **候选 A（恒定 90° 偏置）不成立**，横移是**过渡期（B）而非常态**。
3. **「缩成一团」是位移**走直线的弦效应**：`fAngle` 一帧内跳变后，**阵位偏移按新 `fAngle` 瞬时旋转**（`BattleScene.ts:4250-4251`），而每个单位靠**线性 lerp**（`:4263-4266`）追新阵位 ⇒ 掉头 180° 时每个单位的直线路径**穿过舰队中心**，整个编队半径在 ~0.13s 内**塌到初始的 2.6%**（= 一点），再花 ~1s 展开。仿真：`circle n=24` 180° → 半径最低 **2.6%**；90° → 71%；`wedge`/`line` 同病。
4. **两条现象是同一根因的两面，且"战舰转头"与"舰队缩团"速率严重失配**：编队位置 **~0.6s** 就完成"塌陷→展开"（线性 lerp，快），而舰首要 **3~6s** 才转完（30°/s，慢）⇒ 肉眼看到的是「**战舰还在慢慢转头，整支舰队却已经瞬间砸成一团又炸开、并摆到新朝向**」——与用户原话逐字吻合。
5. **推荐修复**：引入一个**限速的航向角**（如 90°/s），**同时**驱动「位移方向 / 阵型旋转 / 3D 舰首」三者（§4 FIX-3）。一处改动同时消灭两个现象，且天然给出"转弯半径"的物理感；最小改动版 = FIX-1（阵型转角限速，治缩团）+ FIX-2b（提高 `SHIP_TURN_RATE`，治横移）。

## 2. 现象一：舰船横移（舰身横着、往侧面移动、非沿舰首前进）

### 2.1 结论（候选裁定表）

| 候选 | 描述 | 裁定 | 关键证据 |
|---|---|---|---|
| **A** | 恒定偏置：模型前向轴假设错 / 映射公式错 ⇒ 常态恒 90° | **否** | ① `targetYaw = atan2(-cos fa, sin fa)` 在「局部 -Z」下代数正确（见 §2.2 推导）；② GLB 探针：34 模型中 **33 个**最长轴=Z，管线不旋转、假设成立；③ 唯一例外 BirdofPrey 已被 YAW_FIX=90 修正。若真装错只会是 180°（舰尾朝前），不是 90° |
| **B** | 过渡期漂移：位移已按新方向全速，舰首被 30°/s 限速慢追 | **是（主导）** | `BS:4067-4074` 瞬时跳变 vs `B3D:650/3414` 30°/s；仿真 90° 峰值 **90°**、持续 2.52s、横移 34.5px |
| **C** | 位移被 repulse/其它分量主导（与朝向无关） | **次要（局部）** | `BS:4126-4129`：`assembling && d<15` 与 `d<5` 两分支 `rawVX/Y` **只剩 repulse**，方向与 fAngle 无关；`BS:4130-4136` 接敌/巡航分支主体仍是 `cos/sin(moveAngle)·v` ⇒ 只在"快到位/原地"时与朝向脱钩 |
| **★ 设计旁证** | 拖刀战术：撤退+接敌时 `fAngle`=朝敌、`moveAngle`=朝补给点（`BS:4070-4072`） | **设计性"侧移"** | 该分支**故意**让舰首(火炮)与位移分离 ⇒ 撤退时舰身相对位移天然是斜/横的。**用户若在看撤退，这一条也贡献观感**（见 §5 不确定项 U3） |

### 2.2 证据链（行号 + 代数核对）

**（1）2D 运动层：朝向角与位移角一帧内瞬时确定，无平滑**
```
BattleScene.ts
:4062  let fAngle  = fleet.facingAngle || 0;
:4064  let moveAngle = fAngle;                       // 默认一致
:4066  if (distToTarget > 5) {
:4067      fAngle = Math.atan2(fleetTargetY - fleet.y, fleetTargetX - fleet.x); // ← 瞬时跳到新方位
:4068      moveAngle = fAngle;
:4070-4072  if (isRetreating && isEngaging) { fAngle = 朝敌; }   // 拖刀：位移仍朝补给点
:4074      fleet.facingAngle = fAngle;               // ← 无任何限速/插值
:4077-4078 } else if (isEngaging && closestEnemyFleet) { fAngle = 朝敌; fleet.facingAngle = fAngle; }
```
**`fAngle` 全文件无平滑**（`grep facingAngle =` 仅 `:4074/:4078` 两处赋值，均直接赋值）。⇒ 位移方向 `moveAngle` 在改向的那一帧就变成新方向。

**（2）3D 呈现层：舰首以 30°/s 逼近（慢）**
```
Battle3DOverlay.ts
:650   const SHIP_TURN_RATE = Math.PI / 6;      // 30°/s ⇒ 90°需3s、180°需6s（注释自述）
:3405  const fa = fleet.facingAngle;
:3407  targetYaw = Math.atan2(-Math.cos(fa), Math.sin(fa));
:3414  entry.yaw = approachAngle(entry.yaw, targetYaw, SHIP_TURN_RATE * dt);  // ← 限速逼近
:5124  const dt = Math.min(this.clock.getDelta(), 0.05);   // dt = 真实帧时间(秒)，非速度倍率
:5141  this.syncShips(dt);
```
> ⚠ 单位澄清：**3D 层 `dt` 是"秒"**（`clock.getDelta()`，`:5124`），而 **2D 层 `dt` 是"速度倍率"**（`const dt = this.store.currentSpeedFactor`，`BS:3296`）。两个同名变量语义不同 ⇒ **修 bug 时极易看错**，务必按文件区分。

**（3）映射与公式的代数核对（证明 A 不成立）**
- 坐标映射：`世界x = 像素x`、`世界z = -像素y`（`B3D:3262` `vv.z = -u.sprite.y`；`:3411` `dz = -(u.sprite.y - entry.lastY)` 佐证）。
- 像素前进向量 `(cos fa, sin fa)` → 世界 `(cos fa, 0, -sin fa)`。
- 舰首局部 -Z，`rotation.y=θ` 后鼻向 = `(-sinθ, -cosθ)`（`:3403` 注释给出，代数核对：绕 Y 转 θ 把 `(0,0,-1)` 映到 `(-sinθ,0,-cosθ)` ✓）。
- 令 `(-sinθ, -cosθ) = (cos fa, -sin fa)` ⇒ `sinθ=-cos fa, cosθ=sin fa` ⇒ **`θ = atan2(-cos fa, sin fa)`** —— 与 `:3407` **完全一致**。**⇒ 只要「舰首 -Z」成立，公式零误差。**

**（4）「舰首 -Z」假设的实测**（`_v16r1_glb_probe.cjs`）
```
34 个非 LOD 模型中：原始最长轴 = Z 的 33 个；= X 的 1 个（flagship_BirdofPrey.glb）；= Y 的 0 个
```
`shipModels.ts` 管线：先"最长轴归一到 Z"（`:401-406`），再按 `SHIP_MODEL_YAW_FIX`（默认 180°，`:271`）翻正（`:422-423`）。唯一需要旋转的 BirdofPrey **正是**被 YAW_FIX=90 单独修正的那一个（`:266`）⇒ **管线维护者已经踩过这个坑并补好了**。因此「模型朝向装错」这条链**没有系统性问题**。

### 2.3 量化（`_v16r1_sim.cjs`，参数取自源码）

模型：`t=0` 时 2D 位移方向瞬时跳到新方位；3D 舰首以 30°/s 逼近；速度 = `fleetBaseSpeed 0.30 px/帧 × 60fps = 18px/s`（`BS:4119/4135`）。

| 转向幅度 | 角差峰值（舰首 vs 位移） | 角差 >15° 持续 | 完全对齐耗时 | 行进路径 | **其中纯横移** |
|---|---|---|---|---|---|
| **90°** | **90.0°**（= 完全侧向） | **2.52 s** | 3.00 s | 63.3 px | **34.5 px（≈1.4 舰长）** |
| **180°（掉头）** | **180.0°**（= 倒退+侧向） | **5.52 s** | 6.00 s | 117.3 px | **68.8 px（≈2.7 舰长）** |

采样（90°）：`t=0.5s → 75°`、`t=1.5s → 45°`、`t=3s → 0°`；（180°）：`t=0.5s → 165°`、`t=1.5s → 135°`、`t=3s → 90°`。
⇒ **峰值 90° 就是"舰身横过来"**，且要 2.5~5.5s 才消——足够让用户读成"常态横移"。

## 3. 现象二：舰队转向时"缩成一团再展开"

### 3.1 结论

`fAngle` 一帧内跳变 → 单位**目标阵位**被同一角度瞬时旋转（`BS:4250-4251`）→ 每个单位用**线性 lerp** 追过去（`BS:4263-4266`）⇒ 大角度转向时，直线路径**穿过舰队中心**（弦效应）。**候选 E（转向 = 全体格位绕中心旋转，而旋转是靠线性位移"插值"实现的，必过中心）成立**；候选 D（阵型 morph 直线插值的弦效应）**不是本次现象的主因**（morph 只在**换阵型**时触发，纯转向不触发，见下）。

### 3.2 证据链（行号）

```
BattleScene.ts
:4250  const rx = ox * Math.cos(fAngle) - oy * Math.sin(fAngle);   // ← 阵位偏移按 fAngle 旋转
:4251  const ry = ox * Math.sin(fAngle) + oy * Math.cos(fAngle);   //     fAngle 已瞬时跳变 ⇒ 目标阵位瞬时换朝向
:4258  const targetUnitX = fleet.x + rx + breatheX;
:4259  const targetUnitY = fleet.y + ry + breatheY;
:4263  if (uDist > 2) {
:4264      const unitLerp = Math.min(0.08, uDist * 0.003);          // ← 线性 lerp 追目标
:4265      u.sprite.x += (targetUnitX - u.sprite.x) * unitLerp;
:4266      u.sprite.y += (targetUnitY - u.sprite.y) * unitLerp;     //     直线路径 ⇒ 弦穿中心
:4267  }
:4270  u.sprite.rotation = fAngle;                                 // 2D 层精灵角度也瞬时跳
```
- **阵位真源**：`config/formationLayout.ts:9-15` 明确「gx = 舰队前进轴；**调用方**负责 `ox=gx*spacing、oy=gy*spacing` 再**按 fAngle 旋转**」。⇒ 阵位的朝向完全由 `fAngle` 决定，`fAngle` 跳 ⇒ 阵位朝向跳。
- **morph 不是主因（澄清 D）**：`_formMorphA/B` 只在 `formKey` 变化（**换阵型 / 兵力变化**）时启动（`BS:4179-4195`），插值发生在**局部 gx/gy 帧**、时长 `FORMATION_MORPH_DUR = 3.5s`（`BS:68`）且走 smoothstep。**纯转向不改 `formKey`，不触发 morph**；且 morph 的弦效应即使发生也是 3.5s 缓动、不会"突然"。⇒ 用户说的"突然缩团"来自 §3.2 的旋转-lerp，不是 morph。
- **失配**：`BS:4263-4266` 的 lerp 时间常数 τ ≈ `-1/ln(1-0.08)` ≈ 12 帧 ≈ **0.2s**（0.6s 收敛 95%）；而 3D 舰首 `B3D:3414` 要 **3~6s**。⇒ 队形先塌，舰首后转。

### 3.3 量化（`_v16r1_sim.cjs`，格位枚举 = `formationLayout.ts` 忠实移植）

指标：**编队半径 = max(单位到舰队中心距离)**，取相对初始半径的百分比。

| 阵型 / n | 转向 | 半径最低值 | 时间序列（0→1.2s） |
|---|---|---|---|
| `circle` n=24 | **180°** | **2.6%**（t=0.13s） | 100% → 26% → 72% → 84% → 89% → 92% |
| `wedge` n=24 | **180°** | **2.6%** | 同上 |
| `line` n=24 | **180°** | **2.6%** | 同上 |
| `circle` n=24 | **90°** | **70.7%** | 100% → 73% → 86% → 91% → 93% → 95% |
| **对照**：若 `fAngle` 改为限速旋转（同 30°/s，单位沿弧线） | 180° | **100%** | 全程 100%（无弦效应） |

⇒ **掉头 180° 时整个编队半径在 ~8 帧内塌到 2.6%（≈一个点），再 ~1s 展开** —— 与用户「**突然一下子缩减成一团，然后展开，就完成转向了**」逐字吻合；90° 转向是"明显收缩"（71%）但不到"团"。**⇒ 用户描述的应是 ~180° 的掉头**（或拖刀/接敌锁定造成的 `fAngle` 大跳变）。

## 4. 修复方案

> 三个方案都**只动"呈现/运动学"，不动战斗数值口径**：`fAngle` 继续作为火炮/伤害的权威朝向，新增一个"视觉航向"只用于位移方向、阵型旋转、3D 舰首。改动面/风险/验收逐条给出。**本轮不实施**，待主理人派单。

### FIX-1（治"缩团"，最小改动）— 阵位旋转改用**限速的视觉航向角**

- **改动**：`BattleScene.ts` 新增 `let fleet.formAngle`（每帧 `approachAngle(fleet.formAngle, fAngle, FORM_TURN_RATE*dt)`），把 `:4250-4251` 的 `fAngle` 换成 `formAngle`；`Battle3DOverlay.ts:3405/3268/3506` 的 `fa` 源同步换成 `formAngle`。`FORM_TURN_RATE` 建议 **90°/s**（与"舰体缓慢转体"同量级）。
- **改动面**：`BattleScene.ts` ≈ 5~8 行；`Battle3DOverlay.ts` ≈ 3 行（只换朝向数据源）。
- **风险**：低。阵位与舰首**锁相同步旋转**；不再有弦穿中心。**但位移方向仍瞬时** ⇒ 横移（现象一）**只被"对齐"了一半**（舰首与阵型同步，但与位移仍有时差）。
- **验收判据**：① 仿真 180° 转向编队半径 ≥ 85%（FIX-1 后应≈100%，对照行已证）；② 真机 180° 掉头截图：无"砸成一点"帧；③ `tsc` 通过 + 无新增分配（formAngle 是标量）。

### FIX-2（治"横移"）— 提高转向角速度 **或** 让舰首对齐"实际位移方向"

- **2a（一行）**：`SHIP_TURN_RATE` 由 `π/6`（30°/s）提到 **~π/2~π（90~180°/s）**（`B3D:650`）。风险：低改动、但**主动牺牲"缓慢转体"**手感，且与 `:643-649` 注释的初衷相反，需与主理人确认取向。
- **2b（对齐位移）**：3D 舰首基准从 `fAngle` 改为**该舰实际位移方向**（由 `:3410-3412` 已有的 `lastX/lastY` 差分求得，或读 2D 新暴露的 `fleet.moveAngle`），**仅当"停船/接敌锁定"时回退 `fAngle`**。风险：中——与 `:3398-3401` 注释记的"撤退把船尾给敌人（用户早前实报）"**直接冲突**，须先裁定拖刀战术语义（§5 U3）。
- **验收判据**：① 仿真 90° 转向角差峰值 < 15°、持续 < 0.4s；② 真机转向过程中舰首始终在运动方向的 ±15° 内（拖刀分支除外并单独标注）。

### FIX-3（治两现象，推荐·根本）— 引入单一**限速航向角**，同时驱动「位移 / 阵型 / 舰首」

- **改动**：`BattleScene.ts` 新增 `fleet.heading`（rate-limited toward `fAngle`，建议 90°/s），用于：**(a)** 位移方向 `moveAngle`（`:4125-4137` 合成前把 `moveAngle` 平滑为 `heading`）；**(b)** 阵位旋转（`:4250-4251` 用 `heading`）；**(c)** 3D 舰首（`B3D:3405` 读 `heading`）。`fAngle` 仍作火炮/伤害权威。
- **改动面**：`BattleScene.ts` ≈ 8~12 行；`Battle3DOverlay.ts` ≈ 3 行。
- **风险**：中。**改变机动轨迹**（舰队转弯呈弧线、有转弯半径）——这正是用户要的"物理感"，但会轻微影响接敌/包抄的时序与路径长度，**必须回归战斗结果不变性**（同一编成、同种子，胜率/耗时无显著漂移）。
- **验收判据**：① 仿真：角差峰值 < 15°、编队半径 ≥ 85%（两现象同时达标）；② 真机：转向全过程无"横移残骸感"、无"缩团"；③ 战斗数值回归台架（另派 quality-lead）无差异；④ `tsc` + 性能基线与 v12 一致。

## 5. 不确定项清单（需人工/后续验证）

| # | 项 | 说明 |
|---|---|---|
| **U1** | 舰首 ±Z 符号 | 包围盒只能判"长度轴"，**判不出舰首指 +Z 还是 -Z**。33 个 Z-长模型是否都满足"默认 180° 后舰首 -Z"，需按项目自述流程在**模型巡览**用"橙色尾焰锥应落在舰尾最末端"逐个目视复核（`assets/ship/模型命名规范.md`）。若某模型反了 ⇒ 表现为**倒退**（180°），与横移（90°）不同症状，可据此区分。 |
| **U2** | 用户看到的转向幅度 | 仿真显示"缩团"在 ~180° 掉头时才有 2.6% 的塌陷，90° 只有 71%。用户原话难以判定是 90° 还是 180°。**建议复现时记录**：转向瞬间 `fAngle` 的跳变量（可在 `BS:4074` 加临时日志，非本轮）。 |
| **U3** | 拖刀战术语义 | `BS:4070-4072` 让"撤退+接敌"时**舰首朝敌、位移朝补给** ⇒ 设计性侧移。用户"横移"抱怨**可能含这一条**。需策划裁定：撤退时舰首应"朝敌（当前）"还是"沿位移（更像飞船）"。FIX-2b 与此直接耦合。 |
| **U4** | 帧率相关性 | 2D 位移是**每帧**量（`BS:4135` 不含 `delta`），3D 转向是**每秒**量（`B3D:5124` `clock.getDelta()`）。若真机掉帧，两者的**失配比例会变化**（2D 变慢、3D 不变）⇒ 低帧率下"横移持续时长"可能比仿真值更长。建议真机按目标帧率复测。 |
| **U5** | 战斗语义是否真需要"瞬时转向" | FIX-3 限速航向会改变接敌时序。需确认"AI 每帧重算 `fAngle`"（如 `:3868` 读敌朝向、`:4344` 用 `facingAngle` 算角差）是否依赖"朝向瞬变"。 |

```powershell
# 运动学 + 缩团仿真（输出 _v16r1_sim.out.txt）
node _v16r1_sim.cjs
# GLB 轴向探针（输出 _v16r1_glb_probe.out.txt）
```
