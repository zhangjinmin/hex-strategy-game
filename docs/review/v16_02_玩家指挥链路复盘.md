## 1. TL;DR

1. **"右键点击地块前进"从来不是"移动指令"，而是"投放战术信标 `deployFlare`"**——它的语义是「**把离点击点最近的 1 支己方舰队牵引过去**」，不是「控制某支舰队移动到某格」。用户记忆里的"右键前进"= 信标牵引这条链。
2. **在 3D 模式（`3d` / `command`）下，右键信标已经彻底不可达**——3D overlay 用假 pointer 中继地块点击时**硬编码 `button: 0`**（`Battle3DOverlay.ts:5107-5112`），`handleTileClick` 的 `pointer.button === 2` 分支永不进入。**这是"右键前进功能没了"的第一根因，且与 AI 无关，纯输入链断点**。
3. **在 2D（`hex`/`crt`）下右键信标仍在，但被 2026-09-02 新增的"指挥带宽门控"大幅削弱**：`silent` 直接拒发（仅 toast）、`delayed` 转中继、直连频道满也拒发——三条都 `return`；且**只能选"最近舰队"、玩家无法指定收令舰队**。这是"右键前进功能没了"的第二根因（历史回归）。
4. **"无法控制我自己"是代码事实，不是错觉**：玩家对舰队的**直接**命令通道只有 4 条（姿态 stance / 军议 mission / 信标 flare / CP 命令），**其中没有任何一条是"移动这支舰队到该点"**。而 `mission` 走军议面板（给"别人"），`stance` 只改阵型不改位置，`flare` 只能牵引最近舰队（还坏了）。⇒「能指挥其他人（军议派任务），但自己没有控制」——**解读 (b) 成立**，见 §3.2。
5. **"三个按钮"= 索敌/攻坚/驻守，作用是"切姿态 + 自动联动阵型"，不改位置、不指定目标**。3D 模式下这组按钮只在**总指挥旗舰**的 billboard 上出现（`Battle3DOverlay.ts:3799-3824`）；点非旗舰舰队会被 `isDirectCommandAllowed` 拦截并 toast（`BattleScene.ts:2031/2041`）。"作用不明确"= 文案只写"索敌/攻坚/驻守"，玩家预期是"打了/走了"，实际是"换阵型+换 AI 寻路权重"。

## 3. 逐条根因

### 3.0 与 AI 自主行为的接口口径（不越界，仅给口径）

用户"占完补给后原地不动"是 AI 自主问题（另 teammate 复盘）。但与命令链**接口**上可确认两点，供交叉：
- `deployFlare` 只写 `nearest.targetFlare` + `nearest.stance='search'`（`BS:1545-1546`），**不写 `fleet.state`**；`state` 转 `flaring` 依赖主循环 `if (fleet.targetFlare && !isManualRetreat) fleet.state='flaring'`（`BS:3647-3648`）。即信标命令**要能生效，被牵引舰队必须不被 `fallback`/`retreating` 抢态**。
- `mission` 通道（E3）是**唯一写入 `fleet.mission` 的入口**，AI 每帧优先执行（`BS:488-491`）。用户"让有卷去占领补给基地"若走的是军议 `capture_planet`，那"占完之后不动"是任务完成后的 AI 回退行为，**不是命令没送达**。

### 3.1 根因 R1：右键点击地块"没效果"——两个独立断点

**(R1-a) 3D 模式：`button` 透传丢失（决定性断点，本轮新确认）**
- 3D overlay 的 `handlePick`（`Battle3DOverlay.ts:5007`）**不读 `e.button`**；中继函数 `syncTileClick` 构造的假 pointer 硬编码 `button: 0`（`:5107-5112`），注释自述 *"getDistance=0 / **button=0**"*（`:5095`）。
- `handleTileClick` 右键盘分支是 `if (pointer.button === 2)`（`BS:3203`）⇒ **3D 下永假**，右键被当成左键，执行买地/建修补站逻辑。
- 该缺陷**已被记录但未修**：`docs/qa/战术界面质检报告_20260902.md` **B-10（P2，未列入第一批）** 原文即 *"3D 模式下战术信标（右键投放）完全不可用；右键被当成左键，会误触发'购买地块/建修补站'"*。
- **⇒ 只要用户的战斗是 3D 模式（`3d` 或 `command`），"右键前进功能没了"是 100% 必然。**

**(R1-b) 2D 模式：带宽门控造成的"命令有失败率"（历史回归）**
- `deployFlare` 在选到 `nearest` 后进入带宽门控（`BS:1523-1543`）：`silent` → toast 后 `return`（`:1530`）；`delayed` → 转中继队列后 `return`（`:1536`）；直连频道满 → toast 后 `return`（`:1541`）。
- 该门控是 **2026-09-02 新增**（`CommandBandwidthSystem.ts`，见 `docs/qa/指挥带宽系统在途改动_QA门控_20260902.md`），其报告 BW-02 明写 *"……**改动前信标必定生效**"*。⇒ **"之前右键能前进、现在不能"在 2D 下也成立，是一条已记录未修的回归**。
- 同报告 **BW-05** 明写 *"信标派发固定选'离点击点最近的玩家舰队'……**玩家无法指定收令舰队**"*；**BW-03** 指出频道容量仅 `1+⌊统帅/30⌋`（典型 2~4）而 deck 有 8 槽 ⇒ **过半舰队长期拿不到频道、永久收不到信标**。
- **BW-02 的"幽灵信标"至今未修**：`deployFlare` 先建视觉（`BS:1471-1513`）再判定门控（`:1523`），`silent`/频道满时 `return` **不回滚已创建的 `playerFlare`** → 玩家看到华丽信标动画 + "链路中断"toast，但无舰队响应（本轮源码复核，缺陷仍在）。

**(R1-c) 前置条件 `pFac.active`**
- `handleTileClick` 第 3194 行 `if (!pFac || !pFac.active) return;` 在右键盘**之前**。若玩家阵营 `active=false`（如已被判定战败/未激活），**左右键地块交互全部静默失效**，无 toast。属"应该核但当前无证据触发"的观察项（§5）。

**(R1-d) "只能选最近舰队"（设计层缺口，非 bug）**
- `deployFlare` 遍历 `myFleets` 取距信标最近者（`BS:1515-1520`），**无玩家指定舰队的能力**。即便右键恢复，玩家也无法让"我的旗舰"去某点——只会牵引恰好最近的那支。

### 3.2 根因 R2："我能够指挥其他人，但是我自己没有控制"——两种解读的代码裁定

| 解读 | 代码裁定 |
|---|---|
| **(a) 能指挥 NPC 舰队但控制不了自己的舰队** | **部分成立但不精确**。代码里"能指挥的其他人"= `mission`（军议，E3，对所有己方舰队有效）；"自己的舰队"= 总指挥旗舰，本应是唯一可直接指挥者（E2/姿态），但**姿态只改阵型不改位置**，且**没有 move 入口**。 |
| **(b) 能指挥其他舰队（军议）但总指挥旗舰本身无直接控制入口** | **成立（推荐裁定）**。① 军议面板里**旗舰那一行是"直接指挥中"，没有任务表单**（`CouncilWarRoom.vue:29-30`）——即旗舰**不能收 mission**；② 旗舰唯一的"直接控制"是姿态三按钮（不改位置）+ 右键信标（3D 下已死、2D 下不可指定舰队）；③ 系统**全局没有"选中舰队 → 移动到目标格"**这条命令（§2 E★）。⇒ 玩家对旗舰**无任何可用的"指哪去哪"控制**。 |
| (c) 系统设计本意 | `computeSupremeCommander` 的 toast 自述：*"◆ 总指挥：…— 你只能直接指挥其旗舰舰队，其余舰队请用军议面板下达任务"*（`BS:1706`）。**设计本意正是 (b) 的分工**：旗舰=直接指挥、其余=军议。用户感受到的"反了"，是因为**旗舰侧的直接控制实际不可用**。 |

**⇒ 结论**：用户不是"权限矩阵接错了"，而是**旗舰侧的直接控制通道（移动/目标）在设计上就缺，仅有的替代（右键信标）又在 3D 下断了**。所以表现为"我能指挥别人（军议有效），自己却什么都做不了"。

### 3.3 根因 R3：三按钮"作用不明确"

- **实际效果 = 切姿态 + 自动联动阵型**：`applyStanceToFleet`（`BS:2794-2812`）：`search→spindle`、`siege→wedge`、`defend→circle`，并加 12s 用户锁（`BS:2800`）。**不改位置、不改攻击目标**。
- **可见性**：3D 下只有**总指挥旗舰**显示三按钮（`Battle3DOverlay.ts:3795-3824` 的 `directOK` 判定）；2D 下 `App.vue:35-39` 对所有 team1 舰队显示。用户看到"三个按钮"（单组）⇒ 强烈指向 **3D 模式**。
- **可理解性缺口**（"不知道干什么"的来源）：
  - 按钮文案只有"索敌/攻坚/驻守"，**无 tooltip 说明其真实语义**（换阵型 + 换 AI 寻路权重）；
  - `defend`（驻守）是唯一"明显"的效果（原地不动），`search`/`siege` 的效果要等 AI 下一秒重算才体现，**无即时反馈**；
  - 非旗舰点按钮 → **被拦截**（toast "⛔ 扮演提督：你只能直接指挥总指挥旗舰"，`BS:2041`），玩家会觉得"按钮点了没用"；
  - 顶栏/底栏快捷键提示与实际不符（旧 QA B-14：空格实为开面板而非暂停、1-5 既是调速又是变阵），进一步稀释"按钮到底干什么"。
- **⇒ R3 是"UX 缺说明 + 功能范围受限"的叠加**，非纯失效；但**它确实无法替代"移动"**。

## 4. 修复方案选项（含"最小改动恢复右键移动语义"）

> 以下均为**建议**，未实施；优先级按"用户能否重新控制"排序。

### 方案 A（最小改动，恢复 3D 右键信标语义）★ 建议先做
- **做法**：给 `Battle3DOverlay.handlePick` / `syncTileClick` 打通 `e.button`：
  1. `handlePick(e)` 只在 `e.button===0 || e.button===2` 时继续，忽略中键；
  2. `syncTileClick(tile, button)` 把真实 `button` 写进假 pointer（`Battle3DOverlay.ts:5107-5112` 的 `button: 0` → `button`）；
  3. `deployFlare` 补一张 `nearest`（playerFlare）被拒时回滚视觉的补丁（修 BW-02 幽灵信标）。
- **代码量**：约 6–10 行（`Battle3DOverlay.ts` 3 处 + `BattleScene.ts` 1 处）。
- **代价 / 风险**：需与 OrbitControls 右键旋转的 `dragMoved` 阈值共存（现状 4px，设计建议 5px/200ms，见 `02-interaction-spec.md` §1.4）；要实机确认右键拖拽旋转不会误投信标。
- **收益**：**直接恢复用户记忆中的"右键前进"**（3D 模式）。
- **它不解决什么**：仍是"牵引最近舰队"，玩家**仍不能指定是哪支**；2D 下的带宽门控仍在。

### 方案 B（结构性，补"选中舰队 → 移动到点"）——真·直接控制
- **做法**：新增选中模型（选中己方舰队）+ 新命令 `dispatchFleetCommand(fid,'move',{x,y})`；`setupCommandDispatcher` 增 `'move'` 分支写入 `fleet.targetFlare`/`_moveDest`；把 `'move'` 纳入 `DIRECT_COMMAND_TYPES` 走 `isDirectCommandAllowed` 门控（只有旗舰可直接移动，其余走军议）——**与现有权限矩阵天然一致**。
- **代码量**：中等（选中态 + overlay 拾取 + 一条命令分支 + UI 提示）。
- **代价**：需设计拍板"点击地块 = 移动选中舰队还是投信标"的优先级（可能需修饰键区分）。
- **收益**：**真正补上 E★ 这个全局缺失入口**，直接回应"我自己没有控制"。

### 方案 C（解耦带宽门控，恢复"命令有确定性"）
- **做法（三选一，建议 (a)）**：(a) 直连区（`direct`）信标**不占频道、不拒发**，频道仅作软上限；(b) 信标改为"先过滤非 silent 候选再取最近"（修 BW-05）；(c) `getCommCenter()` 增加 `units.length>0` 存活过滤（修 BW-04，避免旗舰舰队阵亡后全side silent）。
- **代码量**：小（各 1–3 行）。
- **代价**：需 design-strategist 给"带宽门控覆盖哪些命令"的统一口径（旧 QA BW-06/BW-09 都指向这个未决裁决）。
- **收益**：让 2D 右键信标重新"必定生效"，消除"下了命令没反馈"。

### 方案 D（UX 澄清，低成本，可与 A/B 并行）
- 三按钮加 tooltip/角标写明"姿态（换阵型，不改位置）"；非旗舰舰队**隐藏**按钮或点击时就地提示"该舰队请用军议派任务"（而非弹 toast）；
- 底栏快捷键提示与实际对齐（旧 QA B-14 / B-5 / B-6 同批）。
