## 3. CRT 强度滑杆的可访问性规格

用户决策已确认：CRT 强度为**可调滑杆，默认 75%**。这直接服务于特效敏感用户。

### 3.1 滑杆本身

完整技术规格见 `materials-and-lighting.md` §6.3。要点复述：

| 项 | 值 |
|----|-----|
| 范围 / 步进 | 0-100%，step 5 |
| 默认值 | **75** |
| 归零行为 | `s = 0` 时扫描线、色差、暗角、噪点**四个参数全部归零**，画面为纯净 3D |
| 性能影响 | 无（仅改 uniform） |

### 3.2 各级别下的 CRT 处理

| 级别 | CRT 滑杆 | 额外能力 |
|------|----------|----------|
| **Basic** | 可用（0-100） | 无 |
| **Standard** | 可用（0-100） | 提供「低刺激」预设档（**CRT ≤ 30%**），一键套用 |
| **Comprehensive** | 可用（0-100） | ① 四个参数**分项独立开关**<br>② **一键关闭全部后处理**（CRT + Bloom 同时关）<br>③ 可设为随场景持久化（每次进战斗自动归位） |

### 3.3 为什么 Comprehensive 需要「分项独立开关」

不同类型的视觉敏感对四个 CRT 参数的反应差异很大：

| 症状 | 主要触发参数 | 建议做法 |
|------|--------------|----------|
| 扫描线引起的条纹闪烁不适 | 扫描线振幅 | 单独关扫描线，保留暗角 |
| 色差引起的边缘彩边/重影 | 色差系数 | 单独关色差 |
| 噪点引起的画面脏乱/颗粒感（常与 Bloom 叠加） | 噪点振幅 | 单独关噪点 |
| 暗角引起的视野收窄/周边信息丢失 | 暗角下限 | 单独关暗角（设 `uVigFloor = 1.0`） |

若只给一个总滑杆，用户为了关掉扫描线就必须把整个 CRT 归零，会连带失去暗角的构图收束作用。分项开关让用户可以「只关掉让自己不适的那一层」。

**R1 补充：滑杆内部已内置优先级排序。** 即便不进 Comprehensive 档分项开关，总滑杆在低区间也会按损害优先级依次归零（**色差 → 噪点 → 扫描线 → 暗角**），采纳 UX 侧 `06` §2.1 的规则：

- 色差在 `s ≤ 30%` 时**恒为 0**（色差糊掉细线框与小字，损害最大，最先归零）
- 噪点用 `s^1.5` 曲线，低区间天然被压制
- 扫描线线性，中区间仍保留
- 暗角最后归零

详见 `materials-and-lighting.md` §6.3。

### 3.4 一键关闭后处理（Comprehensive 必备）

在辅助功能面板提供一个开关：

```ts
// 语义：关闭全部后处理，画面为未经 Bloom / CRT 处理的原始 3D 渲染
const postProcessingDisabled = ref(false);
```

行为：
- `true` → 跳过 BloomPass 与 CRTPass，直接 `renderer.render(scene, camera)`（EffectComposer 旁通）。
- 这是**性能与可访问性双赢**的选项：既服务特效敏感用户，也是最低配设备的最强降级手段（见 `performance-budget.md` §9 降级顺序第 5 步的极端版）。
- 不应与 `crtIntensity = 0` 完全等同：`crtIntensity = 0` 仍保留 Bloom；`postProcessingDisabled = true` 连 Bloom 一起关。

### 3.5 「全部归零」一键预设（R1-C 新增，全档位必备）

UX 侧在采纳独立 CRT 滑块后提出一条**附加条件，本侧完全同意**：必须有一次性把所有视觉参数归零的预设按钮。

> **这不是便利功能，是可访问性验收硬项。** UX 侧的「归零后仍完全可玩」验收项不能要求重度敏感用户逐个滑块拖一遍——那等于把验收门槛转嫁给用户。

**行为**：一次点击，同时置零以下全部参数：

| 参数 | 归零值 | 连带效果 |
|------|--------|----------|
| 特效强度（主控） | **0** | 粒子 0、屏幕震动 0、屏幕闪光 0、自动镜头 0 |
| CRT 强度 | **0** | 扫描线 / 色差 / 暗角 / 噪点四项全 0 |
| Bloom | **0** | 后处理链旁通 |
| 实体层 alpha | **1.00** | 舰船变为**不透明实体**（§3.4 耦合表） |
| 实体层亮度系数 | **×1.00** | **必须同步**——否则不透明舰船会变成沉入 `0x02040a` 的实心暗块 |
| 接地投影 | **0.95 / 0.35** | **不归零，反而增强**（深度锚点，见 `materials-and-lighting.md` §8.4） |

**为什么必须同时改亮度而不只是 alpha**（UX 侧已把此条标注为「反向失效」风险，三处文档均有标注）：只把 alpha 提到 1.0 而亮度留在 ×0.35，得到的是**一片沉入暗背景的实心暗块，比半透明状态更不可读**——"关掉特效"这个动作反而让可读性变差，是典型的反向失效。

**位置**：辅助功能 > 视觉，**所有档位可见**（不是 Comprehensive 专属）。与 §3.4 的「关闭全部后处理」开关的区别：

| | 「关闭全部后处理」 | 「全部归零」预设 |
|---|---|---|
| 类型 | 开关（toggle） | 按钮（一次性动作） |
| 作用域 | 仅后处理（Bloom + CRT） | **全部视觉参数**（含特效主控、粒子、舰船 alpha） |
| 是否可恢复 | 关闭开关即恢复 | 需手动调回各滑块 |
| 面向 | 想保留玩法特效、只要干净画面 | **重度敏感用户，一步到位** |

### 3.6 目标选择脉动的开关（R1-D 新增）

目标选择态使用 **0.83 Hz 的加法脉动轮廓壳**（见 `radar-visual-spec.md` §6）。

| 项 | 结论 |
|----|------|
| 光敏安全性 | `0.83 Hz` 远低于 **WCAG 2.3.1 的 3 Hz 闪烁阈值**，无光敏性癫痫风险 |
| Comprehensive 档 | **必须可关闭**。关闭后降级为**静态轮廓壳**（opacity 恒 0.6，不呼吸）——保留选中反馈，去掉动态 |
| 「全部归零」预设 | 脉动壳随之关闭 |
| 可访问性理由 | 低频脉动虽不触发光敏，但对**前庭敏感与注意力障碍**用户仍是干扰源，应给关闭路径 |

## 4. 半透明实体对低视力玩家的影响与对策

用户选定的「半透明实体 + 线框叠加」会降低画面对比度，对低视力玩家是额外负担。

| 影响 | 对策 | 级别 |
|------|------|------|
| 半透明实体层压低了舰体与背景的对比 | **高对比模式**：实体层 opacity 从 **0.55** 提到 **0.85**（并同步提升亮度系数，见 `materials-and-lighting.md` §3.4 耦合表），并给线框层加描边 | Comprehensive |
| 密集舰队重叠时半透明累加导致糊成一片 | 高对比模式下**关闭远处舰船的实体层**（只留线框），近处保留 | Comprehensive |
| 线框过细看不清 | 提供「线框粗细」选项（1x / 1.5x / 2x） | Comprehensive |
| **暗背景下远处舰船沉入背景**（UX 侧 R-17） | 线框强度**不随距离衰减**；远处改用 LOD 降线数而非降亮度（见 `materials-and-lighting.md` §7.4） | **全部级别** |

> 注：线框粗细在 WebGL 中受 `linewidth` 平台限制（多数桌面浏览器恒为 1px）。若需要加粗，必须改用 `Line2` / `LineMaterial`（`three/examples/jsm/lines/`）或把线框做成细长的 BoxGeometry。**这是需要在架构阶段就确认的技术约束**。

### 5.1 CRT 与特效为何是两个独立滑块（R1 新增）

UX 侧 `06` §2.1 设计为单主控（`CRT = master × 0.8`）。**本侧主张双独立滑块**，理由与折中方案见 `materials-and-lighting.md` §6.4（已列分歧，待 team-lead 裁决）。

对**本分级**的影响：Comprehensive 档的「CRT 分项独立开关」与「一键关闭全部后处理」均**按独立 CRT 滑块设计**。若最终采纳单主控模型，这两项需改为「强制 CRT 归零」的快捷按钮即可，功能等价但少一层控制粒度。

## 6. 色盲友好敌我识别方案

### 6.1 问题

同盟青绿（`0x2dd4bf`）与帝国紫（`0xc084fc`）在部分色盲类型中可能难以区分。

### 6.2 解决方案

| 色盲类型 | 备用配色方案 |
|----------|--------------|
| 红绿色盲（Deuteranopia/Protanopia） | 同盟 = 蓝 `0x3b82f6`，帝国 = 黄 `0xfacc15` |
| 蓝黄色盲（Tritanopia） | 同盟 = 绿 `0x22c55e`，帝国 = 红 `0xef4444` |
| 全色盲（Achromatopsia） | 依赖轮廓 + 底部投影形状 + 高对比描边 |

### 6.3 非颜色识别

即使不开色盲模式，也必须提供：
- 同盟舰：方正轮廓、圆角矩形底部投影。
- 帝国舰：前倾尖首、尖椭圆底部投影。
- 旗舰：顶部独特标志（同盟十字 / 帝国冠羽）。
- 选中敌我：绿色 L 括号 / 红色 X 括号。
- **L3 编队聚合标记**（R1 新增，形状 UX 定 / 颜色本侧定）：同盟 **▲** / 帝国 **◆**。当舰体轮廓与接地投影都退化不可辨时，这是**唯一仍在工作的非颜色识别通道**（详见 `ship-assets.md` §4.4）。

**底面免建模不影响这一条**：剪影由侧轮廓决定，底面永不可见，因此识别通道不受影响（见 `ship-assets.md` §3.3 / §3.4）。

**▲ / ◆ 的灰度可用性是本方案的一个关键收益**：两者是纯形状差异，灰度化（全色盲模拟）后依然可分辨。因此在 §6.2 的「全色盲」档位下，L3 标记不是补充手段而是**主要识别通道**，必须保留且不得因性能降级被裁掉——这一点已写入 `performance-budget.md` §9 的降级顺序（标记最后降级）。

### 6.4 线框粗细的技术前置（需在架构阶段确认）

Comprehensive 档的「线框粗细」选项依赖一个**尚未确认的技术前提**：

| 方案 | 可行性 |
|------|--------|
| `LineBasicMaterial.linewidth` | ❌ **不可用**：WebGL 规范允许实现忽略该值，Chromium / ANGLE 下恒为 1px |
| `Line2` / `LineMaterial`（`three/examples/jsm/lines/`） | ✅ 可行，支持真实屏幕空间线宽；代价是每根线变成 instanced quad，**三角面与 draw call 显著上升** |
| 把线框烘焙成细长 `BoxGeometry` | ✅ 可行，但与「线框层 = 同几何体 `wireframe: true`」的现有结构冲突，需另建一套几何 |

**若架构侧不采用 `Line2`，Comprehensive 档的「线框粗细」选项必须从 UX 规格中删除**，改为用「提高线框 opacity + 提高实体层 alpha」来间接提升可辨度。**这是本侧已知的、尚未解决的依赖**，已同步给 design-strategist 与 team-lead。

## 7. 晕动症限制具体参数（R1 全部修订）

| 参数 | 默认（Standard） | Basic | Comprehensive |
|------|------------------|-------|---------------|
| **相机阻尼 `k`（1/s，指数）** | **7.7** | **5.0** | **13.4** |
| ~~相机旋转阻尼（逐帧 lerp）~~ | ~~0.12~~ | ~~0.08~~ | ~~0.20~~ |
| 缩放动画时长 | 600 ms | 400 ms | 即时（0 ms） |
| **战斗事件相机抖动** | **关闭** | **关闭** | **关闭** |

| 自动旋转 | 关闭 | 关闭 | 关闭 |
| **`maxPolarAngle`** | **0.35π** | **0.35π** | **0.35π** |

### 7.1 阻尼改为帧率无关的指数形式（采纳 UX 侧 C-3）

R0 版的 0.08 / 0.12 / 0.20 是**逐帧 lerp 系数**，隐含 60fps 假设。30fps 下每帧时间翻倍，实际阻尼只有设计值的一半——低配机器（正是我们设 LOD 降级的目标设备）上手感会明显发黏。

UX 侧给出的换算正确，**完全采纳**。改用帧率无关形式：

```ts
// 不要这样（帧率相关）
value += (target - value) * 0.12;

// 要这样（帧率无关）
value += (target - value) * (1 - Math.exp(-k * dt));
```

| 逐帧 lerp（@60fps） | 等效 `k` (1/s) | 30fps 下的等效 lerp |
|:-------------------:|:--------------:|:-------------------:|
| 0.08 | **5.0** | 0.154 |
| 0.12 | **7.7** | 0.226 |
| 0.20 | **13.4** | 0.361 |

**实现直接用 `k = 5.0 / 7.7 / 13.4`**，60fps 下手感与 R0 设计一致，且任意帧率下稳定。

> 附注：战略层 `ThreeStrategicMap.ts` 用的 `controls.dampingFactor = 0.08` 也是逐帧 lerp，同样受此影响。战术层改用指数形式后，两层手感会在低帧率下出现差异——**是否同步改战略层，需与工程侧确认**（不属于本次改造范围，仅记录）。

### 7.2 战斗事件相机抖动：三档统一关闭（采纳 UX 侧 C-2）

R0 版 Basic 档为「开启」。**修订为三档全部默认关闭**，理由：

1. UX 侧指出 3D 下抖动诱发强度远高于 2D——2D 抖动只是画面平移，3D 抖动带**透视位移**，前庭冲突更强。
2. Basic 档比 Standard 档「更容易晕」在逻辑上说不通：Basic 是「无特殊需求玩家」的默认体验，不应比无障碍档位更具诱发风险。

**若保留抖动作为可选功能**（玩家主动开启），必须设硬上限：

| 项 | 上限 |
|----|------|
| 振幅 | **≤ 2 px**（屏幕空间） |
| 时长 | **≤ 120 ms** |
| 频率 | 每次战斗事件最多触发 1 次，不得连续叠加 |
| 可关闭 | **必须可关**，且 Comprehensive 档强制关闭 |
| 与自动镜头的关系 | 抖动不得伴随相机位移（与 UX 侧 M1-M4 一致） |

### 7.3 `maxPolarAngle` 三档统一 0.35π

**修订**：三档统一为 `0.35π`（仰角 27°），不再给 Comprehensive 单独收紧。

- **可读性理由**（UX 侧 R-01，S 级）：R0 的 `π × 0.45` 对应仰角仅 **9°**，是掠射角，一艘舰船可遮蔽其后方 200+ 像素内的全部单位。这影响**所有玩家**，不只是敏感用户。
- **底面免建模依然成立**：见 `ship-assets.md` §3.4 的约束集验算（相机最低高度 3.63 > 最高舰船底面 1.82，余量 2.0×）。底面免建模依赖的是 `maxPolarAngle ≤ 0.35π` **且** `minDistance ≥ 8`，不是某个特定档位值。
- **Comprehensive 的额外保护改由其他手段提供**：更低的旋转速度上限（60°/s vs 120°/s）、「完全锁定相机」、`V` 顶视一键切换。仰角下限解决的是**可读性**，旋转速度解决的是**晕动症**，两者不应混为一谈。

**所有级别都不允许 `maxPolarAngle` 超过 `0.35π`**，也不应提供「解锁自由视角」的开关——这既是可读性下限，也是底面免建模成立的前提。`[PLACEHOLDER · 附验证路径]`

## 8. 与 UX 规格对接

UX 设计必须实现以下设置面板入口：

| # | 面板位置 | 控件 | 文案 |
|---|----------|------|------|
| 1 | **战场显示** section | 滑杆 0-100 step 5 | 「CRT 强度」<br>hint：调节全息战术投影的扫描线 / 色差 / 暗角 / 噪点强度。0% 为纯净 3D 画面，100% 为完整复古 CRT 风格。默认 75%。 |
| 2 | 辅助功能 > 视觉 | 下拉 | 「色盲模式」：关闭 / 自动 / 红绿 / 蓝黄 / 全色盲 |
| 3 | 辅助功能 > 视觉 | 滑杆 + 分项开关 | 「特效强度」：总滑块 + 激光 / 护盾 / 尾焰 分滑块 |
| 4 | 辅助功能 > 视觉 | 总滑杆 + 4 个分项 toggle | 「CRT 后处理」：总强度 + 扫描线 / 色差 / 暗角 / 噪点 独立开关 |
| 5 | 辅助功能 > 视觉 | 开关 | 「关闭全部后处理」：同时关闭 CRT 与 Bloom，画面为纯净 3D 渲染 |
| **9** | 辅助功能 > 视觉 | **按钮**（一次性动作） | **「全部归零」**：一键将特效主控、CRT、Bloom、色差、粒子全部置 0，舰船转为不透明实体。**全档位可见，非 Comprehensive 专属**（可访问性验收硬项，见 §3.5） |
| 6 | 辅助功能 > 视觉 | 开关 | 「高对比模式」：提升舰体实体不透明度并加描边 |
| 7 | 辅助功能 > 操作 | 下拉 / 滑杆 | 「相机运动」：默认限制 / 严格锁定 / 自定义 |
| 8 | 辅助功能 > 界面 | 下拉 | 「文本大小」：1.0x / 1.25x / 1.5x |

**摆放原则**：CRT 总强度放在「战场显示」（语义相邻，玩家调战场模式时顺手调）；CRT 分项开关、「关闭全部后处理」与「全部归零」按钮放在「辅助功能 > 视觉」（面向有明确需求的用户，不干扰普通玩家）。

**「全部归零」必须是一次性按钮而非开关**（UX 侧要求）：它置零的参数包含「特效主控」这类会影响玩法反馈的项，做成开关会让用户误以为关掉后仍能正常游玩战斗反馈。按钮 + 各滑块可手动调回，语义更准确。
