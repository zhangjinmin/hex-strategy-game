# v78 折算按阵位空间序 + 数量量化（用户诊断正确）

日期：2026-10-14。用户实报（**诊断准确**）：
> 阵型中**一半一半**，并不是全部都是模型。就是整个阵型的**后半部分是模型，前半部分是圆点**。
> 镜头拉得更近之后，阵型前部的圆点不见了，**模型也并没有**。
> 会不会是**折算**的问题？折算是把一艘战舰按一定比例折算，折算是固定的，
> 造成只能部分战舰显示，而不是动态的战舰折算，造成模型显示的不全？
> 这个动态折算只能在**切入战场的第一轮计算**，因为后面战损之后阵型是确实要减少的。

---

## 1. 用户判断正确：这是折算问题，不是 LOD 阈值

**决定性证据**（用户自述）：拉近后前部**圆点消失、模型也没有**
⇒ 那些单位不是"没拿到模型的点"，而是**根本不在渲染集里** ⇒ 与 LOD 无关。

## 2. 根因：折算按**数组下标**，而 units 顺序在战损时会错乱

`Battle3DOverlay:3726`（旧）：
```ts
if (!u.sprite || u.sprite.visible === false || u.hp <= 0 || !visibleIndexes.has(ui)) continue;
```

`visibleIndexes` 装的是**数组下标**，而 `fleet.units` 的顺序在战损时会被
`filter` 重赋值、下标整体前移（项目既有行为）⇒ **下标序 ≠ 阵位空间序**。

在错乱的序上做等间隔抽稀 ⇒ 被抽中的下标在空间上**聚集**
⇒ 表现为「某一段全是模型、另一段只有点或干脆没有」。

### 台架量化证据（6 选 3，数组序打乱为 [5,3,0,4,1,2]）

| 路径 | 选中槽位 | 间距 | 结论 |
|---|---|---|---|
| 旧（数组序） | `[2,3,4]` | 1, 1 | **聚集** ← 用户看到的"前后分离" |
| 新（空间序） | `[1,3,5]` | 2, 2 | **均匀** |

## 3. 修复

### 3.1 按阵位空间序折算（核心）

新增 `projectFleetRepresentationBySlot`（`combatRepresentation.ts`）：

1. 按 `formationSlot`（部署期固定、与阵位一一对应）排**空间序**
2. 在空间序上做抽稀
3. 结果映射回原下标

⇒ 战损时是「**整队等比稀疏**」，而不是「砍掉一半/一段」。
⇒ `formationSlot` 缺失时退回下标（零行为变更）；容量 = 全员时跳过排序（零开销）。

### 3.2 数量量化到 5% 档（采纳用户第二条建议）

用户建议「动态折算只能在切入战场的第一轮计算」。
**没有完全采纳**——因为用户同时说「后面战损之后阵型是确实要减少的」，
即减少是期望行为。故取折中：**数量量化到 5% 档**。

```ts
const hpQuant = Math.max(1/20, Math.round(hpPct * 20) / 20);
const requested = Math.max(1, Math.round(visualCapacity * hpQuant));
```

⇒ 血量每变化 5% 才调整一次显示数量 ⇒ 战损仍减少阵型，但**步进稳定**
（原实现连续跟随血量的微小波动 ⇒ 单位忽隐忽现）。
