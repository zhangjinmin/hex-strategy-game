# v37 · 删除「星域棋盘 / 全息战术投影 / 3D 战场」三模式，只留指挥制

> **触发**（用户 2026-09-20）：
> 「后面的游戏模式不会再出现 2d 和格子之类的，可以把设置里面的战场显示去掉，
>   把星域棋盘、全息战术投影、3D 战场这些都删掉，把里面涉及到的代码也删掉 ——
>   因为在战场加载的时候会有一瞬间出现棋盘的内容，而且编写代码的时候经常会出现代码不显示，
>   是因为加载在非指挥模式下的情况。」
>
> **结论**：模式选择（2 处 UI）与三种模式的代码全部删除；**闪现根因是"等 3D 就绪才隐藏 2D 画布"**，
> 已改为**进入战斗立刻隐藏**。L2 验收 **11 PASS / 0 FAIL**（含"加载期零暴露帧"的逐帧断言）。

## 1. 闪现的两条根因（都修了）

| # | 根因 | 证据 | 处置 |
|---|---|---|---|
| **F1** | `battle3d-mode`（隐藏 Phaser 画布的 CSS 类）是在 overlay 的 **`onReady`** 里才加的 —— 而 onReady 要等 3D 地形真正建成（实测 **约 1~2.5 秒**）。那段时间里 Phaser 画布**可见**，画的正是 `buildTileGrid()` 建出来的一整块六角格棋盘 | L2 逐帧采样：修复前"画布存在且未隐藏"的帧 > 0 | 新增 `enter3dMode()`，在**进入战斗时立刻**加类 + `setBattleSceneVisible(false)`；`onReady` 只标记就绪 |
| **F2** | `tryCreate3dOverlay()` 开头调用 `destroyBattle3dOverlay()`，而后者会**移除** `battle3d-mode` 并恢复 2D 画布 ⇒ 每次重试都会把棋盘放出来一帧 | 代码路径 | 拆成 `dispose3dOverlay()`（只销毁实例，不碰可见性）/ `enter3dMode()` / `fallbackTo2D()`（降级时才恢复 2D） |

> **实测**（`_probe_nomode.mjs`，逐帧 rAF 采样）：
> ```
> 采样 37 帧（覆盖 10830ms）
> 首个画布采样 = {"t":157,"cls":true,"canvas":true,"vis":"hidden"}
> 画布存在但未隐藏的帧 = 0 / 30      ← N2 PASS
> ``` 
> 即：画布出现的**第一个采样帧**就已经被隐藏（`vis: hidden`），加载期一帧棋盘都没露。

## 3. ⚠ 保留的东西（这是有意的，需要你确认）

**Phaser 侧的 2D 画布与地块渲染没有删。** 它现在只剩一个身份：

> **「3D overlay 8 秒内建不起来」时的降级显示。**

理由：`App.vue` 原注释写明该降级兜底的存在意义是「任何情况下都不会出现**两块画布都不可见**的黑屏」。
若把 2D 也删掉，一旦 Three.js 起不来（历史上发生过：第二局 Phaser 重建慢），玩家看到的将是**全黑**。

因此：
- `buildTileGrid()`（原 `renderHexMap`）仍然建 `tilesList`/`tilesDict` —— **这是刚需**，
  AI 的探索/目标选择、占领、补给判定全部读它，删掉会让舰队原地不动；
- 每格仍建一个 `poly`/`txt` **占位对象**（正常战斗中不可见），只为占领/买地逻辑调用
  `setFillStyle`/`setText` 时有落点（对象不存在会抛错）；
- 已在该函数头部写明这段身份，并把函数名从 `renderHexMap` 改成 `buildTileGrid`（原名已误导）。

**如果你要连降级路径一起删**（即"3D 起不来就黑屏"），告诉我，这是 1 行开关的事：
把 `App.vue` 的 8 秒 `fallbackTo2D()` 改成只打日志即可。

### ⚠ 实施过程中的两个自查

1. **判据写错一次**：N2c 初版断言"画布出现前的**每一帧** cls 都必须为 true" —— 实测前 2 帧
   `cls=false`（那两帧战斗还没开始，`gameState` 仍是 `sim`）⇒ 是**判据错了**，不是实现错了。
   改为"**画布出现的第一个采样帧就已经被隐藏**"（这才是"类先于画布生效"的正确表述）。
2. **brace 配平被破坏 3 处**：脚本化删除 `if/else` 包裹时，有三次"被删区间没有包含右花括号"
   或"多留了一个右花括号"。**有意思的是总括号数刚好配平**（一处多、一处少互相抵消），
   所以"数括号"这种检查发现不了 —— 最后靠 `vue-tsc` 的语法错误定位修正。
   教训：**脚本化删除块状代码后必须跑一次真编译器，不能只看括号计数。**

## 5. 未做 / 风险

- **未做**：hex `'3d'` 模式残留的难度是 0（已随 `buildTerrain` 删除）；
  但 `Battle3DOverlay` 里 `heightAtPx()` 保留了**同名常量桩**（恒返回 0），因为纯宇宙地面就是 y=0，
  4 个调用点（单位放置 / 舰体基准高 / 补给圈 / 巡航高度）因此零改动 —— 行为与删除前**逐位一致**。
- **风险**：唯一的降级路径（2D 棋盘）现在是"死代码候选"。若你确认永远不需要它，
  下一批可以把 `buildTileGrid` 的视觉部分一并删掉（**数据部分必须留**）。
- **存档兼容**：旧存档里的 `battlefieldMode` 字段不再被读取（`load()` 不再校验），
  不影响其他设置项；下一次 `save()` 会自然把它写掉（已由 N4b 验证）。
