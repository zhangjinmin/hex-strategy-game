### 2.1 为什么新建 `dispatchDeployAction` 而不复用 `dispatchFleetCommand`

既有通道 `dispatchFleetCommand(id, type, payload)` 的接收侧要求
`globalFleets.find(f => f.id === id || f.factionId === id || f.commanderId === id)` 且 `fac.team === 1`
—— 它回答的是"**对某支己方舰队**下令"。而 `start`（开战）/ `formation` / `tactic` 是**全局动作**，
没有舰队可指。借道会触发布阵权限校验并产出无意义的 toast（"你只能直接指挥总指挥旗舰"）。
故新增一条同构但**不带 id** 的通道，接收侧只做取值域校验 + 部署期判定。

### 2.2 为什么内嵌 `CouncilWarRoom` 而不复制它的表单

任务指派（任务类型 / 目标下拉 / 下达 / 总指挥确认卡）逻辑若不共享，必然出现两份实现并互相漂移
（本项目已有先例：`formationTierLayout` 两处重复实现）。故给它加 `embedded` 呈现模式，
由全屏层内嵌渲染；部署期它不再作为独立侧栏出现，**同一功能只有一个入口**。

```ts
// CouncilWarRoom.vue
const visible = computed(() => (props.embedded ? true : (warRoomOpen.value && !deployPhase.value)));
```

## 5. 探针自身的两个坑（本轮踩到，已记入记忆）

1. **文案带字距空格**：按钮是「⚔ 开 始 战 斗」，`textContent.includes('开始战斗')` **永远为 false**
   ⇒ 表现为"点不到按钮"，差点被读成实现缺陷。**匹配前必须归一空白**。
2. **无头环境 `setInterval` 被节流**：SwiftShader + 主线程繁忙时，`setInterval(22ms)` 退化为每帧一次，
   1.4s 只推进 **7 字** ⇒ 打字机类断言必须按"帧环境"放宽等待（改用 3.2s）。
   同类教训：**无头 3fps 下不要用真机时间直觉设阈值**。
