## 1. 「刚开局」排除了折算路径

开局 `hpPct = 1` ⇒ `projectFleetRepresentationBySlot` 的 `requested = capacity`
⇒ **不裁剪任何单位**。⇒ v78 的折算修复（方向正确，对战中生效）**不是本现象的原因**。

⇒ **需要重新定位。**

## 2. 已确认的事实链

| 事实 | 依据 |
|---|---|
| `fleetPx` **确在决策路径上** | 3813/3815（实体分配）、3977（grow）、4161（统计）均用 `v.fleetPx` |
| 同一 `fleet` 对象内部 `fleetPx` **必然统一** | `fleetPx` 由 `acc.get(v.fleet)` 按 fleet 引用聚合均值 |
| ⇒ 同线一半模型一半点 | **必然属于不同的 `fleet` 对象** |

候选（不同 fleet 对象）：
1. **分舰队**（`_detachedFrom`）—— 但「刚开局」通常未分兵
2. **侦察伪舰队**（`getRenderableFleets` 追加 `scoutFlights`）—— 数量少
3. **同阵营相邻的两支舰队** —— 视觉上排成一条线，实为两队

## 3. 本轮交付

### 3.1 诊断面板（`?debug=1`）

在 `syncShips` 第二遍之后（实体已定）收集并显示：

```
tier=FAR lo=14 hi=26 keep=17
<fleetId>  n=<单位数>  px=<fleetPx均值>  mesh=<已获实体数>  MODEL|FADE|DOT
```

**判读方法**：
- 若面板显示**多行**（多支 fleet）各自 px 不同 ⇒ 「多队视觉相邻」⇒ 非 bug，
  可用**舰队间距/标记**区分
- 若**单行**内 `mesh < n`（同队部分无实体）⇒ `fleetPx` 聚合失效 ⇒ 真 bug

⚠ 未带 `?debug=1` 时零开销（不创建 DOM）。

### 3.2 过渡带"点让位"硬截断（恢复 v73 行为，v75 曾删除）

```ts
if (hasMesh && grow > 0.5) return 0;   // 点不再与半透明模型重叠
```

**理由**：若整队 `fleetPx` 落在过渡带（`lodLo~lodHi`），则 `grow ≈ 0.5 ∀成员`
⇒ 整队同时呈现「半透明模型 + 未消失的点」⇒ 用户读作「点+模型共存」。
连续 alpha 衰减（v75 回归的"最早行为"）在 grow=0.5 时点仍有 0.39 alpha ⇒ **不解决重叠**。

硬截断后视觉是单向流动「点 → 半透明模型 → 实心模型」，不再重叠。
