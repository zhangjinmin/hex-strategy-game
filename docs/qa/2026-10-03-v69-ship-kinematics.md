## 1. 病根确认（实测代码，非推断）

用户实报「移动还是不行」。测绘后确认**旧实现的运动学在三个层面上同时失效**：

| # | 病灶 | 位置 | 实测值 |
|---|---|---|---|
| A | **舰种完全同质** | `u.speed` 在 `BattleScene:1518` 被解构后同函数内再未出现 | 全项目仅 2 处引用（写入:1580 / 报告:1461）**均非运动学** |
| B | **转弯半径小于舰长** | R = v/ω = 0.30/(π/240) | R = **22.9px**，战列舰长 33px ⇒ **R/L = 0.69** |
| C | **掉头快档绕过全部物理** | `:7152` `uStep = HEADING_TURN_RATE * RATE_MUL(6) * rateMul` | 战列 180° = **0.67s**（270°/s，物理不可能） |

**C 是「改了参数还是不行」的直接原因**：该分支绕过正常档的角速度惯量与制动律，
即使把 `HEADING_TURN_RATE` 调小也会被 `RATE_MUL=6` 乘回来。

## 4. 关键设计决策

### 4.1 舰队剖面按 hullLen² 加权（不是算术平均）

```ts
const w = k.hullLen * k.hullLen;   // 面积/质量权重
vMax = Σ(k.vMax·w) / Σw
```

**理由**：一支 8 战列 + 2 驱逐的舰队，其"机动性格"应接近**战列**（重舰决定航迹）。
算术平均会让 2 驱逐把整体拉到"中速" —— 这正是"五舰种同质"的另一种表现。

台架实测：8 战列+2 驱逐 ⇒ vMax 0.241，纯战列 0.220（差 9.5%），纯驱逐 0.520。

**排除 '补给'**：运输舰参数极重（vMax 0.16），若参与加权会把整队拖成龟速。

### 4.2 高速舵效衰减（旧实现角速率与速度完全无关）

```
ω_eff = ω_max × (1 − 0.45 × speed/vMax)
```
战列全速时 ω 上限降 45% ⇒ 掉头从 14.3s 拉到 **25.9s**。这正是"沉重"的来源。

### 4.3 应急路径不得慢于旧值（两处 min 钳制）

```ts
accel     = min(kinProfile.accel,     FLEET_ACCEL)     × dt
rateAccel = min(kinProfile.alphaMax,  TURN_RATE_ACCEL) × dt
```

**理由**：溃散档（3× 速度倍率）与 uturn 快档是**应急机制**。若新参数把它们拖慢，
撤退/溃散会变成龟速，玩家会觉得"卡住了"。钳制保证应急路径行为不回退。

### 4.4 掉头快档同步改造（最关键的一处）

```ts
// 旧：uStep = HEADING_TURN_RATE * RATE_MUL(6) * rateMul * dt     ← 绕过全部新参数
// 新：uStep = kinOmegaNow * RATE_MUL(6) * rateMul * dt          ← 走舰种 + 速度衰减
```
战列 free 档 180° 从 0.67s → **2.4s**。仍是"应急快转"，但不再是瞬时扭头。

### 4.5 声明顺序：剖面必须早于 headingStep（const TDZ）

`headingStep`（转向）与 `fleetBaseSpeed`（速度）分处函数前后，但共用同一 `kinProfile`。
`const` 无提升 ⇒ 剖面计算**必须**放在 `headingStep` 声明之前，否则运行时报 TDZ。

## 5. 开发中踩的三个坑

### 5.1 hullLen 填错（台架 G 组抓出，真数据错误）

我按"设计意图"填了高战 30 / 空母 40 / 舰载 12，但**部署期真源**（`BattleScene:1585-1593`）是：

```
isFlagship → 42 | 战列/突击 → 33 | 巡洋/电子 → 25 | 补给 → 40 | 其余 → 18
```

R/L 判据的分母是 hullLen，**填错则整个判据失效**。已全部对齐，并加台架 G 组逐项断言。

### 5.2 ramp 判据方向反了（台架 C 组）

`速度达到 95% 的秒数` **越大 = 越慢起步 = 越重**。我原断言写成 `空母 < 战列 < 巡洋 < 驱逐`，
与物理相反。数据本身是对的（11.9 / 8.3 / 5.6 / 3.8s），是判据写反。

### 5.3 自己写了一个恒等花招并当场清除

接线 `rateAccel` 时写了：

```ts
const kinAlpha = (kinProfile.omegaMax / Math.max(1e-6, kinProfile.omegaMax / (... ?? 7.2e-4))) * dt;
```

这个式子 `(x/(x/y)) = y` **恒等于 `TURN_RATE_ACCEL`**，即"看起来按舰种缩放、实际没生效"。
**自查发现后改为真实 `kinProfile.alphaMax`**，并给 `FleetKinematicsProfile` 补 `alphaMax` 字段。

教训：写完立刻用台架验一遍数值是否真变了，不要相信"看起来对"的表达式。
