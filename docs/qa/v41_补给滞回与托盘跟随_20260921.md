## 1. 「掉头掉一半又掉回来」—— 决策振荡（三层叠加）

| # | 成因 | 修复 |
|---|---|---|
| **1a** | `supplyDecision` **每帧独立判定，无滞回**。会合途中补给回升过 75 ⇒ 翻回 hold/pursue ⇒ 第二次大掉头 | **S-H 回程锁定**（真源内，可断言）：`prevAction === 'return'` 时，只有**强恢复证据**（supply ≥ 90 / 已进补给网 / 船已到附近）才允许翻回；否则维持 return（规则名 `S-H 回程锁定`） |
| **1b** | 「船就在后面不远处」却掉头去会合——会合在**几何上就是掉头**（船从后方来） | **S0 船近停等**（新规则，插在断粮之后）：`supplyShipNear`（船距 < 8×hexR）⇒ **hold 原地停船**，任何进取度/敌态不变。寻路侧配合（`:4825` 分支拆成 near/nearAux）：**近时停船、远时才双向会合** |
| **1c** | 振荡产生的转向多落在 **90~150°**，恰低于掉头吸附阈值 150° ⇒ 走 rateLimit 连续旋转 = **弧线绕圈**（复报多次的「绕点画圈」在振荡场景的还魂） | 吸附阈值 **150° → 90°**（`balance.FORMATION_SPIN.SNAP_MIN_RAD`）；订正 `:5338` 旧注释——「90° 必须连续旋转否则横阵变纵阵」的担心不成立：吸附改的是 formFacing 真源，格位集合按新朝向重排，横阵旋转后仍是横阵 |

**设计决定（台架钉死）**：S0 优先于 S1 —— 断粮（<15%）但船就在旁边时，停下等补给而不是回港。这就是用户说的「哪怕停下来都比掉个头好」。

**实现说明**：`SupplySituation` 新增 `supplyShipNear` 与 `prevAction`（舰队上帧 `_supplyAction` 回传）；`supplyDecision` 拆为 `decideSupplyRaw`（原表）+ 滞回包装，纯函数可整体台架断言。
