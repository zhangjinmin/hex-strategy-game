## §0 全局常量与时间基准（已证实）

| 项 | 值 | 出处 |
|---|---|---|
| 时间基 `dt` | `const dt = this.store.currentSpeedFactor;`（0.5–3，默认 1） | `:3607`（`update(time, delta)` 见 `:3590`） |
| 真实帧时长 `delta` | 毫秒；**仅**在 morph 推进处被消费（`:4569`），运动学主路径**不使用** | `:3590` |
| 限速航向角速率 `HEADING_TURN_RATE` | `Math.PI / 120` = **0.0261799 rad/帧** = 1.5°/帧（**按帧，不按秒**） | `:76` |
| 单帧转角 `headingStep` | `HEADING_TURN_RATE * dt` | `:4426` |
| 阵型 morph 时长 `FORMATION_MORPH_DUR` | 3.5（秒，经 `delta/1000*dt` 推进） | `:68`, `:4569` |
| 阵型格距 `FORMATION_SPACING` | 26 px（超足迹预算时压缩） | `formationLayout.ts:35`, `:425` |
| 基础航速 `fleetBaseSpeed` | `(0.30 + mobility*0.003) * supplyFactor * moraleMult * retreatBonus * cpMult`，默认≈0.30 px/帧 | `:4471` |
| 接火内圈速度 `engageSpeed` | `0.05 * retreatSpeedBonus` px/帧 | `:4483` |
| 撤退加速 `retreatSpeedBonus` | 3.0 | `:4468` |
| 友军排斥（<80px） | `force = (80 - fDist) * 0.02`，上限 1.6 px/帧 | `:4440-4443` |
| 敌我排斥（<200px） | `force = (200 - fDist) * 0.015`，上限 3.0 px/帧 | `:4445-4451` |
| 拥堵减速 `congestionSlowdown` | 0.3–1.0 | `:4463-4467` |
| 理想交战距 `idealDist` | 560 / 700 / 800 / 880（按舰种） | `:2632-2651` |
| 接战门槛 `engageDist` | 900（常规）/ 1000（攻坚） | `:3968` |

> 关键口径：**位移 = speed * dt（px/帧 × 倍率）**；**时长 = xxx / dt（毫秒 ÷ 倍率）**。`HEADING_TURN_RATE` 的步长 `* dt` 因此与位移同源——但它**不乘 `delta`**，所以限速转向在真实时间轴上是**帧率相关**的（见 §2.1 数值）。

## §1 现象①「攻击时舰队后退，像被打中后坐」

### 1.1 根因【已证实·代码事实】

唯一专职「后退」写入点：`:4860-4866`（逐发开火命中后，直接给**目标舰队坐标**加固定位移）：

```ts
// === 受击后坐力：被命中的舰队轻微后推 ===
if (closestEnemyFleet && closestEnemyFleet.units.length > 0) {
    const knockDir = Math.atan2(closestEnemyFleet.y - u.sprite.y, closestEnemyFleet.x - u.sprite.x);
    const knockForce = (finalDmg / Math.max(1, targetShip.maxHp)) * 8; // 按伤害比例后推
    closestEnemyFleet.x += Math.cos(knockDir) * knockForce;
    closestEnemyFleet.y += Math.sin(knockDir) * knockForce;
}
```

**触发条件**：`fleet.state==='engaging'` 且该舰 `time - u.lastAtkTime > u.atkInterval/dt`（开火门 `:4667`），且 `targetShip` 非空（`:4674-4677` 从 `closestEnemyFleet.units` 中射程内**随机**取一艘），且 `closestEnemyFleet` 存在。

**性质（三点，均为已证实事实）**：
1. **作用对象是目标舰队（`closestEnemyFleet`）**，不是开火方自己。`:4830` 的 `fleet.units.forEach((u` 里，`closestEnemyFleet` 归属于 `fleet` 的敌方（`:3830` 过滤 `efFac.team !== myFac.team`）。
2. **是"坐标瞬移"而非"速度/冲量"**：直接 `+=` 到 `fleet.x/y`（位置量，**不乘 dt**、无速度态、无衰减、无上限）。与之对比，全文件唯一的常规位移写入 `:4494-4495` 是速度 × dt。
3. **逐发累加、线性叠加**：没有去重、没有每帧上限、没有目标锁定；命中几次就加几次。

**数值量级（用真实常量算出）**：

| 目标舰种 | `maxHp` | 典型 `finalDmg`≈ | 单发 `knockForce` = (dmg/maxHp)*8 |
|---|---|---|---|
| 战列 | 2000 | ≈ atk 150 − def ≈ 130 | ≈ **0.52 px/发** |
| 巡洋 | 1200 | ≈ 90 − def ≈ 80 | ≈ **0.53 px/发** |
| 驱逐 | 800 | ≈ 120 − def ≈ 110 | ≈ **1.10 px/发** |
| 保底（`finalDmg = maxHp*0.01`，`:4730`） | — | 1% maxHp | **0.08 px/发** |

- 单发区间 ≈ **0.08 – 1.5 px**；理论上限（一发打掉整条 maxHp）**8 px**。
- 舰队级速率：演习路径每实体 1 艘 = 500 兵（`shipScaling.ts:24,468`），一支 10 实体舰队在 dt=1 时各舰 1.8–3.5s 开火一次 ⇒ 约 **5 发/秒** ⇒ 目标舰队被推 ≈ **0.5–5 px/s**（dt=3 ⇒ 约 ×3 ≈ 15 px/s，因开火间隔 `atkInterval/dt` 随倍率缩短）。
- **同帧最坏累加**：若 k 支敌舰队 × m 实体在**同一帧**全部命中同一目标舰队（`+=` 无条件线性叠加），displacement = ΣKnock。取 3 舰队 × 10 实体、均值 0.8 px ⇒ **单帧约 24 px 瞬移**。（常态因初始开火相位错位 `:1020`/`:1194` 而分散，此最坏需相位对齐或长帧——标注【推测】需真机。）

### 1.3 两个修复候选

**候选 A（根因修复·首选）——把后坐力从"位置瞬移"改为"有界冲量速度"，并移出逐发直写**
- 做法：新增 `fleet._knockVX/_knockVY` 速度态；命中时 `_knockV += dir * (finalDmg/maxHp) * K`（K 小），在 W1 处按指数衰减并入 `rawV`（`_knockV *= 0.85`，并 clamp 到上限，如 1.5 px/帧）。位置不再被逐发直写。

- 附带修 (a)(b)：冲量方向改用**舰队质心差**而非单舰 `u.sprite`，消除包围时的方向反转（见 §4-(b)）。

**候选 B（最小改动·次选）——直接删除后坐力块，或改为纯视觉**
- 做法：删除 `:4860-4866`；改在命中处只做精灵抖动/护盾涟漪（已有 `:4881,4889-4915`），不动舰队坐标。
- 取舍：改动面 **极小**（删 7 行）；立即消除"后退"，但失去受击反馈的位移感（可接受，太空战本无整队后坐）；不触 3D。**风险最低**。
- 不推荐"仅调小 8 为 1"这类安抚（不解决位置瞬移 + 逐发累加 + 方向语义三个根因）。

## §2 现象②「三心二意：一会朝这边、一会朝那边」

### 2.1 根因【已证实·代码事实 + 一处强嫌疑】

现象②牵涉一并作用的三条链，按确定性排序：

**(i) `flankAngle` 每帧 `Math.random()` 选边——最强嫌疑，纯代码可证**

`:4202-4210`（每帧每舰队执行）：
```ts
const enemyAngle = closestEnemyFleet.facingAngle || 0;
const flankAngle = enemyAngle + Math.PI + (Math.random() > 0.5 ? Math.PI/4 : -Math.PI/4); // :4205
```
`flankAngle` 无缓存，**每帧重新掷骰**取 ±45°。它被用于侧翼/包抄目标 `:4246-4247` 与 `:4254-4255`：`fleetTarget = enemy + dir(flankAngle)*idealDist`。

数值推演（敌人原点、`idealDist=800`、己方在敌 +x 侧 300px，`dt=1`）：
- 帧 t：取 `+π/4` ⇒ `flankAngle=225°` ⇒ 目标 `(-565.7,-565.7)` ⇒ 由己方指向目标的角 = **213.2°**
- 帧 t+1：掷到 `-π/4` ⇒ `flankAngle=135°` ⇒ 目标 `(-565.7,+565.7)` ⇒ 指向角 = **146.8°**
- 帧 t+2：再掷回 `+π/4` ⇒ 回到 **213.2°**

⇒ `moveAngle/fAngle` 的**目标方向逐帧在 ±66° 间翻相**（近距离可达 ±73°，贴近理想距时约 ±45°）。而限速器单帧只能走 `headingStep = 1.5°/帧`，**远追不上**（66 ÷ 1.5 ≈ 44 帧才走完一次摆幅）。结果 `heading`/`facingSmooth` 在两点角平分线附近**随机游走、左右晃**——正是"三心二意"。

**(ii) `closestEnemyFleet` 每帧两次重算、无滞回——可疑，代码可证其机制**

- 第一遍（`:3826-3847`）：取视野内**非 fuzzy**（`clarity !== 'fuzzy'`）中**最近**者。
- 第二遍（`:3978-3993`）：`engaging` 下再用评分 `score = (1-eHpPct)*300 - ve.dist + ePower*0.1` 在 **`visibleEnemies` 全体（含 fuzzy！）** 中重选 `bestTarget` 并覆写 `closestEnemyFleet`。
- **无任何滞回/锁定**：`fleet._lastTargetFleetId` 只写不读（仅用于友军协同计数 `:4005,4017`），**不参与粘连**。
⇒ 两个近等分目标（残血比/距离/战力接近）会**帧间交替当选**。而 `fAngle` 在"停船锁定"分支直接取 `closestEnemyFleet` 方向（`:4412`），在接近分支经 `fleetTarget`（其位置取自 `closestEnemyFleet`，`:4235/4246/4254/4258`）间接依赖 ⇒ 目标一翻，`fAngle` 目标即反向 ⇒ 同 (i) 的追不上。

**(iii) 双平滑器的结构代价**（`:4416-4431`）
```ts
const headingStep = HEADING_TURN_RATE * dt;              // :4426
if (typeof fleet.heading !== 'number') fleet.heading = moveAngle;      // :4427
if (typeof fleet.facingSmooth !== 'number') fleet.facingSmooth = fAngle; // :4428
fleet.heading      = rateLimitAngle(fleet.heading, moveAngle, headingStep); // :4429
fleet.facingSmooth = rateLimitAngle(fleet.facingSmooth, fAngle, headingStep); // :4430
```
两个目标角 (`moveAngle=位移方向`, `fAngle=舰首`) 都可能因 (i)(ii) 逐帧反相；限速器 (`rateLimitAngle` `:81-86`) 只能缓和、不能消除，故表现为**持续摆动**而非静止。

**转向速率数值（已证实）**：`headingStep = 0.0261799 * dt` rad/帧。
- dt=1 @60fps：90°=60 帧=**1.00 s**；180°=120 帧=**2.00 s**。
- dt=1 @30fps：90°=**2.00 s**（**帧率相关**：转速随帧率腰斩/翻倍——因为步长乘 `dt` 而**不乘 `delta`**）。
- dt=3 @60fps：90°=20 帧=**0.33 s**。
⇒ 注释 `:74-75` 声称"1.5°/帧 @60fps = 90°/s"仅在高帧率且 dt=1 时成立。

## §3 现象③「转向像绕阵型某点公转，不像物理舰船转向」

### 3.1 舰队坐标更新的确切表达式【已证实】

常规位移**唯一**来源 `:4494-4495`：
```ts
fleet.x += rawVX;
fleet.y += rawVY;
```
其右端（取分支 C/D 的通式）：
```
rawVX = ( cos(fleet.heading) * SPEED * terrainSpeedMul + repulseX ) * dt * congestionSlowdown
rawVY = ( sin(fleet.heading) * SPEED * terrainSpeedMul + repulseY ) * dt * congestionSlowdown
```
逐项语义：

| 项 | 语义 | 出处 |
|---|---|---|
| `fleet.heading` | **平滑后的位移航向**（rateLimit 后的 `moveAngle`）——**位移的唯一方向来源** | `:4429` → `:4485,4489` |
| `SPEED` | 分支 C：`0.05*retreatBonus`；分支 D：`fleetBaseSpeed`（≈0.30 px/帧） | `:4483,4471` |
| `terrainSpeedMul` | 地形移动修正 | `:4474` |
| `repulseX/Y` | 友/敌排斥合力（**逐帧无条件累加**，上限 1.6/3.0 px/帧/邻居） | `:4433-4454` |
| `dt` | 速度倍率（0.5–3） | `:3607` |
| `congestionSlowdown` | 近敌减速 0.3–1.0 | `:4463-4467` |

**阵位旋转**（把 `facingSmooth` 施加到槽位偏移，`:4604-4607`）：
```ts
const rx = ox*cos(facingSmooth) - oy*sin(facingSmooth);
const ry = ox*sin(facingSmooth) + oy*cos(facingSmooth);
const targetUnitX = fleet.x + rx + breatheX;   // :4614
u.sprite.x += (targetUnitX - u.sprite.x) * unitLerp;   // :4621, unitLerp<=0.08
u.sprite.rotation = fleet.facingSmooth;        // :4627
```
即：**舰队质心沿 `heading` 平移**；**每艘舰的槽位（含 3D 舰首）绕质心按 `facingSmooth` 旋转**；单舰再以阻尼 lerp 追自己的槽位。

**判定：**
- **舰队质心本身不被阵型牵引**——阵位只作用于 `u.sprite`（`:4614-4622`），**不回写 `fleet.x/y`**。所以"公转"**不能**是"质心被阵位拉动"。
- 但"转向 = 阵位绕质心旋转"是**代码事实**：`facingSmooth` 变化时，每艘舰沿半径 `|(ox,oy)|` 的圆绕质心走 ⇒ **视觉上整个阵型绕一个中心点转圈**，而不是"各舰原地 yaw"。这与用户"基于阵型的一个点绕圈，不是物理舰船转向"的直觉一致【推测·待真机确认观测点】。

**另一种"大半径公转"【推测】——追一个绕敌公转的目标点**：
`:4246/4254` 的侧翼目标 = `enemy + dir(flankAngle)*idealDist`，是**以敌为心、半径 idealDist 的圆上一点**；`flankAngle = enemyAngle + π ± π/4` 随 `enemyAngle`（敌之 `facingAngle`）变化而转动 ⇒ 该目标点**绕敌公转** ⇒ 己方以 `heading` 追之 ⇒ 己方也绕敌公转。`:4258` 的标准接近目标点 `enemy - dir(approachAngle)*idealDist` 亦随 `approachAngle` 移动。

**3–5 帧数值推演（侧翼目标随敌转向的弧线，dt=1）**：
设敌 E 在原点、`idealDist=800`、己方 F 在 (0,300)、选边固定为 `+π/4`、`enemyAngle` 以自身限速 1.5°/帧递增：
- 帧0：θ=0° ⇒ flank=225° ⇒ 目标 `(-565.7,-565.7)` ⇒ F→目标方向 ≈ **236.8°**
- 帧1：θ=1.5° ⇒ flank=226.5° ⇒ 目标 `(-551.5,-580.6)` ⇒ 方向 ≈ **237.9°**（Δ≈1.1°）
- 帧2：θ=3° ⇒ flank=228° ⇒ 目标 `(-535.5,-594.5)` ⇒ 方向 ≈ **239.1°**（Δ≈1.2°）
- 帧3：θ=4.5° ⇒ 方向 ≈ **240.3°**（Δ≈1.2°）

⇒ 目标点与期望航向以≈敌转速率**持续旋转** ⇒ 己方 `heading` 被 `rateLimit` 拉到 1.5°/帧上限后**恒追不上** ⇒ 己方沿一段稳定弧线**持续绕敌打转**（大半径公转）。这不是"到位即停"，而是**追一个永动的点**。

### 3.3 两个修复候选

**候选 A（根因修复·首选）——把"转向"从"阵位旋转"解耦为"单舰 yaw + 阵型整体平移"**
- 转向时：`u.sprite.rotation` 走 `facingSmooth`（各舰绕自身转），但**阵位偏移 `rx/ry` 的旋转改用一条独立、更慢的 `_formSpin`**（或直接不随朝向旋转、只做 morph 插值），使"阵型不再绕质心整块旋转"。
- 配套：`flankAngle` 选边锁定 + 目标滞回（§2.3 A）以消除"追永动点"⇒ 到位即停，不再公转。
- 取舍：改动面 **中-大**（动 `:4606-4607` 旋转源 + `:4205`/`:3978-3993`）；会改变既有"入阵/转向"观感，需真机比对；**触及 3D**（3D 消费 `facingSmooth` 作舰首，若 `facingSmooth` 语义不变则 3D 无需改，但"阵位旋转源"改了不动 3D）。

**候选 B（低成本·次选）——锁 `flankAngle` 选边 + 目标滞回，使目标点静止**
- 不改阵位旋转；仅让 `fleetTarget` 不再逐帧跳动 ⇒ 舰队到位后 `distToTarget<5` 进入 `:4410` 停船分支，`heading` 不再被永动目标拖拽 ⇒ 大半径公转消失。
- 取舍：改动面 **小**（`:4205` + `:3978-3993`）；**不触 3D**；但"到位后阵位仍会绕质心旋转"（小半径转圈）保留——若用户主诉是"整块绕圈"，B 不足，须 A。

## §4 四个疑点的直接回答

**(a) 现象①不自然感：位移过大 vs 位置瞬移？同帧多舰累加？最坏值？**
- **两者皆是，但本质是"位置瞬移"**：`knockForce` 直接 `+=` 到 `fleet.x/y`（`:4864-4865`），是**位置量、无速度态、不乘 dt、无衰减/上限**（对比常规 W1 是 `speed*dt`）。量级本身不大（单发 0.08–1.5 px，上限 8 px），但"非连续速度"的语义使任意一发都读作一次**跳变**，且方向由 `u.sprite`→目标质心决定，会随单舰位置摆动。
- **同帧累加：是，线性 `+=` 无条件叠加**。`closestEnemyFleet.x += ...` 在逐发循环内被调用 N 次即叠加 N 次，无去重/上限。
- **最坏数值**：k 敌舰队 × m 实体同帧命中同一目标。取 3×10、均值 0.8 px ⇒ **单帧 ≈24 px 瞬移**；若触发 `minDmg=1%maxHp` 保底且相位对齐，量级仍同阶（保底单发 0.08 px，但发数多）。**该最坏需相位对齐/长帧**（初始相位错位 `:1020/:1194` 使常态更分散）——标注【推测·需真机】。

**(b) 方向语义：`u.sprite`（单舰）推 `fleet`（舰队）坐标，会否在偏移时反向摇摆？**
- **会。** `knockDir = atan2(fleet.y - u.sprite.y, fleet.x - u.sprite.x)`（`:4862`）取"开火单舰 → 目标舰队质心"，对**不同开口单舰方向不同**。两舰交战时大体一致（≈背离射手）；但**包围/合围**（`formation='circle'`，多名开火方分处目标四周）时，处在目标另一侧的单舰给出的 `knockDir` **指向目标质心的反方向**，与其它舰部分抵消甚至令目标被推向射手。⇒ 推力方向**随开火舰位置摇摆/反向**，加剧"诡异后退"。【已证实为代码事实；包围场景的实际观感需真机确认】

**(c) 现象②"三心二意"：`fAngle` 依赖 `closestEnemyFleet` 帧间切换？追 `closestEnemyFleet` 选取代码**
- **是，确有此路径**（见 §2.1-(ii)）：选取代码**每帧两遍重算**——最近非 fuzzy（`:3841-3847`）+ 评分最优且**遍历含 fuzzy 的全体**（`:3978-3993`，评分 `(1-eHpPct)*300 - dist + ePower*0.1`）；**无滞回、无锁定**（`_lastTargetFleetId` 只写不读）。
- **距离阈值**：第一遍仅纳入 `d < visionRange`（基础 `200*scaleFactor + 情报*2 + 电子*30`，`:2659`）且 `clarity != 'fuzzy'`（fuzzy = `d > visionRange*0.8`）；第二遍在 `minFleetDist < engageDist`（900/1000）时对 `visibleEnemies` 全体评分。
- **判定**：**存在"两个近等分目标交替当选 ⇒ `fAngle` 帧间反相 ⇒ `rateLimitAngle`（1.5°/帧）追不上 ⇒ 左右摇摆"的代码路径**【已证实机制】；是否为该玩家实报场景的主因，与 (i) `flankAngle` 逐帧随机选边叠加——需真机分离。

**(d) 现象③"绕阵型某点公转"：舰队位置是否被朝向/阵位牵引？给确切表达式；逐项语义；能否由 `moveAngle/heading` 取自"阵位锚点相对目标的方向"解释？**
- **舰队质心不被阵位牵引**（阵位仅作用于 `u.sprite`，`:4614-4622`，不回写 `fleet.x/y`）。
- **质心更新的确切表达式**：`fleet.x += rawVX; fleet.y += rawVY;`（`:4494-4495`），右端 = `(cos/sin(heading)*SPEED*terrain + repulse) * dt * congestion`（项语义见 §3.1 表）。
- **公转的两种可解释来源**：
  1. **阵位绕质心旋转**（`rx/ry` 由 `facingSmooth` 决定，`:4606-4607`）⇒ 视觉上"整块绕一个中心点转"——**代码可证**；是否用户所指的"那个点"（质心）需真机确认。
  2. **追绕敌公转的目标点**（`:4205` 随机选边 + `:4246/4254` 半径 idealDist 的圆上点随 `enemyAngle` 转动）⇒ 己方沿弧线绕敌打转——**代码可证**（§3.1 3 帧推演）。
- "取自某个阵位锚点相对目标的方向"这一假设**不成立**：`moveAngle` 源自 `fleetTarget`（战术目标点，`:4402`），`fleetTarget` 源自 `closestEnemyFleet`/地块/信标/自身（`:4063-4384`），**不取自阵位锚点**。故"公转"不是"阵位锚点几何"直接导致，而是 (1) 阵位旋转视觉 + (2) 永动目标追迹 的合成。
