**断言结果（跨 v3/v4 两次运行稳定复现，共 6 条 FAIL）**：
- `FAIL C3.1 切卡后 cpCommandMode 应归 false（不残留）` → `{"cpCmd":true,"pend":"ecm_jam","candSize":1,"panelVisible":false,"sel":null}`
- `FAIL C3.1 切卡后无高亮残留` → `cpCmd=true candSize=1`

- `FAIL C3.1(DOM) 切卡后 cpCommandMode 应 false` → `{"cp":4,"cpCmd":true,…,"effects":["morale_rally"]}`
- `FAIL C3.1(DOM) 切卡后无高亮残留` → `residHighlight=true`
- `FAIL C3.1(DOM) 切卡后无幽灵执行` → `{"cp0":4,"fid":0.7008959322655236,"r":true,"cp1":2,"ghosts":["morale_rally","ecm_jam"]}`

**违反的验收判据**（派单 C3.1 逐字）：*「目标态中点另一张卡，目标类+非目标类各试，旧选目标态不得残留：`cpCommandMode` 必 false、`targetCandidates` 清空、无高亮残留、CP 正确、`selectedAbilityId` 归 null」* —— **五项中「`cpCommandMode` 归 false / `targetCandidates` 清空 / 无高亮残留」三项不满足**。

**根因（源级确证，非猜测）**：
- `App.vue` L155-160 `handleCommandExecute` 仅执行 `pendingCallback(null)` + `visible=false`，**未通知 BattleScene 退出选目标态**（未调用 `exitTargetSelect` / `closeCommandPanel`）。
- `BattleScene.executeCommandFromPanel`（L2625）末尾虽清 `commandBridge.selectedAbilityId` 并 `store.isPaused=false`，但**不清理 `cpCommandMode`**（实现日志明确记录「不清 `cpCommandMode`」）。
- 对照 `closeCommandPanel`（L2597，清退态）与 `tryExecuteOnFleet`（L2562，清退态）可见此处为**遗漏路径**。

**后果（数据完整性）**：
1. 面板已关、`isPaused=false`，但 `cpCommandMode=true` 残留，敌方高亮继续脉动（误导玩家）。
2. 战场随后任意点击经 `handlePick` 的 `cpCommandMode` 前置分支 → **幽灵执行**：DOM 层 CP `6→4→2`，`effects=["morale_rally","ecm_jam"]` —— **在无面板、无用户意图的情况下二次扣费 2 CP**。这是**状态机泄漏导致的非预期资源消耗**，属对战公平性/数据一致性缺陷。

**严重度**：**Blocker**（选目标态下点任一无目标卡即 100% 触发；直接可复现的二次扣 CP）。
**优先级**：P0。
**修复建议（供 engineering-lead-4 参考，非验证者实现）**：`handleCommandExecute` 在执行非目标类命令时应同步退出选目标态（调用 `closeCommandPanel()` 或补 `exitTargetSelect()` + 清 `cpCommandMode/targetCandidates`），使「执行任何命令」都归一到「清态」路径；或在 `executeCommandFromPanel` 内统一清 `cpCommandMode`。
