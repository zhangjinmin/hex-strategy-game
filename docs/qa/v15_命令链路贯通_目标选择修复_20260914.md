## 1. 缺陷：三条断链（行号为修复前）

| # | 位置 | 现象 |
|:--:|------|------|
| **A** | `CommandPanel.vue` `selectCommand()` | 7 个 `requiresTarget:false` 命令点卡片 → 走 `emit('close')`；`App.handleCommandClose` 把它当"执行信号"，但 `commandBridge.selectedAbilityId` **恒为 null** ⇒ `pendingCallback` 内层 `if(selectedAbilityId)` 为假 ⇒ **静默不执行**（不扣 CP、无效果、无提示）。 |
| **B** | `CommandPanel.vue` + `App.vue` | 4 个 `requiresTarget` 命令点卡片 → 只写 `selectedAbilityId`，无后续；overlay 全屏模态拦截战场点击 ⇒ 玩家点战场触发 `close` ⇒ `pendingCallback(null)` ⇒ **扣 CP 零目标执行**（`ecm_jam` 完全无效）。 |
| **C** | `CommandPanel.vue` `close()` | Esc / ✕ / 点遮罩全部走 `close` = 执行信号 ⇒ **取消被误当执行**。 |

**根因**：`selectedAbilityId`（选择态）与「执行」共用一个 `close` 事件，语义混叠；且目标命令缺"选目标态"与战场拾取通道。

## 2. 修复

### 2.1 事件语义分离（CommandPanel.vue / App.vue）

CommandPanel 新增 4 个 emit，**统一先写 `commandBridge.selectedAbilityId`**：

| emit | 触发 | App 处理 |
|------|------|----------|
| `execute(id)` | 非目标命令点卡片 | `pendingCallback(null)`（内层 `if(selectedAbilityId)` 现为真 ⇒ 执行）→ `visible=false` |
| `select-target(id)` | 目标命令点卡片 | 写 bridge + `bs.enterTargetSelect(id)`；**面板保持打开** |
| `cancel-target()` | 再次点选中卡片 / Esc（已选态） | 清 `selectedAbilityId=null` + `bs.exitTargetSelect('cancel-target')`；**面板不关、暂停不解除** |
| `cancel()` | ✕ / 列表态 Esc | 丢弃 callback（置 null）+ `bs.closeCommandPanel()`（退选 + 关面板 + 恢复实时） |

契约①非目标命令点击=执行；②目标命令点击=进入选目标态；③再次点选中卡片/Esc 一次=退选；④✕、Esc 两次=关面板取消；⑤Space=取消（BattleScene `update` 内接进 `closeCommandPanel`）；⑥**任何取消不扣 CP、不入库 ActiveEffect**；⑦执行/取消后 `selectedAbilityId` 一律归 null。

**Vue→BattleScene 通道**：优先 `getGameInstance()?.scene.getScene('BattleScene')`（与 App.vue 既有 `setBattleSceneVisible` / `tryCreate3dOverlay` 同口径），未就绪时兜底只清桥（无请求字段轮询）。

### 2.2 overlay 非模态化（CommandPanel.vue）

`.command-panel-overlay`：`position:fixed; inset:0` → **`pointer-events:none`**、删 `@click.self`、**去暗色底**；`.command-panel` 本体 `pointer-events:auto`、右侧停靠 `width:320px`（`03` §2）。⇒ 点击穿透到战场用于选目标，`z-index:1200` 仍盖住 3D canvas。

### 2.3 选目标态（BattleScene.ts）

新增公用函数与公共方法：
- `computeValidTargets(casterFleet, pFac)`：可见性复用 `buildStaffBriefing` 口径（友军建筑 300px / 友军舰队 250·450px）+ L1 敌方 + L2 存活 + **L4 收紧 `dist ≤ getVisionRange(旗舰)×0.8`**（07 §2.1，与迷雾 `clarity!=='fuzzy'` 同口径）；按「距旗舰升序，同距 fleetId 升序」排序。
- `enterTargetSelect(abilityId)`：置 `cpCommandMode=true / pendingAbilityId`、写 `targetCandidates`、toast「选择目标：{命令名}｜Esc 取消」、面板保持打开、暂停不解除、**不扣 CP**。
- `tryExecuteOnFleet(fleetId)`：非法 → toast 原因 + **保持选目标态**；合法 → `exitTargetSelect` + `executeCommandFromPanel`（**CP 只在执行成功这一刻扣**）+ 关面板清桥。
- `exitTargetSelect(reason)`：清 `cpCommandMode / pendingAbilityId / targetCandidates`（overlay 每帧据此恢复高亮，无残留）；**不动 isPaused**。
- `closeCommandPanel()`：退选 + 清桥 + `isPaused=false`（✕/Esc/Space/取消共用）。

### 2.4 拾取

- **3D**（`Battle3DOverlay.handlePick` 前置分支）：`cpCommandMode` 时走 `pickFleetAtScreen(clientX, clientY)`——扫 `unitVis`，`sx/sy`（drawingBuffer px）与指针（CSS px → 按 `domElement.width/rect.width` 折算到同口径）最近邻；**只拾取 `targetCandidates` 内合法候选**；阈值 **40 CSS px**，超过视为"点空"→ 静默保持选目标态（07 §5.2/C3）。返回真实 `fleet.id`。
- **2D**（BattleScene `create`）：scene 级 `pointerup`（`getDistance()>30` 过滤拖拽）+ `pickFleetAtWorld`（世界坐标最近邻到候选舰队任一舰 sprite，阈值 40px）。按 `mapStyle` 分流，3D 模式不走此路避免双触发。

### 2.5 候选高亮（最小集）

`Battle3DOverlay.writeFleetMarks`：`cpCommandMode && targetCandidates.has(fid)` 时轮廓亮度脉动 `0.45↔1.0`、周期 1.2s（0.83Hz，07 §3.1）。每帧由既有行重写 ⇒ 退出选目标态后**自动恢复原值、无残留**。不做：编号徽章 / 数字键 / Tab / 雷达 / 包围盒。

### 2.6 无合法目标置灰（07 §6）

`commandBridge` 新增 `hasVisibleTargets`（CommandBridge.ts）；`openCommandPanel` 打开时算一次写入；CommandPanel 对 4 个 `requiresTarget` 卡片置灰 + 原因「当前无可见敌方舰队」。**500ms 动态重算归 2a-2**（本单不做）。

### 2.7 附带修正

`App.vue` 全局 `handleKeyDown` 的 `Escape` 分支：`commandBridge.visible` 为真时提前 `return`，避免命令面板/选目标态下按 Esc 误触发 `returnToMetaMenu`（退出战斗）。

## 5. 取舍与偏离说明

1. **2D 拾取用 `pointerup` 而非派单建议的 `pointerdown`**：2D 相机平移是 `pointermove + isDown`；若用 `pointerdown`，"从敌方舰上起手的平移"会被误判为选目标。改用 `pointerup` + `getDistance()>30` 过滤拖拽，语义与既有 `handleTileClick` 一致。
2. **候选高亮走 `fleetMarks` 轮廓透明度脉动**（派单建议），不新建对象；因 `writeFleetMarks` 每帧重写透明度，退出后自然复位，满足"不残留"。
3. **L4 收紧口径**：候选额外要求 `dist ≤ getVisionRange(旗舰)×0.8`（07 §2.1），比 `buildStaffBriefing` 的宽可见性更严——报告中明确以 07 §2.1 为准。
4. **拾取阈值 40 CSS px**、3D 坐标按 DPR 折算到 `unitVis.sx/sy` 的 drawingBuffer 口径（否则高 DPR 下偏移）。
5. **`hasVisibleTargets` 只在面板打开时算一次**（07 §6 判定时机的一半），500ms 动态重算属 2a-2。
6. **执行后立即关面板恢复实时**（不实现"保持暂停 1.2s"）——该设置项状态为"待定"（`03` §5），不在本单。

## 10. 补丁 2a-1（候选脉动全档可见性）

> 本报告既有小节止于 §7；本节按派单指定编号 §10 追加（§8/§9 未占用）。§1–§7 原样不改（留痕）。

### 10.1 缺陷（修复前，行号为 `Battle3DOverlay.ts` 修复前）
§5.1 复核项的**加重量化**：远景档候选与非候选**零差异**、近景档候选**完全不可见**，即候选脉动只在**中景**一档可见。
根因（`writeFleetMarks`，`refPx` = 全场统一参考 px）：

| 档 | refPx | fadeOut/meshOff | `:2660` base `m.outlineMat.opacity` | 旧 `:2665` `max(base, pulse)` 结果 | 旧 `:2672` `m.outline.visible` |
|----|-------|----------------|-----------------|-----------------|----------------|
| 远景 | ≤ DOT_IN_LO(3.2) | fadeOut=1, meshOff=1 | `min(1, max(1, 1.6)) = 1` | `max(1, pulse∈[0.45,1]) = **1 恒值**`（脉动被吃掉） | `visible=true` |
| 中景 | 5.0–14 | fadeOut=0, meshOff=1 | `min(1, max(0.35, 0.08)) = 0.35` | `max(0.35, pulse)` → **0.45↔1.0**（正常） | `visible=true` |
| 近景 | ≥ MESH_IN_HI(26) | meshOff=0 | `min(1, max(0, 0)) = 0` | `max(0, pulse)` → 0.45↔1.0（**但被 visible=false 吃掉**） | `visible = markerAlpha>0.01 = **false**` |

⇒ 远景：候选 = 非候选 = 1.0（无法区分）；近景：`outline.visible=false`（脉动不可见）。

### 10.2 修法（两处 + 注释标 `[2a-1]`）
**① 候选透明度：直接覆盖 base（去 `max()`）** — 原 `:2661-2666`
```diff
       if (cands && cands.has(fid)) {
         const pulse = 0.45 + 0.55 * (0.5 + 0.5 * Math.sin((this.clock.elapsedTime * 2 * Math.PI) / 1.2));
-        m.outlineMat.opacity = Math.max(m.outlineMat.opacity, pulse);
+        m.outlineMat.opacity = pulse;
       }
```
**② 候选可见性：近景强制可见** — 原 `:2672`
```diff
       m.fill.visible = visible && markerAlpha > 0.02;
-      m.outline.visible = visible;
+      m.outline.visible = visible || (cands !== null && cands.has(fid));
       if (visible) shown += 1;
```
不变式：`cands === null`（非选目标态）时，两处分别退化为「不进分支」与「= `visible`」，与修复前**逐位一致**；`fill.visible`(:2673) 不动；`shown`/`lastStats.marks` 计数口径不动。

> 触发者：quality-lead-3 第三方独立验证（`docs/qa/v15_命令链路贯通_独立验证_20260915.md`）判 BLOCK，C3.1 切卡边界。
> §1–§10 原样不改（留痕）。本补丁只改 `BattleScene.ts` + `App.vue` 两处。

### 11.1 缺陷（Blocker · 幽灵执行二次扣 CP）
**触发**：选目标态下**改点另一张非目标卡** → 面板关闭、命令执行扣费，但选目标态残留 → 之后战场任意点击触发**幽灵执行**，二次扣 CP。

**因果链**（行号为 2a-2 前）：
1. `CommandPanel.vue:131-152 selectCommand`：仅"再次点同一张卡"（`:135`）走取消；点**另一张非目标卡**走 `:148-150 emit('execute')` —— 这是唯一**不经过退态**的切换路径。
2. `App.vue:155-160 handleCommandExecute()`：只做 `pendingCallback(null)` + `visible=false`，**未通知 BattleScene 退态**。
3. `BattleScene.ts:2430-2436 pendingCallback` → `:2632 executeCommandFromPanel(selectedAbilityId, null)` → 执行 + 扣 CP；末尾（`:2636-2638`）只清 `bridge.selectedAbilityId` 与 `isPaused`，**不清 `cpCommandMode`/`pendingAbilityId`/`targetCandidates`**。
4. 残留态下战场点击 → `:402 if (!this.cpCommandMode) return;` 通过 → 拾取 → `:2562 tryExecuteOnFleet(fid)` → `:2563` 两字段皆真 → 命中候选 → **无面板、无用户意图的二次扣费 2 CP**。

**修复前复现**（`_2a_ghost_before_stdout.txt`，DOM 真链）：选目标态点非目标卡后 `{"cpCommandMode":true,"targetCandidates":size1,"residHighlight":true,"panelVisible":false}` ⇒ `T3-a/b/c` 三项 **false**（残留态成立），随后战场点 `tryExecuteOnFleet` 返回 **true**（幽灵路径可达）。

### 11.2 修法（两处，均改）
**Edit 1（根因）— `BattleScene.ts executeCommandFromPanel` 方法体首行（`if (!this.cpState) return;` 之前）前置退态：**
```diff
     private executeCommandFromPanel(abilityId: string, targetFleetId: number | null) {
+        // [2a-2] BUG-1 修复：执行即退选目标态。此前本方法只清 bridge，不清
+        //   cpCommandMode/pendingAbilityId/targetCandidates ⇒ 选目标态切非目标卡执行后残留 ⇒
+        //   战场点击被 2D/3D 拾取当作合法目标 ⇒ 无面板、无用户意图的"幽灵执行"二次扣 CP。
+        //   exitTargetSelect 幂等（tryExecuteOnFleet 已先调 'done'，此处再调无副作用）；
+        //   本方法不依赖上述三字段（abilityId 由参数传入），故可安全前置。
+        this.exitTargetSelect('execute-other');
         if (!this.cpState) return;
```
**Edit 2（契约层双保险）— `App.vue handleCommandExecute()` 首行前置退态：**
```diff
 function handleCommandExecute() {
+  // [2a-2] BUG-1 契约层双保险（根因修复在 BattleScene.executeCommandFromPanel）：
+  //   本路径不经 closeCommandPanel，若不清退态，残留的 cpCommandMode/targetCandidates
+  //   会让随后的战场点击触发幽灵执行。exitTargetSelect 幂等，可放心前置。
+  battleSceneApi()?.exitTargetSelect?.('execute-other');
   if (commandBridge.pendingCallback) {
     commandBridge.pendingCallback(null);
   }
   commandBridge.visible = false;
 }
```
**幂等性**：`exitTargetSelect` 只置 `cpCommandMode=false; pendingAbilityId=null; targetCandidates=null`，重复调用无副作用；`tryExecuteOnFleet` 已先调 `'done'`、`closeCommandPanel` 已先调 `'close'`，均与新调用共存安全。
**仅两处改动的字节级证明**：CRLF 感知反向还原两处后重算哈希 ⇒ `BattleScene.ts = 56C60CD8…C7ECAE2E2`、`App.vue = 3ED3442E…15845F70`（= 2a-2 前值），`EXACT=true`（`_2a2_reverse_check.txt`）。
