# v76 近景档 LOD（相机高度判据）

日期：2026-10-14。用户实报：「为什么还是近景有很多的小点，而不是全模型？」

---

## 1. 诊断：点确实是舰船光点，不是星空

先排除两个候选：

| 候选 | 排除依据 |
|---|---|
| 性能治理收缩 budget | `perfOn` 未开时 `meshBudget` 恒 = `MAX_MESHES`(400)，不收缩 |
| 星空背景点 | 星空 `size = hexR×1.2 = 31.2`，在 r=2500~4000 处投影约 **12px**；截图里的点是 1~3px |

⇒ **截图中 1~3px 的点 = 舰船光点**（`DOT_MIN_PX = 3.6px`）。

**结论**：近景时视锥内仍有单位 `px < MESH_KEEP(17)` —— 即视锥"后半部分"的远处单位。
逐单位 LOD 把它们留成光点 ⇒ 用户读作「近景还是点模共存」。

## 2. v75 已消除回归，但不足以满足"近景全模型"

v75 把阈值/相机距离**逐项回归 v60-v66**（用户说"最早版本没问题"的那个版本），
但用户仍报同一问题 ⇒ 说明**逐单位 LOD 本身**无法满足「近景全模型」的诉求。

⇒ 需要一个显式的**近景档**。

## 3. v74 的失败教训（判据错误）

v74 曾按相机距离切档，但判据是：
```ts
const camD = this.camera.position.distanceTo(this.controls.target);   // ❌
```
**"跟随舰队"逻辑只移动 target、不移动 position** ⇒ `camD` 实际是"舰队距相机多远"，
与用户缩放无关 ⇒ 判档必然失效。

## 4. v76 修复：改用**相机高度**

```ts
const ratio = Math.abs(this.camera.position.y) / this.initCamY;
const enter = this.lodNear ? 0.92 : 0.78;   // 滞回
```

相机高度**只受 OrbitControls dolly 影响**（follow 只移 target）⇒ 是缩放级别的可靠代理量。

### 两档阈值

| 档位 | 条件 | lo/hi/keep/drop | 效果 |
|---|---|---|---|
| **近景** | ratio < 0.78 | **5 / 9 / 6 / 5** | px≥9 即纯模型 ⇒ **几乎全模型** |
| **远景** | ratio > 0.92 | 14 / 26 / 17 / 15 | 保留点阵（雷达观感） |

### 标定实测（span=1300 小图）

| 相机距离 | ratio | 档位 |
|---|---|---|
| 104（minDistance） | 0.13 | 近景 |
| 400 | 0.50 | 近景 |
| 600 | 0.74 | 近景 |
| 700 | 0.87 | 滞回带 |
| 806（初始） | 1.00 | **远景**（点阵雷达） |
| 1000 | 1.24 | 远景 |

⇒ 初始视角保持点阵（符合"远景圆点=雷达效果"的既有口径），
拉近到初始的 78% 以内即全模型。

⚠ 初版用 0.55/0.70 过严 —— 只拉近 25%（dist 600）就退回远景档。
用户拉近但未拉到底时仍看到点模共存 ⇒ 已放宽到 0.78/0.92。

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 档位切换瞬间 grow 突变 | 同一 px 在近景档 `sstep(5,9)` vs 远景档 `sstep(14,26)` 下取值不同 ⇒ 跨阈值缩放时模型尺寸跳变。滞回已降低切换频率 |
| `MAX_MESHES = 400` | 近景档下若视锥内单位 > 400，超出部分仍为点。近景时视野窄、单位少，一般不会触顶 |
| L3 真机未验证 | 阈值 0.78/0.92 是**推算**的，需真机按手感微调 |
