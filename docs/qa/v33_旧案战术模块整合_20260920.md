## 2. P0 三项：落地口径与定量结果

### 2.1 P0-1 阵型互克收口

**互克环（唯一真源，`formations.ts:FORMATION_COUNTERS`）**

```
wedge → line → spindle → circle → square → wedge
```

台架断言（全部 PASS）：出度全 1 / 入度全 1 / 单一 5-环（非 3+2 分裂）/ `FORMATION_COUNTERS` 与 `FORMATIONS[].counters` 逐项一致（证明没有第二张表）/ 5×5 矩阵恰为 5 克制 + 5 被克 + 15 互不克制。

**⚠ 行为变更面：3 组对翻转（初稿凭印象写成 2 —— 台架纠正了人工结论）**

| 阵型 | 旧（BattleScene 内联） | 新（formations.ts） |
|---|---|---|
| wedge | 克 spindle | 克 **line** |
| line | 克 wedge | 克 **spindle** |
| square | 克 line | 克 **wedge** |

`spindle` / `circle` 两组不变。

**倍率口径**：克制 ×1.30（`FORMATION_COUNTER_BONUS`）、被克 ×**0.70**（`FORMATION_COUNTERED_PENALTY`）、互不克制 ×1.0。
值取 0.70 而非该常量原来的 0.90，是为了让**收口只改"关系"不改"幅度"**（0.70 = 原内联值）；原 0.90 从未被任何代码消费，改变它零外部影响。

### 2.2 P0-2 列位 × 距离带

**列位**：`gx` 区间三分（`gx` 越大越靠前）。`circle` / `square` 恒 `center`。

**台架实测乘区表（基准 = 三档等权平均 ⇒ 期望恒 1.0）**

| 阵型 | near | mid | far | \|Δ\| | 三档均值 |
|---|---|---|---|---|---|
| wedge | 0.839 | **1.139** | 1.023 | 0.300 | 1.000000 |
| line | 0.976 | **1.040** | 0.984 | 0.064 | 1.000000 |
| spindle | 0.939 | **1.164** | 0.897 | 0.267 | 1.000000 |
| circle | 1.000 | 1.000 | 1.000 | 0.000 | 1.000000 |
| square | 1.000 | 1.000 | 1.000 | 0.000 | 1.000000 |

**读法**：五个阵型的**整场期望乘区恒为 1.0 ⇒ 零净增益**（这点由台架逐阵型断言）。矩阵只把"能否维持理想交战距"变成**阵型敏感项**：
- 楔形 / 纺锤对距离**敏感**（|Δ| 0.30 / 0.27）—— 站错距离会显著掉火力；
- 横阵**最稳健**（|Δ| 0.064）；
- 圆形 / 方阵**完全不吃**列位红利（无前后轴），其平衡与 v32 完全一致。

**滞回**（防伤害数字逐帧跳变）：进入 near 阈值 0.85、退出 0.90；进入 far 1.15、退出 1.10。
台架断言：阈值附近抖动 60 帧 → **翻转 1 次**（无滞回时会是 30 次）。

## 3. P1 五项：落地口径

### 3.1 P1-4.1 地形索敌列 + 损伤列 + 2 种新地形

**地形表收口**：原三处并列 `switch`（移速 / 射程 / 闪避）合并为 `terrainEffects.ts` 单一真源。**既有 4 种地形的既有乘数原样保留**（台架逐项断言：nebula 0.60/1.20、asteroid 0.70/0.80、gravity 1.30、debris 0.85）。

| 地形 | 移速 | 射程 | 闪避 | **索敌（生效值）** | 损伤/分钟 |
|---|---|---|---|---|---|
| nebula 星云 | 0.60 | 1.00 | 1.20 | 0.955 | — |
| asteroid 小行星带 | 0.80 | 0.70 | 1.00 | **0.797** | — |
| gravity 引力点 | 1.30 | 1.00 | 1.00 | **0.797** | — |
| debris 残骸区 | 0.85 | 1.00 | 1.00 | **0.797** | — |
| **mine 机雷区（新）** | 0.55 | 1.00 | 1.00 | 0.887 | **30.0% maxHp** |
| **jeff 杰夫粒子云（新）** | 0.90 | 1.00 | 1.00 | 0.955 | 16.0% maxHp |

**⚠ 「索敌」列必须削弱后生效**（实现期发现的硬约束）：
`getVisionRange()` 的返回值是**索敌硬门**（`d < visionRange` 才进 `visibleEnemies`，`closestEnemyFleet` 又只取非 fuzzy 者）。实测基线视野 ≈ **484px**（hexRadius=50），若直接采用旧案等级「索敌 大 = 0.55」⇒ 视野掉到 **266px（≈5.3 格）** ⇒ **舰队看不见敌人、目标永久丢失、AI 空转**。
故经 `TERRAIN_RULES.VISION_STRENGTH = 0.45` 削弱：最坏 **−20%**（台架断言最坏生效值 ≥ 0.75）。这是"改一个乘数打断一个系统"的典型，已写入 balance 注释。

**新地形投放**：`mine` 4% / `jeff` 3%，从原"空白格"里取 ⇒ **不挤占既有 4 种的权重**（保持既有地图手感）。标记：mine 红 `✳`、jeff 青 `⋮`。

**DOT 实现纪律**：只改 `u.hp`，**不在 DOT 里处理死亡** —— 既有的每帧清理（过滤 `u.hp <= 0`）会统一走旗舰沉没叙事 / 战损账单 / 指挥带宽降级那条完整链路，另写一份必然漏项。

### 3.2 P1-4.2 拦截（迎击导弹）减伤

**不做弹道实体**（现项目无弹道层，加实体收益/成本比不成立），改为 `finalDmg × 1/(1+rate)`。

台架实测：纯巡洋 **0.375** / 纯战列 **0.250** / 纯舰载 **0.000**；击毁防空舰后由 0.188 → 0.000（**编成可被针对性削弱**）。
- 防空权重取旧案偏序（巡航舰 150 全表最高 ⇒ 现项目"巡洋"成为防空核心）。
- 特技 `intercept_bonus` 加值上限 0.25，总量上限 `INTERCEPT.MAX = 0.55`。
- **热路径纪律**：`fleetInterceptRate` 需遍历受击方全部单位，逐发调用是 **O(N²)/帧** ⇒ 新增 `interceptRateOf(fleet)`（250ms TTL 缓存，与 v12.2 syncShips 的既有优化约定同源）。

### 3.3 P1-4.3 阵型崩溃状态

**概念澄清（已落地）**：旧案把「崩溃」列在**阵型表**里，是那张表按"当前状态"视角列条目（同表的「无阵」亦然）⇒ 本项目实现为**状态** `fleet._formationCollapsed`，**不是玩家可选的阵型项**。

**定位 = 士气链的中间档**：
```
士气<40 且 兵力<60%  → 崩溃（火力/防御/机动 ×0.5，还能打但打不动）
士气<25              → 撤离（retreatDoctrine withdraw）
士气<1               → 溃散（rout）
```
**三个触发源**（与旧案一致）：士气+兵力态势 / **旗舰被击破**（`_flagshipSunkAt`，在既有旗舰沉没分支写入）/ 敌方特技施加（`forced`）。
**强滞回**：恢复门槛 `RECOVER_MORALE = 70` ≫ 进入门槛 40（台架断言：已崩溃 + 士气 50 仍维持崩溃）—— 否则士气在 40 附近抖动会让乘区**逐帧翻转**。
**特技抵抗**（旧案「棋手」）：`resist >= 1` 完全免疫；部分抵抗只抬高士气门槛（0.5 → 门槛 20），**不免疫旗舰沉没与特技施加**（物理事件与外部施加不因"阵型控制力强"消失）。

### 3.4 P1-4.4 特技战术效果扩维（+3 维）

`CombatModifiers` 7 维 → **10 维**：新增 `collapseResist`（钳 [0,1]）/ `intercept`（上限由 `INTERCEPT.SKILL_MAX` 钳）/ `weaponFire`（与 attack 共用 `MAX_MODIFIER`）。

**⚠ 实现期发现的前置缺口**：战场侧此前**完全拿不到提督特技**（`skills` 只在战略层 `gameStore` 用）。故 `initFactions` 新增把 `admiralSkills` 带进 faction 配置，**玩家与敌方对称**（避免"机制只加给玩家"的不对称）。读取走 `skillModsOf(fleet)`（按舰队对象缓存，每帧算一次）。

### 3.5 P1-4.5 舰种偏好距离带

不新增数据结构，只在**语义层**给每个舰种标注偏好的距离带（用**集合**而非单值 —— 单值会让"纯战列舰队永远在 mid"这类正常编制吃惩罚）；命中 +5%、未命中 −3%、未登记（运输）中性。台架断言乘区远离 1.0 的幅度 ≤ 6%（不碾压）。

## 4. 台架基础设施升级（可复用的工程改进）

**问题**：`_v31*` / `_v32*` 台架把源码常量与算法**抄了一份**（如 `MANEUVERS` / `DEGRADES` 表）⇒ 源码改了台架不会红，属**假通过**。

**本轮解法**：台架**直接 `require` 真源码 `.ts`**（Node 22.22 原生类型剥离）。
**遇到的坑**：源码用 TS 风格**无扩展名相对导入**（`import { X } from './balance'`），而 Node ESM 要求说明符完全指定扩展名 ⇒ 传递依赖报 `ERR_MODULE_NOT_FOUND: .../config/balance`。
**解法**：`_ts_resolve.mjs` 注册一个 resolve 钩子，在 Node 自身解析失败后补 `.ts` / `/index.ts` 重试（钩子以 **data: URL 内联**注册 ⇒ 只多一个文件）。仅服务离线台架，不参与 `vite build` / `vue-tsc`。

```bash
node --import ./_ts_resolve.mjs _v33_tactics_sim.cjs
```

**台架覆盖 10 组 / 131 项断言**：A 互克收口 · B 列位三分与净增益审计 · C 距离带滞回 · D 三向方向装甲 · E 拦截减伤 · F 崩溃状态机 · G 组合乘区钳制 · H 地形索敌与损伤 · I 舰种偏好带 · J 总开关回退。

### 4.1 台架在交付前纠正了 3 处人工结论

| # | 人工初稿 | 台架/对抗复核实测 | 处置 |
|---|---|---|---|
| 1 | 「互克翻转面为 **2** 组对（wedge/line）」 | **3** 组对（wedge / line / **square**） | 修正文档与注释 |
| 2 | 「方向装甲开方压缩（EXP=0.5）」 | 开方下 战列(5→2.24) 与 高战(8.33→2.89) **双双撞上 REAR_MAX=2.00** ⇒ "高速战舰最怕后击"的旧案偏序**被 clamp 抹平** | **EXP 0.5 → 0.30**（全部落入 clamp 区间，偏序完整：高战 1.89 > 驱逐 1.71 > 战列 1.62） |
| 3 | 「背面档加 ×1.5 保底，维持旧'打痛'手感」 | 该保底会把 空母 1.34 / 补给 1.32 / 电子 1.44 **全部抬到 1.5**，把同一张装甲表的偏序**再次抹平** | **删除保底**。CRIT! 阈值本就是 1.2，不为提示而改数值 |

第 2、3 条是**同一个错误的两处表现**：*用 clamp / 保底"兜住"极端值，结果把区分度一起兜掉了*。单看每一档都"温和"，只有把 7 个舰种 × 3 个方向全部算出来才会看到饱和。这正是台架存在的理由。

> 第 3 条是**写报告时做对抗性复核才发现的**（台架覆盖不到 BattleScene 内的这行保底），说明"台架全绿"≠"没有自相矛盾"。

## 5. 组合乘区钳制（预先规避的失败模式）

`finalDmg` 在 v32 已有 **9 个乘区**，v33 追加 4 个（列位 / 舰种带 / 崩溃火力 / 拦截）。理论上限会被推到 5× 以上。

**处置**：对**本轮新增的 4 个乘区先合并再钳制**（`TACTICAL_COMBO_CLAMP = [0.30, 1.80]`），**不动既有 9 个**（它们的平衡已 playtest）。

台架实测：未钳制理论区间 `[0.222, 1.397]` —— **下界 0.222 确实越过钳制下限 0.30**（证明钳制不是装饰；下界比上界更早触底，因为崩溃 ×0.5 与拦截 ×0.645 会叠乘）。
