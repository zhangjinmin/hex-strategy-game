## 二、损坏事实与证据

### 2.1 损坏签名

同一路径**同时**出现在 `git diff --cached` 的删除列表与 `git ls-files --others` 的未跟踪列表中。

`D ` 表示"索引里记录这个文件的删除已暂存"，`??` 表示"索引里完全没有这个文件的记录"——两者对同一个路径同时成立在逻辑上不可能，是索引损坏的确定性签名。

### 2.2 实测证据

| 指标 | 实测值 | 期望值 |
|---|---|---|
| `git ls-files`（索引中跟踪的文件数） | **9** | 402 |
| `git ls-tree -r HEAD`（HEAD 树中的文件数） | **402** | 402 |
| `git diff --cached --diff-filter=D`（暂存的删除数） | **393** | 0 |
| 工作区内这些文件是否真实存在 | **全部存在** | — |
| `.git/index` mtime | **2026-09-06 22:48** | — |

即：索引中 393 个条目的删除状态被暂存，而对应的文件在工作区完好无损。损坏发生在 2026-09-06 22:48（最后一次 commit `9a9eb6b` 之后）。

### 2.3 真实风险

损坏期间，**933 个文件**（含 `frontend/src/**` 全部源码）对 git 而言处于 untracked 状态：

- 一次 `git clean -fd` 会**删除整个项目源码**
- 一次 `git commit` 会记录 393 个文件被删除
- `git status` 显示的"待提交内容"完全失真，无法作为版本保护判断依据

从 9/6 至 9/11 的五天内，v6.9（伊谢尔伦）到 v6.13.1（全息光锥）的全部工作都处于**无版本保护**状态。
