## 0. 一句话结论

**v36 的地形实现从未在实机上显示过一个像素。** 不是 alpha 太低，是**结构性不可见**：
地形画在 Phaser（2D）层，而指挥制走 Three.js 覆盖层，3D 就绪后
`body.battle3d-mode` 的 CSS 把**整个 Phaser 画布** `visibility:hidden` 掉了。

修法：把地形画进 Three.js 层（`Battle3DOverlay.buildTerrainZones`），并补 DOM 图例。
同时把地形**生成方式**从"逐格独立掷骰"改为"区域化生长" —— 否则画出来的是六边形彩色马赛克。

---

## 1. 根因（两条，都要证据）

### 1.1 结构性不可见 —— 主因

```css
/* frontend/src/App.vue */
body.battle3d-mode #phaser-canvas-container canvas { visibility: hidden; }
```

`App.vue` 的 `is3dBattle = mapStyle === '3d' || mapStyle === 'command'`；
overlay `onReady` 后 `document.body.classList.add('battle3d-mode')` 并
`setBattleSceneVisible(false)`。用户的 `battlefieldMode` 默认就是 `command`
（`_probe_terrain3d` 实测 `batchMode=true`）。

⇒ 画在 `BattleScene.renderTerrainMarkers()` 里的任何东西都**不可能被看到**。

**实证**（`_probe_terrain_vis.mjs` + `_vis_analyze.py`）：

| 做法 | 结果 |
|---|---|
| 把 795 个地形斑**填成不透明品红** `setFillStyle(0xff00ff, 1.0)` 后截图 | 屏幕上**品红像素 = 0** |
| 同帧对照（A/B 全图差异） | 只有星域/噪点的随机抖动，与地形无关 |

> ⚠ 这一步我**先做错过一次**：第一版探针改的是 `setAlpha`，而 Arc 的可见强度在
> **`fillAlpha`**（由 `setFillStyle` 设置）上、对象 `alpha` 恒为 1 ⇒ 那次实验
> 实际是把 1 降到 0.9，等于什么都没验。第二版改用"不透明品红打标"才拿到决定性证据。

### 1.2 3D 层根本没有"空域地形"这一概念

`Battle3DOverlay.ts` 全文件 **零处**引用 `t.terrain`：

```
buildTerrainMarkers(tiles)  →  只按 t.type 分派（relay/planet/fortress/mine/tower/pier/castle），
                               且 spaceMode 下过滤为 relay / castle / fortress
```

⇒ 六个消费者（移速/射程/闪避/索敌/机雷 DOT/地面标记）里，**唯一**的视觉呈现
就是那段不可见的 Phaser 代码。

### 1.3 附带确认：地形斑的"强度"也确实是错的

`ΔRGB` 实测（`_vis_analyze.py`，取样点 = 由打标图反推的地形格内部）：

```
fillAlpha = 0.13  →  ΔRGB 中位 ≈ 13（8bit 台阶 = 1，JPEG 噪声 ±2~3）
背景亮度中位 = RGB(4, 13, 12)
```

即便不看 1.1 那条，0.13 叠在近黑底上也只是"勉强可测"，不是"看得见"。

## 2. 修法

### 2.1 地形画进 Three.js 层（`Battle3DOverlay.buildTerrainZones`）

| 决策 | 理由 |
|---|---|
| **fill = 每格六边形扇形三角化，按类型合并成 6 个 BufferGeometry** | 6 个 draw call，而不是 800 个 Object3D；数值地 1:1 对应格子覆盖 |
| **风险地形额外描边（带状网格，非 LineSegments）** | `LineBasicMaterial.linewidth` 在 WebGL 下恒为 1 物理像素，远视角看不见 ⇒ 用 2 个三角形做一条带 |
| **`AdditiveBlending` + `depthWrite:false`** | 与项目既有的 Tron 语言一致（网格/星环/护盾全是 additive），叠在星域上读作"发光空域" |
| **y = 0.06 × hexR** | 略高于 y=0 的网格基准面，避免 z-fighting |
| **只在 spaceMode 调用** | hex `'3d'` 模式的地形是**六棱柱实体**，平面会被柱体顶面遮住 ⇒ 那一侧要靠"给柱体 instanceColor 叠地形色"，另批 |

### 2.2 只给"会掉血的地形"描边（这一个决定修掉了马赛克）

`nbSame`（跳过内部边）的触发概率 = **P(相邻格是同一种地形)**。实测密度 26%、6 种均分
⇒ 单邻居同类概率仅 **≈4.3%** ⇒ **96% 的边都是边界** ⇒ **每一格都套一圈亮边**
⇒ 首版（`EDGE_ALPHA=0.6`）画面上就是"六边形彩色马赛克"。

改为"只给 `dotPct > 0` 的两种（机雷区 / 杰夫粒子云）描边"：
马赛克消失，而**唯一有玩法意义的信号**（哪里会持续掉血）反而更突出。

### 2.3 生成方式：逐格独立掷骰 → 区域化生长（`TERRAIN_RULES.REGION_GEN`）

这是"看起来像彩色拼贴"的**真正根因**，不在配色：

| | 旧（逐格独立掷骰） | 新（播种子 + 泛洪生长） |
|---|---|---|
| 相邻同类占比 | ≈16.7%（理论 1/6） | **93.5%**（实测） |
| 连通区域 | 750 个孤立格 | **118 片，最大 62 格** |
| 观感 | 撒盐粒 / 六边形马赛克 | **成片的空域**（一片星云、一条小行星带） |

真实宇宙地貌是**空间连贯的区域**，不是白噪声 —— 所以问题在**生成粒度**。

**类型按权重配额分配**（而不是给每个区域随机取类型）：
首版随机会让一片 111 格的杰夫吃掉半张地图（实测 `jeff 419 / nebula 5`），
图例于是成了空头支票。现按 `TERRAIN_DRAW` 权重表逐类型分配配额。

### 2.4 DOM 图例（`App.vue`）

地形此前只有"世界里的颜色"，**没有任何地方解释它是什么、有什么影响**。
新增左下角「空域地形」图例（可折叠），行数据由 `terrainEffects.terrainLegendRows()`
**从效果表推导**（改数值 ⇒ 图例文案自动跟随，不手抄）。

## 3. 验证

### 3.1 台架 / 静态

| 项 | 结果 |
|---|---|
| `vue-tsc --noEmit` | **EXITCODE=0** |
| `vite build` | 见 `_v36d_build.txt` |

### 3.2 L2 无头浏览器（`_probe_terrain3d.mjs`）—— **13 PASS / 0 FAIL**

```
地形分布 = {debris:87, mine:89, gravity:92, nebula:147, asteroid:129, jeff:69}  合计 613 / 3169
terrainZoneStats = {cells:613, types:6, fills:6, edges:2}
相邻同类占比 = 93.5%   连通区域 = 118 片，最大 62 格   覆盖率 = 21.0%
边映射自检：检查 3589 对相邻格，最大中点偏差 = 0px
```

关键判据：

- **Z0** 确认处于 `battle3d-mode`（即 Phaser 画布确实被隐藏）—— 靶心对了
- **Z3** `fill 顶点数 == cells×12`（每格 4 三角形）—— 几何构造自洽
- **Z4** **边映射自检**：地形格第 k 条边的中点 == 邻居格第 (k+3) 条边的中点，
  偏差 **0px**（3589 对）—— 证明"邻居方向 ↔ 六边形边号"没有错位
  （错位会让边界画在错误的边上，是这类实现最容易静默出错的地方）
- **Z4b** 网格不透明度 == 真源 `TERRAIN_ZONE`（防硬编码覆盖）
- **Z6/Z7** 相邻同类 > 30% 且存在 ≥15 格大片 —— 证明已脱离白噪声形态
- **Z9** 最热/最冷类型比 ≤ 4×（实测 **2.13×**，权重表期望 2.0×）

### 3.3 像素级可见度（开/关对照）

同一冻结帧、同一机位，唯一变量 `terrainZoneGroup.visible`：

| 指标 | 值 |
|---|---|
| 有效变化像素占比（阈值 >8） | **22.09%** |
| 地形区相对背景 ΔRGB | **(+19, +16, +15)** |
| OFF 图背景中位 | RGB(3, 13, 14) |
| 最大通道差 | 145 |

对照（修复前的 2D 路径）：ΔRGB 中位 ≈ 13 **且品红打标像素 = 0** ⇒ 从"结构性不可见"
变为"22% 屏幕面积上的 +19 ΔRGB"。

附：`_terrain3d_side_by_side.png`（上=地形层开 / 下=关，同机位）。

### 3.4 调参过程中的两个坑（已写进代码注释，防复发）

1. **不能按线性直觉取 alpha**：3D 层全屏合成 shader 会做 sRGB 编码
   （`col=pow(col,1/2.4)`），而 sRGB 在暗区**大幅抬升对比** ——
   线性 +0.07 落在 0.005 背景上，显示端是 6/255 → 76/255。
   实测 0.20 读作"彩色拼贴"，一路收到 **0.07** 才落到"环境底色"的量级。
   **以后调这个值必须用 L2 截图实测，不要按数值比例推。**
2. **首版把那 795 个 Phaser 对象留下了**：现在它是**降级路径**
   （overlay 8 秒建不起来时 2D 画布重新可见），已补注释说明，并把 `fillAlpha`
   0.13 → 0.30 免得降级时也看不见。

## 4. 未做 / 取舍 / 风险

### 未做（明确排除）

| 项 | 说明 |
|---|---|
| hex `'3d'` 模式的地形呈现 | 需给六棱柱 `instanceColor` 叠地形色；用户用的是 command 模式，另批 |
| 3D 标志物（小行星岩块 / 星云雾团） | 现在只有"地面色盘"。要"远看就像宇宙地形"需要几何体，属效果上限更高的方案 |
| 「清除 / 冒险使用」两列 | 旧案地形表的第 4、5 列，需要新指令与新机制，仍留白 |

### 取舍

- **覆盖率 27% → 21%**：区域化后大片的视觉重量高于零散格，故总体覆盖率下调
  （`TERRAIN_RULES.COVERAGE = 0.18` 为"可放置格"占比，实测落在 21%）。
  这是**玩法数值变更**，不是纯观感 —— 一键回退见下。
- **地形形状仍是六边形轮廓**：与"指挥制隐藏 hex"存在张力。
  但地形效果本来就是**逐格判定**的，画成圆斑会让玩家误判边界，故保留格子轮廓、
  只把亮度压到"底色"量级。

### 回退

| 开关 | 效果 |
|---|---|
| `TERRAIN_RULES.REGION_GEN = false` | 回到旧的逐格独立掷骰（27% 覆盖） |
| `TERRAIN_RULES.BATTLE_ENABLED = false` | 地形只看得见、无数值影响 |
| `TERRAIN_ZONE.FILL_ALPHA / EDGE_ALPHA` | 亮度一键收敛 |
| `TERRAIN_VISUAL`（`terrainEffects.ts`） | 颜色**单一真源**：3D 分区层 / 2D 降级路径 / DOM 图例三处同源 |

### 需真机确认

1. **地形斑的亮度是否"看得见但不刺眼"** —— L2 只给得出 ΔRGB，给不出观感。
2. **区域化后的地形是否让"绕行危险区"成为可用战术** —— 这是本批次最想要的玩法收益，
   但需要人实际指挥一次才能判断。
3. **图例的位置/字号**是否与军议面板、右下角视角按钮冲突。
