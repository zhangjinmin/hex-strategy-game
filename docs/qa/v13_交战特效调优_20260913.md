## 1. 缺陷根因分析（三条逐一）

### 1.1 激光「太粗」= 单层实心柱，径向尺寸按 0.022~0.035·hexR 直给

- before `spawnLaser`（基线 `:4395-4409`）为**单层 Mesh**：
  `radius = power≥2 ? 0.022·hexR : 0.035·hexR`，`color=传入色`，`opacity 0.95`。
- 标准图 `hexR=50` ⇒ 普通激光**半径 1.75 世界单位**。而探针实测舰长 `L≈25.4` ⇒ **激光直径 = 3.5 = 13.8% 舰长**。
  单舰时视觉占比可接受；**战舰一多，几十条 13.8% 舰长的实心彩柱叠满屏幕 ⇒ 「粗就很丑」**。
- 且是**实心不透明柱**（无内核/晕两级），加色混合下曝光成"光带"，缺乏"激光"应有的锐芯感。

### 1.2 导弹「跳跃感」= **旧 `updateMissiles` 每帧 `Math.random` 白噪声缩放**（本单最硬证据）

- before（基线 `:4740-4741`）：
  ```ts
  const headPulse = 0.9 + Math.random() * 0.2;          // ← 每帧 + 每枚 独立白噪声
  M.flame.scale.setScalar(this.hexR * 0.007 * 1.4 * headPulse);
  ```
  头部亮核球形每帧被 **独立随机数**缩放。60Hz 下相邻帧跳变 ⇒ 人眼读作**「跳」**（而非"平滑能量脉动"）。
- **实证（逐帧 trace，`hexR*0.007*1.4=0.49` 基准）**：

  | 帧 | `M.t` | before `scale` | after `scale` |
  |---:|---:|---:|---:|
  | 1（未出膛） | 0.000 | 0.490（`visible=false`） | 0.300 |
  | 5 | 0.091 | **0.447** | **0.318** |
  | 15 | 0.182 | **0.467** | **0.299** |
  | 25 | 0.273 | **0.446** | **0.282** |
  | 35 | 0.364 | **0.464** | **0.302** |
  | 40 | 0.455 | — | **0.318** |

  - **before**：scale 在 0.446 / 0.467 / 0.446 / 0.464 之间**无规律跳变**，且**与 `t` 完全无关** ⇒ 白噪声确证。
    （理论范围 0.49×[0.9,1.1]=0.441~0.539，实测落在其内。）
  - **after**：**0.318 → 0.299 → 0.282 → 0.302 → 0.318**——随 `t` **单调段内平滑变化**，一个完整呼吸周期
    （`0.3·(1+0.06·sin(el·32+seed))`，范围 0.282~0.318）⇒ 确定性、无随机。
- 另一条"跳跃感"来源（用户"就是一条直线，显得很粗"）：before 弹体是**单位圆柱 scale 出来的直棒 + 1.25× 晕层 + 球头**，
  **无拖尾、无渐隐、无出膛过渡**，出膛瞬间 `visible` 直接由 false→true（**"弹入"**）。

### 1.3 尾焰「显得有点大」= 粒子尺寸/拖尾/寿命三项均过大，且色相是**青蓝**（用户要金红）

- before（基线 `:468-469` / `:1735-1737` / `:1780-1787`）：

  | 量 | before 公式 | 物理含义（相对舰长 L） |
  |---|---|---|
  | `FLAME_PER_SHIP` | 14 | 每舰 14 粒子 |
  | `FLAME_LIFE` | 0.55 s | 存活更久 ⇒ 拉更长 |
  | `back`（拖尾长） | `k·L·(1.5+j·0.8)` | 最大 **2.30·L** |
  | `aSize`（粒子尺寸） | `L·(0.55+(1-k)·1.15)` | 最亮 **1.70·L** |
  | 片元 `hot/mid/cool` | `(1.0,0.96,0.85)` / `(0.45,0.82,1.0)` / `(0.12,0.30,0.85)` | **白 → 青 → 蓝** |

- 「大」的量化：**最亮粒子尺寸 1.70×舰长、拖尾最长 2.30×舰长** ⇒ 视觉上尾焰（含拖尾）比整条战舰还长。
- 「色不对」的量化：`mid` 的 B 通道 = 1.0、`cool` 的 B = 0.85 且 R 仅 0.12/0.45 ⇒ **冷色为主 = 青蓝**，与用户要的**金红**相反。

## 2. ① 激光变细 —— 单层粗柱 → 「细白核 + 柔色晕」双层 Group

### 2.1 实现（`spawnLaser`，终版 `:4410-4435`）

```ts
const heavy = power !== undefined && power >= 2;
const coreR = (heavy ? 0.006 : 0.008) * this.hexR;   // 细白核
const haloR = coreR * 2.6;                            // 柔色晕 ≈ 0.0156~0.0208·hexR
const group = new THREE.Group();
const coreMat = new THREE.MeshBasicMaterial({ color: 0xffffff, opacity: 0.95, ...additive, depthWrite:false });
coreMat.userData.baseOpacity = 0.95;
group.add(new THREE.Mesh(new THREE.CylinderGeometry(coreR, coreR, len, 5), coreMat));
const haloMat = new THREE.MeshBasicMaterial({ color /*传入色*/, opacity: 0.22, ...additive, depthWrite:false });
haloMat.userData.baseOpacity = 0.22;
group.add(new THREE.Mesh(new THREE.CylinderGeometry(haloR, haloR, len, 5), haloMat));
group.position.copy(from).addScaledVector(dir, 0.5);
group.quaternion.setFromUnitVectors(new THREE.Vector3(0,1,0), dir.clone().normalize());
this.lasers.push({ mesh: group, life: 0.4, max: 0.4 });
```

- `LaserEntry.mesh` 由 `THREE.Mesh` **放宽为 `THREE.Object3D`**（`:401-407`）——普通激光是 Group、雷神之锤是 Mesh，**共用同一池**。
- `updateFx`（`:4719-4744`）改为对 `L.mesh.traverse` 逐 mesh：
  `opacity = fade * (mat.userData.baseOpacity ?? 0.95)`，`fade = max(0, L.life/L.max)`；
  回收时**逐 mesh** `geometry.dispose()` + `material.dispose()`。

### 2.2 参数对照（`hexR=50`，标准图）

| 量 | before | after | 变化 |
|---|---|---|---|
| 层级 | 1 层实心柱 | **2 层（白核 + 色晕）** | 新增锐芯感 |
| 普通激光半径 | `0.035·hexR` = **1.75** | 白核 `0.008·hexR` = **0.40**；晕 `0.0208·hexR` = 1.04 | 核心 **−77%**；含晕 **−41%** |
| 重激光半径（`power≥2`） | `0.022·hexR` = **1.10** | 白核 `0.006·hexR` = **0.30**；晕 `0.0156·hexR` = 0.78 | 核心 **−73%**；含晕 **−29%** |
| 核心色 | 传入色 | `0xffffff` | 锐白芯 |
| 透明度 | 单层 0.95 | 核 0.95 / 晕 0.22 | 依赖 `userData.baseOpacity` |
| 激光直径 / 舰长 | **13.8%** | 核 **3.1%** / 含晕 8.1% | 显著收细 |

### 2.3 红线核对：`spawnFortressBeam`（雷神之锤，`:4358`）兼容性 ✔

- 雷神之锤仍推入 `lasers` 池，其 `mesh` 是**单 Mesh、无 `userData.baseOpacity`**。
- `updateFx` 的 `?? 0.95` 回退 ⇒ 其 `opacity = fade × 0.95`，**与改动前逐位一致**（旧代码即 `opacity = max(0, life/max)` 且材质初值 0.95）。
- 探针 `laserInfo` 实测接火后池内 2 条激光正常淡出回收；**未改动雷神之锤粗细**（`widthPx` 参数与 `spawnFortressBeam` 本体零改动）。

## 3. ② 导弹重设计 —— 「直线粗棒」→「弹尖 + 细弹体 + 引擎光点 + 渐变拖尾」

### 3.1 实现（`spawnMissileSalvo`，终版 `:4437-4520`；`updateMissiles`，`:4800-4835`）

**结构（弹尖朝前、拖尾在后，local `-z` = 飞行方向，spawn 时一次性定向）**：

| 部件 | 几何 | 参数 | 材质 |
|---|---|---|---|
| 弹体 | `CylinderGeometry(rTail, rTip, bodyLen, 6)` 经 `rotateX(π/2)` + `translate(0,0,bodyLen/2)` | `bodyLen=0.13·hexR`、`rTip=0.0035·hexR`（尖）→ `rTail=0.006·hexR`（尾） | 白，additive，`opacity 0.8` |
| 引擎光点 | `SphereGeometry(1)`，挂 `z=+bodyLen` | 半径 `0.006·hexR` | 传入色，additive，`0.85` |
| 拖尾 | 单位锥 `CylinderGeometry(0.35,1,1,8,1,true)` 经 `rotateX(π/2)`+`translate(0,0,0.5)` | `trailLen=0.42·hexR`、`trailR=0.004·hexR`，近端 1 → 远端 0.35 | `ShaderMaterial`：`a=pow(1-vZ,1.5)*0.38*uFade`，additive、`depthWrite:false` |

**每帧（`updateMissiles`）**：

```ts
const el = M.t * M.dur;
const fadeIn = Math.min(1, el / 0.07);                                  // 出膛 0.07s 淡入
M.flame.scale.setScalar(this.hexR * 0.006 * (1 + 0.06 * Math.sin(el * 32 + M.seed)));  // 确定性呼吸
M.bodyMat.opacity  = 0.8  * fadeIn;
M.flameMat.opacity = 0.85 * fadeIn;
M.trailMat.uniforms.uFade.value = fadeIn;                                // 拖尾同步 ramp
```

- **`Math.random` 整段删除**：`seed: m * 2.5`（`:4514`，纯由齐射序号决定，无随机）。
- **出膛淡入**消灭"弹入"：`delay` 结束起 0.07s 内，弹体 / 引擎光点 / 拖尾**同步** 0→1。
- **齐射节奏保持**：出膛横向散布（`perp × (m-count/2+0.5)×0.22·hexR`）+ 逐枚 `delay = m*0.05`。
- **直线弹道**：朝向 spawn 一次定死，`sway` 未复活。
- **资源**：材质每枚独立（中途命中 dispose 不影响同批）；几何按齐射共享、回收**不** dispose 几何；**每枚仍 3 mesh ⇒ draw call 不涨**（与 before 相同）。
- 命中仍走原 `spawnHit`（未改）。

### 3.2 参数对照

| 量 | before | after | 说明 |
|---|---|---|---|
| 弹体 | 单位圆柱 scale（`boltR=0.007·hexR`，直棒） | 细锥 `0.0035→0.006·hexR` | 更细，有收束 |
| 弹头 | 球 `1.4·boltR` + **每帧随机脉动** | 去掉独立球头；`rTip` 即弹尖 | 消除闪烁源 |
| 拖尾 | **无** | 锥形 `0.42·hexR` + `pow(1-vZ,1.5)` 渐隐 | 新增"质感"与方向感 |
| 晕层 | `1.25×boltR` 直棒 | 由拖尾+引擎光点替代 | — |
| 出膛 | `visible` 直切 | 0.07s 同步淡入 | 消灭"弹入" |
| 每帧随机 | **`Math.random()` × 1/帧/枚** | **0** | 消除"跳跃感"根因 |
| mesh 数/枚 | 3 | 3 | draw call 不涨 |

## 4. ③ 尾焰重设计 —— 尺寸/拖尾大砍 + 金红三档

|---|---:|---:|---|---|

## 8. 实现中超越派单 spec 的额外改动（独立验证 CONCERNS · 补档）

> **背景**：独立验证（quality-lead-3）判定 **PASS + 1 CONCERNS** —— diff hunk #18（`L4514`）在派单 spec 之外额外移除了 `Math.random()`：
> `seed: m * 2.5 + Math.random()` → `seed: m * 2.5`。派单 spec 未声明此项。本节按要求补档（只加文档，**产品代码零改动**，见 §8.4）。

### 8.1 该 `seed` 的全部消费点（grep 确认）

`grep seed`（终版源码全量命中）：

| 行 | 内容 | 性质 |
|---|---|---|
| `:432` | `seed: number;  // 确定性呼吸相位（v13：不再用于摆动/噪声）` | 接口字段声明 |
| `:4514` | `seed: m * 2.5,` | **唯一写入点**（`spawnMissileSalvo`，每枚） |
| `:4815` | `M.flame.scale.setScalar(this.hexR * 0.006 * (1 + 0.06 * Math.sin(el * 32 + M.seed)));` | **唯一读取点**（`updateMissiles` 呼吸相位） |
| `:4439` / `:4802` | 注释文本 | 非代码 |

**结论：`seed` 除 `updateMissiles` 的呼吸相位外，无任何其他消费点。**

**出膛横向散布是否受影响 → 否，且无需补偿**（逐行核对）：

- 散布实现（`:4509`）：`from: from.clone().addScaledVector(perp, (m - count / 2 + 0.5) * this.hexR * 0.22)` —— 仅用**齐射序号 `m`**，**与 `seed` 无关**。
- 逐枚节奏（`:4513`）：`delay: m * 0.05` —— 同样仅用 `m`。
- ⇒ 散布与节奏**均由 `m` 决定**，移除 `seed` 上的随机项**不触及**二者，**无需补偿**。

**补档关键发现（before 侧）**：before 基线中 `seed` **已是死字段**——`:4456` 写入 `seed: m * 2.5 + Math.random()`，但全文件**无任何 `.seed` 读取**
（`grep seed` 于基线仅 3 处命中：声明 `:419`、赋值 `:4456`，**零读取**）。
⇒ before 的 `+ Math.random()` 属**纯死代码**（写入一个从不被读取的字段），**即使不删也零行为影响**；删除它是**零风险清理**。
（`:419` 旧注释「蛇形相位种子」对应 v6.4 及之前的 `sway` 侧偏——`sway` 已在 v6.5 整段删除，字段成为遗留；v13 让该字段**从死字段复活为呼吸相位种子**。）

### 8.2 动机（与「去随机 / 去跳跃」目标的一致）

- 用户诉求的「跳跃感」根因即**随机噪声**（§1.2）；本单原则是**该热路径端到端去随机**。
- `seed` 是**每枚**导弹的字段；`m * 2.5 + Math.random()` 使**同序号**导弹在不同齐射间相位漂移。
- 派单 spec 只要求删 `updateMissiles` 的**每帧**随机；但既然 `seed` 现在**服务于呼吸相位**，把 spawn 时的随机注入一并去掉，才能让"确定性呼吸"**真正端到端确定**——否则相位仍带 spawn 随机，`missileScaleTrace`（§1.2 的逐帧实证）也就**无法逐位复现**。
- 一致性判断：这是一处**与派单目标同向、且更彻底**的清理 ⇒ 实施并在报告披露（而非静默越过 spec）。

### 8.3 影响面

| 维度 | before | after | 说明 |
|---|---|---|---|
| 呼吸相位 | 每帧白噪声缩放；`seed` 为死字段 | `Math.sin(el*32 + m*2.5)` | 相位差 = 序号 × 2.5 rad，**错峰** |
| 同场景可复现性 | 否（白噪声不可复现） | **是**（纯由 `m` 决定） | 探针 `missileScaleTrace` 逐位可比即此 |
| 齐射观感「随机性」 | 由 per-frame/per-missile 白噪声承担（**= 用户抱怨的闪烁**） | **改由序号决定性错峰承担**：散布(`m`) + delay(`m*0.05`) + 呼吸相位(`m*2.5`) 三者均按 `m` 匀布 | 视觉仍有「错落感」，但**无 60Hz 闪烁** |
| 宏观战场自然度 | — | **不受影响** | 「何时/哪艘舰开火」仍由 gameplay/AI 决定（AI 内 `Math.random()` 未动，如 `:4865`） |

⇒ **结论**：该项额外改动**消除了一处残留随机源**，使呼吸相位**端到端确定（可复现）**，且**未削弱齐射观感**（错峰由 `m` 承担）、**未影响出膛散布与逐枚节奏**。独立验证的 CONCERNS 经本补档澄清。
