## 1. 为什么四代都失败——病根是概念，不是参数

单位目标位的公式（:5560）：

```
targetUnit = 锚点 + rotate(阵位偏移, formFacing)
```

**`formFacing` 的任何旋转（无论快慢、连续还是离散、单写还是双写）都恒等于单位绕锚点公转。** 四代方案全部撞在这条几何恒等式上：

| 代 | 方案 | 失败形态 |
|---|---|---|
| v34 snap | 格位一帧吸附 | 单位横穿中心 → **缩成一团再展开** |
| v41b 协议连续转 | formFacing 跟舰体快转 | **画圈**（更快更明显） |
| v41c 每帧吸附 | 跟 fAngle 每帧重排 | fAngle 会动（会合/AI 重选）→ **画圈 + 拖刀下双写打架 → 左右晃** |
| v41e 上升沿一次 | 只在进入时吸附 | 仍是"吸附"→ 缩团穿心没有根治 |

**用户要的「每艘战舰自身原地旋转向」在代码里的直接翻译就是：格位不转，舰体转**——而 `u.sprite.rotation = facingSmooth`（:5580）本来就是逐舰的。之前四代一直在错误的量（formFacing）上找"正确的旋转方式"，而正确答案是不旋转。

## 2. v42 方案

| 量 | 行为 |
|---|---|
| **formFacing（格位朝向）** | **冻结**：只在部署/变阵时初始化（兜底 `:5366`），战斗中**永不旋转** |
| **facingSmooth（舰体朝向）** | 保留 v41b 协议：大角度（>50° 进 / <30° 出，滞回）快转 6×（180°≈0.67s），拖刀例外保留 |
| **推力** | 协议期压死 0.06（原地），退出后恢复 |
| **单位** | 目标位恒定（格位不动）⇒ 原地转身 + 跟随锚点整体平移，**无画圈/无缩团/无晃动** |

代价（明确的语义变化）：**掉头后阵型平面保持旧朝向**（楔形阵变成"反向楔形"）。太空战舰无气动约束，任何方向都能飞；银英原作中舰队转向同样是各舰转身保持队形（亚斯提会战的同盟转向正是此形态）。3D 托盘朝向与格位同源（`markerAxes(formFacing)`），继续正确框住单位。

**删除的代码**（净 −46 行）：协议上升沿吸附、`_isUturn`/snap/arc/对称分支/`rateLimitAngle` 连续旋转、`turnDiscipline` 消费、`balance.FORMATION_SPIN` 整块。

## 4. 教训（终版）

1. **四代修复共同错误**：在"formFacing 怎么旋转"里找答案，而正确答案是"不旋转"。**连续五次实报才逼出这个结论——因为"阵型要朝向航向"是无人提出过的隐性假设。**
2. **几何恒等式优先于参数调优**：`rotate(偏移, θ)` 的 θ 变化必然产生公转位移，与速率/方式无关。
3. **用户语言就是规格**：「每艘战舰自身原地旋转变向」——逐字实现即可，不需要先验"阵型必须指向移动方向"。
