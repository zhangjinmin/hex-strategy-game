#### A-1 推导与复现（P0，建议优先实机确认）

代码依据：
- `Battle3DOverlay.ts:324` — `new THREE.PerspectiveCamera(50, w/h, 0.1, 4000)`，`far` 此后再无赋值（`resize()` `:1378-1388`、`buildTerrain()` `:633-740`、`setViewPreset()` `:1361-1376` 都不碰 far）。
- `Battle3DOverlay.ts:637` — `this.hexR = bs.hexRadius || 26`。
- `BattleScene.ts:1311-1315` — `hexRadius` 按总舰数取 26 / 32 / 38 / 44 / 50。
- `BattleScene.ts:1941-1949` — 默认地图 `random` = 半径 32 → **3169 格**；`x = R·(√3·q + √3/2·r)`，`y = R·1.5·r`（`:994-995`，3D 模式 `yScale=1`）。
- `Battle3DOverlay.ts:654-659` — `span = max(Δx, Δy, 8R)`，`dist = max(span·1.15, 20R)`，`camera.position = (cx, dist·sin0.96, -cy + dist·cos0.96)`。

几何结果（沿视线方向的深度，`depth = dist − (z+cy)·cos0.96`）：

| hexRadius | 格数 | span | 相机视距 dist | 近边深度 | 远边深度 | far=4000 下的可见比例 |
|---|---|---|---|---|---|---|
| 26 | 3169 | 2882 | 3314 | 2598 | 4032 | **97.6%**（远边微裁，几乎看不出） |
| 32 | 3169 | 3547 | 4079 | 3198 | 4963 | **45%** |
| 38 | 3169 | 4212 | 4844 | 3798 | 5891 | **9.7%** |
| 44 | 3169 | 4877 | 5609 | 4398 | 6820 | **0%（近边就超出 far）** |
| 50 | 3169 | 5543 | 6374 | 4997 | 7750 | **0%** |

而**演习（skirmish）模式下 hexRadius 恒 ≥ 38**：`scaleMapForFleetCount`（`BattleScene.ts:1285-1317`）中 `totalShips = 玩家已填 deck 槽数 + activeFactionCount × 6`。默认 `activeFactionCount = 2`（`gameStore.ts:2249`）→ 敌方已占 12；阈值 `≤12→38 / ≤16→44 / >16→50`。即**玩家 deck 一个槽都不填也是 38**。

**复现步骤**：主菜单 → 战术模拟/演习 → 地图保持默认「随机宙域(random)」→ 战斗界面风格选 3D → 开局。预期：画面近黑，只有零散星点；滚轮大幅拉近后才出现地形。

**2026-09-02 复核补充**（与 engineering-lead-2-3a82 交叉验证后修订，取代本节原「建议修法」）：

1. **判据是视空间深度，不是径向距离。** 远裁剪面是垂直于视轴的平面而非球面，故 `depth = dot(P − cam, forward)`。因 forward 的 x 分量为 0，**最大视深与横向偏移无关**：`depth_max = camD + cos(0.96) × Zhalf`，其中 `Zhalf = 48·hexR`（y 展 96·hexR，x 展 110.85·hexR，故 `Zhalf = 0.433·span` 而非 `span/2`）。上表数值即按此式计算，复核后误差 <3（4030 / 4960 / 5890 / 6820 / 7750），**原表数字有效**。
2. **`span / hexR = 110.85`，已从源码确证**（枚举全部 3169 组 (q,r)）：`BattleScene.ts:1941-1943`（半径 32）+ `:994-995`（正向公式）+ `Battle3DOverlay.ts:654`。无需实机打印。
3. **hexR=26 一档为临界**：仅超出 30 / 4000（0.75%），地形高度噪声即可使其翻转，且该档需 `totalShips ≤ 4`（`:1311`），默认路径（`activeFactionCount=2` → 敌方 12 艘）下恒 ≥38。故实操结论为「hexR ≥ 38 四档确定超出，26 档可忽略」。
4. **缩放才是上限瓶颈**：`maxDistance = dist × 1.6`（`:663`）。拉满后所需 far 为 6019 / 7408 / 8797 / 10186 / **11575**（hexR 26→50）。→ **far 必须每帧或随 controls change 更新，只在 `buildTerrain` 设一次不够。**
5. **推荐修法（取代原「dist + mapSpan × 1.5」，原式偏保守）**：置于 `tick()` 的雾更新块 `:1341-1345`（已算好 `camD`，需将其从 `if` 内提出）：
   ```
   camera.far  = camD + mapSpan * 0.5;
   camera.near = Math.max(1, hexR * 0.2);   // 5.2 ~ 10
   camera.updateProjectionMatrix();           // 必须
   ```
   充分性可证：`depth_max ≤ camD + 0.287·span`（因 `Zhalf ≤ span/2`），取 `0.5·span` 有 ≥1.7× 理论余量；实测五档 ×（初始/拉满）共 10 情形余量稳定 **12–18%**。near 取 `hexR×0.2` 时最坏深度比 12969/10 ≈ **1297:1**，而 `minDistance = hexR×3 = 150 ≫ 10`，无误裁风险。
6. **与 D-9 的联动（排期注意）**：`buildStars()` 星点半径 2500–4000（`:552`），`frustumCulled = false`（`:577`）只跳过 CPU 剔除，GPU 远裁剪仍生效 → far=4000 时远侧约一半星点被裁，这正是 A-1 现象「仅少量星点」的成因。**放大 far 后星点会回来，但随即被雾吃掉**（`PointsMaterial` 默认 `fog:true`，而 `fog.near` 已被 `:1343` 推到 `camD + span×1.05` ≈ 1.2w+）。故 D-9 会从「星空被裁」转为「星空被雾」，**建议 A-1 与 D-9 同批修**，否则修完 A-1 会收到一轮「星空发灰」新反馈。

**为什么之前没被识别**：`a7e38ce`/`4b0ebdd` 修的「雾致黑屏/半屏」把 `fog.near` 从 `0.32×mapSpan` 提到 `1.05×mapSpan`（现 `Battle3DOverlay.ts:1341-1345`）。雾确实被推走了，但 **far 平面吃掉地形的问题与雾无关，两次修的是两个不同症状，后一个还在**。

**27°/俯视预设也救不回来**：`setViewPreset`（`:1364`）保留当前 `dist`，只改俯仰角 → 到地图中心的深度仍是 `dist`（4844~6374），恒 > 4000。

#### B-2 详解（选目标流程断裂）

链路：
1. `CommandPanel.vue:118-128` `selectCommand()`：`requiresTarget` 为真时只 `emit('select-target', cmd.id)`，**面板不关**（`commandBridge.visible` 仍为 true）。
2. `App.vue:148-151` `handleCommandSelectTarget()`：只写 `commandBridge.selectedAbilityId = abilityId`，注释称"目标选择由 BattleScene 的 pointer 事件处理"——**但 BattleScene 没有对应的 pointer 处理**：`BattleScene.ts` 中唯一的地块交互是 `poly.on('pointerup')`（`:1098`），且 3D 模式下 Phaser 画布 `visibility:hidden` 收不到事件；`pendingAbilityId`（`:124`）声明后从未被读写。
3. 玩家此时只能：点面板外 → 命中 `.command-panel-overlay` 的 `@click.self="close"`（`:2`）→ `handleCommandClose()`（`App.vue:141-146`）→ `pendingCallback(null)` → `executeCommandFromPanel(selectedAbilityId, null)`（`BattleScene.ts:1556-1557`）→ `executeCommand` 照扣 CP、照起冷却（`CommandPointSystem.ts:69-70`），`targetFleetId = null`。

影响按技能拆分（`config/commandAbilities.ts` 中 `requiresTarget: true` 的共 4 个）：

| 技能 | CP / 冷却 | target=null 时的实际效果 |
|---|---|---|
| 集中火力 focus_fire | 2 / 60s | 走 `casterFleetId` 分支（`CommandPointSystem.ts:124`）→ 效果照常。但"集火单一目标"只是描述，效果层本就没有目标概念 |
| **电子干扰 ecm_jam** | **2 / 120s** | debuff 分支要求 `e.targetFleetId === fleetId`（`:128`）→ **作用于 0 个舰队，2CP + 120s 完全打水漂** |
| 阵型突击 formation_charge | 2 / 90s | 走 `casterFleetId`（`:172`）→ 效果照常 |
| 双璧的猛袭 reuenthal_blitz | 3 / 240s | `implemented: false`，UI 已置灰，入口挡住（`CommandPanel.vue:120`）→ 无影响 |

**建议修法**：`selectCommand` 里 `requiresTarget` 为真时**关闭面板**（`emit('close')` 的同时置 `selectedAbilityId`），进入"待选目标"态；BattleScene 加一个 pointer/raycast 拾取：2D 用 `this.input.on('pointerdown')` 找最近敌舰队，3D 在 overlay 的 `handlePick` 里对 `this.ships` 做 raycast，命中后 `pendingCallback(fleetId)`。期间 Esc 应取消并**退还 CP**。

## ③ 已知的可用性缺口（非 Bug，但影响体验）

1. **3D 模式没有地形图例**（C-4）。2D 靠色块+文字（`⚙ 🌍 ✧ ♜ ⚲`），3D 改成几何形状后玩家无从对应。
2. **3D 模式没有舰队选中态**。2D 有跟随面板常驻显示，3D 什么都没有（B-1）。即便补了 HP 条，也需要一个"当前选中舰队"的视觉锚点。
3. **3D 模式没有相机操作提示**。OrbitControls 的左键旋转 / 滚轮缩放 / 右键平移没有任何 UI 说明；27° 与俯视按钮（`App.vue:47-50`）也没有 tooltip 之外的引导。
4. **指挥面板是全屏模态**（`CommandPanel.vue:146-150`），打开即遮住整个战场。策略游戏在"看战场 → 下命令"之间反复切换，全屏遮罩对节奏是负面的（B-2 放大了这个问题）。
5. **战斗日志从未接线**（B-7），玩家缺少击杀/受创的即时文字反馈，3D 模式下尤其明显（火焰变红是唯一反馈）。
6. **`implmented: false` 的技能仍占位显示**（`reuenthal_blitz`）。UI 已置灰并标注"效果尚未实现"（`CommandPanel.vue:57`），处理是对的，但该技能占着提督专属栏位，长期看应隐藏或标注"敬请期待"。
7. **暂停态下 `renderIntentLines()` 只在指挥面板打开时绘制意图线**（`BattleScene.ts:1806-1808`）。2D 模式能看到敌方攻击意图，3D 模式下这条红色意图线画在隐藏画布上 → **3D 暂停时看不到敌我交战意图**。
8. **3D 模式下 CRT 边框被隐藏**（`App.vue:586`），但 3D 层自带 CRT shader（`Battle3DOverlay.ts:344-378`）。观感一致，但意味着"CRT 风格"的开关与 2D/3D 模式选择被耦合在一起，玩家无法只要 3D 视角、不要 CRT 滤镜。
