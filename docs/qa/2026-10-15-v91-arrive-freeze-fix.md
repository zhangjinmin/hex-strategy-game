# v91 修复"舰队完全不动"（v85 制动律在 d≈0 时冻结速度）

日期：2026-10-15。用户实报两个问题：
> ① 近景模型后**舰船数明显偏少**，和远景的粒子图不成比例
> ② **我方舰队都不动**，就停在原地，**下达军议命令也不会有任何动作**

---

## 问题②（严重，游戏不可玩）：根因 = v85 制动律在 `d = 0` 时把速度压成 0

### 仿真复现

| `distToTarget` | `vAllow = √(2·a·d)` | 期望速度（原满速 0.22）被缩放为 |
|---|---|---|
| **0** | **0.0000** | **0.0000** ← 完全冻结 |
| 1 | 0.0290 | 0.0290 |
| 10 | 0.0917 | 0.0917 |
| 50 | 0.2049 | 0.2049 |
| 200 | 0.4099 | 0.2200（不干预） |

### 为什么会 `d = 0`

本工程**多处**把 `fleetTargetX/Y` 设为 `fleet.x/y`（语义 = "目标即自身"，用于驻守/停留/待命）：

```
6538  fleetTargetX = fleet.x;  fleetTargetY = fleet.y;
6604  fleetTargetX = fleet.x;  fleetTargetY = fleet.y;
6620  fleetTargetX = fleet.x;  fleetTargetY = fleet.y;
6627  fleetTargetX = fleet.x;  fleetTargetY = fleet.y;   // 停留恢复
```

⇒ `distToTarget = 0` ⇒ `_vAllow = 0` ⇒ 期望速度被**无条件缩放为 0**。

**为什么"下达命令也没反应"**：命令改变的是**目标**（`fleetTarget`），
但制动律在**同一帧**把速度压成 0 ⇒ 目标虽更新，速度仍是 0 ⇒ **舰队不动**。

### 修复：制动律只在"确实在接近目标"时施加

```ts
if (distToTarget > 2) {            // ← 新增门控
    const _vAllow = Math.sqrt(2 * kinAccel * Math.max(0, distToTarget));
    ...缩放...
}
```

**职责分离**：制动律只负责"**防超速**"，不负责"**决定要不要动**"。
已到点（d ≈ 0）时**不干预**，由外部逻辑（期望速度本身是否为 0）决定停或走。

⇒ 驻守分支的 `rawVX/rawVY` 本来就是 0 ⇒ 仍会停；但**命令推进目标后能立即起步**。

## 问题①：模型数偏少 —— 已排除折算裁剪，倾向"视野窄"

| 检查项 | 结果 |
|---|---|
| `_visualCapacity` | **全项目仅两行**（读 + 回写），**从未被设置** ⇒ `= units.length` ⇒ **不裁剪** |
| `projectFleetRepresentationBySlot(units, 200)` | `cap >= n` ⇒ 走"全员"分支 ⇒ 不抽稀 |
| `lodKeep`（近景档） | **0** ⇒ 所有舰队都建实体 |

⇒ **渲染侧已无裁剪。** 剩下最可能的解释：**近景时视锥窄，本来就只框住舰队的一部分**
（远景看全局 ⇒ 200 个点；近景看局部 ⇒ 只见其中 ~40 个）⇒ 观感"不成比例"。

**待用户确认**：把 `?debug` 面板数据给我（`n=` 与 `mesh=` 两列）——
若 `n` 本身就小（如 40），即"视锥内只有这么多"；若 `n=200` 而 `mesh` 只有 40，才是真 bug。

**可立即尝试**：在**近景档范围内**把相机略微拉远（ratio 仍 < 0.75 ⇒ 仍是全模型档），
可见范围会变大、模型数量随之增加。
