# v75 LOD 回归 v60-v66 + 舰队级统一判定

日期：2026-10-14。用户实报：
「近景和远景有问题。我在远景的状态下也可以看到模型，近景的状态下同一个舰队看到的点+模型，
而不是全模型。**最早的版本这个是没有问题的**。现在的问题出在哪里？」

---

## 1. 定位：这是我自己引入的回归

用户给出关键线索「最早的版本没问题」⇒ 查 git 历史逐版本对比：

| 阈值 | v60-v66（用户说没问题） | v73（我改的） |
|---|---|---|
| `MESH_IN_LO` | 14 | **9** |
| `MESH_IN_HI` | 26 | **15** |
| `MESH_KEEP` | 17 | **12** |
| `MESH_DROP` | 15 | **10** |
| 初始相机 | `span×0.62, hexR×24` | **`span×0.50, hexR×20`** |
| 点让位 | 连续 alpha 衰减 | **grow>0.55 硬截断**（我加的） |

**根因**：v73 为"让初始视角就是纯模型"把**阈值降低近一半**并**拉近相机**，
导致：
- **「远景也能看到模型」**：px 12~17 的单位原为纯点，降门槛后变模型
- **「近景同队点+模型混合」**：混合带从 px 17~26 移到 12~15，而后者恰好覆盖常用视角

⇒ **取景距离与 LOD 阈值是一对校准值**，只改一个必然破坏既有观感。

## 2. 另一处 v74 失效

v74 加"按相机距离切 LOD 两档"想解决近景点模共存，但没生效：

```ts
const camD = this.camera.position.distanceTo(this.controls.target);
```

`controls.target` 会被**跟随舰队**的逻辑拉走（只移 target、不移 position）
⇒ `camD` 实际测的是"舰队离相机多远"，**不是用户的缩放级别** ⇒ 判档依据错误。

⇒ 已删除两档联动（回到单一阈值，语义明确）。

## 3. 修复

### 3.1 完全回归 v60-v66 原值
- 阈值 14 / 26 / 17 / 15
- 初始相机 `span×0.62, hexR×24`
- 点让位回归连续 alpha 衰减（删除硬截断）

**对照验证**：4 个阈值 + 相机距离与 `1e1c1b7` 逐项一致。

### 3.2 唯一保留的改进：舰队级统一判定

用户实报「**同一个舰队**看到的点+模型」—— 逐舰 LOD 的固有缺陷。

新增 `UnitVis.fleetPx` = 舰队成员 px 均值；**LOD 决策一律用它**：

| 用途 | 旧 | 新 |
|---|---|---|
| 实体分配（keep/drop） | `v.px` | **`v.fleetPx`** |
| 候选排序 | `b.px - a.px` | **`b.fleetPx - a.fleetPx`** |
| `grow`（长出动画） | `sstep(lo,hi,v.px)` | **`sstep(lo,hi,v.fleetPx)`** |
| `pooled` 统计 | `px` | **`fleetPx`** |

⇒ **整队一起切档**（要么全模型、要么全点），符合"舰队是一个整体"的感知。

⚠ `px` 保留原语义（点径/分屏分桶/尺寸），仅**决策**改用 `fleetPx`。
⚠ 用均值而非 max：max 会让"有一艘特别近"就整队变模型（远处舰模型过小）。

## 5. 教训（本轮最重要）

**不要为"更早出现某个效果"单方面下调感知校准过的参数。**

v73 我做了两件事：① 刚体运动学（有依据的新架构）② LOD 阈值收紧 + 相机拉近（无依据的参数变更）。
用户对 ① 的反馈是"移动问题"，对 ② 的反馈是"不如之前"。

⇒ **参数是校准值，不是设计变量。** 改参数前必须问："这个值是谁、在什么条件下校准的？"
⇒ 引入新机制时，**只改该机制必需的参数**，不顺手调其他。
⇒ 用户说"最早版本没问题"时，**逐项 diff 找出所有差异**，而不是猜。
