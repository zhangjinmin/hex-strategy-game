## 3. Part C｜修复（据证据执行）

### C1. `autoLodByLoad` 增加帧时压力判据（`Battle3DOverlay.ts`）

原判据**只看实体数量**（≥300→low / ≥170→medium / <120→high），修正为 **数量判据 ∪ 帧时压力棘轮**：

```ts
// (2) 帧时压力棘轮（0.5s 冷却；跳过 PERF_WARMUP_FRAMES 避免编译期误判）
this.lodCooldown -= dt;
const perfWarm = this.perfFrame >= PERF_WARMUP_FRAMES;
if (this.lodCooldown <= 0 && perfWarm) {
  if (this.frameEmaMs > PERF_BUDGET_MS && this.lodPressure < 2) { this.lodPressure += 1; this.lodCooldown = LOD_COOLDOWN_S; }
  else if (this.frameEmaMs < PERF_COMFORT_MS && this.lodPressure > 0 && meshCount < LOD_RECOVER_COUNT) { this.lodPressure -= 1; this.lodCooldown = LOD_COOLDOWN_S; }
}
let wantIdx = Math.max(countIdx, this.lodPressure);   // 帧时压力是**下界**，数量判据不得抵消
wantIdx = Math.max(wantIdx, ceilIdx);                  // 不高于用户上限（语义保持）
```

- `updatePerfGovernor`：**帧时 EMA 改为无条件计算**（原只在 `perfOn` 时算 ⇒ 默认关时帧时降档完全失效）；仍保留既有 WS7 调试契约（未开 governor 时 `lastStats.frameMs` 恒 0、`meshBudget = MAX_MESHES`）。
- **开发过程中的自我修正（诚实记录）**：首版把帧时增量直接加在同一个 `wantIdx` 上，与数量判据每 0.5s **互相拉锯** ⇒ 实测 120s 内**档位抖动 23 次**（`after` 轮数据）。改为**棘轮 `lodPressure` 取下界**后抖动 **23 → 0**（`after2` 轮）。这是探针直接抓到的自身回归。
- **第二处自我修正**：帧时判据初版未受 `PERF_WARMUP_FRAMES` 保护，会用"着色器/地形编译期的暂时慢"触发冷启动降档 ⇒ 加 `perfWarm` 门（`after3` 轮）。

### C2. 实体池逐帧限流 + 换档分帧迁移

```ts
const MESH_ADD_PER_FRAME   = 32;   // 每帧新建实体上限
const MESH_DROP_PER_FRAME  = 64;   // 每帧回收实体上限（滞回回收 + 超预算回收**共享**此预算）
const LOD_MIGRATE_PER_FRAME = 24;  // 换档时每帧淘汰的旧档实体上限
```

- `ShipEntry` 新增 `tier` 字段（记录构建档位）；`addMesh` 写入 `tier: this.detailTier`。
- `autoLodByLoad` 的**换档全量 `dispose+clear` 删除**，改为**逐帧淘汰旧档实体 ≤24 个**，下一帧由实体池第二遍按新档经 `addMesh` 自然补回（同时受 32/帧限制）⇒ **任何一帧的建/销都被限流约束，无整档尖峰**。
- `lastStats.kept` 改报**实际持实体数**（`this.ships.size`）：限流/迁移下可与预算 `keep` 短暂不等，稳态相等 ⇒ 调试读数更诚实。
- 语义保持：光点层仍覆盖全部 `unitVis`，被限流/迁移的舰**不产生"隐形洞"**（只是实体长出被摊到后续帧）。

## 5. A/B 数据

### 5.1 ⚠ 口径缺陷声明（**必读**）

`_ws13_probe.cjs` 的 **A 段（全景）**相机由"framing 全部舰队"计算，而舰队初始位置/朝向来自未固定种子的随机 ⇒
**三次运行的相机距离不一致**（`before=10309.3` / `after2=8040.2` / `after3=8783.9`）。

在这一前提下，A 段三次运行的 `syncShips` 为 **42.8 / 29.7 / 55.4 ms/帧**——而 A 段相机的代码路径完全相同（`meshes=0`），
**波动幅度（±50%）远大于任何修复效应**。因此：

> **A 段的绝对值不可作为 A/B 证据**；`after2` 曾出现的"A 段改善"（47.6→36.4）经 `after3` 反证为**噪声**。
> **B 段**用 `__b3dFocus` 固定 `dist=275 / elev=0.3`，口径一致，**是唯一可信的端到端 A/B 口径**。
> 纯判据类指标（`maxAddFrame`、档位切换次数）与相机/负载无关，**最可信**。
