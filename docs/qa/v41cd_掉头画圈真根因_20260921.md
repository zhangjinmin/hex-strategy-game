## 1. 我的判据错了两次（这是"修了还坏"的直接原因）

| 代 | 判据 | 为什么测不出画圈 |
|---|---|---|
| v41b | **锚点位移**（实测 2.3~3.4px，全绿） | 画圈时**锚点几乎不动**——整阵绕它转，锚点位移当然小。**假通过** |
| v41c | 全程**每艘舰**路径效率（worst 3.67~10.53） | 窗口混入了正常战斗机动（排斥/呼吸/追击抖动）：低净位移个体效率天然可以很大 ⇒ 指标被污染，判不出画圈 |
| **v41d** | **仅在协议期内**的每艘舰路径效率 | ✅ 干净：协议期只有掉头一件事 |

**数据实锤**：v41b 全绿时锚点路程仅 30px，而同期单位路程 278px / 净位移 222px、最差个体效率 3.67——**锚点判据与用户看到的完全是两件事**。

⚠ 第二次判据陷阱（v34 的老教训重犯）：**绕锚点转角零判别力**——直线穿越中心与绕弧公转的绕心角都是 180°（实测 snap 180.00° / circle 178.63°）。有效判据是**路径效率**（路程/净位移）：弧线 1.40、直线 1.00。

## 2. 真根因：几何恒等式 + 一个被绕过的分支

```
单位目标位 = 锚点 + rotate(阵位偏移, formFacing)          ← :5550-5552
```

**`formFacing` 连续旋转 ⇒ 单位绕锚点公转 ⇒ 画圈**（这是几何恒等式，不是参数问题）。

而 v41b 我犯的错是：让 `formFacing` **跟着 `facingSmooth` 连续转**——等于把画圈做得更明显。正确做法必须让格位**一帧吸附**到目标航向（格位集合瞬间重排，单位走直线），舰体自转交给 `facingSmooth`。

**第二个洞**：`_isUturn` 原判据是 `_dTo > 90°`（`_dTo` = 速度方向 vs formFacing 的差）。协议期刚开始时 `_dTo` 还很小 ⇒ wedge 落进下面的 `rateLimitAngle` **连续旋转分支** ⇒ 格位被拖着转 = 画圈。修法（最小侵入）：`_isUturn = _uturn === true || _dTo > 90°`。

**第三个洞**（v41b 引入的回归）：协议块无条件设 `formFacing`，**绕过了对称阵型的"原地转身"分支**。现已恢复：对称阵型（line/circle/square）协议期不动 formFacing ⇒ 单位目标位完全不动 = **真·原地转身**（台架实测路程 0.00px）。

## 3. 修复清单

| 文件 | 改动 |
|---|---|
| `BattleScene` 低通块 | 协议期 `formFacing` **一帧吸附**到 `fAngle`（非对称），对称阵型不动；`facingSmooth` 仍快档自转（舰体转身） |
| `BattleScene` 阵位旋转 | `_isUturn` 并入 `_uturn === true`（最小侵入，结构零改动） |
| `balance.FACING_TURN` | 参数（ENTER 50° / EXIT 30° / RATE_MUL 6 / THRUST 0.06）|

## 5. 教训（三条，全部已入记忆）

1. **判据对象必须等于"用户看到的东西"**——用户看到每艘舰，我却测锚点。测错对象 ⇒ 全绿假通过。
2. **窗口必须干净**——混了正常机动的窗口里，低净位移个体的路径效率天然爆炸。
3. **绕心转角零判别力**（第二次踩）；`Math.min` 初值给 0、顶点数当密度（v39）等同类错误已多次发生 ⇒ **先问"这个量在两种假设下会不会不同"**。
