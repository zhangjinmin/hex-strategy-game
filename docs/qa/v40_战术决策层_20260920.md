## 0. 诊断：为什么「说了无数遍」没修掉 —— 三个「半改」

用户观察全部属实，且每一条都能指到具体行：

| 用户观察 | 代码出处 | 性质 |
|---|---|---|
| 「补给变黄就集体回头，不论性格」 | `BattleScene:4977`（原）`needsTethering = currentSupply < 75` —— **硬阈值，无性格无态势** | **v29 半改**：v29 只把「撤退触发」（`:4556`）改成了 `doctrine.retreatThreshold` 性格驱动，但**探索期补给锚定**这条更早生效的逻辑原样留着 |
| 「转向就是三角形绕定点画圈」 | 转向速率恒 `FORM_FACING_RATE`，**与接敌状态无关** | 缺「转向纪律」维度 |
| 「谁都是直线冲，只有一种 AI」 | `_maneuverLateral` 只在**接敌后**（`:4853+`）生效；**接敌前**三路目标点完全相同 | 缺「接近阶段航路」——与 v35 的 G2 诊断一致 |

**核心教训（已写入记忆）**：这不是「没做」，是**每次只改了同一系统的三分之一**。散落在 `BattleScene` 里的阈值判断（`< 75`、`< 90`、`< 30`）没有一个统一入口，改一处漏两处是必然的。

## 1. 方案：一个决策函数 + 三条接线（不新增 AI 系统）

用户说「用 if/switch 都可以」——**正是这么做的**，但收进一个**可被台架直接 require 的真源码模块**（本项目铁律：逻辑必须可离线断言）。

### 1.1 新真源 `frontend/src/game/combatDoctrine.ts`（214 行）

三个纯函数，全部**带规则名返回**（每条决策可追溯到是哪条规则在起作用 —— 便于 L2 断言与玩家侧调试）：

```
supplyDecision(s) → { action: 'pursue'|'hold'|'return', rule: 'S1..S12', reason }
```

**12 条规则，按优先级排列**（回答「罗列几十条判断」——先落 12 条，每条都独立可断言）：

| 规则 | 条件 | 动作 | 对应的小说表达 |
|---|---|---|---|
| S1 | 补给 ≤ 危急线 且 **敌我劣势** | `return` | 打不下去就撤 |
| S2 | 补给 ≤ 危急线 但 **我方大优（≥1.35×）** 且 进取度 ≥ 0.65 | `pursue` | **「补给变黄也要看能不能吃掉对方」**——莱因哈特式追击 |
| S3 | 补给 ≤ 危急线 且 **补给船已在途** 且 进取度 ≥ 0.55 | `pursue` | 「后续补给船正在过来，可以不断追击」 |
| S4 | 补给 ≤ 危急线 但 **驻守/围攻姿态** | `hold` | 攻城不因断粮动摇 |
| S5 | 补给 ≤ 危急线 但 **敌人正在转向脱离** | `pursue` | 敌转我追，一鼓作气 |
| S6 | 补给 ≤ 警戒线 且 敌我劣势 | `return` | 且战且退 |
| S7 | 补给 ≤ 警戒线 且 **补给船在途** | `hold` | 等补给，不溃退 |
| S8 | 补给 ≤ 警戒线 且 驻守 | `hold` | |
| S9 | 补给低 但 **我方优势** 且 进取度高 | `pursue` | 优势时不因补给缩水放弃机会 |
| S10 | 补给低（其余） | `return` | 常规锚定（保留 v29 语义，但**阈值经 `doctrine` 调制**） |
| S11 | 补给充足 | `hold` | 什么都不做（**不再有 `<75` 硬锚定**） |
| S12 | 补给船在途 且 不急 | `hold` | |

⚠ **关键点**：S10 的阈值不再是常数 `75/30`，而是 **`90 − aggression×30`**（进取 0.9 的提督 63% 才锚定，谨慎 0.3 的 81% 就锚定）——「性格因素」第一次进入补给判定。

```
turnDiscipline(s) → { mode: 'free'|'limited'|'denied', rateMul, maxStep, reason }
```

**转向纪律三态**（回答「还在对战就不能转向」）：

| 态 | 触发 | 效果 | 对应表达 |
|---|---|---|---|
| `free` | 未接敌 | 原速 | 「没有敌人的情况下直接转向」 |
| `limited` | 脱离中（retreating） | **×0.55** | 「对战时要缓慢后退，再逐步转向」——亚斯提会战同盟之败的反面 |
| `denied` | **交战中 + 大角度（>72°）** | **×0.14 + 单帧步长钳制**（6.5°） | 「还在对战就不能转向」；小幅修正不受限 |

⚠ 与 v31-D/v34 的关系：**只改速率与单步上限，不改旋转几何**（snap/arc 模型不动）。

```
approachLateralOffset(lateral, dist, engageDist, maxSpan) → 侧向偏移(px)
```

**接近阶段航路**：分兵各路在**接敌前**获得按 `_maneuverLateral`(−1/0/+1) 的侧向分量，**随距离线性收敛到 0**（`engageDist` 处归零 ⇒ 接敌瞬间已对齐，不产生横向抖动）。这是 G2 的最小正确实现——不动 `fleetSplitManeuver.ts`（其契约明写「仅视觉层」），在移动层补缺。

### 1.2 接线（BattleScene 三处）

1. **`:4993` 补给决策**：`supplyDecision(...)` 每帧结算 → `_supplyAction/_supplyRule` 挂舰队；`needsTethering` 改由 `action==='return'` 派生（**硬阈值删除**）。
2. **`:4811` 补给圈内停船**：`< 90` 常数 → 经 `supplyDecision` 裁决（pursue 时不停船）。
3. **`:5300+` 转向纪律**：`turnDiscipline(...)` → `_turnDisc` → 速率乘区 + denied 单帧钳制。
4. **接近分支**：`approachLateralOffset` 叠加到目标点。
5. **进取度派生**：`faction._aggression` 由提督 `aggression` 标签（无标签退 0.5）+ 阵营种子调制 ⇒ **双方进取度实测 0.75 vs 0.583**。

## 3. 实施中的自查

1. **f3 未定义先使用**（TDZ）：台架 helper 定义在使用之后 → 上移修复。
2. **重复导入**：`NEUTRAL_DOCTRINE` 被并发补丁写了两处 import → 去重（此前记忆已有「同文件并发 Edit 会丢一条」的坑，这次是**同一文件两条补丁叠加**导致重复，同源不同症）。
3. **「一次性改到位」的正确理解**：不是一次改完所有战术（不可能），而是**把判定收进单一真源**，让之后每加一条规则都是「在 12 条旁边加一行 S13」而不是「在 6779 行的 BattleScene 里再埋一个 `< 75`」。
