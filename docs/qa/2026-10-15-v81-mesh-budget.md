# v81 实体预算 400→900（诊断面板一轮定位）

日期：2026-10-15。**用户提供诊断面板截图 ⇒ 根因一轮确定。**

---

## 1. 诊断数据（用户截图面板实测）

```
tier=FAR lo=14 hi=26 keep=17
n=150  px=18.5  mesh=150  MODEL
n=150  px=22.2  mesh=150  MODEL
n= 80  px=19.0  mesh= 80  MODEL
n= 50  px=16.7  mesh=  0  FADE     ← 过渡带：淡模型 + 有点
n= 50  px=17.0  mesh= 20  MODEL    ← 只给了 20/50
```

### 三处硬证据

| # | 证据 | 结论 |
|---|---|---|
| 1 | 总需求 = 150+150+80+50+50 = **480**；拿到实体 = 150+150+80+0+20 = **400** | **恰好 = `MAX_MESHES = 400`** ⇒ 预算耗尽 |
| 2 | 第 5 支 `px=17.0 ≥ keep=17` 却只有 `mesh=20/50` | **被预算挤出**（不是阈值问题） |
| 3 | 第 4 支 `px=16.7` ⇒ `grow≈0.13`，旧点让位阈值 0.15 判不出 | 该队"淡模型+点" ⇒ 用户读作"点" |

**用户"是折算的问题"的方向自始正确** —— 只是机制是 `MAX_MESHES` 预算，
而非前几轮猜的 `hpPct` 折算 / LOD 阈值 / 图层退场。

---

## 2. 修复（三处）

| 项 | 旧 | 新 | 依据 |
|---|---|---|---|
| `MAX_MESHES` | 400 | **900** | 480 需求 vs 400 上限。400 是早期（单位少）取值；900 覆盖常见规模，性能由 `perfOn` 自适应兜底 |
| `MESH_ADD_PER_FRAME` | 32 | **96** | 480/32 = 15 帧（≈0.25s 的"半边空"窗口）⇒ 96 时 5 帧补齐 |
| 点让位阈值 | 0.15 | **0.02**（等价"有实体即去点"） | 实测 `grow≈0.13` 判不出 ⇒ 改为二值化 |

### 点让位的二值语义（重要）

```ts
if (hasMesh && grow > 0.02) return 0;
```

- **有实体**（`fleetPx ≥ keep`）⇒ **纯模型**（浓淡由 `grow` 控尺寸，不再是点）
- **无实体**（px 太小）⇒ 纯点

⇒ 不再有"模型与点并存"的中间态 —— 这正是用户反复反馈的观感。

## 5. 未闭合

- **更大规模**：若战场 > 900 单位，仍会有舰队被挤出 ⇒ 届时看是否继续提高
  （或用 `perfOn` 自适应，但那会主动降实体数）。
- **性能**：900 实体在低配机上可能超 22ms 预算 ⇒ `perfOn` 会收缩 `meshBudget`。
  若用户遇到，需权衡"全模型 vs 帧率"。
- 第 4 支（`px=16.7 < keep=17`）现在**有实体**是因为预算充足后
  `cand` 仍要求 `fleetPx ≥ keep`——**等等，16.7 < 17 不该进 cand**。
  实际修复后该队仍应为点。**本轮修复只把"有实体的队"点去掉**；
  `px < keep` 的队保持点（符合原校准）。若用户希望它也变模型，需下调 `keep`。

## 6. 方法论（本轮最重要）

**v79 加的诊断面板，一轮定位了前 5 轮都猜不到的根因。**

证据链完全来自用户截图上的数字：`400 = MAX_MESHES` 这个整数等式是决定性证据。

⇒ **当代码层已排除所有可能、现象仍存在时，植入可观测性 > 继续猜测。**
⇒ 本项目 v70~v77 的反复失败正是"猜一版改一版"；v79→v81 是"给数据→一轮定位"。
