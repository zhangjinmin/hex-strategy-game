## 1. 判据设计（本轮最重要的方法论修正）

前七轮之所以反复"修了还坏"，一半原因是**判据打错了对象**：

| 轮次 | 判据对象 | 问题 |
|---|---|---|
| v41b | 舰队锚点位移 | 画圈时锚点几乎不动 ⇒ **假通过** |
| v41c | 全程每艘舰路径效率 | 窗口混入正常机动 ⇒ 被污染 |
| v42e | `facingSmooth` 累计转动量 | **转动量大 ≠ 抖动**（单向慢转也大） |

**本轮判据 = 3D 层 `entry.yaw`（`group.rotation.y`）与舰队级 `facingAngle` 的「方向翻转次数」。**

理由：
- 用户看到的是 3D 舰体（`Battle3DOverlay:3712-3723`，`entry.yaw` 直接吃 `fleet.facingSmooth`，无二次限速）；
  `DOT_N = 1` ⇒ 光点层是"1 舰 1 点"，用户看到的**只能是实体模型**；
- 「摇头」的充要条件是**朝向方向反复翻转**（来回），不是"转了多少度"。
  ⇒ 判据必须统计 `sign(Δθ)` 的翻转次数，并加 **0.5° 噪声门限**（`1e-6` 会把 dF 跨零的浮点 churn 记成翻转，
  实测出现过"反向 0.0°/0.1°"的伪计数）。

台架/探针（判据打在终态上，可复跑）：
`_probe_v43.mjs`（场景侦察）· `_probe_v44.mjs`（接敌分段）· `_probe_v45.mjs`（**受控输入复现台**）
· `_v44_diag.cjs` / `_v45_diag.cjs`（逐帧取证，不重跑浏览器）。

## 3. 根因（四层，全部有读数支撑）

1. **硬阈值无滞回**：`minFleetDist < idealDist*0.35` 单阈值。`mfd` 在 266~298 摆动即反复穿越 280
   ⇒ 目标点在「拉开点（自身后方 0.5×idealDist）」与「包抄点（敌后方 idealDist）」之间反复跳，
   二者相距 **1400+px**。
2. **意图被敌方朝向驱动**：`flankAngle = enemyAngle + π ± π/4`（`enemyAngle` = **敌方舰首朝向**）
   **每帧重算** ⇒ 敌方一转身，我方包抄目标点就绕敌旋转。
3. **双方互为输入 ⇒ 正反馈**：敌方同样吃我方朝向 ⇒ 两队互相触发
   ⇒ 用户截图里"两支舰队都在摆"。（`angleDiff` 帧间实测 82°→11°，一帧 70°+）
4. **`denied` 把转向压成蠕动（v42b 我引入的放大器）**：
   `turnDiscipline` 的 `engaged` 用 `state === 'engaging'`，而该状态 **900px 外就已置位**
   ⇒ 整段接近航路都被判"交战中禁止转向"；`rateMul = 0.06~0.16` ⇒ 实测 **0.61°/帧**
   ⇒ 转 97.6° 要 **174 帧（≈3 秒）**。
   ⚠ 语义冲突：协议期进入条件 `dGoal > 50°` 与 `denied` 触发条件 `deg > 25°` **几乎完全重叠**
   ⇒ 协议期几乎必然是 `denied` ⇒ **"6 倍快转"被自己的纪律抵消**。

## 5. 一次回归与它的教训（G 的回退）

曾加 G：对敌方朝向做一阶低通（τ≈10 帧），动机是"压掉它 70°+ 的帧间跳变"。

**实测反而使 `facingAngle` 方向翻转 0 → 4 次**（同一受控输入，`td=limited` 也出现在本不该出现的帧）：

```
#67  反向 59.5°   adiff=1.542  mfd=288.7
#128 反向 116.4°  adiff=1.718  mfd=279.9      ← 与 #67 方向相反 ⇒ 真的来回摆
```

**教训：耦合不能靠"改变相位"来断，只能靠"锁死不跟随"来断。**
低通让 `angleDiff` 滞后于「翼侧角锁定」所依据的原始朝向，两者时序错配 ⇒ 相位在错误时刻切换。
⇒ **回退 G，只保留 A~F**（"只保留有数据支持的改动"）。
