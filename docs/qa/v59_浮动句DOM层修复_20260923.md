## 1. 实报与根因

**症状**（用户真机）：① 战斗中的浮动一句话（banter 闲聊）没有出现；② 进场（舰队出击）的
那句话也没有出现。

**根因（渲染层，一处）**：指挥制下 Phaser 画布**整体不可见**——
`App.vue:37` `body.battle3d-mode .game-canvas { display: none }` + `main.ts:36`
`body.battle3d-mode #phaser-game { display: none }`；战场视觉真源 = Three.js `Battle3DOverlay` + Vue DOM。

v58 把 banter 搬进 Phaser 气泡（`showFleetDialogue` 的 Container）⇒ **气泡画在一块被隐藏的
画布上 = 凭空消失**。进场/接敌/受创/占领/击毁等事件气泡自 v37（画布隐藏）起就从未真正可见，
v58 又把闲聊迁入同一死路。右侧立绘卡（v58 删除前）之所以"能看见但被挡"，正因为它在 DOM 层。

## 3. 逐层排除过程中揪出的两个隐藏问题

### ① v58 探针假绿（教训：断言打在不可见层）
J8（v58）只断言 Phaser 容器对象存在（`activeDialogues.length===1`）——它在**不可见画布**上
照样"存在"。**逻辑存在 ≠ 视觉可见**；L2 探针判据必须落在用户可见层（DOM/overlay），并
按真机渲染链验证。

### ② `cam.worldView/midPoint` 冻结在 preRender 前的全 0 陈旧值
J9b 相机中心投影自检首跑 FAIL：`midX=0, wvx=0`（互不一致——若相机真在原点，worldView.x
必为负）⇒ 指挥制下 Phaser 渲染链停摆，投影输入全是死数据，坐标被钳位到视口左下角。
修复：`worldToScreen()` 投影前 `try { cam.preRender?.(scale.width, scale.height, 1) }`（幂等）。
复测 `centerX=792.0 == iw/2` 精确命中；`wvx=-931.8` 与 `midX=0` 恢复自洽。

## 5. 工具链事故（本轮最值得记的教训）

**并行发两个 Edit 时，只有后者落盘，前者"报成功但丢失"**——本轮 3 处并行 Edit 的第一个
全部静默丢失（`showFleetDialogue` 尾段、跟随循环、store 返回清单），回读时才发现。
MEMORY 铁律原本只禁"同一文件多处 Edit 并发"，实测**跨文件并行 Edit 同样丢**：
⇒ 规则升级为 **Edit 一律严格串行，任何并行都不允许；改完必须回读验证**。
（工作区另有 `flagshipOf`/`placeFlagshipAtRear` 等非本会话改动，疑似并行编辑源，已向用户提示。）
