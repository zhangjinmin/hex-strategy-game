### 1.3 断点嫌疑（⚠ 待确认）

**战场 tile 对象的字面量里没有 `terrain`**（`:2145-2150`）：

```ts
const tile = {
  q, r, cost, ownerId, type, typeName, tileClass, tier, hp, maxHp, x, y,
  sprite, text, lastTowerShotTime, connected: false, captureProgress: 0,
};                      // ← 无 terrain
```

而 `terrain` 在全 `BattleScene.ts` 里**只有两处读**（`:2710` 的 `?.terrain`、`:2782` 的 `t.terrain`）
与**一处写**（`:4059-4066` 的 `t.terrain = ...`，写在 `mapDataMatrix` 的元素上）。

⇒ 若 `:2145` 的 `data` 与 `:4059` 的 `t` **是同一份 `mapDataMatrix`**，那么断点就是**这一行漏搬字段**，
修法 = 字面量补 `terrain: data.terrain`（一行）。
⇒ 若不是同一份（例如战场另有一套格子生成），则要顺着调用链找真正的断点。

**⚠ 这与上一轮 L2 观察吻合**：演习模式读到的战场格子里**没有任何地形**。
**⚠ 不吻合的地方**：用户看到的是**指挥制/后勤战**（有中继点），模式可能不同 ⇒ 断点位置可能不同。
**⇒ 所以先做一次 L2（见 §6），不猜。**

`01_策划案正文_结构化整理.md` 的战场地形表是 **10 种 × 5 列**（名称 / 移动 / 射程 / 索敌 / 特殊）。

## 2. B · 中继点占领：机制有，但不告诉玩家

### 2.1 机制（✓ 存在）

- **目标**：指挥制后勤战在中线带布置中立星球中继（`:556`、`:2176-2180`），
  占领后纳入补给网（`getNearestSupplySource` 支持，`:1645`）。
- **占领方式 = 靠近即自动占领**（不是点击）：
  `processSupplyAndCapture` 按**空间距离**找最近可占领目标（`:1799-1811`），
  在圈内累计 `captureProgress += captureSpeed`（`:1840`），到 100 即占领（`:1846-1855`），
  并触发**占领语录**（`showFleetDialogue(fl,'capture')`）+ 玩家侧横幅（`:1782`）+ toast（`:1854`）。
- 格子透明度反映剩余 HP（"越低越接近占领"，`:1766`）。

⇒ **用户看到的"别人占领时有动画效果"就是这个** ✓（AI 舰队自己去占，玩家看到了反馈）
⇒ **用户右键点自己部队没反应**，是因为：**右键是"设战术信标"**（`targetFlare`），
   而占领**根本不消费右键** ⇒ 玩家点中继点不会触发任何占领专属提示。

### 2.2 缺什么（= 用户真正抱怨的）

| 缺口 | 具体 |
|---|---|
| **入口不可发现** | 没有任何 UI 说"把舰队开进中继圈即可占领" |
| **右键无反馈** | 右键点中继点 ⇒ 只落一个信标，**不提示"已标记为占领目标"** |
| **进度不可见** | `captureProgress` 只反映在格子透明度上，**没有进度环/百分比** |
| **射程不可见** | 占领圈半径（`SUPPLY_RELAY_RADIUS`）**不画出来** ⇒ 玩家不知道"要飞到多近" |

⇒ **半天量级**可做出最小可用回路：右键点中继 → 画占领圈 + toast「已标记：中继 N（占领需进入圈内）」→
舰队飞入 → 圈内显示进度环 → 完成横幅（已有）。

## 3. C · 舰队 AI：**航路几何写了但从未接线**

### 3.1 决定性证据

`config/fleetSplitManeuver.ts`（三幕包抄的闭式不互穿几何）在**全项目**只有 5 处提及，
**全部是注释**：

```
BattleScene.ts:173   「拆分后各路会由战法航路继续牵引（几何复用 config/fleetSplitManeuver.ts）」
BattleScene.ts:1150  「机动几何复用 config/fleetSplitManeuver.ts（已具备三幕包抄的闭式不互穿保证）」
BattleScene.ts:3431  「…在结构上无法表达（这正是 fleetSplitManeuver.ts 声明"不接任何玩法触发"的原因）」
taskForce.ts:15      「机动几何（两翼不互穿的闭式解）复用既有的 config/fleetSplitManeuver.ts」
taskForce.ts:71      「钳形包抄：…（几何复用 fleetSplitManeuver）」
```

⇒ **零 `import`、零调用** —— 注释宣称"已复用"，实际**从未接上**。
⇒ **这正是用户说的"为分而分"**：分兵只写入了角色标签，**没有任何航路几何**。

### 3.2 已接线的部分（不要误判为全无）

`_maneuver*` 的消费分支**存在**（`:4905-5000`）：

```ts
const mRole = fleet._maneuverRole;          // 'left' | 'right' | 'main' | …
const mKind = fleet._maneuverTargetKind;    // 'enemy_supply' | 'enemy_fleet' | …
const wantsFlank = mRole === 'left' || mRole === 'right';                 // :4910
const raidTarget = mKind === 'enemy_supply' ? findEnemySupplyTarget(...) : null; // :4912
```

⇒ 所以"侧翼偏好"与"后勤猎杀"**是**生效的，但它们只改变**接敌时的目标点**，
**不改变"分兵后到接敌前这段路怎么走"** ⇒ 观感仍是"三路一起朝敌方压过去"。

### 3.3 因此 C 的真实缺口

| 层 | 现状 |
|---|---|
| 战法选择（选哪条战法） | ✓ `taskForce.selectManeuver`（含降级链、`maxRoutes` 修正） |
| 分队编成（拆几路、各多少兵） | ✓ `splitFleet` + `splitUnitCounts` |
| **机动航路（分兵后怎么飞）** | ❌ **`fleetSplitManeuver` 零接线** ← **缺的就是这一层** |
| 接敌行为（侧翼/后勤/包抄） | ✓ `wantsFlank` / `raidTarget` 分支 |

⇒ **观感公式**：有编成、无航路 ⇒ "三支舰队一起直线冲"，即用户所说"一窝蜂"。

## 4. D · 开局军议：侧栏 ≠ 作战会议

### 4.1 实测

`components/battle/CouncilWarRoom.vue`：

```css

            max-height: calc(100% - 200px); overflow-y: auto; z-index: 30; }

```

⇒ **292px 侧栏 + 10~13px 字号**，与用户描述"右上角那个，不注意真的以为是界面卡死了"完全吻合。

### 4.2 暂停逻辑（用户说"莫名其妙没有逻辑"）

`activateDeployPhase()`（`:929-992`）：

| 条件 | 行为 |
|---|---|
| 战役模式，或 指挥制演习 | `store.isPaused = true` + `battleDeployPhase = true` + 展开军议 |
| 非指挥制演习 | **不暂停**，仅展开军议（`warRoomOpen = true`），并 `planAiFactionsForDeploy()` |
| 演习 | 额外 20s 倒计时（`DEPLOY_COUNTDOWN_SEC`），倒计时结束自动开战 |
| 悬停军议面板 | 倒计时暂停（`@mouseenter → setCountdownPaused(true)`） |

中央有 `deployText`（`:995-1010`，"…[回车] 立即开战"），但它是**14px 的一行 monospace 文本**。

⇒ 所以"暂停"本身**有逻辑**（部署窗口），但**玩家读不到**：
- 唯一的说明是中央一行小字 + 右上角 292px 侧栏
- 没有"为什么暂停、现在该干什么、下一步会发生什么"的**明确指令**
- 用户描述"才只要按回车"⇒ 他最终是靠回车才脱困的

### 4.3 用户要的"大界面"（人像 / 讨论 / 布置）

现状 **0%** 具备：无全屏层、无提督立绘、无对白、无推演。
⇒ 属**新增功能**（2~3 天量级），不是修补。

## 5. 建议路线（明确建议，非选项罗列）

**按"成本 / 感知强度"排序，建议这个顺序：**

| 序 | 项 | 理由 |
|---|---|---|
| **1** | **A · 接上地形** | 唯一已确认的"数据链断裂"；一行量级；**感知最强**（整张地图从"空的"变成"有 6 种地形 + 色块标记 + 移速/射程/索敌/损伤全部生效"）。⚠ 会**改变战斗手感**（移速/射程/闪避/索敌/伤害五处），须走 `TACTICAL_V33` 开关并做一次 L2 对照 |
| **2** | **B · 中继占领的可见回路** | 半天；把"看不懂"变成"能玩"：右键标记 + 占领圈可视化 + 进度环。**不动任何战斗数值** |
| **3** | **C · 接上战法航路** | 用户最在意的"动脑子的成分"就在这里。`fleetSplitManeuver` 已有闭式几何，**接线成本 < 重写成本**，且能直接产出"迂回/包抄"的可辨识轨迹 |
| **4** | **D · 开局军议全屏化** | 感知强但成本最高；且它**依赖 C 的语义**（大界面要展示"给哪支舰队下什么任务"，而任务的效果感来自 C）⇒ 放在 C 之后做，才不是空壳 |

**为什么不先做 D**：用户对军议的抱怨一半是"看不懂在干什么"。就算换成全屏人像，
若下面的战术系统（C）仍无差异化行为，玩家依然会觉得"布置了也没用"。
**先让战术真的不同，再给仪式感。**
