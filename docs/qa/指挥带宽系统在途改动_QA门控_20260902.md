1. **门控的失败路径必须成对处理"已产生的副作用"**。BW-02 是典型：先创建了视觉、后判定拒绝，被拒时忘了回滚已落地的对象。这类 bug 在"给已有流程插入新校验"时极常见，建议后续每加一处门控都自查：被拒时前面已经改了什么状态、创建了什么对象。
2. **新增 UI 的赋值时机要对着"它什么时候可见"去验证**。BW-01 的问题是赋值点在暂停分支之后，而 UI 只在暂停时可见——两个条件互斥。这类问题单看代码很难发现，建议在合入前实际打开面板看一眼数值，不要只依赖类型检查通过。
