## 0. 放行口径（先定这一条，否则后面全是假绿）

> **放行标准 = 纯函数绿 + 真机字段有值。**
> 不是"全绿"。

原因：本卡里只有 `flankAngleDiff` 与舰种键归一两类能在 CI 里稳定跑；包抄退出、移动令完成、停船收敛三类都必须真机取数。若把标准写成"全绿即放行"，那三类会**永远绿在"没测"上**——这正是本 bug 潜伏多轮的方式。

## 1. 根因：三条独立路径，终点角度不同

`facing` 的真源是「到**目的地**的方位」：`fAngle = atan2(fleetTarget − fleet)` `[代码]`。目的地取决于分支，于是"舷侧"有三条互不相同的成因，**不能合并成一句"朝向没朝敌"**。

### 路径 A · 包抄支 → 稳定 90°

`_mPhase===1` 且 `(isAggressive || wantsFlank) && !isBehind` 时，目标为
`P = _lead + (cos,sin)(_flankAngleLock) · idealDist`，而 `_flankAngleLock` 是**接战那一刻锁定的世界角** `[代码]`。
⇒ 这是一个**固定的世界点**，舰队抵达时的航向取决于接近弧，**90° 是常见稳定解**。

`[代码]` `isAggressive === wantsFlank`，而 `wantsFlank = shouldFlank({ commanderAggressive: command > 80, maneuverRole })` ⇒ **只有高统帅（>80）或被战法指定侧翼的舰队**走这条路。

### 路径 B · 标准接近支（`_mPhase 0→1`）→ **180° 尾对敌**

这是最容易误判的一条，代数如下 `[代码]`：

```
û      = (E − me)/|E − me|            // 我→敌
P      = _lead − idealDist·û           // 标准接近支的目标点
P − me = (d − idealDist)·û + (_lead − E)
```

- `d > idealDist` ⇒ 目标在**前方**（≈0°，正对敌）。
- `d < idealDist` ⇒ 目标在**正后方**（≈180°）。

而 `_mPhase` 的 0→1 进入线是 `d < 0.70·idealDist`，**必然已经 < idealDist** ⇒ 进入 phase 1 前后，`fAngle` 早已是 180°，且 `fleet.facingAngle` 已被写成 180°。
`_backing`（唯一把舰首拉回敌向的分支）要求 `_mPhase === 2` ⇒ **phase 0 不生效** `[代码]`。
进入 phase 1 后 `target = self` ⇒ `distToTarget≈0` ⇒ 停船分支 ⇒ `fAngle = fleet.facingAngle` = **180°** ⇒ 尾对敌固化。

**翻转点不是 `d = idealDist`，而是 `d ≈ idealDist − (_lead − E)·û`**（前置追踪的横向/纵向偏移会把翻转点推前或推后）`[推算]`。5px 停船门只在这个翻转点附近提供一条 5px 宽的死区：
`ideal−d ≈ 5` 时不触发掉头；一旦越过，目标点落到身后 5px 以外，就进入"转 180° → 飞 5px → 目标翻回前面 → 再转 180°"的极限环 `[推算]`。
该环的单周期 ≈ `brake(5~10s) + turn(14~28s) + reform(10s)` ≈ 30~48 秒 `[推算]`（与用户实报的"一直在转"时间尺度吻合）。

### 路径 C · `_mPhase 2→1` → 0°（唯一稳定的对射线）

phase 2 期间 `_backing` 把 `fAngle` 改回敌向，块尾把 **0°** 写进 `fleet.facingAngle`；退出到 phase 1 后停船沿用 0° ⇒ **正对敌** `[代码]`。
这是唯一"正确"的终点，但它的进入条件是敌贴到 `<0.35·idealDist`，在正常交战里不常出现。

### 三条路径对照

| 路径 | 触发条件 | 停船/稳定朝向 | 是否"真舷侧" |
|---|---|---|---|
| A 包抄 | `command>80` 或被指定侧翼；`_mPhase===1` | **≈90°** | 是 |
| B 标准接近 | `!isCautious && !isAggressive`（command 40~79）；`d<ideal` | **≈180°** | 是（尾对敌） |
| C 拉开后回缠斗 | `_mPhase 2→1` | **≈0°** | 否（正确） |

> **对本页早期结论的更正**：此前"两条非包抄路径都停在正对敌"**不成立**；`0→1` 是 180°。更正来自 `general-purpose-2` 的代数反证，已逐行复核 `[代码]`。
> 另一处更正：`FIX-⑫`（停船回瞄）让 `fleet.facingAngle` 出现**第二个写点**，早前"全文件唯一写点"的口径作废。

### 为什么"舷侧"的代价是停火而不是掉血

- 射界：`isTargetWithinFireArc(heading, …, halfArcRad = π*0.42)` ⇒ 全锥 **151.2°**，半角 **75.6°** `[代码]`。
- 62° 以外即不可开火；90°/180° 必然为 0 输出。
- `visHeading` 在 v74 被统一钉成 `fleet.facingSmooth`（舰队姿态）⇒ 全舰队共用一个前锥 `[代码]`。
- 方向装甲：`dirArmorMul` 读 `SHIP_ARMOR[classType]`（中文键），战役轨 `classType` 是英文 ⇒ 查到 `undefined` ⇒ **恒返回 1.0** `[代码]`（该缺陷已由"修-2 键归一"修复，见 §2）。

⇒ 所以用户说的"这个不得被打爆"在数值层其实是"**打不出去**"，不是"挨得多"。这条区分决定了修法：优先修朝向/射界，而不是调装甲。

### 项 3 现状、作废理由与复活条件

**现状**
> `869c49e`（"停船交战期舰首按射界分档限速回瞄（推翻 v72「完全解耦」）"）曾以「推翻既有契约」的形式落地该改动，同一笔提交还改写了 `scripts/fleetIntentSim.cjs` 的两条守卫 —— **属于越权提交**。
> 裁决不变：**撤**。已排期 `git revert`；回退后 `fleetIntentSim.cjs` 恢复原文。
> 注意：分档（射界外 1.0 / 射界内 0.35）只是把"瞬间甩"换成"慢慢拧"，**没有改变 `改舰首 = 改阵面` 这个耦合**，因此不构成保留理由。

**理由**
1. 实测 `scripts/fleetIntentSim.cjs` 变 RED（且该 RED 被同笔提交改守卫所掩盖，这正是需要 revert 的原因）。
2. 手段（把舰首绑回敌向）会重新制造"阵面跟着甩"——因为 `formFacing` 恒等于 `facingSmooth`（v73/v74），改舰首 = 改阵面。这正是用户本次抱怨的症状形态。
3. 它只覆盖 `distToTarget <= 5 && isEngaging`；而路径 B 的 180° 掉头发生在**飞行段**，本改动完全没碰到。

**复活准入条件（缺一不可）**
- R1：`bow===1` 期间 `maneuver.phase !== 'brake'` 的样本占比 **≥ 95%**（防回瞄误触发 brake ⇒ `motion='hold'` ⇒ 永久停船）。
- R2：`off` 收敛时限按**舰种**计算，不得写死 30s：`T = (θ0 − 75.6°)/(ω·1.0) + (75.6° − 20°)/(ω·0.35)`，容差 +15%（战列 ≈20.9s，空母 ≈40s）。
- R3：不新增 `fleet.facingAngle` 的第二写点；若必须写，须在同一次提交里把它收口为单一 setter（当前第二个写点本身就是隐患）。
- R4：`fleetIntentSim` / `tacticalCombatSim` 回绿，且 `orbitAudit` 的 F1 不因它升高。
- **R5：任何未来的"重绑舰首"方案，必须证明「阵面不随之旋转」——即 `formFacing` 与 `facingSmooth` 已解耦（两者的 `|wrap(ff − fs)|` 可在转向期间显著非 0）。未解耦前一律不批。**

> 一句话：这个改法**不是错在方向，是错在时机**——在"阵面 ≡ 舰首"没解耦之前，任何"改舰首"的动作都会连带甩阵面。

## 4. 判据（可直接落成断言）

### 4.1 `flankAngleDiff` 相位转移表

### 4.2 绕圈（`scripts/orbitAudit.cjs`）

分析单元 = **交战片段**（`enemyId` 连续 + `stance` 不变 + `engaged` + 采样间隔 < 1.0s）。
**不用 3 秒窗口**：本作 `vMax ≈ 13.2 px/s`，3 秒只有约 40px（≈一艘战列的长度），全在量化噪声里。

**F1 · 原地公转**
`|Δff| ≥ 90°` 且 `pathLen < 0.25·R̄` 且 `ΔfireSeq === 0`，且 `cruise` 占比 ≥ 70%、`bow===1` 占比 ≤ 10%，且未进入敌后半球、未换带、未撤退。

**F2 · 无效绕飞**
`|Δβ| ≥ 90°` 且 `|d_end − d_start| / d_start < 15%` 且 `ΔfireSeq === 0`，且未进入敌后半球、未换带、未撤退、机动协议占比 ≤ 30%。

常量理由见脚本头部注释（`F1_SPIN_DEG` / `F1_PATH_FRAC` / `F2_SWEEP_DEG` / `F2_DRIFT_FRAC` / `REAR_ENTER_DEG` 等）。

**四类豁免（脚本里逐条写成 predicate，不是注释）**
1. `brake/turn/reform` 占比 > 30%；
2. `bow===1` 占比 > 10%（仅 F1）；
3. `retreatTier !== 'none'` 或 `motion === 'reverse'` 占比 > 10%；
4. 进入敌后半球（`angleDiff` 由 ≤120° 跨到 >120°）或 `band` 变化。

另：`enemyId` 变化 ⇒ 切片段（不是豁免）。

**BLOCKED（缺字段不判）**
以下任一成立 ⇒ 该片段输出 `BLOCKED`，**不计入通过**（与 §0 的"字段不存在 ⇒ BLOCKED"同一口径）：
- `fireSeq` 缺失（否则 `Δfire` 被当成 0 ⇒ 假阳性）；
- `phase` 缺失（无法排除原地转向）；
- `d` 缺失（无法判距离不变性）；
- `off` 缺失（仅 F2：`Δβ` 会退化成 `Δfs`，任何姿态变化都会被误判成绕飞）；
- 样本数 < 20 或时长 < 2 模拟秒。

**可用性门槛（结论级，不是片段级）**
- 可用片段 ≥ 1；
- 可用片段的模拟时长合计 ≥ 10s；
- BLOCKED 片段占比 ≤ 50%。

任一不满足 ⇒ 结论行打印「**结论不可用**」并 exit **3**。**0 命中在样本不足时不算通过**——与"缺字段 BLOCKED"是同一条原则，只是发生在样本层。

**自测（`--selftest`，15 条，已跑通）**
- A 原地转 120°、不动、不开火 ⇒ F1 **必须命中**；
- B 绕弧 110° 且进入敌后 ⇒ F1/F2 **必须不命中**；
- B2 原地转 120° 但进入敌后 ⇒ F1 必须被豁免（**最容易漏写的对照组**）；
- C 绕敌 100°、距离不变、不开火、未进敌后 ⇒ F2 **必须命中**；
- D 机动协议占多数 ⇒ 必须豁免；
- E 有开火 ⇒ 不得判无效绕圈；
- F 缺 `fireSeq` ⇒ 必须 **BLOCKED** 而非命中；
- G 缺 `off` ⇒ F2 必须 **BLOCKED**（防 `Δβ` 退化）。

### 4.3 `arcBlockedSec`（保留件，供修-4 复活时使用）

不用"没开火"，用"**射界阻塞**"。没开火有四种原因（无目标 / 超距 / 冷却 / 射界），只有最后一种该触发退出。

```
inRangeAll_u   = 距离 ≤ effectiveRange 的敌舰数          // 现有 inRangeUnits 过滤前
inArcInRange_u = inRangeUnits.length                    // 现有数组
arcBlocked     = (Σ_u inRangeAll_u > 0) && (Σ_u inArcInRange_u === 0)

_fireObs = { arcBlockedSec: 0, fireSeq: 0 }
每帧:  if (arcBlocked) arcBlockedSec += dtSec
      else if (恢复已持续 ≥ 0.5s) arcBlockedSec = 0     // 0.5s 退出滞回
开火:  fireSeq += 1
```

触发（三条同时）：`phase === 'cruise'` 且 `contact.engaged` 且 `arcBlockedSec >= 1.0`。

- **必须**有 `phase === 'cruise'` 前置：`brake/turn/reform` 三个相 `motion='hold'`，天然打不出炮；不加这条，14~28 秒的原地转向会被判成"射界阻塞"，包抄支会被自己的撤退逻辑踢掉。
- 触发时刻的帧率无关性（30/60/144 FPS 误差 ≤ 0.15 sim 秒）才是这条判据的真正价值。

### 4.4 `move` 到位即完成

- 静态：`/directOrder\s*=\s*null/g` 匹配数改前 === 1（唯一清除点是溃散）；改后必须 ≠ 1。
- 纯函数 `shouldCompleteMove({ kind, dist, arrivedEps, completed })`：
  - `dist=0, eps=8, completed=false → true`
  - `dist=9, eps=8 → false`
  - `completed=true, dist=0 → false`（**幂等**）
  - `kind='attack' → false`
- 真机：到位后 1s 内 `directOrder === null`，且 60s 内不再出现 `active`（读 `_dbg.doState`）。

## 6. 使用说明

```bash
# 合成自测（无样本也能跑，CI 可 gate）
node scripts/orbitAudit.cjs --selftest

# 审计真机样本（__fleetTrack() 的 JSON）
node scripts/orbitAudit.cjs samples.json
node scripts/orbitAudit.cjs samples.json --no-gate   # 只报告，不改退出码
```

退出码：`0` = 样本可用且未命中；`1` = 样本可用且命中 F1/F2（可 gate）；`2` = 参数/读取错误；`3` = **结论不可用**。

> **`3` 是本轮新增的一条铁律**：空样本 / 总模拟时长 < 10s / BLOCKED 占比 > 50% 时，脚本打印
> `结论不可用：样本不足或字段缺失 —— …` 并 exit 3，**不是** 打印 `F1=0 段` 就算通过。
> 理由与 BLOCKED 同源：**"没测"和"没问题"必须在输出上可区分**。若只落在文档里，下一个人仍会把 0 命中读成"已修复"。
