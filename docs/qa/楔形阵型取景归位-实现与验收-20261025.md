## 二、系统实现方案

### 2.0 T0 为什么**回滚**（记录在案，不再实施）

假设：`beginEntryPhase()` 三条 early-return（`!ENTRY_HOLD_PAUSE` / `entryFxStyle==='off'` / 无 3D 层）
都不置 `entryPhase = true` ⇒ `endEntryPhase()` 开头 `if (!this.entryPhase) return;` 拦住
⇒ 挂在里面的 v102 定妆重摆不执行 ⇒ 开场阵型散。

**真机实测证伪**（`_diag_entryfx_off.cjs --mode off`，锚-舰偏差）：

```
开战后 0.3s  entryPhase=false  δ=90°  camEl=35°  dist=3436  devMax=0.00px
开战后 3.3s  entryPhase=false  δ=0°   camEl=60°  dist=406   devMax=0.80px
开战后 8.3s  entryPhase=false  δ=0°   camEl=60°  dist=406   devMax=8.12px
```

`devMax` 恒在 1~8px，**没有**历史那次 2130px 的"锚-舰脱钩" —— 因为 `state==='assembling'` 时
v100b 集结期硬锁每帧把 sprite 钉在槽位。⇒ 为一条没有观测到症状的路径改入场时序，回归风险大于收益。

**裁定**（裁定人：制作人　日期：2026-10-25）：**本批不做**。`BattleScene.ts` 的对应改动
**全部回滚**（`_battleStartSettled` 字段、`settleFormationOnBattleStart()` 方法、三条分支调用、
`endEntryPhase` 的闸门替换全部撤销），**不留任何"已实现 / 真机 PASS"的记录** ——
上面那组读数只作**证伪依据**，不代表当前树。核对方式：`grep -rc "settleFormationOnBattleStart" frontend/src`
应为 0。

**遗留项 W-1（重开条件）**：任一路径出现 **>50px** 的锚-舰偏差读数 ⇒ 按原设计在
`beginEntryPhase` 三条 early-return 内、`isPaused = false` **之前**插入重摆，
同时把 `entryDoorSim` 的对应断言从"结构断言"升级为**时序断言**（settle 记录点 < unpause 记录点）。

**断言侧的连带修正（QA-B3，已落）**：`entryDoorSim` 原先用逐字字符串匹配整行
`if (this.entryFxDisabledBySetting()) { this.store.isPaused = false; return; }` —— 它锁的其实是
「early-return 里没有别的东西」这个**旧形态**，将来按 W-1 插入重摆会**改对了反而变红**。
现改为**结构 + 顺序**断言：三条分支各自必须「显式解除暂停 → 其后的 return」；若出现
`settleFormationOnBattleStart(` 则必须位于 unpause **之前**。

### 2.1 T0′ 归位落下时刻（本单真正的「开场」）

**职责**：让"正三角取景"在**第一个可渲染帧**就成立，而不是 3 秒后。

- **证据（同一次真机采样）**：`0.3s → δ=90° / 仰角 35° / dist=3436`（`buildSpaceWorld` 固定机位，
  阵型正侧面 + 远景，读不出任何形状）；`3.3s → δ=0° / 仰角 60° / dist=406`（归位才落下）。
  用户口中的「开场」就是这段空窗。
- **关键改动**：
  - `OPEN_REFRAME_DELAY_MS` **900 → 200 → 0**（武装当帧即可执行）；
  - `OPEN_REFRAME_RETRY_MS` **300 → 100**、`OPEN_REFRAME_MAX_TRIES` 20 → 30（≈3s 窗口）；
  - 新增**就绪判据** `if (!this.spaceBuilt) return false;` —— 世界未建好时不对焦
    （否则 `heightAtPx` 取不到地形高、目标点偏一整个地形高度，而"已成功"标记会让我们不再重试）；
  - 新增 `_openReframeArmedAt` + `openingFrame.sinceEntryMs`：把"多晚落下"变成**可读数字**，
    否则改了也不知道有没有改善（这一条是我第一次验收时被自己的测量方式骗了才加的）。
- **为什么 0ms 不"太早"**：归位在 `tick()` 里**紧跟 `syncShips()`** 执行 ⇒ 该帧的质心/档位
  （`lastTierY`）/阵面朝向都是新鲜的；`startBattleAfterDeploy()` 在推 `entry_start` **之前**已
  `placeUnitsAtFormationSlots` ⇒ 武装那刻 sprite 已在槽位。
- **验收口径**：自按键起 ≤500ms 内落位，且 δ≤20°、仰角∈[50,70]（见 §4 实测）。

### 2.2 T1 开场取景归位

- 唯一幂等入口 `runOpeningReframe()`：`_openReframeDone` 闸门 ⇒ 重复调用**位姿逐位不变**；
  拖拽期（`now < _camUserDragUntil`）**只推迟不抢镜头**（不消费"未就绪"重试预算）；
  绝对期限 20s 防挂死。执行点：`startEntryFx()` 武装、`tick()`（syncShips 之后、增量跟随之前）、
  `entry_end` 兜底。
- 距离自适应：`max(halfDep/tan(fovY/2), halfLat/tan(fovX/2)) × 1.2`，夹 `[6,18]×hexR`；
  半跨**相对质心**（用包围盒会高估近一倍）。
- 对外接口 `focusOnFleet(id, { dist, elevAboveHorizon, rebaseFollow, releaseUserDrag })`，
  默认值 = 旧行为逐位不变；**不碰** `controls.minDistance/maxDistance`。
- 增量跟随（AC-W4④）：`|d|<0.6` 的"跳过"改为**限速补偿**（每帧 ≤`FOLLOW_MAX_STEP=0.05rad`，
  `_camFollowFa` 只推进已转过的量 ⇒ 误差跨帧收敛）；注视舰队换人时重基线不补转。

### 2.3 T2 阵型轮廓常显

- `outlineAlpha = max(max(fadeOut, MARKER_FLOOR_OUTLINE)×meshOff, MARKER_OUTLINE_MIN×(1−sstep(150,260,refPx)))`；
  **填充策略一字未改**；`m.outline.visible = outlineVisible || 候选脉动`。
- **迷雾门禁**：`if (!this.isFleetIntelVisible(fl)) continue;`（`_intelDisplayMode` 同源）⇒ 雾内轮廓 0 条。
- **单折线**：仍是 `markerNormShape` 的**一个** `LineLoop`（台架断言恰好 1 个）。
- **draw call 口径**：零新对象/几何/材质；但中近景此前描边被 `visible=false` 剔掉，现在每支**可见**
  舰队各画 1 条 `LineLoop` ⇒ 增量 ≤ 可见舰队数（这是"常显"的目的本身）。

### 2.4 T3 注释订正

- `fleetTierLayout.ts`：`LAYER_GAP = max(比例项, 几何下限)`，**两者都可能胜出**（判据
  `maxShipH < 3.84⁻¹·spacingEff = 6.77`）：89 舰（5.89）比例项 8.125 胜出、198 舰（8.83）下限 10.6 胜出。
  `TIER_GAP_K` 仍是死参数。厚度 121.9/159.0 偏大：**挂账不动**（归位已把常态视角钉在 60°）。
- `formationLayout.ts`：`SHIP_VISUAL_SCALE` 注释 0.42 → **0.40**，派生数同步重算；台架加跨文件一致性断言。

qa 复算：δ=15°（视觉正常）Spearman = −0.26、δ=45°（已歪）+1.00 ⇒ 分箱统计**只能当线索**。

## 六、技术债与风险

1. **T0（开战定妆重摆）已裁定不做，遗留项 W-1**：off/2D 降级路径上定妆重摆不执行，实测 devMax 恒 1~8px
   （集结期硬锁在兜）。重开条件 = 任一路径出现 **>50px** 锚-舰偏差 ⇒ 按 §2.0 方案插入（unpause 之前）。
2. **队内厚度偏大（挂账不动）**：121.9（89 舰）/ 159.0（198 舰）；AC-W3 = 0.301/0.306，门禁内但余量一般。
3. **T2 draw call**：中近景每支可见舰队 +1 条 `LineLoop`。可退化为"玩家方 + 交战中的敌方"。
4. **楔尖小舰断裂（未做，等数字）**：排距恒 26px 而小舰舰长远小于 26 ⇒ 楔尖与第二排纵深断开；
   战列舰长 25.39 ≈ 格距，驱逐 13.86 只有一半 ⇒ 小舰打头才出现可见断口。
   **归位修不掉**，禁止擅动 `wedgeCells`/槽位。制作人裁定：本批不修，另立专项（下一单第一项）。
5. **贴脸档轮廓收 0**（`refPx ≥ 150px`）未做多分辨率实测。
6. **`_camUserDragUntil` 已加 5s 硬上限**（`CAM_USER_DRAG_MAX_MS`）：原先 `start` 置 `Infinity`，
   `end` 一旦丢失 ⇒ 方位跟随与开场归位**双双永久失效**（症状：拖过一次之后每场开场都停在侧面）。
7. **验收方法学四条（本次踩过，写下来防复发）**：
   - 时间戳必须**页内打点**（Node 端 50ms 轮询 + `evaluate` 往返会放大几百毫秒，实测把 143ms 量成 845ms）；
   - 幂等/阵位断言必须在**暂停态**采样（否则舰队自己移动会被误判成"不幂等"）；
   - 拖拽基准必须**先置 ∞、再取基准**（否则漏掉中间一两帧的跟随）；
   - 测退出码**不能过管道**（`cmd | tail` 拿到的 `$?` 是 tail 的）——`runAllSims` 第一版就是这么假绿的。
