# v74 舰首朝向收口 + LOD 档位联动

日期：2026-10-14。用户实机反馈（附截图）：
「你这改了还不如之前呢，近景依然是属于点点和模型共存的状态，
近景中各种朝向的舰船都有，什么情况，朝向乱起八糟，修改」

---

## 1. 问题①：朝向乱七八糟（严重，结构性冲突）

### 根因

v73 刚体模型与旧的「位移差分求舰首」**结构性冲突**。

`BattleScene` 旧逻辑：
```ts
const _dx = u.sprite.x - u._px, _dy = u.sprite.y - u._py;
const _wantH = _rigid ? fleet.facingSmooth : Math.atan2(_dy, _dx);   // 位移差分
```

刚体模型下每舰位移 = **中心位移 + 旋转分量**，两者方向不同：

| 来源 | 后果 |
|---|---|
| ① 紧凑转压缩 `lateral` | 每舰产生与舰队朝向**垂直**的位移 |
| ② 推力硬上限产生惯性滑行 | 中心速度（旧方向）≠ 队列姿态（新方向） |
| ③ 每舰位置不同 ⇒ 旋转分量不同 | **每舰朝向各不相同** ← 截图实证 |

### 修复

```ts
const _wantH = fleet.facingSmooth ?? fleet.facingAngle ?? fAngle;   // 舰队姿态，始终
```

**物理依据**：刚体航行时所有舰船姿态一致，舰首朝向由舰队姿态（刚体 heading）单点给出。
**战舰允许惯性滑行**（速度 ≠ 舰首方向）—— 这是"重"的体现，不是要修的侧滑。

v47 时代用位移差分是为了在"舰队中心 = 无质量点"的旧架构下消除侧滑观感；
刚体模型下舰队朝向**本身就是运动意图方向**，舰首朝它就是正确的。

同时删除死代码：`_px/_py` 采样、`_rigid` / `_inManeuver` / `_spd2` 判据块。

### 保留成立的行为

拖刀（舰首朝敌、质心后退）：`fAngle` 已被设为朝敌，`facingSmooth` 追它
⇒ 舰首朝敌而质心后退，无需位移差分参与。

## 2. 问题②：点与模型共存

### 根因

LOD 阈值是**固定值**（v73 收紧到 `MESH_IN_LO 9 / MESH_IN_HI 15`），
近景时仍把远处单位留成点 ⇒ 用户读作「近景还是点点和模型共存」。

### 修复：LOD 阈值与相机距离联动（两档）

| 档位 | 条件 | lo / hi / keep / drop | 效果 |
|---|---|---|---|
| **近景** | 相机距 target < 跨度×0.45 | **3 / 6 / 4 / 3** | px≥6 即纯模型 ⇒ **几乎全模型** |
| **远景** | 否则 | 9 / 15 / 12 / 10 | 保留点阵（银英雷达观感） |

远景档**刻意保留点阵**：用户明确要求保留"远景圆点 = 雷达效果"（见 v73 前的口径确认）。

实现：新增 `updateLodTier()` 在 `syncShips` 开头调用，7 个消费点改读 `this.lod.*`。

### 对抗性复核抓到的问题：档位抖动

单阈值会让相机在 `span×0.45` 附近抖动时**档位来回切** ⇒ 全场单位 `grow` 突变 ⇒ 闪烁。

**加滞回**：进入近景用 0.45、退出用 0.58（滞回带 13%）⇒ 只有明确拉远才回远景档。

## 3. 验收判据

| 判据 | 结果 |
|---|---|
| 舰首朝向 = 舰队姿态（无位移差分） | `_wantH = fleet.facingSmooth` |
| 位移差分路径彻底移除 | 台架负向守卫：`_rigid` 块不存在、`_wantH` 不含 `atan2(_dy,_dx)` |
| 近景档几乎全模型 | lo/hi=3/6 ⇒ px≥6 纯模型 |
| 远景档保留点阵 | lo/hi=9/15 |
| 档位不抖动 | 滞回 0.45→0.58 |
| 死代码清理 | `_px/_py`、`_rigid` 判据块已删 |

### `fleetIntentSim` 金标订正

旧断言锁 `_rigid` 声明存在（v47~v73 契约）。v74 删除该块 ⇒ 金标过时。
订正为 v74 契约 + 两条负向守卫（防止位移差分回退）。

**教训重申**：行为契约变更必须同步排查源码文本元断言类台架。
