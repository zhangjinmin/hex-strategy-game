## 2. 机制 A 的实测证据（钉敌场景：敌保持撤退态但被困原地）

修复前（v46 终态代码）：
```
#206  mfd=278（0.35×800 阈值下方 2px）⇒ 进入 _mPhase=2（拉开）
      ⇒ 目标点跳 1470px（前进点 → 自身后方 0.5×idealDist）⇒ fAngle 反向（掉头）
      ⇒ 拉开态持续 254 帧（约 4.2s），此后 mfd>400 退出 ⇒ 前进追 ⇒ 又 <280 ⇒ 又拉开
```
**"回头-前进-回头"的循环结构**：mfd 在滞回带 [0.35d, 0.50d]=[280,400] 内做锯齿波 ——
我方推进使 mfd↓、敌逃跑使 mfd↑，两个动态叠加必然反复穿越。滞回只拉长周期、不消除往返。

**为什么这是战术语义错误而不只是参数问题**：
"拉开距离"的设计场景是**对射保持理想交战距**。敌军正在撤退/背对我时执行"拉开"，
等于把逃跑窗口送给敌人 —— 与 doctrine S6（敌露背后 ⇒ 追击窗口）**层间打架**
（v41 教训的复现：决策层说追、执行层说退）。

## 3. 修复（v48，一处）

`_mPhase` 状态机加**追击豁免**：
```ts
const _foeFleeing = angleDiff <= Math.PI * 0.3 || closestEnemyFleet.state === 'retreating';
// 进入拉开需 ! _foeFleeing；已在拉开态的遇 _foeFleeing 立即退出
```
- `angleDiff ≤ 0.3π` = 我在敌后半球（v46 已推导：`angleDiff` 小 ⇔ 敌背对我）——**零新增概念**；
- 敌 `state === 'retreating'` 是公开字段，直接读。

## 5. 探针基建的两条新经验

1. **停 3D 渲染 + 缩小 Phaser 视口 = 无头帧率 1.3fps → ~57fps**（24×）：
   `ov.tick = function(){}`（实例覆盖，只停 Three.js 渲染与特效，Phaser 逻辑照常）+
   `game.scale.setGameSize(320,240)`（渲染像素 −97%，世界坐标不变）。
   **凡是只采样队级 2D 逻辑数据的 L2 探针都应默认加这两刀** —— 接战场景（特效满屏）下
   不减负连 rAF 都排不上。
2. **页面内采样代码必须自含全部辅助函数**：本探针引用了 Node 侧的 `D()`（角度转度），
   `tick` **首帧即 ReferenceError 断链**，表现为诡异的"0 帧且无报错"。修复：tick 全体
   try/catch 把 stack 写进 `window.__v47.err` + 注入后 6s 探活 —— 一次定位。
   （前两轮误判为"渲染负载压死主线程"，方向错了；**先让失败自己说话，再归因**。）
