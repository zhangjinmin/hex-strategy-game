# v92 模型最小屏幕尺寸下限 + 全链路复盘（"席特尼空荡"）

日期：2026-10-15。用户实报：
> 左边是莱茵哈，右边是席特尼，为什么？莱茵哈特的模型齐整，席特尼就是空空荡荡，
> 但是舰队数是一样的都是 20000。如果是分舰队的问题，席特尼的分舰队虽有悬浮标志，
> 但是没有任何显示。整个逻辑和流程复盘下，看看问题出在哪里。

---

## 1. 面板数据（决定性）

```
tier=NEAR lo=0 hi=8 keep=0
n=200  px=21.9  mesh=200  MODEL      ← 模型明显
n=141  px=27.5  mesh=141  MODEL
n= 80  px= 6.5  mesh= 78  MODEL      ← 模型仅 6.5px ⇒ 肉眼几乎不可见
n= 12  px= 7.5  mesh= 12  MODEL
```

**关键：所有舰队 `mesh ≈ n`（模型都建了）** ⇒ **不是漏渲染**。

## 2. 全链路复盘（兵力 → 实体 → 渲染）

| 环节 | 机制 | 本轮是否异常 |
|---|---|---|
| ① 兵力 → 编制位 | `fac.composition`（满编）+ **`fac.entityBudget`（全场分摊后的实体预算）**，由 `spawnPlan.player[index]` / `spawnPlan.enemy` 逐队下发 | 正常（各队编制本就不同） |
| ② 分舰队 | `child = { ...parent, units: slice, _detachedFrom: parent.id }` ⇒ **母队被分走一部分 units**（总数不变） | 正常（设计如此） |
| ③ 渲染取数 | 3D 层 `getRenderableFleets()` + `visibleIndexes` | 正常 |
| ④ LOD 门槛 | v90 已二值化：近景 `keep=0` ⇒ 全建 | 正常 |
| ⑤ **模型投影尺寸** | `px ∝ 1/距离` ⇒ **席特尼 px=6.5 而莱茵哈特 21.9** ⇒ **模型小 3.4 倍** | ⚠ **这就是"空荡"的直接原因** |

**⇒ 结论：不是"没渲染"，是"渲染了但太小"。**

- **"分舰队有悬浮标志却没显示"** = 分队的标记（按 `fleet` 渲染）在，但其 units 的**模型投影只有 6~7px** ⇒ 看不见
- **"两队都是 20000 但视觉差很多"** = ① 分兵让**母队 units 减少**（分给了护卫队）② **距离差异 ⇒ px 差 3.4 倍**

## 3. 修复：模型最小屏幕尺寸下限（`MIN_MESH_PX = 14`）

```ts
const _minK = (v.px > 0.1 && v.px < MIN_MESH_PX) ? (MIN_MESH_PX / v.px) : 1;
g.scale.setScalar(entry.baseScale * (0.25 + 0.75 * ge) * _minK);
```

| 原 `px` | 放大 | 视觉长度 |
|---|---|---|
| 6.5 | **2.15×** | 14.0px |
| 7.5 | 1.87× | 14.0px |
| 12 | 1.17× | 14.0px |
| 21.9 | 1.00× | 21.9px |
| 27.5 | 1.00× | 27.5px |

⇒ **远小的透视层次保留**（21.9 vs 27.5 仍有差异），但 **"远不过小"**（不小于 14px）。

⚠ 代价：部分削弱"远小近大"的真实感（用户明确要"看得见"优先）。
下限值可调：调大 ⇒ 远处更醒目、透视更弱。
