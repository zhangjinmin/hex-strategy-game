## 2. 路线选择

1. **推荐：保留现有战场、资源、舰种与渲染，替换战斗控制核心。** 从接战与运动开始，随后统一任务、后勤和协同，最后贯通战斗生命周期。每阶段都集成进真实 BattleScene，移除对应旧写入路径。
2. 继续局部修阈值：变更小，但多处目标/姿态写入继续互相覆盖，不能解决整场战斗逻辑。
3. 全部推倒，连渲染和引擎一起换：范围过大，与本次问题没有直接收益。

## 3. 必须成立的行为规则

### 3.1 接战、脱离与运动

采用适合银英舰队战的有限加速度运动规则，不追求完整轨道力学。

- 未接战大角度转向：减速停稳 → 每舰以自身位置为中心转舰首 → 有限速度重编队 → 队形达到要求后加速。任何阶段不得把整个舰队作为刚体绕中心转动。
- 将舰首方向、舰船速度、编队槽位分离。舰首由当前机动阶段控制，不从每帧追槽位产生的微小位移反推。
- 掉头时冻结各舰世界位置（停稳后）和本次目标航向；不是只冻结相对于仍在移动的舰队中心的槽位。
- 重编队开始时一次分配新槽位。优先就近、保持左右相对次序；对称阵型掉头允许交换槽位身份，避免全舰穿越中心。窄通道采用分批重排与局部避让，不能通过瞬移落位。
- 重编队有位置和航向容差、稳定时间及失败处理。受阻则等待/局部重规划；主编队不能无限拖走未归位舰船。
- 接战后收到撤退或大角度转向意图：先保持对威胁方向的正面，以低速倒退脱离，仍可在武器射界内还击。
- 持续追击维持接战锁定，绝不因撤退计时结束就允许掉头。无法脱离时继续抵抗、请求掩护或溃散，不保证撤退必然成功。
- 接战跟踪全部相关敌军，结合舰船有效射程、射界与近期有效火力接触。只有所有威胁均离开接战范围，且无接触时间达到门槛，才允许转向。不能仅凭最近舰队中心距离或敌人暂时丢失可见性解锁。
- 出入接战使用不同阈值和延时，避免边界闪烁。小角度跟踪威胁与整队掉头分开处理；溃散也不豁免速度和转向约束。

阶段：巡航 → 制动 → 原地转向 → 重编队 → 巡航；接战 → 倒退脱离 → 确认脱战 → 制动/转向/重编队。

### 3.2 补给与后勤战

- 保留切断补给线 → 储备消耗 → 士气/战力下降 → 持续断供造成舰船损失的玩法。连通不等于瞬间满补给，消耗和输送均以游戏时间结算。
- 后勤评估输出风险、可持续作战时间和可用补给方案，不直接覆盖舰队朝向或移动目的地。
- 决策比较：剩余储备、净消耗、运输舰抵达时间、航路安全、敌我战力、当前任务收益、撤退暴露风险、友军掩护。
- 补给变黄本身不触发返航。在途补给足以支撑当前作战时维持任务；补给不足以支撑深入时缩短追击；断线时可以抢回中继、保护运输舰、等补给、请求接替或组织撤离。
- 极低补给可以提出紧急撤离意图，但执行仍必须经过接战/脱离阶段。
- 士气在舰队级每个模拟步只更新一次，使用按实际舰数加权的补给状况。舰船损失单独结算，避免渲染实体数改变后勤惩罚。
- 重新接通补给不能立即恢复攻击；恢复条件与再次投入任务的风险评估分开，并保留当前机动阶段的稳定性。

### 3.3 友军与敌军 AI

双方使用同一决策与执行系统，输入限于各自可知情报。提督性格影响风险容忍、任务选择和协同倾向，不改变运动规则。

任务层保留并明确：攻击指定舰队、占领节点、守点、掩护友军、切补给、护送运输、撤离补给。每个任务具有目标类型、稳定 ID、执行条件、成功/失败条件及中止原因。

候选行动采用可解释评分，先过滤物理/指挥约束，再比较任务收益、损失风险、补给压力、航行耗时与协同收益。保留当前任务的承诺时间和换任务收益门槛；目标覆灭、航线受阻等关键事件允许提前重评。

协同层分配正面牵制、侧翼、预备队、后卫、运输护航。包抄使用持续航路，不每帧追逐随敌舰首旋转的侧后目标。友军不会全部追同一个最近目标，也不会因为补给风险同时放弃前线。

玩家命令保留目标意图，不能由定时 AI 静默覆盖；执行不可行时展示原因，例如“撤离命令已接受，正在敌火下倒退脱离”。

## 4. 结构与战斗流程

建议新增独立模块：态势快照、任务仲裁、后勤评估、接战跟踪、机动状态机、编队控制。场景负责输入、调用与表现，不再同时充当多个决策者。

固定模拟时间步作为统一时钟；倍率增加模拟时间，暂停冻结模拟。较低频率进行战术评估，每个模拟步处理接战与运动，渲染独立插值。卡顿积压采取有限追帧，不能以超大 dt 瞬移。

每步：命令入队 → 更新可知态势/后勤 → 任务与行动仲裁 → 接战/机动阶段 → 舰船运动 → 射界与攻击结算 → 伤亡/士气/占领 → 胜负判断 → 发布只读表现快照。双方使用一致快照决策，避免数组遍历先后改变待遇。

战斗生命周期：初始化与部署 → 正式战斗 → 结束判定 → 停止模拟与命令 → 结算一次 → 回写战略层 → 清理场景、计时器和事件。现有战役/演习入口、指挥权限、任务 UI、补给节点与运输系统均须接入验证。

表现至少显示：当前任务、当前机动阶段、主要决策理由。战报只记录状态变化，避免每帧刷屏。

## 5. 分阶段实施与验收

1. **建立新行为回归和统一时间基准。** 加入固定种子战斗快照；旧台架中违反新规格的断言明确替换。验证 30/60/120 FPS 下相同游戏时间运动接近一致，暂停/倍率不改变状态机语义。
2. **接战与运动闭环。** 接入真实场景，替换旧转向、倒退和逐舰追槽位朝向控制。验证五种阵型 90°/180° 转向，原地转向时各舰位置稳定、受追击不能掉头、脱战后能重排恢复前进、重排中再接敌能中止。
3. **后勤与任务仲裁。** 取消多处直接低补给返航，修正士气重复结算。覆盖黄补给持续作战、近船补给、断线争夺中继、无掩护撤退、持续断粮损耗。
4. **双方协同与全流程。** 覆盖目标消失、友军掩护、侧翼持续推进、运输护航、全队覆灭、成功撤离、结算幂等和战略回写。

验收不能止于纯函数测试：需要真实场景运行与录屏/逐帧位置、航向、阶段日志，尤其检查转向后继续航行时的摆头。类型检查与构建通过是基础，不代替行为验收。
