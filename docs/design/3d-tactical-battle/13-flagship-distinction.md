# 13 · 旗舰视觉区分方案（Flagship Distinction）

> 主题：让旗舰在「远景只剩光点、近景淹没在舰海中」两种极端下都能被一眼认成指挥舰。
> 归属：美术方向 / 技术美术（视觉身份 + 资产规格）。实现归程序侧。
> 真源文件：`frontend/src/game/three/Battle3DOverlay.ts`（下述行号均为本方案写作时实读行号）。
> 状态：**方案待用户拍板**，本文不含代码改动。

---

## 0. 一句话结论

现有旗舰区分集中在「把同一个东西做大、做白」——这是**近景有效、远景有毒**的杠杆；
远景（`meshes = 0`、全场只剩光点）之所以认不出旗舰，根因是旗舰的辨识信息**全部挂在"点阵抽签"这一个通道上，且可能根本没被画出来**。
因此本方案主张：**为旗舰单开一条不参与抽签、不依赖实体、与阵营配色正交的「指挥标记层」**（主），
再以**专属轮廓（近景）**与**慢周期动势**为辅。

---

## 1. 现状盘点（三层机制 · 真源行号 · 各档生效情况）

现行区分手段共三层，全部在 `Battle3DOverlay.ts`：

| # | 机制 | 常量 / 函数 | 真源行号 | 生效档位 |
|---|------|-------------|----------|----------|
| 1 | **实体放大 1.7×** | `FLAGSHIP_VISUAL_GAIN = 1.7` | **147**（定义） | **仅实体档**（px ≥ `MESH_KEEP` 17 才建模型；`MESH_KEEP` 见 **480**） |
|   | 消费点：在 `dimsOf()` 内 L/W/H 同乘 | `const FG = flagshipName ? FLAGSHIP_VISUAL_GAIN : 1` | **2510**（消费） | 远景：**完全失效**（远景实体数为 0，不参与渲染） |
| 2 | **光点点径 2.4× + 偏白** | `FLAGSHIP_DOT_GAIN = 2.4` | **149**（定义） | **全档**（点层每帧为所有可见舰写点） |
|   | 点径消费：`dotPxSize = … × (isFlag ? FLAGSHIP_DOT_GAIN : 1)` | — | **3285** | 远景：**唯一生效手段**，但受 §5 反例约束 |
|   | 偏白消费：`dotTmpColor.lerp(WHITE, 0.45)` | — | **3273**（光点）/ **3250**（光晕） | Δ色偏小 → 辨识度低（见 §2） |
| 3 | **指挥光环 + 竖直光柱** | `attachFlagshipFx()`；`FLAGSHIP_RING_K = 1.35`、`FLAGSHIP_BEAM_K = 3.2` | **3132**（函数）、**151–152**（常量） | **仅实体档**（`addMesh` 内调用，见 **3168**；换装补挂见 **3023–3025**） |
|   | 光环自转 | `FLAGSHIP_RING_SPIN = 0.55` | **154**（更新在 **3099**） | 远景：**完全失效** |

**旗舰身份的真源**（供实现对照，勿另造第二真源）：

- `flagshipSet` 每帧由 `fleet.units[0]` 重建 —— **2920–2924**
- `isFlagshipUnit = (fleet.units).indexOf(u) === 0` —— **3162**
- `flagshipKeyOf()`（旗舰名 → `FLAGSHIP_MODEL_ALIAS`）—— **2187**
- 专属 GLB 候选链 `flagship_{key}.glb → {faction}_{class}.glb → {class}.glb` —— **2529–2533**

**LOD 判档与实体池**（决定"哪个档生效"的机制）：

- 三档判据注释：`近景 px ≥ MESH_IN_HI` / `中景 px ≥ DOT_IN_LO` / `远景 仍是光点` —— **2837–2843**
- 阈值：`DOT_IN_LO = 3.2`（**464**）、`DOT_IN_HI = 5.0`（**465**）、`MESH_IN_LO = 14`（**472**）、`MESH_IN_HI = 26`（**473**）、`MESH_KEEP = 17`（**480**）、`MESH_DROP = 15`（**481**）
- 实体池：`MAX_MESHES = 400`（**498**）、按 `px` 降序取前 N（排序 **2977**、取用 **2980–2987**）、perf governor 下限 `MESH_BUDGET_MIN = 120`（**512**）
- 光点层：`DOT_N = 1`（**527**）、`DOT_PITCH_MIN_PX = 3.2`（**556**）、`DOT_DIAM_K = 0.85`（**558**）、`DOT_MIN_PX`（派生，**565**）、`DOT_SCALE = 0.30`（**547**）、`HALO_GAIN = 1.15`（**576**）
- 关键事实：**距离 ~6000 时 `meshes = 0`** ⇒ 三层机制里的第 1、3 层在远景**一起归零**，只剩第 2 层的"点径 2.4× + 偏白"。

> **结论**：三层里有两层是"实体专属"，而实体在远景不存在。旗舰区分在**用户最痛的远景**上，实际只押注在两件事上：**点更大、点更白**。这就是问题全貌。

## 2. 问题定性（第一性原理：远景的信息通道）

不要问"是不是不够亮"，要问"**在远景，一艘舰到底有哪几个自由度可以携带信息**"。答案由渲染管线决定，不由美术决定：

远景唯一被绘制的图元是**光点**（`DOT_N = 1`，1 舰 1 点），其写入逻辑见 `writeDotLayers()`（**3204**）。该函数对每个可见舰可调的**逐舰自由度只有 4 个**：

| 自由度 | 具体字段 | 真源行号 | 现状对旗舰的用法 |
|--------|----------|----------|------------------|
| ① 屏幕位置 | `v.x/v.z`（世界）→ `sx/sy`（屏幕） | 位置写入 **3296–3298** | 无差别（旗舰不挪位） |
| ② 点半径 | `dotPx` ← `dotPxSize` | **3285** | × 2.4 |
| ③ 点颜色 | `dotCol` ← `dotTmpColor` | **3272–3276** | lerp 向白 0.45 |
| ④ 点透明度 | `dotAlpha` | **3270** | 与普通舰相同（下限 0.78） |

**但关键约束是：这 4 个自由度只对"分格胜出者"生效。** 光点层先按屏幕空间方格分桶（`DOT_PITCH_MIN_PX = 3.2` px 边长，见 **3229**），**每格只留 1 个代表点**，胜出优先级为：

> ① 已持实体者优先 → ② `px` 大者 → ③ `key` 字典序最小 —— **3238–3241**

于是远景旗舰的实际处境是：

1. **它可能根本没被画。** `FLAGSHIP_DOT_GAIN`（径）与偏白是**逐舰属性**，但**不参与**格胜出优先级。旗舰若与邻舰落入同格，且邻舰 `px` 更大或 `key` 更小，则本格胜出者是邻舰 —— **旗舰的点径 2.4×、偏白，全部落空，一个像素都没渲染**。（这正是并行验证进程 `_v7_flagship_flicker_probe.cjs` 的 `FAIL_squeezed_by_dot` 判据要测的东西。）
2. **偏白是一个"低信息量"通道。** 阵营主色由 `FACTION_SCHEMES` 决定且**可切换**（`frontend/src/config/factionThemes.ts`，实际取值见 **937** `factionColor` 的兜底）。四套配色的同盟主色分别是 `0x2dd4bf`（青绿）/ `0x00A8FF`（蓝）/ `0xFFB703`（琥珀）/ `0xFFE600`（黄）。向白 lerp 0.45，在"青绿 / 蓝"上还算可辨，在"琥珀 / 黄"上几乎不动 —— 也就是说**旗舰的"更白"在浅色配色下等于没画**。更糟的是白色本就是**光晕层**（**3249–3257**）、**护盾白芯**（`SHIELD_FS` **338–339**）、**激光**共用的"能量色"，白 ≠ 旗舰。
3. **放大点径是"自杀式"通道。** 见 §5：远景把点做大 → 相邻点合并 → 直接违反既有验收标准"不糊成块"。

> **重述问题（不是"不够亮"）**：
> 远景旗舰的辨识信息**只有 2 个维度可用（径、色），且两者都是"逐舰"属性——会被格抽签吞掉，还都是低信息量/与既有特效撞车的通道**。
> 要让旗舰远景可辨，必须增加一个**（a）不参与格抽签、（b）不依赖实体、（c）与阵营色正交**的新通道。

## 3. 方案主体（分档：远景 / 中景 / 近景）

设计主线：**"形状 + 动势"是主通道，"尺寸 + 颜色"是辅助**。理由见 §4。

### 3.1 远景档（px < `DOT_IN_LO`＝3.2，`meshes` 可为 0）

**视觉意图**：在全场只剩光点的"电子战术盘"上，旗舰是一枚**会慢慢自转的指挥徽记**，像海图上的旗舰三角旗——不是"更大的圆点"。

**手段 F1 · 专属指挥标记层（本方案核心）**

- **几何**：4 角星形箭簇（双 V 形 chevron 旋转 45° 叠成四角），**带孔/留缺口**（外半径 6.5px、内半径 2.2px，笔画宽 1.1px）。**故意不做实心圆盘** —— 保证连通域小，不违反"不糊成块"。
- **颜色**：白芯 `0xFFFFFF` + 一圈**阵营色描边（1px）**。芯白保证任何配色下可辨；描边保留"这是哪一方"。**形状是主通道、颜色是次通道**（色盲安全，见 §6）。
- **动势**：整体慢自转，角速度复用 `FLAGSHIP_RING_SPIN = 0.55 rad/s`（**154**）；周期约 11.4s，读作"指挥中"而非"闪"。**不做脉冲闪烁**（见 §5）。
- **绘制通道**：**独立于 `dotPos/dotCol` 与 `halo*` 的新缓冲/新 group**（建议命名 `flagMarkerGroup`），**每旗舰恒写 1 枚，不参与 `dotGrid` 分格**。这是与现有三层最本质的区别，也是它能在远景存活的原因。
- **预算**：全场旗舰 ≤ 8~16，若用 `InstancedMesh`（billboard 面片 × 每旗舰 × 每标记 1 instance）**全场新增 1 个 draw call**；若不实例化则每旗舰 1 DC（≤ 16）。顶点：四边形 ×2（含孔用两次抽样）≈ 每旗舰 < 32 顶点。**完全不吃 `MAX_MESHES` 实体池**。
- **落地钩子**：
  - 位置真源**复用** `unitVis` 的 `{x, y, z}` 与 `sx/sy`（**2962** 写入），无需新遍历 —— 直接在 `writeDotLayers()`（**3204**）的第一遍循环里顺手写标记；或紧随 `syncFleets` 主循环之后单起一小段。
  - 存活判据同 `flagshipSet`（**2920–2924**）；`hp <= 0` 即不写。
  - update 路径：与 `cmdRing` 同挂每帧 sync（**3099** 处已有旋转推进的先例）。

**手段 F2 · 点径「抬底」而非「放大」（`FLAGSHIP_DOT_GAIN` 改为 floor 语义）**

- 现状 **3285** 是**乘法**（`× 2.4`）：近处 anchor 会把点径推到 `3.2×0.30×2.4` 再叠加 `px` 增长，很容易触顶 `dotMat.uMaxPx = 24`（上限注释见 **2264**）→ 糊块。
- 建议改为**下限**（floor）：`dotPxSize = max(FLAGSHIP_DOT_FLOOR_PX, px × DOT_SCALE)`，且**旗舰支路不乘 `(1 − grow)`**（远景无 grow，恒 1，等价；但语义更清晰）。
- 参数：`FLAGSHIP_DOT_FLOOR_PX = 5.0`（＝ `DOT_IN_HI`，略大于普通点 `DOT_MIN_PX = 2.72`），**硬上限仍由 24 把关**，永不超过。
- 效果：只在"点本就很小"的远景把旗舰点抬到 5px；近处交还给实体档，不再叠加放大。

**手段 F3 · 反抽签保格（anti-eviction，1 处判据修改，收益最大）**

- 在格胜出优先级（**3238–3241**）里**插入一档"旗舰属性优先"**：
  `if (vIsFlag !== curIsFlag) → 旗舰胜；else 沿用 ①hasMesh ②px ③key`。
- 目的：保证 F2 的抬底与偏白**真的被画出来**（否则都浪费在"没被选中的点"上），并直接消除 `FAIL_squeezed_by_dot`。
- 风险：同格两旗舰时回落原判据（按 `px`），确定性不受影响；不会造成跨帧 flap（旗舰集合每场稳定，见 `_v7` 的 (g) 判据）。

### 3.2 中景档（`DOT_IN_LO` ≤ px < `MESH_IN_HI`，实体可能存在）

**视觉意图**：从"徽记"过渡到"有形体"，此时旗舰的**轮廓**就已经不一样。

- **手段 M1 · 专属指挥轮廓（silhouette）**
  在程序化造型分支里，旗舰额外长出一段**舰桥塔 / 指挥天线**：细高锥或盒，高 ≈ `0.35 × 舰长`、底半径 ≈ `0.06 × 舰长`，**沿用既有线框/线条化渲染语言**（不新增实体材质）。
  - 这不是"把普通舰放大"，而是**轮廓本身不同** —— 直接回应用户对"几何化敷衍"的反对。
  - 预算：**每旗舰 +1 draw call**（程序化造型已在，仅加 1 个子对象），落在"每旗舰最多 +1~2 DC"预算内。
- **手段 M2 · 徽记 → 光环的交棒**
  让 F1 标记的 alpha 与"该舰是否已持实体"联动：`hasMesh` 时标记淡出（×0.2），把辨识权交给 `cmdRing`（**3132**）。避免"点 + 徽记 + 光环"三重重叠刷屏。
- **手段 M3 · 编队锚点（可选增强）**
  旗舰所在格在舰队标记层用一个**菱形指挥锚**（区别于普通舰队的圆角矩形底框），让旗舰在阵型里天然"占位"。

### 3.3 近景档（px ≥ `MESH_IN_HI`＝26）

**视觉意图**：旗舰的"旗舰感" = 专属造型 + 有节律的动态信号（不是更多零件）。

- **手段 N1 · 造型专属化**：M1 指挥塔 + 专属 GLB 钩子（`flagship_{key}.glb`，候选链**已存在**，**2529–2533**）。有真实资产时优先走 GLB。
- **手段 N2 · 光环 + 光柱"活起来"**（零几何成本）
  - 光柱改为**呼吸**：不透明度 `0.30 ± 0.15`，周期 `2.4s` 正弦，**相位按 `key` 哈希错开**（避免多旗舰同频）。
  - 光环改为**双层逆旋**：外环顺 `+0.55 rad/s`、内环逆 `−0.55 rad/s`，读作"指挥锁相"。
  - 两者维持既有 additive + `depthWrite = false`（**3137、3148**）。
- **手段 N3 · 护盾涟漪专属化（被动补充，不作主手段）**
  旗舰受击时，护盾半球涟漪给 `uAlpha × 1.3`、环宽 `0.12 → 0.09`（`SHIELD_FS`，**334**）。因为它是**被动触发**的，只能作为"被打才知道是旗舰"的补充。

## 4. 候选方向与取舍

| 方向 | 说明 | 优点 | 缺点 / 成本 | 覆盖档位 |
|------|------|------|-------------|----------|
| **A 造型专属化** | 专属 GLB / 指挥塔，旗舰"长得不一样" | 最贴用户"特殊模型"的字面诉求；近景说服力最强 | **远景完全失效**（meshes=0）；无 GLB 资产时只能程序化；DC 成本随零件数上涨 | 中/近景 |
| **B 光信号专属化** | 指挥标记层 + 点径抬底 + 反抽签保格 | **唯一在远景也成立**；DC 极低（可全场合 1 DC）；与阵营配色正交；不占实体池 | 仍是"抽象符号"，成败取决于**形状设计**（要防"敷衍感"） | **全档** |
| **C 编队空间专属化** | 旗舰格菱形锚 + 预留护航空位 | 利用既有 marker/阵型系统，语义强（"旗舰周围有空位"） | 依赖编队布局，单舰脱离队形即失效；易与现有 marker 抢视觉 | 中/近景 |
| **D 动态时间专属化** | 呼吸 / 逆旋 / 脉冲等时间信号 | 零几何成本，读作"活的" | **静态截图无法验收**；高频闪烁违反跨帧稳定性判据，必须慢周期（≥2s）且相位错开 | 全档（辅助） |

### 推荐

> **以 B 为主干，N1（A 的近景造型）与 D（慢周期动势）为辅，C 作为可选增强。**

**推荐理由（三条，按权重排序）**：

1. **用户痛点在远景，只有 B 覆盖远景。** 用户原话是"旗舰在大堆舰船中不显眼"——"大堆舰船"正是远景 `meshes = 0` 的光点海。A/C 在远景归零，等于没解决主诉。
2. **B 是本方案里唯一同时满足两条硬约束的方向。** draw call 预算（现状实测瞬时 4291，**每旗舰只能 +1~2 DC**）：标记层可压到**全场 1 DC**；且它**不占 `MAX_MESHES = 400` 实体池**，不与其他舰争名额。
3. **B 把辨识主通道从"颜色"迁移到"形状 + 动势"**，天然对策：（a）四套阵营配色切换（`factionThemes.ts`）下都成立；（b）色盲友好（形状 ≠ 颜色）；（c）不与"白光晕/护盾白芯/激光"撞车。这三点正是 §2 里现有"偏白"通道失败的地方。

**A 不能单独用**（远景漏），但近景它是"特殊模型"直觉的必要兑现，故作为 N1 并入。
**D 不能做大**（违反稳定性判据），只保留慢周期呼吸/逆旋。

## 5. 反例 / 风险（什么做法会失败）

**反例 1 —— 继续放大尺寸（把 `FLAGSHIP_VISUAL_GAIN`/`FLAGSHIP_DOT_GAIN` 从 1.7/2.4 抬到 3×~5×）。三档各自怎么崩：**

- **远景（最致命）**：远景点径 = `px × DOT_SCALE × FLAGSHIP_DOT_GAIN`，`px` 已被 1.7/更大放大。在 `DOT_PITCH_MIN_PX = 3.2` 的分格下，**旗舰点与同格/邻格的点会合并成一个连通域**。既有验收标准（`_v6_dot_lattice_probe.cjs` 判据 (c)）明确要求：**`blobCount ≥ 10` 且 `largestBlobShare ≤ 0.5`**。放大点径 = 抬高 `largestBlobShare` = **直接踩爆既有验收线**。**"放大点径"与"点阵不糊成块"是直接互斥的**，不能作为主手段。
- **中景**：实体池 `MAX_MESHES = 400` 是**按全场 `px` 全局降序**取的（**2977/2980**）。旗舰 `px` 变大只会**更早挤占别的舰的名额**——旗舰自己的可辨性没变好，反而让**全场可见实体数下降**，捡了芝麻。
- **近景**：旗舰先占实体档本身没问题，但点径叠加放大极易触顶 `uMaxPx = 24`（**2264**），多旗舰同框即糊团。

> **定性**：尺寸是**近景有效、远景有毒**的杠杆。它只能做辅助（且必须改成"抬底"而非"放大"，见 F2），不能做支柱。

**反例 2 —— 只加颜色（把 `lerp(WHITE, 0.45)` 提到 0.7+）。**
浅色配色下（`alliance` 在 `default`＝青绿、`highcontrast`＝黄）几乎不动；且白／亮既是**光晕**、又是**护盾白芯**、又是**激光**的能量色，**白 ≠ 旗舰**；同时**色弱用户不可辨**（违反可访问性基线）。

**反例 3 —— 给旗舰加几十个零件的独立模型。**
draw call 已吃紧（实测瞬时 4291）。每旗舰 +几十 DC × 8~16 旗舰 = 直接塌帧，与"每旗舰最多 +1~2 DC"的硬约束冲突。

**反例 4 —— 高频闪光 / 脉冲。**
违反跨帧稳定性判据 `winnerKeyJaccard.min ≥ 0.98` 与"非解释性 flap == 0"（`_v7` 判据 (g)），也与用户"不要刷屏特效"的既定偏好冲突。

**反例 5 —— 只改实体档（只加指挥塔 / 只改 `attachFlagshipFx`）。**
远景 `meshes = 0` 时**完全无效**——而这恰是用户主诉场景。

## 6. 验证方式（每条视觉主张配可复现判据）

沿用本项目既有台架风格：**无头 Playwright + 源码 SHA256 守卫（验证期间不得落盘）+ 数值/像素双判据**。范式见 `frontend/_v6_dot_lattice_probe.cjs` 与 `frontend/_v7_flagship_flicker_probe.cjs`。

| # | 主张 | 方法 | 可复现判据（验收线） |
|---|------|------|----------------------|
| V-A | 远景旗舰点**不再被同格邻舰挤掉**（F3） | 扩 `_v7` 判据 (f)，距离档 `D ∈ {3000, 6000, 7560}` | 每旗舰在其格 `selfWon == true`；`FAIL_squeezed_by_dot == 0` 且 `CONCERNS_neighbor_mesh == 0` |
| V-B | 指挥标记层**每旗舰恒存在**且**不糊成块**（F1） | 扩 `_v6` 像素法：`only-markers − nothing` 帧做 Δ 掩膜 | `markerBlobCount == flagshipCount`（每旗舰一团）；`largestMarkerBlobShare ≤ 0.35`（带孔形状）；每团外接 ≥ 8px |
| V-C | 标记**与阵营配色正交**、**色盲可辨** | 对全部 4 套 `FACTION_SCHEMES` 各跑 V-B，并算旗舰标记 vs 最近邻普通点的对比 | 亮度差 `ΔLuma ≥ 40` 或 `CIEDE2000 ΔE ≥ 25`（4 套配色全通过）；形状通道独立成立 |
| V-D | **draw call 预算**不破 | 读 `renderer.info.render.calls`，记录加旗舰标记前后 Δ | 8 旗舰下 DC 增量 ≤ 8（InstancedMesh 则 ≤ 1）；相对基线记录 |
| V-E | 近景**轮廓确有差异**（M1/N1） | 近景截图，量旗舰与同级普通舰的包围盒长宽比 | 旗舰 `bbox.h / bbox.l ≥ 0.28`（指挥塔抬高），普通舰 < 0.20 |
| V-F | **跨帧稳定**（F1/N2 动势） | 复用 `_v7` 判据 (g)，连采 120 帧 | 非解释性 flap == 0；`winnerKeyJaccard.min ≥ 0.98`；标记慢转在 120 帧（≈2s）内转过的角度 < 2π |
| V-G | 全流程**源码未被改动** | SHA256 前后比对（`_v6`/`_v7` 已有实现） | `hashStart == hashEnd`，否则记 `CONTAMINATED` |

> 备注：V-B / V-C 的"掩膜"需新增"只画标记层"的调试开关（`__b3dDebugLayer = 'markers'`），与 v6 现有的 `nothing / dots_only / marks_only / full` 档位同风格。
