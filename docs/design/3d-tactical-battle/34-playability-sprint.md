# 34 · 可玩性冲刺（一次性交付）

> 用户指令（2026-10-15）：
> 「继续改吧，把后续的**一次性改完**，都做好流程，我才能玩。现在我是**看不出有什么变化**的，
> 还是和之前一样，没什么变化，**界面什么都没有什么变化**，**友军有的会动，有的不动**，

> 做好流程就行了，我最后再看」
>
> 背景：P1（统一舰队生成入口）、P2（提督配置带过来）**都是底层数值改造，零 UI 呈现**
> ⇒ 用户"看不出变化"是**必然结果**，不是感知问题。本次冲刺的目标是
> **把"能不能玩"这件事一次性解决**，而不是继续做用户看不见的重构。

流程：**多人做 → 反对（红队）→ 测试（审核）→ 总审核（lead）**，与 P1/P2 一致。

## 1. 侦察结论（分工三路，见 §5）

### 1.1 ★★ 头号病灶：3D 模式下"可见 UI 缺口"

`App.vue` 的 CSS：

```css
body.battle3d-mode #phaser-canvas-container canvas { visibility: hidden; }  /* 画布整层隐藏 */
body.battle3d-mode .fleet-ui-layer { display: none; }                        /* 舰队信息条隐藏 */
```

**⇒ 3D 模式（= 唯一玩法）下，画在 Phaser 上的 UI 全部失效**：

| UI | 实现位置 | 3D 模式可见性 | 后果 |
|---|---|---|---|
| 战前部署中央菜单（阵型 1-5 / 姿态 T / 回车开战 / 倒计时） | `BattleScene.updateDeployText()`（Phaser text） | **不可见** | 玩家不知道部署期存在、不知道能改阵型/姿态、不知道何时开战 |
| 阶段横幅（战役开始 / 全面会战 / 战局转折 / 决战时刻 / 增援抵达） | `BattleScene.showBattleBanner()`（Phaser） | **不可见** | 无节奏感、"流程乱" |
| 战斗结束提示 | `battleLossText`（Phaser） | **不可见** | 输赢都不知道 |
| 舰队浮动信息条 **+ 姿态按钮** | `.fleet-ui-layer` 被隐藏，**但 `Battle3DOverlay.initBillboardLayer()` 已补回 DOM 版**（`.b3d-bb-layer`，`three/Battle3DOverlay.ts:4254`） | **可见** | ✅ **无需修改**（含 名称/HP/补给/士气/态势 + 索敌·电子战·攻坚·驻守 四按钮） |
| 旗舰浮动气泡 | `FloatBubble.vue`（DOM） | 可见 | ✅ **唯一已修好的**（`[v59]` 注释自述"Phaser 画布被隐藏"） |

⇒ **`[v59]` 只修了"气泡"一个，其余全部漏掉** —— 这正是"界面什么都没有"的根因。

## 2. 冲刺工作包（W1~W6）

> 原则：**先解决用户能感知的，再解决用户看不见的**。
> P3（数值口径统一）降为最低优先级 —— 它重要但不是"不能玩"的原因。

### W1 · 可见层（★最高优先级）
把画在 Phaser 画布上的 UI **搬到 DOM**（复用 `FloatBubble` 已验证的"3D 坐标→屏幕坐标"通道）：

- W1.1 **部署期面板**：阵型（1-5）/ 姿态（T）/ 倒计时 / [回车开战] → DOM 覆盖层
- W1.2 **阶段横幅**：战役开始 / 全面会战 / 战局转折 / 决战时刻 / 增援抵达 → DOM 覆盖层
- W1.3 **战斗结束提示 / 战损账单** → DOM
- ~~W1.4 舰队信息条~~ ⇒ **已存在，勿重复实现**：`Battle3DOverlay.initBillboardLayer()`（`:4254`）
  已用 3D→屏幕投影驱动 DOM 层 `.b3d-bb-layer`（名称/HP/补给/士气/态势 + 索敌·电子战·攻坚·驻守），
  且**未被 CSS 隐藏**。

> **★ 修正记录（2026-10-15，lead 失误 + 实现者纠正）**
> 侦察 2 号只看到 `body.battle3d-mode .fleet-ui-layer{display:none}` 就下了"舰队信息条看不到"的结论；
> **lead 未交叉验证"是否已有 DOM 替代层"便写入定稿** ⇒ 该结论错误。
> W1+W2 实现者当场发现 `initBillboardLayer` 已补回，并**主动回退了自己的重复实现**（正确处置）。
> **方法论教训**：任何"某 UI 不可见"的结论，必须同时查"**有没有 DOM 替代层/新实现**"，
> 否则会基于"旧代码被隐藏"而重复造轮子。
> 唯一小缺口：billboard 内「N 艘」是 `[v12.1]` **按用户要求主动删除**的 ⇒ **不要擅自加回**。

### W2 · P2 成果可见（★高）
- W2.1 战前 `<N>艘` 改用 `resolveAdmiralComposition`（消除与 P2 的口径不一致）
- W2.2 战前指派面板：显示**该提督的教范阵型 + 编成明细**（舰种图标 + 数量）
- W2.3 战场 HUD：显示当前阵型（中文名）与编成摘要

### W3 · 舰队自主行动（★高）

**用户实报**：「友军有的会动，有的不动」「敌方也是原地不动」。

**已核实的三条根因**（侦察 1 号发现 + **lead 逐条独立验证**）：

| # | 机制 | 位置 | 后果 |
|---|---|---|---|
| R1 | **`stance === 'defend'` ⇒ `rawVX/rawVY` 恒 0** | `:7490` `} else if (fleet.stance !== 'defend') {` | **零位移**（不是"慢"） |
| R2 | `hold_point(自身坐标)` ⇒ `dist<120 ⇒ 'defend'`，且 mission 不清 ⇒ 永久 | `planFactionBattle:1316` + `:3258` + `:872 continue` | 开局即驻守、永不落回独立评估 |
| R3 | **停滞看门狗排除玩家**：`myFac.type !== 'player'` | `:6332` | 玩家舰队卡住后**无自愈** |
| R4 | 军议任务只命中该 faction **第一支**舰队（`find` 返回首个） | `:3326-3327` | 分兵后其余舰队收不到任务 |
| R5 | `deployTactic` 可为 `defend` ⇒ `startBattleAfterDeploy` 写 `pFleet.stance='defend'` | `:1237` | 玩家本队开局站桩（若是显式选择则属预期，但**需 UI 明示**） |
| R6 | 战役轨 `if (isCampaign) continue;` 跳过 1Hz 战略姿态评估 | `:879` | 战役轨 AI 无每秒决策（改动风险高，**本包暂不动**） |
| R7 | `_deployTactic` 断供 ⇒ `deployAdj` 恒 1.15 | `:950-951` / `:1215-1217` | 该机制实际失效（**非回归**，需决定"恢复"或"移除"） |

**修正一条早期假设**：玩家方 `index>=1` 的僚舰其实是 `type:'ai'` ⇒ **会自动行动**；
真正"只能手动"的是 `index===0` 的**玩家本队**（`type:'player'`）。⇒ 与用户"有的动有的不动"精确吻合。

**W3 方案**：
- W3.1 **玩家舰队自愈**：看门狗不再整体排除玩家 —— 允许"推进/目标施压"对玩家舰队生效，
  但**仍然不越权覆盖玩家的直接指令**（`w1DOrder` 判定要同时覆盖玩家）
- W3.2 **`hold_point` 加超时**：到位后 N 秒（建议 25s）转 `search`（巡逻），避免永久驻守
- W3.3 **任务下达改为广播**：`dispatchFleetCommand` 的 mission 分支命中该 faction **全部**舰队
  （至少把 mission 同步到同 faction 的所有舰队，而非只第一支）
- W3.4 **开局姿态明示**：部署界面若选 `驻守`，必须提示"该舰队不会主动移动"
- W3.5 **敌方主动**：`planFactionBattle` 的末位 `hold_point` 分支改为
  "在己方据点附近巡逻 + 接敌即战"，而非原地死守
- W3.6 `_deployTactic` 断供：**移除该机制**（保留消费侧无害，但在注释中标明"已废弃"），
  或恢复写入（二选一，实施者给理由）

### W4 · 流程与引导（★高）

**已核实**：
| # | 机制 | 位置 | 后果 |
|---|---|---|---|
| P1 | **演习部署期 20s 倒计时到点自动开战** | `:1146-1172`（`DEPLOY_COUNTDOWN_SEC`） | 玩家还没布置完就被推进战斗（战役是无限等待 `:1195`） |
| P2 | `BattleIntroOverlay` 可 Esc 收起，收起后**无任何阶段提示** | `App.vue:78` + 组件内 `closed` | "无 UI 黑洞"（唯一提示曾画在隐藏画布上） |
| P3 | `GameFooter.vue:10` 文案错误：把「开指挥点面板」写成「空格暂停…」 | — | 玩家永远找不到 11 条指挥技能 |

**方案**：
- W4.1 演习倒计时：**默认不自动开战**（改为到点只提示"部署时间到，可继续调整"），或提供"暂停/关闭倒计时"开关
- W4.2 部署层收起后必须留**常驻状态条**（当前阶段 + 主要操作提示）
- W4.3 阶段切换提示（进入部署 / 开战 / 交战 / 结束）—— 与 W1.1 横幅共用实现
- W4.4 修正所有错误的操作提示文案（`GameFooter` 等）

### W5 · 控制手感（★高，已由侦察 3 号补全）

**已核实的三条主因**：

| # | 机制 | 位置 | 后果 |
|---|---|---|---|
| Q1 | **`1-5` 双绑定**：同时换阵型 **且** 换速度档 | `BattleScene:785-838` + `App.vue:437-447` | 想调速却改了阵型（提示文案只写了调速） |
| Q2 | **CP 指挥点面板只有空格键能开**（11 条技能无 UI 入口） | `BattleScene:5716` / `GameFooter:10` | 玩家不知道有这个系统 |
| Q3 | **右键指令静默失败**：分兵后需先点选（`pickDirectOrderFleet` 返回 null）；点歪>40px；被选目标态吞掉 | `TacticalCommandSystem.ts:268-279` / `BattleScene:5610` | "点了没反应" |
| Q4 | **移动物理过重**：战列起步 0→95% 需 **8.3s**、掉头 180° **14.3s**、停船 **57.6px** | `shipKinematics.ts:120/130` + `SHIP_KINEMATICS:74` | 操作迟滞感的核心 |
| Q5 | **左键=旋转相机**（未覆写 OrbitControls `mouseButtons`）与"左键点选舰队"共用 | `Battle3DOverlay:1432` | 反直觉；靠 4px 阈值区分 |
| Q6 | 无"回到主舰队 / 重置视角"入口（只有俯仰预设） | `:5788` | 找不到自己的舰队 |
| ~~Q7~~ | ~~相机"跟随舰队"~~ | — | **不存在**（陈旧注释；`controls.target` 仅 3 处赋值，无每帧跟随）⇒ **勿按此假设改** |

**方案**：
- W5.1 **解开 `1-5` 冲突**：阵型与速度分离键位（建议速度档改用 `[` `]` 或 F1-F5），并更新全部提示文案
- W5.2 **CP 面板补 UI 按钮**（`GameControls` 或 `GameFooter` 内），修正文案
- W5.3 **点击即时回执**：右键按下立刻出"已下令 → X 舰队：向(x,y)机动"（不等下一帧 ack）；
  失败（点空/点歪/权限/分兵未选）**就地提示**，不进 toast 队列
- W5.4 **机动可读化**：选中舰队的浮标常显 意图 + 速度百分比 + 机动相位（`cruise/brake/turn/reform`）⇒ 让"8.3s 起步"变成可读的"正在加速"
- W5.5 **视角辅助**：加"回到主舰队"按钮（复用 `__b3dFocus` 的投影逻辑，但要走正式通道）
- W5.6 **加速度（可选，需谨慎）**：`kinAccel` 取 `min(kinProfile.accel, FLEET_ACCEL=0.055)` ⇒ 战列实得 0.00042。
  ⚠ **参数是感知校准值**（v75 教训：不得单方面下调）⇒ 若要上调必须有台架 + 红队攻击；
  **优先做 W5.4（把慢"读出来"）而非直接改数值**
