## 0. 结论先行

现状"不像太空战舰、不好玩"**不是参数没调好，是架构决定了质感上限**。

三个结构性病灶，任何单点调参都无法绕开：

| # | 病灶 | 位置 | 为什么调参解决不了 |
|---|---|---|---|
| **A** | **舰队级与舰级是两套互不共享的物理** | 舰队：指数趋近 `BattleScene.ts:6796`；舰级：硬上限 `fleetKinematics.ts:188` | 舰队是"无质量的可漂移点"，舰船是追随槽位的影子。运动主体错了，参数无处可施 |
| **B** | **转弯半径小于舰长** | R = v/ω = 0.30/(π/240) = **22.9px**，战列舰长 33px | R < L 在视觉上等价于"原地打转"。这是"跟奇怪"最直接的一刀 |
| **C** | **1% 保底伤害** | `BattleScene.ts:7250-7251` | `finalDmg = max(dmg, maxHp×0.01)` ⇒ 任何单位必掉血。**厚重感的另一面是抗性**，保底伤害把抗性彻底抹平 |

**最高杠杆的单点改动**：`FLEET_ACCEL` 从 `0.055` 降到 `0.00625`（慢 9 倍），配合按舰种重算角速度。这是 1 行常量，但它决定整个战场的节奏感。**建议作为阶段 1 独立验证**——先验证这一条能带来多少改善，再决定是否投入后续全部阶段。

## 2. 第一性原理：厚重感的四个可观测通道

不调参数，先确认"厚重"由什么构成。缺任何一项，质感立刻塌陷。

```
厚重感 = 推力有限性 × 质量尺度 × 因果反馈 × 空间参照
```

| 通道 | 定义 | 当前 | 缺它的后果 |
|---|---|---|---|
| **① 推力有限性** | 任何机动的时间正比于舰体尺寸；无任何倍率档可绕过 | 0（6× 加速档直接绕过） | 一切"厚重感"归零 |
| **② 质量尺度** | 舰种/舰级在**转动惯量与推力**上可区分 | 0（舰种同质） | 没有"重舰"这个概念 |
| **③ 因果反馈** | 推力→尾焰、发射→后坐、受击→震感，链路上每一环可见可听 | 0（全解耦） | 战舰是"贴纸"不是"物体" |
| **④ 空间参照** | 近景参照物 + 多层景深，提供速度感与尺度感 | 0（纯黑 + 静态白点） | 移动看起来是"贴纸在滑动" |

**④ 是最被低估的一项**。太空题材最容易犯的错：把"太空"做成"黑色背景"。真空中没有雾，但**有尺度参照**——近景漂浮物、远处行星、中景星云。没有近景，战舰位移在任何速度下看起来都一样。

## 3. 架构重构：舰队锚点降级，舰船自主

### 3.1 现状结构（问题根源）

```
fleet.x/y  ──(无质量指数趋近)──▶  位移
   │
   └─▶ 槽位旋转(formFacing)──▶  目标槽位
                                    │
   每舰 sprite.x/y ──(硬上限追槽)──┘
   每舰 visHeading ──(有限差分求位移方向)──▶ 舰首
```

问题：
1. `fleet` 是唯一运动主体 ⇒ 舰队无质量，舰船无质量感
2. 舰首方向 = 自身位移的有限差分 ⇒ 静止时退化，位移 < 0.02px 时触发刚性例外（`BattleScene.ts:7018-7020`）
3. `formFacing` 三态冻结（`BattleScene.ts:6809-6820`）是**为对抗"格位绕中心画圆"这一病灶而生的补丁**，注释记录了 v31-D / v41b / v42 三代失败方案
4. 转弯时 `motion:'hold'` 只清期望速度，舰队惯性滑行 ~50 帧 ⇒ **"原地转向"实为"边滑边转"**（`2026-10-02` 定案已记录）

### 3.2 目标结构

```
指挥锚点 anchor（无渲染、不参与碰撞）
   └─ 由任务层直接设定目标点，可瞬移（它是"命令位置"，不是物体）
        │
        ▼
编队槽位（anchor + formFacing 旋转）
        │
        ▼
每舰：真实刚体（位置 / 速度 / 朝向 / 角速度 / 推力档位）
        │  独立积分：推力 → 加速度 → 速度 → 位置
        │  独立积分：姿控力矩 → 角加速度 → 角速度 → 朝向
        ▼
     渲染（2D 精灵 / 3D 网格 / 尾焰 / 震感）
```

**关键变更**：

| 变更 | 说明 | 消除了什么 |
|---|---|---|
| **舰队不再是运动主体** | `fleet.x/y` 降级为"编队锚点"，只由任务层写入，不积分 | 病灶 A |
| **每舰独立积分推力** | 复用 `fleetKinematics.stepShipMotion` 的四重约束（已实现且 15/15 台架通过），但输入从"追槽位移"改为"追槽的**期望速度方向**" | 病灶 A/B |
| **舰首由角速度积分** | 不再用有限差分反推。`visHeading` 改为 `∫ω dt` | 刚性例外四分支 |
| **formFacing 简化为"阵型朝向"** | 取消三态冻结，改为按编队锚点朝向的**单向限速跟随**（不再是补丁） | 画圆补丁链 |
| **新增 `thrustLevel`** | 每舰 0~1 推力档（推力/制动/倒推/停船），是音效/尾焰/3D 特效的**唯一输入源** | 反馈全解耦 |

### 3.3 为什么"舰队锚点可以瞬移"是对的

玩家的"全速前进"是对**编队**的命令。如果命令对象瞬移，舰队会瞬间抵达——那不叫厚重。
正确做法：命令对象是**目标位姿**，舰船各自用有限推力去达成。锚点只是"目标在哪"，它的运动是为了给舰船一个渐变的参考系。

若锚点瞬移 → 槽位整体跳变 → 舰船全速冲向新槽位 → 视觉上是"舰队被拉扯"，**这恰好是正确的**（舰队确实在转向新航向）。

**实现约束**：锚点位移速度必须 ≤ 舰船最大速度（否则槽位永远追不上，产生持续跟随误差）。锚点速度 = 任务层的期望速度，与舰船同量级。

## 4. 运动学重写

### 4.1 统一到单一物理形式

废弃两套数学形式，**统一为"推力 → 加速度 → 速度"**（带硬上限，与 `stepShipMotion` 现有的 `|Δv| ≤ a·dt` 同式）。

```
// 概念式（伪代码，实际实现见 fleetKinematics 扩展）
a = thrustDir · (maxAccel[class] · thrustLevel)
v += a · dt                    // |Δv| ≤ maxAccel·dt，天然满足
if braking:  a = -sign(v) · maxAccel[class] · brakeLevel
v = clampSpeed(v, maxSpeed[class])
x += v · dt

// 姿控（纯力矩，质心不动 —— 真空中唯一正确的原地转向方式）
τ = clampAngle(θ_target - θ, ±π) · torqueGain
ω += clamp(τ, ±maxAngAccel[class] · dt)
ω -= ω · angDrag · dt          // 阻尼：松开姿控推力就停止旋转
θ += ω · dt
```

**关键：掉头不再是"档位"，而是力矩的自然结果。** 180° 掉头时间 = 由 `maxAngAccel` 与角阻尼自然决定，**不存在任何倍率旁路**。

### 4.2 舰种运动学表（新增 `src/config/shipKinematics.ts`）

| 舰种 | 2D 舰长 | 3D 舰长 | R/舰长 | R(px) | v_max(px/帧) | ω_max(°/s) | 180°(s) | maxAccel | 定性 |
|---|---|---|---|---|---|---|---|---|---|
| 战列 | 33 | 900 | 1.8 | 60 | **0.22** | **12.6** | 14.3 | 0.0060 | 缓慢转向，需护航 |
| 高战 | 30 | 760 | 1.8 | 54 | **0.28** | **17.8** | 10.1 | 0.0075 | 战列的加速版 |
| 巡洋 | 25 | 570 | 1.5 | 38 | **0.34** | **30.8** | 5.8 | 0.0090 | 灵活，可独立机动 |
| 驱逐 | 18 | 260 | 1.2 | 22 | **0.52** | **81.0** | 2.2 | 0.0130 | 快速迂回，不宜硬拼 |
| 空母 | 40 | 1100 | 2.2 | 88 | **0.16** | **6.3** | 28.6 | 0.0042 | 几乎不能转向 |
| 舰载 | 12 | 180 | 1.0 | 12 | 1.20 | 300 | 0.6 | 0.0300 | 特殊单位 |
| 突击 | 30 | 520 | 1.4 | 42 | 0.46 | 38.0 | 4.7 | 0.0120 | 高速突击 |
| 电子 | 25 | 480 | 1.5 | 38 | 0.30 | 27.0 | 6.7 | 0.0080 | 支援 |
| 补给 | 40 | 1800 | 2.5 | 100 | 0.16 | 5.8 | 31.0 | 0.0040 | 极重，后勤核心 |

**校验**：ω = v/R（弧度/秒换算已计入）。战列 0.22/60 = 0.00367 rad/帧 = 12.6°/s ⇒ 180°/12.6 = 14.3 s。✔

**这张表带来的战术含义**：
- 空母 180° 掉头 28.6 秒 ⇒ 战斗中几乎无法转向，必须靠护卫与站位
- 战列 14.3 秒 ⇒ 掉头是一次**战术决策**，不是随手操作
- 驱逐 2.2 秒 ⇒ 快速迂回是驱逐舰的专属价值
- **巡洋成为"机动主力"**（5.8s 掉头 + 720 射程）⇒ 与现有数值表契合

### 4.3 关键：转弯半径必须 > 舰长

这是本次重构的第一判据。所有舰种 R ≥ 1.0 L。战列 R=1.8L 意味着掉头时舰首划过约 **106px（3.2 舰长）的弧线**——肉眼可见一条大弯，而不是原地扭头。

**验收**：`scripts/shipKinematicsSim.cjs` 断言每个舰种 R/L ≥ 1.0，且战列 ≥ 1.5。

### 4.4 高速舵效衰减

```ts
// 角速度上限随速度上升而下降（舵面效率 / 姿控推力器功率有限）
omegaCap = omegaMax * (1 - 0.45 * (speed / maxSpeed))
```
战列全速时 ω 上限降 45% ⇒ 高速中掉头时间进一步拉长到 ~20s。**这正是"沉重"的来源**。

### 4.5 保留的既有成果

`fleetKinematics.ts` 已实现的**四重约束 + 两个已实锤的坑**必须保留：

1. **反向转向奇异**：`dot(v0,v1) ≥ sp0·(sp0−accel·dt)`（`fleetKinematics.ts` 内已注）
2. **绕槽螺旋**：`ARRIVE_EPS = 2.5px` 死区 + 死区内期望 = 槽速前馈（`ARRIVE_EPS` 0.5→2.5 的教训）
3. 死区 2.5px 带来阵位残差 ≤2.37px（0.09 槽宽）——**新架构下需重新评估**，因为现在船不再"必须到槽位"，允许在槽位附近保持航向等待归位

## 5. 武器系统重构：炮塔 + 火控

### 5.1 为什么必须加炮塔

"转进"（turn-in）这个战术动作，**在当前架构里没有存在理由**——舰队移动只是为了到达目标点，不存在"为了把炮转到某方向而移动"的概念。加炮塔后，转进立刻获得战术意义：

> 我在敌舰 900px 方位，但我的主炮塔射界只有相对舰体 ±60°。我必须**边转进边把炮塔转过去**，才能持续命中。

这才是银英式的战斗：**移动与射击是同一个动作的两面**。

### 5.2 炮塔数据模型（新增 `src/config/shipTurrets.ts`）

```ts
export interface TurretSpec {
  id: string
  offsetAlong: number      // 沿舰体轴向位置，-1(舰尾) ~ +1(舰艏)
  mount: 'fore' | 'aft' | 'beam'   // 炮位：舰艏/舰艉/舯侧
  arcHalfRad: number       // 相对舰体的射界半角
  traverseRate: number     // 炮塔旋转速率 rad/s（独立于舰体）
  salvo: number            // 齐射门数
  salvoSpreadMs: number    // 齐射内相邻门的间隔
  reloadMs: number         // 装填
  damageShare: number      // 占单舰总伤害的比例
  elevation: number        // 仰角（未来扩展）
}
```

### 5.3 炮塔逻辑（纯函数，纳入裁决层）

```
目标航向 θ_tgt
炮塔当前航向 θ_tur
期望 = clampToArc(θ_tgt, 舰体朝向 + offset ± arcHalf)
θ_tur += clamp(期望 - θ_tur, ±traverseRate · dt)

可开火 ⟺ 装填完成 ∧ |θ_tur - θ_tgt| ≤ 容差 ∧ 距离 ≤ 射程 ∧ 视界清晰
开火 ⟹ salvo 门在 salvoSpreadMs 内依次打出 ⟹ 每门产生 recoilImpulse（反作用于舰体）
```

**射界差异创造战术位置价值**：只有舯侧炮的巡洋，必须让敌舰处于侧面才能持续输出；这是"绕后"的真实收益。

### 5.4 齐射视觉语言

一艘战列舰 = 2 组主炮塔 × 3 联装 = **6 道光束在 0.45s 内依次打出**，指向同一目标，构成一道扫掠光幕。**这是"厚重"最强的一张牌**——比任何尾焰都有效。

### 5.5 命中判定：去保底，加几何

**废除** 1% 保底伤害（`BattleScene.ts:7250-7251`）。

替换为：
```
baseDmg = (atk − effectiveDef) · terrainDodge^−1
hitMul  = 距离衰减 × 装甲角度因子 × 炮塔精度   // 全部 ∈ [0.35, 1.0]
finalDmg = max(1, round(baseDmg · hitMul · 乘区链))
```

**方向装甲改读炮塔射线方向**（而非受击方运动方向，`BattleScene.ts:7189-7191`）——这才与 5.1 的转进逻辑闭环。

**不引入随机命中**。理由：战棋的可预测性是可玩性基础；随机命中会让"调整阵位"这一决策失去意义。改用**几何**：距离衰减 + 装甲角度，纯确定性但有丰富空间。

### 5.6 命中后的连锁（新增）

- 装甲过载：连续命中同一部位 → 该部位损伤累积 → 局部降速/降转向率
- 这让"集火同一目标"有明确的战略价值（打瘫而非打死）
- 与已有 `shipTacticalProfile.dirArmorMul` 对称，实现 `localDamage`

## 6. 反馈通道重构

### 6.1 thrustLevel：唯一因果源

新增每舰字段 `thrustLevel ∈ [0,1]`，由运动学在积分时写入。**它是所有表现层效果的唯一输入**：

| 表现 | 当前 | 目标映射 |
|---|---|---|
| 3D 尾焰长度 | `0.05~0.10L` 时间驱动 | `0.10L + 0.35L·thrustLevel` |
| 3D 尾焰亮度 | 固定 | `0.5 + 0.5·thrustLevel`，加 8Hz 抖动 ∝ thrustLevel |
| 3D 引擎喷口辉光 | 无 | 喷口位置随 thrustLevel 增亮 |
| 2D 尾焰长度 | 舰种硬编码 | 同样映射，长度 ∝ thrustLevel |
| 2D 尾焰 alpha | `0.85~1.0`（±15%） | `0.35 + 0.65·thrustLevel`（±65%） |
| 引擎音效 | 无 | 低频锯齿波，音量 ∝ thrustLevel，音高 ∝ 速度 |

**这是全项目性价比最高的一处改动**：一个字段，激活 6 处表现。`Battle3DOverlay.ts:1783-1785` 注释记录用户曾实报"尾焰几乎是没的，只是几处微白光"——原因是长度被 v22 从 0.22~0.37L **收短**到 0.05~0.10L。收短是对的（避免"廉价光带"），但**同时必须引入与推力的因果耦合**，否则就只是"没有尾焰"。

### 6.2 音效系统（新增 `src/services/SfxManager.ts`）

**程序化合成（WebAudio），零音频资源依赖。**

选这个方案的理由：文件音频**无法随推力连续调制**（预录音频做不到"推力 0.3 时引擎是这个音高"）。程序化合成是唯一能让"推力→声音"成为连续函数的方式，这对厚重感是刚需。

```
引擎：sawtooth osc → lowpass(f = 80 + 260·speed) → gain(0.08 + 0.22·thrust)
主炮：noise burst 60ms + sine sweep 180→40Hz + exp decay
爆炸：sine 120→28Hz over 0.9s + noise tail
受击：3 个不谐和正弦 (f, f·1.41, f·1.93) 短促衰减 = 金属应力
结构应力（受击但未破防）：lowpassed noise 400ms，音量 ∝ 伤害/装甲
```

与已有 `MusicManager` 并存（BGM 不变），`unlockAudio()` 复用其解锁逻辑。

### 6.3 3D 震感（新增 trauma 模型）

```ts
// 加法累积，按平方衰减
trauma = min(1, trauma + amount)
shake = trauma²
// 每帧：trauma -= 1.6·dt
```
| 事件 | trauma |
|---|---|
| 战列主炮开火 | +0.18 |
| 巡洋开火 | +0.09 |
| 本舰受击 | +0.10 × (dmg/maxHp) |
| 敌舰沉没（近景） | +0.30 |
| 舰队转向（角加速度） | +0.15 × (|ω|/ω_max) |

相机偏移用 perlin noise × shake，**3D 层实现**（2D 的 `cameras.main.shake` 保留给降级路径）。

### 6.4 开火后坐

```ts
// 主炮开火反作用
recoil = normalize(fireDir) · (salvoCount · impulsePerGun / massFactor)
u.v -= recoil   // 真的推动舰体
```
战列 6 门齐射的后坐 ≈ 巡洋 1 门 4 倍。**后坐是"厚重"最直接的物理证据**——炮越重，打出去自己越往后顿。

同时：`formationOffset` 脉冲 + 音效低频 + 相机微幅后拉。三者同步。

## 7. 空间环境重构

### 7.1 近景参照物（速度感的唯一来源）

新增三层，**这是让"移动"变可见的关键**：

| 层 | 内容 | 视差 | 目的 |
|---|---|---|---|
| 近景 | 稀疏尘埃/冰晶粒子（1000 点，相机跟随盒内循环） | **极强** | 速度感。粒子向后飞驰的速率直接编码速度 |
| 中景 | 星云（3~5 张大尺度加性 sprite）+ 远处行星/卫星（已有 `planetModels.ts`） | 中 | 空间纵深 + 尺度参照 |
| 远景 | 现有 1200 点星空 | 极弱 | 底色 |

**近景粒子必须存在**。纯星空里，战舰以 0.22px/帧 移动和以 4px/帧 移动看起来一样——因为没有参照。粒子流速让速度立刻可读。

### 7.2 光照与材质

- 太空没有大气散射 ⇒ **移除雾的暗示**。当前 `scene.fog` 每帧按相机距离动态设（`Battle3DOverlay.ts:5566-5572`），本质是"太空里的空气透视"，物理上不成立，但可为可读性保留（远景淡出是必要的战术信息）
- 保留但重命名 `spaceFade`，语义从"雾"改为"战术可见性衰减"
- 引擎光：新增 `PointLight` 挂在主炮口，开火瞬间点亮周围（持续 0.2s）

### 7.3 阵型与规模的尺度感

战列 3D 舰长 900m，驱逐 260m。**3.3 倍的尺寸差在当前相机距离下不可读**。
建议：远景档位下对大舰体做**尺度夸张**（战列视觉放大 1.15×），维持"重舰压迫感"。

## 9. 明确不做的事

| 不做 | 理由 |
|---|---|
| 换引擎 / 换渲染框架 | 渲染不是病灶。`Battle3DOverlay` 5791 行功能完整，扔掉重建的收益远低于风险 |
| 完整轨道力学 | 策略游戏不需要万有引力。保留"有限加速度 + 有限推力"即可 |
| 随机命中 | 破坏可预测性，让"调整阵位"失去决策价值（见 5.5） |
| 引入导弹/鱼雷 | 用户已裁定"导弹的效果有点差"（`BattleScene.ts:7321-7323`）。若要做弹道武器，形态应是"高相位炮"而非导弹 |
| 继续给 `formFacing` 打补丁 | 架构变更后它是多余层，不是要修的东西 |
| 一次性全量重构 | 已验证的 26 台架 + 15/15 运动学台架是资产。分阶段保住回归面 |
