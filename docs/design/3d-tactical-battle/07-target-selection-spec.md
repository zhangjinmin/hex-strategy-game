## 2. 目标合法性判定规则

### 2.1 判定条件（逐条，附代码依据）

| # | 条件 | 判据 | 代码依据 | 不满足时的反馈 |
|:--:|------|------|----------|----------------|
| **L1** | 阵营为敌 | `targetFac.team !== playerFac.team` | `BattleScene.ts:2163` 视野逻辑同款判定 | `目标必须为敌方舰队` |
| **L2** | 舰队存活 | `fleet.units.length > 0` **且** `faction.active` | `BattleScene.ts:2152`、`2162` | `该舰队已溃散` |
| **L3** | 在视野范围内 | `dist(fleet, target) < getVisionRange(fleet, myFac)` | `BattleScene.ts:2164` | `目标不在我方视野内` |
| **L4** | 清晰度足够 | `dist <= visionRange × 0.8`（即 `clarity !== 'fuzzy'`） | `BattleScene.ts:2165` | `情报不足：该目标仅模糊侦测` |
| **L5** | 距离上限 | **不设限** | `CommandAbility` 数据中无 `range` 字段，4 个命令均未填 | — |
| **L6** | 舰种限制 | **不设限** | 数据中无舰种字段 | — |
| **L7** | 无敌状态 | **不构成非法**，仅提示 | `evasive_maneuver` 的 `shield 1.0` 在规则层生效后会使目标减伤 90% | tooltip 提示 `目标处于回避状态，伤害将被大幅削减` |

**L3 / L4 的合并写法**：`dist < visionRange × 0.8` 一条即可覆盖（L3 是 L4 的父集）。分开列是为了让实现时能分别给出不同的拒绝原因文本。

### 2.2 关于 L5（距离上限）的设计判断

**结论：不加。** 理由是决策 6（战斗规则零改动）——数据中不存在 `range`，加距离限制等于新增规则。

**但要登记一个未来风险**：若层 2 修好 `teleport` 与 `speed_boost` 后，`reuenthal_blitz`（传送到目标身后）与 `formation_charge`（冲锋到目标身后）将允许玩家对**地图另一端**的目标下达命令，产生一次跨越全图的位移。这在平衡上是可疑的。**建议层 2 立项时同步评估是否需要补距离限制。**

### 2.3 判定执行时机

| 时机 | 行为 |
|------|------|
| 命令面板打开时 | 计算一次，用于决定命令卡片是否置灰 |
| 目标选择态期间 | **每 500ms 重算一次** `[PLACEHOLDER]`，更新候选集与列表 |
| 玩家点击瞬间 | **再做一次实时判定**（不依赖缓存），防止 500ms 窗口内的状态漂移导致下达无效命令 |

## 4. 编号分配与锁定规则（实现要求）

> 这条规则的目的是：**玩家在 3D 中转视角、拉远近时，不应该看到编号乱跳。** 3D 特有的问题，2D 不存在。

### 4.1 快照机制

```
进入目标选择态的瞬间：
  1. 计算合法目标集（§2）
  2. 按「距玩家旗舰距离」升序排序
     距离相同时按 fleetId 升序（保证结果确定性，不依赖遍历顺序）
  3. 截取前 9 个，写入不可变快照 targetSnapshots[0..8]
  4. 快照在整个目标选择态期间只读
```

### 4.2 五条锁定规则

| # | 规则 | 说明 |
|:--:|------|------|
| **N1** | **不因相机移动重排** | 排序键是"距玩家旗舰的世界距离"，与相机无关 |
| **N2** | **不因目标自身移动重排** | 快照是进入时的距离快照，战斗中舰队持续移动，若按实时距离重排编号会持续跳动 |
| **N3** | **目标消失时保留空位** | 该编号**不回收、不重新分配**；徽章隐藏，目标列表项置灰并标注「已溃散」。避免"我刚要按 3，结果 3 变成了另一支舰队" |
| **N4** | **新出现的目标追加到末尾** | 不插入中间。若已用满 9 个编号，新目标**不分配编号**，只能通过鼠标点击或列表选择 |
| **N5** | **退出选择态即销毁快照** | 执行成功或取消后销毁；再次进入时重新计算 |

### 4.3 编号与三种选择方式的对应

| 方式 | 可用编号范围 |
|------|-------------|
| 数字键 `1`–`9` | 快照中前 9 个且当前仍存活的目标 |
| `Tab` / `Shift+Tab` 循环 | **跳过已溃散的空位**，只在存活目标间循环 |
| 鼠标点击 | 无限制，可点选任何合法目标（含未分配编号的第 10+ 个） |

**为什么 `1`–`9` 可用**：阵型键 `1`–`5` 在暂停态被禁用（`BattleScene.ts:266`：`if (!newForm || this.store.isPaused || ...) return`），命令面板打开时游戏处于暂停，因此数字键完全空闲。已核对代码。

## 5. 取消路径

### 5.1 支持的取消方式

| 输入 | 行为 | 层级 |
|------|------|:----:|
| **`Esc`** | **取消当前命令**，退出目标选择态 → 回到命令面板的命令列表（**不退出暂停，不关闭面板**） | 主 |
| **再次点击已选中的命令卡片** | 同 `Esc`，取消该命令的选择 | 主 |
| **命令面板的「返回」按钮** | 同 `Esc` | 主 |
| **`Space`** | 关闭整个命令面板 + 恢复实时（取消一切未确认操作） | 全局 |
| 点击面板外空白区域 | **无效果**（面板为非模态，点击战场是选择操作，不是取消） | — |

### 5.2 明确不支持的取消方式（及理由）

| 输入 | 是否取消 | 理由 |
|------|:--------:|------|
| **右键** | ❌ **不取消** | 右键在 3D 下承担「轨道旋转」与「投放战术信标」两个高频操作（`02` §1.4）。若右键同时能取消命令，玩家转视角时会误取消。这是 3D 相对 2D 新增的冲突，必须显式排除 |
| **点击空域** | ❌ **不取消** | 玩家在 3D 中很容易点空（远景、杂乱区）。点空即取消会让命令下达过程反复中断 |
| **点击非法目标** | ❌ **不取消** | 同上，且需要给玩家纠正机会；只提示原因 |
| **相机移动/旋转** | ❌ **不取消** | 选目标时需要转视角找目标（`03` 步骤 1 已明确：暂停态相机保持完全可操作） |

### 5.3 目标在选择过程中失效的处理

| 情况 | 处理 |
|------|------|
| 已锁定的目标在**确认前**溃散 | 撤销锁定 → 回到候选选择 → 底部提示 `目标舰队已溃散，请重新选择`；编号保留为空位（N3） |
| 已锁定的目标在**确认前**变为 `fuzzy` | **保留锁定**，徽章变为 `?`，提示 `目标信号衰减，仍可下达命令`。理由：玩家已明确做出选择，不应因 AI 移动而剥夺；且规则层不阻止对 fuzzy 目标下达命令 |
| 快照中全部目标溃散 | 退出目标选择态 → 回到命令列表 → 该命令卡片置灰并标注 `当前无可见敌方舰队` |
| 确认瞬间目标溃散（500ms 窗口内） | **拦截执行**，不扣 CP，提示 `目标已消失，命令未执行`。**CP 必须在执行成功后才扣除** |

## 6. 无合法目标时的处理

**结论：禁用命令卡片，不进入目标选择态。**

| 项 | 规格 |
|----|------|
| 判定时机 | 命令面板打开时计算一次；之后每 500ms 重算 |
| 表现 | 命令卡片置灰 + 显式原因文字 `当前无可见敌方舰队` |
| 点击已禁用的卡片 | 卡片红色抖动 200ms + 拒绝音 + 提示原因（**不允许静默失败**） |
| 敌舰进入视野 | 命令自动启用（淡入动画 200ms + 短促提示音） |
| 备选方案为何不用 | "先下达、执行时提示无效"会让玩家损失一次点击并产生挫败，且需要明确 CP 是否退还——**从源头禁用可以避免整个问题** |

## 7. 一命令对多目标：结论是不做

**明确结论：MVP 不支持一个命令指定多个目标。**

| 判据 | 分析 |
|------|------|
| 数据结构 | `ActiveEffect.targetFleetId: number \| null` 是**单数**；扩展为 `targetFleetIds: number[]` 属规则层改动，违反决策 6 |
| 命令语义 | 4 个 `requiresTarget` 命令的描述均为单目标：「集火**单一**目标」「**目标**敌方舰队」「冲锋到**目标**身后」「传送到**目标**身后」 |
| 与 Q3 一致性 | Q3 已裁定 MVP 不做框选与多选。多目标选择需要多选交互作为前置 |
| 收益 | 无。不存在任何需要多目标的命令语义 |

**若未来要做**，前置条件依次是：① 扩展 `ActiveEffect.targetFleetId` → `targetFleetIds[]`；② 补多选交互（Q3 的 P2）；③ 重新平衡（多目标 `ecm_jam` 会显著增强）。
