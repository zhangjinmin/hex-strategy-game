## 1. 现状诊断：2D 流程有两层断点

### 1.1 代码级事实

现有流程（`BattleScene.ts:1497-1535`、`App.vue:130-143`、`CommandPanel.vue`）：

| 步骤 | 实现位置 | 状态 |
|------|----------|:----:|
| ① `Space` → 暂停 + 打开命令面板 | `BattleScene.ts:1969-1979` | ✅ |
| ② 面板显示 CP / 命令列表 / 可用性 | `CommandPanel.vue` | ✅ |
| ③ 点击命令 | `CommandPanel.vue:101` | ✅ |
| ④ **在战场上点选目标** | — | ❌ **未实现** → ✅ **2026-09-15 已实现（2a）**：`BattleScene.enterTargetSelect` `:2545` / `tryExecuteOnFleet` `:2562`；3D 拾取 `Battle3DOverlay.pickFleetAtScreen` `:5066` |
| ⑤ 执行命令 | `executeCommandFromPanel` | ✅（但 `targetId` 恒为 `null`） |

**证据**：`commandBridge.pendingCallback` 在整个 `frontend/src` 中只有三个出现位置——定义（`CommandBridge.ts:13`）、赋值（`BattleScene.ts:1510`）、以及**以 `null` 调用**（`App.vue:135`，关闭面板路径）。没有任何一处传入非空 `targetFleetId`。

> **2026-09-15 复核**：上述「只有 `null` 调用」**已过时**。2a 落地后，目标命令的执行路径会传入真实 `targetFleetId`（`tryExecuteOnFleet` → `executeCommandFromPanel(abilityId, fleetId)`）。`App.vue` 现有 4 个 handler（`:155` execute / `:168` cancel / `:182` select-target / `:188` cancel-target）；`CommandPanel.vue` 声明 4 emit。旧行号（`BattleScene.ts:1510` / `App.vue:135`）属版本漂移。

同时，`BattleScene.handleTileClick` 首行即 `if (... || this.store.isPaused) return;`（`BattleScene.ts:1867`），即命令面板打开（暂停）期间地块点击被吞掉，玩家无法回战场做任何点选。

## 2. 建议流程（7 步）

设计目标：**在 3D 中完成"选一个 3D 空间中的舰队"这件事，且全程不遮挡战场、不丢失相机控制。**

### 步骤 1 — 进入战术暂停

| 项 | 内容 |
|----|------|
| 触发 | `Space` |
| 游戏状态 | 时间冻结（模拟暂停，非 UI 挂起） |
| **玩家看到** | ① 画面整体降饱和 15% `[PLACEHOLDER]`<br>② 扫描线强度 ×1.4 `[PLACEHOLDER]`<br>③ 四角 L 形 HUD 记号收拢 8px<br>④ 屏幕中上出现「战术暂停」角标<br>⑤ **敌人意图线全显**（2D 现状即如此，保留）<br>⑥ 命令面板从右侧滑入 |
| 相机 | **保持完全可操作**。这是 3D 相对 2D 的关键增强：选目标需要转视角、拉远看清全局，暂停期间不得锁死相机 |
| 音频 | 战斗环境音降低至 40%，叠加一个短促 UI 音 |

### 步骤 2 — 命令面板（非模态）

| 项 | 内容 |
|----|------|
| 形态 | **右侧竖向卡片，宽 320px，不遮挡战场中心**。⚠️ 与现状不同：现状 `CommandPanel.vue:128` 是 `position: fixed; inset: 0` + 半透明黑遮罩，会遮住半个战场 |
| 内容 | CP 条（常驻数值 + 进度）、通用命令 6 条、提督专属命令、每条显示名称/CP 消耗/描述/冷却 |
| 不可用命令 | 置灰 + **显式原因文字**：`CP 不足` / `冷却 42s` / `需指定目标` / `需莱因哈特同场` |
| 关闭 | `Space` 或 `Esc` → 退出暂停，恢复原速度档 |

### 步骤 3 — 选择命令，进入目标选择态

> 本步骤的完整规格（合法性判定、脉动参数、编号锁定、取消路径、无合法目标处理）见 **`07-target-selection-spec.md` §2–§6**。此处只列流程位置。

| 项 | 内容 |
|----|------|
| 触发 | 点击命令卡片 |
| 分支 A | `requiresTarget: false`（7 个命令）→ **直接执行**，跳到步骤 7 |
| 分支 B | `requiresTarget: true`（4 个命令）→ 进入目标选择态 |
| **玩家看到（分支 B）** | ① 命令面板**收缩**为右下角紧凑卡片（保留命令名 + `Esc 取消` 提示 + 返回按钮）<br>② 战场全局轻微压暗 10%（非遮罩，均匀降低环境光）<br>③ **所有合法目标**显示脉动轮廓（0.83 Hz）+ **编号徽章 ①②③…**<br>④ 非法目标（友军 / `fuzzy` / 已灭）降饱和 60% 且不显示徽章<br>⑤ 光标变为靶心样式<br>⑥ 右下角卡片顶部显示：`已选: 集中火力 — 点击目标 或 按 1-9` |

### 步骤 4 — 选择目标（四种等价方式）

| 方式 | 输入 | 说明 |
|------|------|------|
| **A. 鼠标点击（3D 战场）** | 左键点击任意合法目标舰船 / 接地投影 / 编队标记 / 编号徽章 | 走 `02` §3 的四层递进拾取；**忽略遮挡**，后排目标可直接点中 |
| **B. 数字键快选** | `1` – `9` | 对应编号徽章。可用是因为阵型键 `1`–`5` 在暂停态被禁用（`BattleScene.ts:266`）。编号**一次性锁定不随相机重排**，见 `07` §4 |
| **C. 键盘循环** | `Tab` / `Shift+Tab` 循环 → `Enter` 确认 | 循环时相机自动转向使目标入画（可关闭；Comprehensive 档位下不移动相机） |
| **D. 点击雷达** ⭐ Q2 通过后新增 | 点击雷达上的候选目标标记 | 与方式 A 完全等价；**解决了"目标在屏幕外"的极端情况**。见 `08` §4 |

| 悬停反馈 | 内容 |
|----------|------|
| 悬停合法目标 | 靶心锁定环收紧 + 目标高亮 + D 层 tooltip（舰队编号 / 提督 / 舰种构成 / HP / 阵型 / 距我方 `n` 格）+ 从施令舰队到目标的**预演命令弧线**（虚线） |
| 悬停非法目标 | 无高亮；tooltip 显示**拒绝原因**：`目标必须为敌方舰队` / `情报不足：该目标仅模糊侦测` / `该舰队已溃散` |

### 步骤 5 — 确认

| 项 | 内容 |
|----|------|
| 高成本命令需二次确认 | 判据：**`cpCost ≥ 3` 或 `cooldownMs ≥ 240000`** → 显示确认条 `确认对 第3舰队 使用「双璧的猛袭」? [Enter 确认] [Esc 取消]`<br>命中命令：`reinhard_roar` / `yang_magic_counter` / `kirscheis_guardian` / `reuenthal_blitz` / `bucock_bastion` |
| 低成本命令 | 直接执行。判据外的命令（1–2 CP）不需确认，避免拖慢节奏 |

### 步骤 6 — 目标失效的兜底

| 情况 | 处理 |
|------|------|
| 候选列表刷新 | 每 **100ms** `[PLACEHOLDER]` 重算一次合法目标集（暂停态下开销可忽略） |
| 已选目标在确认前被消灭 | 撤销选择 → 回到步骤 4 → 底部提示 `目标舰队已溃散，请重新选择` |
| 已选目标在确认前移出视野（`fuzzy`） | 保留选择，但徽章变为 `?` 并提示 `目标信号衰减，仍可下达命令` |
| 无任何合法目标 | 步骤 3 即拦截，命令卡片显示 `当前无可见敌方舰队`，不进入目标选择态 |

### 步骤 7 — 执行与恢复

| 项 | 内容 |
|----|------|
| 立即 | CP 扣除（HUD CP 条有 300ms 下降动画 + 消耗数字 `-3` 浮动）<br>命令进入冷却（命令卡片显示倒计时）<br>战斗日志写入一行：`[CP] 集中火力 → 帝国第3舰队` |
| 世界表现 | 见 §4「三态反馈」 |
| 恢复实时 | **执行后保持暂停 1.2s** `[PLACEHOLDER]`，播放命令生效表现，然后自动恢复原速度档<br>设置项「命令执行后保持暂停」默认关；开启则等待玩家再按 `Space` |

## 3. 3D 下目标选择的可用性问题与解法

| # | 问题 | 为什么 2D 不存在 | 解法 |
|---|------|------------------|------|
| **C1** | 目标被前排舰船遮挡，点不到 | 2D 俯视无遮挡 | 拾取忽略遮挡（`02` §3 P1）；被遮挡目标的编号徽章走 W+ 层 `depthTest=false`，永远绘制在最上层 |
| **C2** | 目标在相机背后 / 视口外 | 2D zoom 到 0.3 时全场在屏内 | `Tab` 循环自动转向；D 层标签在视口外时钳制到边缘 + 方向箭头（**相机背后则隐藏**，避免方向误导）；雷达（Q2）直接点选 |
| **C3** | 点空（点中虚空 / 棋盘空格） | 2D 点地块即可 | 半径 18px 屏幕空间近邻搜索兜底；仍无命中 → **保持目标选择态，不取消**（防误操作中断） |
| **C4** | 误点友军 | 2D 同样存在，但无空间歧义 | 友军完全不响应（无 hover、无高亮、不进候选集）；点击后底部提示 `目标必须为敌方舰队`，不改变状态 |
| **C5** | 误点 `fuzzy` 目标（视野边缘，规则上不可锁定） | 2D 同样存在 | 徽章显示为 `?` 而非编号；不可选；悬停提示 `情报不足：需靠近或提升情报值`（对应 `visionRange = 基础 + 情报×2 + 电子科技×30`） |
| **C6** | 深度误判——以为点的是近处目标，实际选中远处 | **2D 不存在，3D 特有** | 悬停时显示**接地环 + 垂直虚线**（把舰船在棋盘平面上的位置显式化）；靶心锁定环显示在舰船**接地投影**上而非舰体上 |
| **C7** | 命令作用范围误解（玩家以为作用于单舰，实际作用于整个舰队） | 2D 同样存在 | 确认阶段用**编队包围盒高亮 + 贴地编队轮廓线**明示作用范围；命令描述中"指定舰队"四字加粗 |
| **C8** | 半透明舰船叠加时，分不清编号徽章属于哪支舰队 | **3D 特有** | 编号徽章锚定在**编队几何中心**而非单舰；同舰队所有舰船的轮廓同步脉动（同相位），视觉上成为一个整体 |
| **C9** | 目标编号在相机转动后重排，玩家记不住"3 号是谁" | **3D 特有** | 编号在**进入目标选择态时一次性分配并锁定**，直到退出选择态都不随相机/距离变化重排 |
| **C10** | 命令面板挡住目标 | 2D 是全屏遮罩但不影响（选目标靠点地块……实际也影响，只是没实现） | 命令面板收缩为右下角卡片（步骤 3）；面板可拖移；`H` 键临时隐藏全部 UI |

## 4. 命令反馈：三态状态机

玩家需要区分"命令已下达 / 正在生效 / 已结束"。三个状态必须有**视觉上可区分**的表现。

### 4.1 状态定义

| 状态 | 触发 | 世界表现（W/W+ 层） | UI 表现（D/H 层） | 音频 |
|------|------|--------------------|------------------|------|
| **Issued**<br>已下达 | `executeCommand` 返回非 null | ① 施令舰队头顶出现**命令图标**（0.3s 弹出）<br>② 施令旗舰 → 目标的**命令弧线**（贝塞尔，0.4s 沿路径绘制，末端爆点）<br>③ 目标端出现靶心环（0.4s 收紧） | ① 命令面板卡片变「执行中」0.6s 后关闭<br>② 战斗日志 `[CP] 命令名 → 目标舰队名`<br>③ HUD CP 条下降动画 + `-N` 浮动数字 | 命令音效（按 `effect.type` 分 8 种） |
| **Active**<br>生效中 | `ActiveEffect` 进入 `state.effects` | ① 目标/施令者身上的**状态光环**（形状编码见 §4.2，非纯颜色）<br>② 目标舰队接地投影边缘同一光环色脉冲 | ① **活跃效果条**新增条目：`[图标 命令名 12.4s]`（**数字倒计时，非纯进度条**）<br>② 目标舰队 tooltip 内显示活跃效果列表<br>③ HP 条旁显示增益角标 | 持续低频环境音（可选，默认关） |
| **Expired**<br>已结束 | `remainingMs ≤ 0` | 光环收缩并淡出（0.3s），无爆点 | ① 活跃效果条条目移除（0.3s 淡出）<br>② 战斗日志 `「集中火力」效果结束` | 短促下落音 |

### 4.2 八种命令效果的非颜色编码（色盲硬要求）

`commandAbilities.ts` 中 `CommandEffect.type` 共 8 种。每种必须有**独立形状**，颜色只是辅助通道。

> **范围说明**：本节只定义**效果的视觉呈现规格**（活跃效果条上的图标、世界空间的状态光环），**不涉及效果的实现**——那属于层 2，本次不做。
> 8 种里当前只有 `damage_boost` 与 `debuff` 会在实际战斗中出现（层 1 完成后）；其余 6 种的呈现规格仍需定义，因为它们会用在**命令描述与活跃效果条**上，且层 2 上线后可直接使用。

| `effect.type` | 颜色 | **形状（主编码）** | 位置 | 动画 |
|---------------|------|-------------------|------|------|
| `damage_boost` | 红 `0xef4444` | **3 个向上三角 ▲** 环绕 | 施令舰队 | 逆时针环绕，1.5s/圈 |
| `shield` | 绿 `0x10b981` | **六边形球壳** | 目标舰队 | 呼吸缩放 0.95–1.05，2s/次 |
| `reflect` | 青 `0x06b6d4` | **双层反向旋转环** | 目标舰队 | 内外环反向旋转 |
| `debuff` | 紫 `0xa855f7` | **向下三角 ▼**（悬浮头顶） | 目标舰队 | 上下浮动 ±3px |
| `speed_boost` | 黄 `0xf59e0b` | **双箭头 »»**（尾部） | 施令舰队 | 向后流动 |
