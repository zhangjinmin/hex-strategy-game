## 2. 三个全局性前置问题（不解决，单个命令修了也白修）

> **2026-09-15 复核**：本节三个前置问题中，**§2.2 与 §2.3 已被代码侧处理 / 证伪**：护盾现走 `getIncomingMultiplier`（下限 `Math.max(0.05, ...)`，`CommandPointSystem.ts:162`），故 `evasive_maneuver` 的 shield 1.0 近似「95% 减伤」；**士气系统已真实存在**（`BattleScene.ts:973` 字段、`:4107` 影响移速、`:4330` 影响伤害）。**§2.1（`durationMs: 0` 语义）仍待办**——`reuenthal_blitz` 仍未实现。

### 2.1 `durationMs: 0` 的语义未定义 ⚠️ 阻塞 `reuenthal_blitz`

**问题**：数据层注释写 `durationMs: 0 = 瞬时`，但实现层：

```
executeCommand:  remainingMs = ability.effect.durationMs      // = 0
updateCPState:   remainingMs -= dtMs  →  若 <= 0 则 splice    // 入库即被移除
```

即 `durationMs: 0` 表示**"入库即过期"**，与"瞬时（执行一次然后结束）"的语义相反。`reuenthal_blitz` 正是 `durationMs: 0`。

**建议方案（推荐）**：**瞬时效果不进 `state.effects`，在 `executeCommand` 内立即结算；只有持续性效果进 `effects`。**

- 优点：`durationMs: 0` 的问题从根上消失；`effects` 数组只装真正需要倒计时的东西
- 若工程上不方便改结构，退而求其次：`durationMs` 必须 > 0（见 §3.5 的具体建议值）

### 2.2 `Math.max(0.1, mult)` 下限使「无敌」变成「90% 减伤」⚠️ 影响 `evasive_maneuver`

**问题**：`getDamageMultiplier` 末尾 `return Math.max(0.1, mult)`。`evasive_maneuver` 的 `shield value = 1.0` → `mult *= (1 - 1.0) = 0` → **被夹到 0.1**。

**即「2 秒无敌帧，闪避所有攻击」实际是 90% 减伤，仍然会掉血。** 描述与行为不符。

**建议**：引入独立的 `invulnerable` 判定（在扣血前短路 `return`，不参与乘数计算），而不是靠 `mult = 0`。需产品确认"无敌"是字面意义还是 90% 减伤即可（见 §4.3）。

### 2.3 士气系统完全不存在 ⚠️ 阻塞 `morale_rally`

**问题**：`BattleScene.ts` 全文"士气 / morale"仅 2 处出现（import 语句与其定义），**没有任何消费点**。

**即 `morale_rally` 不是"接一个函数就行"，而是需要新建一整套机制**：士气值字段 → 士气如何变化 → 士气影响什么。这是本任务中工作量最大的一项，见 §3.3 与 §4.1。

**验收标准：**

- **下一击伤害 ×3.0 ±5%，且只能触发一次**（触发后标记立即清除）
- 8s 内未攻击则标记失效，不残留
- 3CP 与 240s 冷却正确扣除

## 5. 层 2 playtest 验证清单（独立可用）

> **本清单不依赖本次 3D 化的任何文档。** 每项都是"怎么证明它真的生效了，而不是又一次看起来实现了"。

### 5.0 通用前置验收（适用于全部 9 项）

- [ ] **每个修复都必须有一个"开 / 关对比"测试**：同一战斗场景、同一随机种子，开命令与不开命令，对比目标量。只测"开了之后有变化"不算通过——必须测得**变化量符合数值预期**
- [ ] **每个修复都必须能被 UI 读到**：活跃效果条显示该命令的剩余时间；受影响的舰队有明显视觉标识。**看不到就等于没修**
- [ ] **每个修复都必须在战斗日志中有条目**
- [ ] **不得出现"数值改了但行为没变"**：例如 `getSpeedMultiplier` 接入了但交战分支没接（§3.2 的坑）

### 5.1 `shield` 类（4 项）

- [ ] `emergency_repair`：旗舰受伤 ×0.5，持续 5.0s ±0.2s（待 §4.2 决策后调整）
- [ ] `evasive_maneuver`：按 §4.3 决策结果验收；两种情况都需验证"命令描述已修正为与实际一致"
- [ ] `kirscheis_guardian`：伤害转移生效（注意这是新机制，不是 shield）
- [ ] `bucock_bastion`：受伤 ×0.5，持续 30.0s ±0.5s；其余两项按 §4.4 决策
- [ ] **专项**：同时叠加多个 shield 时，减伤是否为乘法叠加（当前 `getDamageMultiplier` 是连乘），是否会出现负减伤
