## 1. 输入映射总表

### 1.1 与 2D 现有键位的冲突核查

设计前先核对 `BattleScene.ts` 已占用的输入，避免撞键：

| 现有输入 | 2D 用途 | 代码位置 | 冲突处理 |
|----------|---------|----------|----------|
| 左键拖拽 | 平移相机 | `BattleScene.ts:225` | **改用途**：左键拖拽改为框选（若实现）或保留平移；见 §1.3 |
| 滚轮 | 缩放（clamp 0.2–2.5） | `BattleScene.ts:231` | 保留 |
| `Space` | 开关命令面板（同时暂停） | `BattleScene.ts:1969` | 保留 |
| `1`–`5` | 阵型切换（**暂停时禁用**） | `BattleScene.ts:266` | **关键**：命令目标选择态（处于暂停）下 `1`–`9` 完全空闲 → 复用为目标编号快选 |
| `T` | 部署阶段切指令卡；UI 上标为主炮快捷键 | `BattleScene.ts:251` | 顶视切换改用 `V`，避开 `T` |
| 右键点击 | 投放战术信标 `deployFlare` | `BattleScene.ts:1885` | 与"右键拖拽 = 轨道旋转"按**位移阈值**区分，见 §1.4 |

### 1.2 相机操作映射（推荐方案）

| 操作 | 输入 | 备注 |
|------|------|------|
| **轨道旋转（Orbit）** | **中键拖拽**（主）<br>**右键拖拽**（备，见 §1.4） | 水平位移 → 方位角 `yaw`；垂直位移 → 仰角 `pitch` |
| **平移（Pan）** | **中键 + `Shift` 拖拽** 或 **`W`/`A`/`S`/`D`** 或 **方向键** | 键盘平移是晕动症敏感用户与精确操作的首选 |
| **缩放（Dolly）** | **滚轮** | 朝光标方向推进（光标下的世界点保持不动） |
| **复位（Reset）** | **`Home`** | 回到默认俯角 + 玩家舰队居中 + 默认距离 |
| **聚焦（Focus）** | **`F`** | 相机**平移**到选中编队，不改变角度与距离 |
| **跟随（Follow）** | **`F` 双击** 或 **`Ctrl+F`** | 锁定跟随选中编队；再按一次解除 |
| **顶视切换（Top-down）** | **`V`**（按住 = 临时，单击 = 切换） | **一键切到正俯视 90°**，等价于 2D 可读性。这是大量可读性风险的兜底出口 |
| **全局档切换** | **`G`**（再次按下退出） | 一键在「默认档 / 全局档」间切换。**完整规格见 `09-dual-zoom-modes.md`** |
| **精调慢速** | 按住 **`Shift`** | 相机速度 ×0.35 |
| **禁止** | — | 相机中心点不允许移出【棋盘 AABB 外扩 20%】的范围 |

> 为什么 Orbit 用中键而非右键：右键在 2D 中已被"投放战术信标"占用且是**战斗中高频操作**（视野/情报玩法）。把轨道旋转放中键可彻底避免冲突，代价是需要玩家适应——这个代价小于让"放信标"变成需要精确拖拽阈值判定的操作。右键拖拽旋转作为备选保留，用阈值与点击区分。

### 1.3 选择操作映射

| 操作 | 输入 | 行为 |
|------|------|------|
| **选择舰队** | 左键单击任意舰船 / 其接地投影 / 其编队标记 | 选中该舰船**所属舰队**（8 艘整体） |
| **选择单舰** | **`Alt` + 左键单击** | 选中单舰（仅用于查看信息，无对应指令） |
| **追加/取消** | **`Shift` + 左键** / **`Ctrl` + 左键** | 若实现多选（P2）：追加 / 切换 |
| **框选** | 左键拖拽（位移 > 8px 才进入框选，避免误触） | 屏幕空间 AABB，命中所有**投影中心**落在框内的舰队。**MVP 不实现，见 §4** |
| **取消选择** | **`Esc`** 或 左键点击空域 | 清空选择 |
| **循环候选** | **`Tab`** / **`Shift+Tab`** | 在可见敌方舰队间按距离升序循环；`Enter` 确认 |
| **悬停查询** | 鼠标悬停 120ms | 显示 D 层 tooltip（阵营/舰种/HP/状态/阵型），不改变选择 |

**关键设计决策：编队级选择优先于单体选择。**

理由不是"方便"，是**规则驱动**的：

- `commandAbilities.ts` 中全部 4 个 `requiresTarget` 命令的 `targetType` 均为 `enemy_fleet`，最小作用单位就是舰队。
- 战斗规则零改动 = 不存在作用于单舰的玩家指令。单舰选择没有任何对应动词。
- 因此：左键单击 = 选舰队；单舰选择降级为 `Alt+点击` 的**纯信息查询**能力。

### 1.4 右键双击用途的阈值区分

右键同时承担"轨道旋转"与"投放战术信标"。判定规则：

| 判定 | 条件 | 行为 |
|------|------|------|
| 右键**点击** | 按下时长 < 200ms **且** 累计位移 < 5px | 投放战术信标（原 2D 行为） |
| 右键**拖拽** | 累计位移 ≥ 5px 或 时长 ≥ 200ms | 进入轨道旋转；松开时不投放信标 |

`[PLACEHOLDER · 附验证路径]`：200ms / 5px 需 playtest 校准。验证路径 = 让测试者在战斗中连续 20 次"放信标"与 20 次"转视角"，统计误判率，目标 < 5%。

## 2. 相机参数建议

### 2.1 角度限制

Three.js 惯例：`polarAngle` 从 +Y 轴起算。为便于讨论，下表同时给出"视线高于水平面的仰角"。

| 参数 | 美术规格值 | **UX 复核建议** | 理由 |
|------|-----------|----------------|------|
| 默认 `polarAngle` | — | **0.25π（仰角 45°）** | 兼顾立体感与遮挡可控 |
| `maxPolarAngle`（最低仰角） | ~~Basic `0.45π`~~ / ~~Standard `0.40π`~~ / ~~Comprehensive `0.35π`~~<br>**R1 修订：三档统一 `0.35π`** | **三档统一为 `0.35π`（仰角 27°）** ✅ **美术 R1 已采纳** | ① 仰角 9° 时画面下缘有效仰角为 **−16°**，相机看向棋盘平面**以下**，直接违反用户决策「禁止看底部」；② 前排遮挡纵深在下缘达 150px（旗舰 649px）。详见 `05` R-01 |
| `minPolarAngle`（最高仰角） | — | **0.08π（仰角 75.6°）** | 再高就与 `V` 顶视重合，无需连续可调 |
| `V` 顶视 | — | **polar = 0（仰角 90°）** | 2D 等价可读性出口 |

### 2.2 运动速度与阻尼（晕动症相关）

| 参数 | Basic | Standard | Comprehensive | 说明 |
|------|:-----:|:--------:|:-------------:|------|
| 方位角速度上限 | 120 °/s | **90 °/s** | 60 °/s | `[PLACEHOLDER]` |
| 仰角速度上限 | 60 °/s | **45 °/s** | 30 °/s | `[PLACEHOLDER]` |
| 平移速度上限（屏幕空间） | 1800 px/s | **1200 px/s** | 800 px/s | 按屏幕像素而非世界单位定义，保证不同缩放下手感一致 |
| 缩放速度 | 1.2 档/s | **0.8 档/s** | 瞬时 | 缩放走离散档位而非连续值，见 §2.3 |
| 相机阻尼 `k`（指数，1/s） | 5.0 | **7.7** | 13.4 | 见下方换算 |
| 自动镜头运动 | 关 | **关** | 关 | 全部可独立关闭 |
| 事件触发抖动 | 关（见 Q6） | 关 | 关 | |

**阻尼换算（重要，涉及与美术规格的一致性）**

美术 `accessibility.md` §5 给出的"相机旋转阻尼 0.08 / 0.12 / 0.20"是**逐帧 lerp 系数**，在低帧率下行为不一致（30fps 时实际阻尼只有 60fps 的一半）。建议改为**帧率无关指数阻尼**：

```
value += (target - value) * (1 - exp(-k * dt))
```

换算表（@60fps）：

| 逐帧 lerp | 等效 `k` (1/s) | 30fps 下的等效 lerp |
|:---------:|:--------------:|:-------------------:|
| 0.08 | **5.0** | 0.154 |
| 0.12 | **7.7** | 0.226 |
| 0.20 | **13.4** | 0.361 |

即：维持美术给定的三档手感，直接采用 `k = 5.0 / 7.7 / 13.4`。

### 2.3 缩放：走离散档位

连续缩放在 3D 下会让玩家"卡在两个都不舒服的中间态"，且加剧相机漂移感。建议：

- **`dMin` = 8 世界单位**（美术 `ship-assets.md §3.4` 约束 C2，底面免建模的硬前提）。R0 版写的 `dMin = hexRadius × 2.5` 作废：按 1 单位 ≈ 15px，`hexRadius` 26px 时该式给出 4.3 单位 **< C2 的 8 单位**，会在小规模战斗（1v1）中击穿底面免建模约束。**直接取常量 8，不再用 `hexRadius` 表达。**
  - UX 侧确认：**C2 不损害最近缩放体验**。d = 8 时可见宽度 13.3 单位（≈199 个 2D px），战列舰投影 333px（约屏幕高度的 31%），适合"贴近检视旗舰"，且是 `minDistance` 而非强制距离。
- **`dMax`（默认档）= 使棋盘 AABB 完整填满屏幕短边的距离** ≈ 100 单位，战列舰 25px。**不复刻 2D 的 `zoom = 0.2`** —— 2D 在该缩放下地图只占屏幕宽度 26%，战列舰缩到 6.6px，是遗留的屏幕空间浪费。按新定义，默认档下战列舰 ≈25px，仍 ≥ 24px 最小可点直径，**拾取问题在构造上被排除**。
- **全局档（Q7 已拍板双档）**：固定位姿，不参与连续缩放。`G` 一键切换，滚轮外滚到底自动进入、内滚自动退出。**完整规格见 `09-dual-zoom-modes.md`**，本表只覆盖默认档的连续缩放。
  - ✅ **Q2 雷达已拍板通过**，全局态势由雷达补偿，本条代价已消解。且 Q7 双档拍板后，全局档进一步提供"主动看全局"能力。
- 滚轮一次 = 一档，共 **8 档** `[PLACEHOLDER]`。
- 档位间用 400ms（Standard）过渡，`k = 7.7` 指数阻尼。
- 任意一档下，最远舰队的屏幕投影高度不得 < 24px（否则触发 L2/L3 聚合，见 `05` §4.2 的重定标阈值）。**全局档是唯一例外**——它强制进入 L2/L3 聚合模式，见 `09` §3。

## 3. 点击拾取（Picking）可用性规格

### 3.1 问题（R1 重定标）

R0 版写的是"最远舰船投影 3–8px"，**这个判据错了**。按 1 单位 ≈ 15px 与实际缩放范围重算（`05` §4.1），**战列舰的可达投影是 25px（全图档）～333px（最近档），全程 ≥ 24px 最小可点直径**——常规舰船不存在拾取困难。

**真正点不中的是舰载机**：Fighter 尺寸 0.4 单位 = 6 个 2D px，全图档投影 **4.6px**、标准交战档 **8.7px**，任何常规缩放下都远低于可点阈值。且它由航母持续释放、数量多。

因此本节的解法分为两条：
- **舰载机 → 归属母舰编队**（主解法，规则对齐，见下方 P4）
- **常规舰船 → 代理体 + 邻域搜索兜底**（防未来扩容/小窗口/极端档位）

### 3.2 解法：四层递进拾取

按以下顺序依次尝试，命中即停止：

```
第 1 层 — 精确射线拾取
  Raycaster 对舰船实际几何体求交。

第 2 层 — 拾取代理体（Pick Proxy）
  对每艘舰船挂一个不可见的代理球，半径：
      r_pick = max(r_body, 2 * MIN_PX * d * tan(fov/2) / viewportH_px)
  其中：
      r_body        = 舰船包围球半径（世界单位）
      MIN_PX        = 12 px   // 最小可点半径 [PLACEHOLDER]
      d             = 舰船到相机的距离
      fov           = 垂直视场角
      viewportH_px  = 视口像素高度
  例（fov=50°, H=1080, MIN_PX=12）：r_pick = max(r_body, 0.0104 * d)
  r_body 取包围球半径（战列舰 ≈1.15 单位、舰载机 ≈0.25 单位）：
    战列舰：d > 110 单位时代理体生效 —— 而 dMax ≈ 100 单位，
           即**常规舰船在可达范围内根本不需要代理体**（投影已 ≥24px）。
    舰载机：d > 24 单位即生效 —— 即**几乎整个可达范围都需要代理体**。
  → 这印证了 §3.1 的重定标：代理体机制实质上是给舰载机和小单位用的。
  → 代理球之间允许重叠；重叠时取"射线到球心距离最小"者。

第 3 层 — 屏幕空间近邻搜索
  在光标位置做半径 R_FALLBACK = 18 px [PLACEHOLDER] 的圆域搜索，
  取所有投影中心落在该圆内、且距光标最近的舰船。
  （这一层同时覆盖"点到了接地投影/编队标记但没点到舰体"的情况）

第 4 层 — 判定为空域点击
  不改变当前选择；若在命令目标选择态，保持选择态不取消（防误操作）。
```

### 3.3 拾取的三条硬性规则

| # | 规则 | 理由 |
|---|------|------|
| **P1** | **拾取忽略遮挡。** 被前排挡住的目标必须仍然可被点击（用第 2/3 层代理体，不做深度剔除） | 否则玩家无法对后排目标下达命令，这是 3D 引入的、2D 不存在的能力退化 |
| **P2** | **拾取结果永远是舰队，不是单舰**（`Alt+点击` 除外） | 与命令的 `targetType: 'enemy_fleet'` 对齐 |
| **P4** | **舰载机不参与单体拾取。** 命中舰载机（含其代理球/邻域）时，结果解析为**其母舰所属的舰队**；舰载机不进入 `Alt+点击` 的单舰选择候选集 | ① 规则层不存在作用于单机的玩家指令；② 2D 版本舰船本就完全不可选中；③ 舰载机投影 4.6–8.7px，任何代理体补偿都会在密集时产生歧义。这条把 R-14 从"补偿缺陷"变成"规则对齐" |
| **P3** | **不可交互对象不响应。** 友军 / fuzzy 目标 / 已灭舰队：无 hover 高亮、不进入拾取候选集 | 静默忽略会让玩家困惑，需要在 UI 上明示 |

### 3.4 拾取失败的补偿：`Tab` 循环器

当鼠标点不中（或玩家不愿用鼠标）时的等价路径：

- **`Tab`** 在**合法候选目标**间按"距玩家舰队距离升序"循环。
- 循环时：相机**自动平滑转向**使该目标进入视口（可关闭；Comprehensive 档位下改为不移动相机，仅在雷达上高亮）。
- 当前候选目标显示**编号徽章 + 靶心锁定环**。
- **`Enter`** 确认，**`Esc`** 取消。
- 这一步同时满足"仅使用键盘可完成一场战斗"的可访问性验收项。

## 4. 关于框选与多选的建议：MVP 不实现

**建议：MVP 只实现舰队级单选，不做框选与多选。**

| 判据 | 分析 |
|------|------|
| 是否有对应动词 | **无**。战斗规则零改动 = 不存在任何作用于多舰队的玩家指令。选中两支舰队后，玩家能做什么？没有答案 |
| 3D 实现成本 | 高。屏幕空间 AABB × 投影中心 × 深度排序 × 半透明叠加高亮，且框选结果在透视下难以预览（玩家不知道框住了什么，因为框外的船可能在框内船的后面） |
| 2D 是否已有 | **无**。2D 版本舰船完全不可选中。这是净新增能力，不是迁移 |

若用户坚持需要框选，降级方案（P2）：框选结果**仅作用于信息面板对比与相机聚焦**，不产生任何指令。

## 5. 输入响应规格

| 参数 | 值 | 说明 |
|------|:--:|------|
| 单击判定阈值 | 位移 < 8 px 且 时长 < 300 ms | 超过则视为拖拽，不触发选择 |
| 悬停 tooltip 延迟 | 120 ms | 低于 100ms 会在快速移动鼠标时闪烁 |
| 双击判定间隔 | 300 ms | 用于 `F` 双击跟随 |
| tooltip 消失延迟 | 0 ms（立即） | 移出即消失 |

## 6. 相机自动运动：默认全部关闭

3D 化后**新增**的自动镜头运动（2D 只有 `centerOn` / `setZoom`，本质是瞬移且无持续运动）必须遵守：

| 规则 | 内容 |
|------|------|
| R1 | 所有"事件触发的相机运动"（一骑讨名场面、击沉特写、命令执行推进）**默认关闭** |
| R2 | 若开启，任意玩家输入（`WASD` / 鼠标拖拽 / 滚轮 / 任意按键）**立即中断**当前运动 |
| R3 | 运动前后**完整保存并恢复**相机位姿（位置 + 朝向 + 距离），不得残留偏移 |
| R4 | 单次自动运动时长上限 **2.5 s** `[PLACEHOLDER]`，超时强制中断 |
| R5 | 设置项「自动镜头运动」三档：全部关闭 / 仅关键事件 / 全部开启。**默认"全部关闭"** |

**一骑讨（双方舰队距离 < 95px 触发）的专门建议（Q4）**：3D 下不再移动相机。改为「时间减速至 0.5x + 台词卡 + 双方旗舰双高亮 + 屏幕四角 L 形记号收拢」。理由：2D 俯视下相机移动不影响玩家的空间定向（全场都在屏幕内），3D 下相机被夺走 = 玩家丢失"我在看哪里"的心理模型，代价高出一个量级。
