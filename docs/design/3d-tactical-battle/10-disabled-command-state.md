## 2. 四种卡片状态（不是三种）

现有的 `.disabled`（CP 不足 / 冷却中）是**临时**不可用，与本文件的**永久**不可用必须视觉可区分，否则玩家分不清"等 42 秒"和"这个坏了"。

| 状态 | 数量 | 会恢复？ | 语义 | **现值数量（2026-09-15）** |
|------|------|:--------:|------|------|
| **可用** | 2 | — | 正常 | **6** |
| **部分生效** ⭐新增 | 1 | 版本更新后 | 能用，但效果比描述少 | **4** |
| **临时不可用** | 动态 | ✅ 会 | CP 不足 / 冷却中 | 动态 |
| **未实现（置灰）** ⭐新增 | 8 | ❌ 不会 | 效果尚未实现 | **1**（`reuenthal_blitz`） |

> **2026-09-15 复核**：四种状态的**模型本身仍然有效**（永久不可用 vs 临时不可用必须视觉可区分，这条设计判断不因计数变化而失效）；**仅数量列更新为现值**。

## 3. 视觉规格

### 3.1 未实现（置灰态）

| 属性 | 规格 | 理由 |
|------|------|------|
| **主要手段** | **`filter: grayscale(1)`（去色）** | **不用 opacity**。面板背景是 `rgba(10,20,40,0.95)` 的极暗底，`opacity: 0.4` 会把文字压到几乎不可读——而我们需要玩家**读得懂为什么不可用**（"不允许静默失败"原则）。去色保留亮度与可读性，只抽掉"可用"的色彩语义 |
| 背景 | `rgba(0, 0, 0, 0.35)`（比可用态的 `rgba(0,0,0,0.2)` 更暗） | 视觉退后，但不至于看不见 |
| **边框** | **`1px dashed rgba(148,163,184, 0.35)`**（**虚线**） | 虚线是"缺失 / 未完成"的通用语义，与可用态的实线边框形成明确区分。**这是灰度截图下也能分辨的关键** |
| 边框颜色 | 中性灰 `rgba(148,163,184,...)`，**不是阵营青也不是提督金** | 该卡片已失去阵营/专属语义，用中性色避免误导 |
| 文字 | `--color-text-disabled`，**但实测对比度须 ≥ 4.5:1**；不足则提级到 `--color-text-secondary` | 可访问性硬要求 |
| **角标** | 卡片右上角 `⚠ 未实现`，10px | 用 **⚠ 而非 ⊘**：⊘ 的语义是"你不能做"（责任在玩家），⚠ 是"这里有问题"（责任在游戏）。**玩家没做错任何事，不该收到禁止信号** |
| `cursor` | `not-allowed` | |
| hover | **不响应高亮**（与临时不可用一致） | |
| 提督专属卡的金色边框 | **一并去掉**（改用中性灰虚线） | 专属语义已失效 |

### 3.2 部分生效（`reinhard_roar`）

| 属性 | 规格 |
|------|------|
| 外观 | **保持与可用态完全一致**（实线边框、正常色彩、可 hover、可点击） |
| 描述区 | 末尾追加一行 `⚠ 部分生效：移速加成尚未实现`（11px，warning 色） |
| CP 消耗 | 正常显示 |
| 原因 | 保持可用的理由：**+50% 伤害是真实生效的，置灰等于剥夺一个能用的强力命令**。正确做法是可用 + 诚实标注 |

### 3.3 与临时不可用的区分（关键）

| 维度 | 临时不可用（CP不足/冷却） | **未实现** |
|------|--------------------------|-----------|
| 视觉 | `opacity: 0.4`（现有，保持不变） | 灰度 + 虚线边框 + ⚠ 角标 |
| 会恢复 | ✅ 会（显示倒计时） | ❌ 不会 |
| **点击反馈** | 红色抖动 200ms + **拒绝音** | **❌ 不抖动、❌ 不播拒绝音**；改为底部非模态提示条 |
| 原因文案 | `CP 不足` / `冷却 42s` | `效果尚未实现，将在后续版本开放` |

**为什么点击反馈必须不同**：临时不可用是"当前条件不满足"，用拒绝信号是合适的；未实现是**游戏没做完，玩家没做错任何事**——给玩家一个"你操作错了"的红色抖动加提示音，会让他们以为是自己按错了。**给玩家的操作错误信号与不给，必须用不同通道。**

## 4. 文案规格

| 位置 | 文案 |
|------|------|
| 卡片角标 | `⚠ 未实现` |
| 描述区下方一行 | `效果尚未实现 · 后续版本开放` |
| hover / focus tooltip | `「双璧的猛袭」的效果尚未实现，将在后续版本开放。你仍可查看它的效果说明与指挥点消耗。` |
| 点击后（底部提示条，非模态，2s 淡出） | `「双璧的猛袭」效果尚未实现，将在后续版本开放` |
| 面板顶部汇总行 | `⚠ 8 / 11 个命令的效果尚未实现，将在后续版本开放`（⚠️ **2026-09-15 复核：计数现值应为 `1 / 11`**；若保留半生效标注可写 `1 / 11 未实现 · 4 半生效`） |

**两条硬规则：**
1. **玩家可见文案中不得出现内部术语**（"层 2"、"效果层"、"handler"、"调用点" 一律禁止）。
2. **面板顶部必须有汇总行**。没有它，玩家会以为这 8 个灰卡是各自独立的 bug；有了它，玩家知道这是系统性的、已知的状态。

## 5. 是否显示 CP 消耗：显示

**结论：显示，但降为 disabled 色；不加删除线。**

| 判断 | 理由 |
|------|------|
| 为什么显示 | ① 让玩家建立"这个命令将来值多少 CP"的价值认知，层 2 上线后不陌生；② 隐藏后卡片信息残缺，与相邻卡片无法横向对比 |
| 为什么不加删除线 | 删除线的语义是"已取消 / 已作废"，而这里是"尚未开放"。语义不符 |
| tooltip 补充 | `这是该命令今后将消耗的指挥点数` |

## 6. 排序：保持原位，不移到末尾

**结论：8 个未实现命令保持在原有分组与顺序中，不集中移到末尾。**

| 判断 | 理由 |
|------|------|
| 为什么不移到末尾 | ① 现有分组是「通用命令 6 条 → 提督专属命令」，移到末尾会**破坏这个分组语义**；② 11 个里 8 个灰，移到末尾等于"整个面板后半截全是灰的"，视觉上比穿插更糟；③ 玩家肌肉记忆被打乱（⚠️ **2026-09-15 复核：「8 个灰」为旧值，现值仅 1 个置灰；但**保持原位**的结论仍然成立**） |
| 为什么保持原位 | 原位保留能让玩家看到**完整的命令系统全貌**——哪些存在、哪些将来会有什么，形成系统认知而不是一堆灰块 |
| 配套 | ① 面板顶部汇总行（§4）；② 设置项「隐藏未实现命令」（**默认关**），给想要干净界面的玩家 |

## 7. 状态优先级

一个命令可能同时满足多个不可用条件（例如 `formation_charge` 既未实现、又没有可见敌舰）。

**优先级：`未实现` > `无合法目标` > `冷却中` > `CP 不足`**

理由：**永久状态优先于临时状态**。玩家最需要知道的是"这个根本用不了"，而不是"它现在还差 2 个 CP"。

## 8. 可访问性

| 项 | 规格 |
|----|------|
| 非颜色冗余编码 | 三重：**虚线边框**（vs 实线）+ **⚠ 图标**（形状）+ **文字标签** |
| 灰度截图 | 虚线 vs 实线可辨；⚠ 形状可辨；文字标签直接可读 ✅ |
| 键盘 focus | **可 focus**（不是 `disabled` 属性，否则无法被读屏与键盘访问） |
| 屏幕阅读器 | 朗读：`「双璧的猛袭」，不可用，效果尚未实现，将在后续版本开放` |
| 对比度 | 卡片内文字 ≥ 4.5:1（`var(--color-text-disabled)` 需实测，不足则提级） |
| 与「隐藏未实现命令」设置的关系 | 隐藏后仍需在设置项旁显示计数 `已隐藏 8 个未实现命令`（⚠️ **2026-09-15 复核：计数现值 `已隐藏 1 个未实现命令`**） |
