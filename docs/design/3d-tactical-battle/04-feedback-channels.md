# 04 · 反馈通道诊断：玩家在 3D 中如何感知关键事件

---

## 0. 2D 现有反馈资产与 3D 重定义

| 2D 资产 | 代码位置 | 2D 实现 | 3D 重定义 | 理由 |
|---------|----------|---------|-----------|------|
| **伤害数字** | `spawnDamageNumber`<br>`BattleScene.ts:1563` | Phaser `Text`，11px 白 / 暴击 14px 金，上浮 40px / 900ms，`setDepth(45)` | **改为 DOM 投影层（D 层）** | 3D 中的文字精灵会被透视压扁、被 bloom 糊掉、被色差拆成红蓝重影。且 3D 精灵文字的清晰度随距离剧烈变化 |
| **敌人意图线** | `renderIntentLines`<br>`BattleScene.ts:1579` | 直线连接施动者与目标 + 末端红三角；**仅在命令面板打开（暂停）时绘制** | **改为贴地贝塞尔弧线**（W+ 层，`depthTest=false`） | 3D 空间直线会穿过舰体内部、多条线在屏幕上重叠成一团。贴地弧线贴合棋盘平面，空间关系明确 |
| **激光束** | — | 2D 屏幕空间细线段 | **3D 空间圆柱/带状几何 + 面向相机的 billboard 段** | 需处理：光束在近处过粗（遮挡目标）、远处过细（看不见）→ 宽度做**屏幕恒定补偿** |
| **命中表现** | — | 目标舰体短暂闪烁 | 保留 + 增加**命中点局部闪光**与**护盾涟漪**（美术已定规格） | 3D 下需要更明确的"打中了哪"的空间信息 |
| **命令执行** | `showCommandEffect`<br>`BattleScene.ts:1537` | 一个 `r=40, alpha=0.4` 的圆，600ms 缩放到 2 倍并淡出 | **废弃圆形闪光**，改为三态状态机（见 `03` §4） | 2D 的圆形闪光只能表达"发生了某事"，无法表达"对谁、什么效果、持续多久" |
| **HP 条** | `hpBarsGraphics`<br>`BattleScene.ts:1987` | 每帧 `clear()` + 重绘的 Graphics | **改为 W+ 层屏幕恒定尺寸条**（见 `01` §3） | 2D 的 HP 条随 zoom 缩放；3D 下必须反向补偿 |
| **伤害/被击中的方向感** | — | **2D 不存在**（全场在屏内） | **新增：屏幕边缘方向指示器** | 3D 下战斗可能发生在视野之外，玩家完全没有感知通道 |

## 1. 逐事件反馈通道设计

### 1.1 命中（我方击中敌方）

| 通道 | 设计 | 参数 |
|------|------|------|
| **视觉 · 世界** | ① 激光束（面向相机 billboard，宽度屏幕恒定 2.5px `[PLACEHOLDER]`）<br>② 命中点闪光（点光 + 短促爆点）<br>③ **护盾涟漪**（美术 `signature-effects.md` 已定椭圆 rx/ry/span）<br>④ 目标舰体闪烁 2 帧 | 光束存活 80ms `[PLACEHOLDER]`；涟漪 400ms |
| **视觉 · UI** | 伤害数字（D 层，DOM 投影） | 见 §2「伤害数字聚合规则」 |
| **音频** | 命中音（按武器类型分 3 种：主炮/副炮/舰载机） | 音量随同帧命中数衰减，避免叠加爆音 |
| **判定** | 玩家能否回答"我打中了谁、打了多少"？ | 是（伤害数字 + HP 条 delta 段 + 日志） |

**HP 条 delta 段**（新增，2D 无）：受伤时 HP 条上先显示一段**白色残影**（代表刚失去的量），200ms 内收缩消失。这让玩家即使错过伤害数字，也能从 HP 条读出损失量级。

---

### 1.2 被击中（我方被敌方命中）

**这是 3D 引入的最严重感知缺口。** 2D 俯视下整个战场在屏幕内，玩家不会"没看到"。3D 下相机只能覆盖战场的一部分（尤其 `hexRadius=50` 时），发生在视野外的战斗中，玩家完全没有反馈。

| 通道 | 设计 | 参数 |
|------|------|------|
| **视觉 · 世界** | 同 §1.1（激光/闪光/涟漪），仅在目标位于视口内时可见 | — |
| **视觉 · 屏幕边缘（★新增，关键）** | **屏幕边缘方向指示器**：玩家舰队任一单位受伤时，按伤害来源相对相机的**方位角**，在屏幕边缘对应位置显示一段弧形红光，弧长与伤害量成正比 | 持续 800ms，峰值不透明度 0.55 `[PLACEHOLDER]`；弧中心角 = `atan2` 换算的屏幕角度；若伤害来源在相机背后，指示器显示在**屏幕顶部**（代表"身后"） |
| **视觉 · UI** | ① 伤害数字：屏幕外来源的伤害**不在世界空间绘制**，改为**聚合到屏幕边缘指示器旁**（一个数字 + `×N`）<br>② 阵营卡片 HP 条下降（GameHeader 已有）<br>③ 战斗日志逐条记录（精确数值权威源） | — |
| **视觉 · 雷达（依赖 Q2）** | 雷达上对应位置闪红点 | 400ms |
| **音频** | 受击音（比命中音低沉，音色可区分） | 同时受击单位 ≥ 4 时合并为一次"齐射受击"音，避免爆音 |
| **判定** | 玩家能否回答"我的哪支舰队在挨打、从哪个方向"？ | 是（边缘指示器给方向，雷达给精确位置，日志给数值） |

### 1.4 命令执行

见 `03` §4「三态状态机」。此处只补充两点：

| 补充 | 内容 |
|------|------|
| **失败反馈** | 命令因 CP 不足 / 冷却中 / 无合法目标而失败时，必须有明确反馈：命令卡片**红色抖动 200ms** + 底部提示原因 + 拒绝音。**不允许静默失败** |
| **被命令作用的目标** | 敌方被施加 `debuff` 时，敌方玩家（AI）无感知需求，但**玩家必须看到 debuff 生效**——目标舰队身上的向下三角 ▼ 状态光环（见 `03` §4.2）+ 战斗日志 |

### 1.5 蓄力完成

2D 版本的蓄力表现需确认具体形式；3D 规格如下：

| 通道 | 设计 | 参数 |
|------|------|------|
| **视觉 · 世界** | ① **蓄力条**（W+ 层，屏幕恒定 24×4px，位于舰船上方，不随距离缩小）<br>② 蓄力中：舰体边缘光渐强 + 炮口聚光点<br>③ **完成瞬间**：环形冲击波（0.3s 扩张）+ 舰体过曝 1 帧 | 冲击波 300ms；过曝 1 帧（16ms） |
| **视觉 · UI** | 蓄力剩余时间仅在**选中/悬停**该舰队时于 D 层显示精确秒数；不选中时不显示（避免满屏进度条） | — |
| **音频** | 蓄力音（持续升调，音高与蓄力进度线性相关）+ 完成音（短促高音） | 同屏蓄力单位 ≥ 3 时只播放最近的一个，避免音高打架 |
| **判定** | 玩家能否在蓄力完成时立刻注意到？ | 是（冲击波 + 过曝是极强的瞬态信号，且不受后处理归零影响——冲击波用几何体而非 bloom） |

### 1.6 敌人意图

| 通道 | 设计 | 参数 |
|------|------|------|
| **视觉 · 世界（★重定义）** | **贴地贝塞尔弧线**：起点 = 施动者接地投影，终点 = 目标接地投影，末端箭头。**弧线不做几何抬升** —— R0 版写的"抬起至平面上方 8 单位"是单位换算错误（1 单位 ≈ 15px，8 单位 = 120px，弧线会浮到舰船上方）。正确做法：弧线用 `polygonOffset` 贴着棋盘平面绘制，靠 `depthTest = false` 保证不被棋盘吞掉；需要"浮起"的观感时由**亮度/辉光**表达，不由高度表达。`[PLACEHOLDER]` | 线宽屏幕恒定 1.5px；`depthTest=false`；常显态不透明度 0.25，暂停态 0.5 |
| **视觉 · 分级（★新增）** | 2D 是"暂停时全画"，3D 下 8v8 会画出几十条线 | **三档显示：**<br>① **暂停态**：全显（与 2D 一致）<br>② **实时态 · 默认**：**只画目标是玩家舰队的威胁线**（实线 + 向我方箭头）<br>③ **实时态 · 按住 `Alt`**：全显（含敌对 AI 互相之间的线，用虚线区分） |
| **视觉 · 非颜色编码（色盲）** | **不靠红/蓝区分**。用**线型 + 箭头方向**：<br>实线 + 箭头指向我方 = 威胁我方<br>虚线 + 双向箭头 = 敌方内部交战<br>末端 `?` 标记 = 目标情报不足（fuzzy） | — |
| **音频** | 无（意图是预测信息，不应产生持续音） | — |
| **UI** | 悬停某条意图线 → D 层 tooltip 显示 `第2舰队 → 你的第1舰队（预计 4.2s 后接触）` `[PLACEHOLDER：预计接触时间需新增计算，若规则层不支持则只显示距离]` | — |

## 2. 伤害数字聚合规则（认知过载红线）

### 2.1 问题

2D 版本的 `spawnDamageNumber` 是**每次命中无条件创建一个 Text**。在 8v8（64 艘）+ 3x 速度下，同屏同时存在的伤害数字可达数十个，直接淹没战场。2D 靠"数字小、上浮快、战场大"勉强扛住；3D 加上透视与后处理后，数字会在近处糊成一片白团。

### 2.2 规则

| 层级 | 规则 |
|------|------|
| **聚合窗口** | 同一舰队在 **500ms** `[PLACEHOLDER]` 内受到的伤害**累加为一个数字**显示，而非逐次弹出 |
| **显示优先级** | 完整伤害数字**仅**对以下目标显示：<br>① 玩家舰队（含友军）<br>② 当前选中 / 悬停的目标<br>③ 任意旗舰<br>其余目标：**不显示数字**，只用「HP 条 delta 段 + 舰体闪烁」表达 |
| **同屏上限** | 同屏伤害数字总数上限 **12 个** `[PLACEHOLDER]`。超限时，最旧的数字立即淡出 |
| **暴击区分** | 暴击（`isCrit`）**不能只靠金色**（色盲 + bloom 会吃掉金色）。必须同时改变**字形**：加粗 + 外描边 + 字号 14→16px + 前缀 `!` |
| **精确数值** | 战斗日志是**唯一权威数值源**。世界空间的数字允许聚合与省略，日志不允许 |
| **屏幕外** | 玩家舰队被屏幕外敌人击中 → 伤害数字**不在世界空间绘制**，聚合到**屏幕边缘指示器**旁，显示为 `-142 ×3` |

### 2.3 层数与后处理

伤害数字走 **D 层（DOM）**，因此：

- 不受 bloom / 色差 / 扫描线影响，永远清晰可读
- 字号受「UI 文字缩放」设置控制（1.0x / 1.25x / 1.5x）
- 不受透视缩放，字号恒定

## 3. 反馈通道完备性自检表

每个事件必须在**至少两个通道**上有表达（视觉世界 / 视觉 UI / 音频），且至少一个通道在「特效强度 = 0%」时仍有效。

| 事件 | 视觉·世界 | 视觉·UI | 音频 | 特效归零后仍可用？ |
|------|:---:|:---:|:---:|------|
| 命中 | ✅ 光束/闪光/涟漪 | ✅ 伤害数字 + HP delta | ✅ | ✅ HP delta 段 + 日志 + 数字 |
| 被击中 | ✅（视口内时） | ✅ **边缘指示器** + 雷达 + 日志 | ✅ | ✅ 边缘指示器（纯几何，非 bloom） + 日志 |
| 舰船损失 | ✅ 爆炸 | ✅ 日志 + 舰数 -1 + 阵营卡 | ✅ | ✅ 日志 + 舰数数字 |
| 命令执行 | ✅ 状态光环 + 命令弧线 | ✅ 活跃效果条 + 日志 + CP 条 | ✅ | ✅ 活跃效果条（纯 DOM） + 日志 |
| 蓄力完成 | ✅ 冲击波 + 过曝 | ✅（选中时）秒数 | ✅ 升调音 | ✅ 升调音 + 选中时的秒数 |
| 敌人意图 | ✅ 贴地弧线 | ✅ 悬停 tooltip | ❌ | ✅ 弧线是几何体，不依赖后处理 |

**结论：所有事件在特效归零后仍有至少一个可用通道。** 这是 `06` 的验收硬要求。
