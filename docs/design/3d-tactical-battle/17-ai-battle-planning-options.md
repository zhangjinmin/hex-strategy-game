## 0. 结论摘要（主理人直读）

### 0.1 四条判断

| # | 判断 | 依据 |
|:--:|------|------|
| **1** | **不建议做"学习型 / 真正的 AI"**（神经网络、强化学习）。理由：① 单机战术层训练样本不足；② **不可解释**——玩家读到"AI 变强"却不知为何，会把"AI 笨"改判成"AI 作弊"；③ 迭代成本与"每轮真机反馈都要改"的节奏冲突 | §2.3 可解释性风险 · `15` §2.4「失败可归因」缺口 |
| **2** | **"显得笨"的主因不是"没有规划"，而是三件更基础的事**：(a) **战略层只跑 `fleets[0]`**；(b) **没有目标分配**；(c) **所有阈值都是瞬时量** | §1.2 关键发现 F1/F2/F3 · 锚 `const fleet = fleets[0];`（`:504`）/ `alliesOnTarget`（`:3743-3751`）/ `calculateFleetPower`（`:3209`） |
| **3** | **战前规划层（B）值得做，但它最大的收益是"可读性"，不是"棋力"**。而**基础设施已经存在**：`Mission` 五类原语 + `executeMissionTick` 执行器 + `_missionDest` 牵引 + `deployPhase` 暂停窗口，全是现成的（`TacticalCommandSystem.ts:69-109`、`executeMissionTick` `:2011`、`_missionDest` 牵引 `:4095`、`activateDeployPhase` `:719-748`） | §2.2 接入点表 |
| **4** | **必须先修 F1**（战略层从 `fleets[0]` 扩到全部舰队）——**它是 B 与 C 共同的地基**，且单独修 F1 的性价比高于任何新层 | 锚 `const fleet = fleets[0];`（`:504`） |

### 0.2 推荐与 MVP

**推荐：D（B → C 分期），先做 B。**

**MVP（B-0，约 2 人日）**：① 修 F1（锚 `const fleet = fleets[0];` `:504`）② 新增 `planFactionBattle()`，按 `role` 为每支 AI 舰队写一个既有 `Mission`（**不新增任务类型**）③ `fleetIntentText`（`TacticalCommandSystem.ts:129-144`）显示 `role`。
**验收判据**：开战 10 秒截图——AI 各舰队 `_missionDest` 互不相同、每支头顶有 `role + mission` 文本、同种子两次运行计划一致、`tsc` EXIT=0、战斗数值路径 hunk 为空。

**先 B 还是先 C：先 B。** 除 §3.1 的理由外还有一条工程理由——**C 的一切改动都要挂在"某支舰队想干什么"之上**；没有 `role`，C 得先自己解决"我是谁、我该干什么"，等于把 B 重做一遍（详见 §3.3）。

### 2.1 方案 A · 维持反应式 + 补齐短板

**类型：规则**（不新增架构层）

**机制草图**：

| 项 | 内容 |
|----|------|
| A1 | **战略层覆盖全部舰队**：锚 `const fleet = fleets[0];`（`:504`）改为 `for (const fleet of fleets)`，并按舰队"角色"分派 `stance`（角色来源见 A2） |
| A2 | **目标占用表**：复用 `claimedTargets`（`:4037-4055`）的思路，为舰队目标（而非仅地块）建同阵营占用表，避免撞车；`_lastTargetFleetId`（写入 `:3770`，已存在）作为占用记录 |
| A3 | **阶段化行为**：把 `battleStage`（判定 `:2341-2345`）从"播报"升级为"AI 行为开关"——阶段 1 不深入敌方半场、阶段 3 全军压上 |
| A4 | **撤退/驻留调参**：驻留退出阈值 `regroupDone = currentSupply > 80`（`:3894`）的 80、`_avoidUntil`（`:585-587`）的 3 秒 |

**接入点**：`const fleet = fleets[0];` `:504`（A1/A2 的主战场）· `:3720-3751`（A2）· `:2298` / `:2341-2345`（A3）· `:3894` / `:585-587`（A4）

**开发量级**：**2–4 人日**（A1 半天 + A2 1 天 + A3 1 天 + A4 半天）

**风险**：平衡低（改的是缺陷）；性能无；可解释性低（改的是坏行为，玩家只会觉得"不那么怪了"）

**"聪明感"改善预估**：**低**。玩家感觉"AI 不那么坏了"，但**不会觉得它变聪明了**——因为没有产生新信息（头顶还是一片沉默）。

**真机验证方式**：逐现象前后对照（R10-A1 同款：同场景跑修复前后两版，断言 `_missionDest` 不重叠 / `stance` 分布变化）。

**判定**：**应当做，但它是 B 的前置，不是 B 的替代。** 单做 A，AI 从"有 4 个坏行为"变成"没有明显坏行为"，而**用户原话的诉求（"开战前先规划再进场"）不会被满足**。

### 2.2 方案 B · 战前规划层（轻量）★用户设想的方案

**类型：规划**

#### ① 机制草图

| 步 | 内容 |
|:--:|------|
| **1** | **开战前生成计划**：复用 `deployPhase` 暂停窗口（`activateDeployPhase` `:719-748`），为每个 AI 阵营跑一次 `planFactionBattle(fac)`。**输入**：己方舰队清单（位置/兵力/补给/统帅）、敌方可见舰队、地块图（`planet`/`relay`/`castle`）、`castlePos`、难度、`personalityType`。**输出**：每支舰队一份 `BattlePlan { role, missions[], phaseGoals[], retreatCondition }` |
| **2** | **角色定义**（沿用 `15` §1.4 术语）：`main_force`（主攻）/ `flank`（侧翼）/ `reserve`（预备）/ `screening`（掩护·断链） |
| **3** | **计划 → 执行**：把 `role` 翻译成**既有的** `Mission`（**原样复用 5 类，不新增类型**），写 `fleet.mission`。执行完全走现成通路：`executeMissionTick`（`:2011`）→ `stance` + `_missionDest` → 每帧牵引（`:4095`） |
| **4** | **阶段目标**：`plan.phaseGoals[stage]` 在 `battleStage` 推进时（`:2341-2345`）**切换 `mission`**——**这是把"播报"变成"行为"的关键**（直接治 P7） |
| **5** | **重规划（事件驱动，低频）**：仅 **3 个**触发条件——① 主攻舰队/旗舰被歼 ② 己方兵力比跌破阈值 ③ 敌主攻轴被我方识别（按 `_lastTargetFleetId` 聚类）。**明确不做每帧重算**——否则等于退回反应式 |
| **6** | **撤退条件进计划**：显式写出（如"损失 > 40% 且未达成阶段目标 → `retreat_supply`"），替代现在纯瞬时的 `powerRatio` 判断（`canEngage` `:3762-3766`） |

#### ② 接入点（file:line，全部为现值 · 附内容锚点）

| 落点 | 现值 | 用法 |
|------|------|------|
| **战前暂停窗口** | `activateDeployPhase`（`:719-748`） | 追加 `this.planFactionBattle(aiFac)`（放在 `updateDeployText` `:773` 那批 `_deployTactic` 之后） |
| 开战瞬间（备选落点） | `startBattleAfterDeploy`（`:777-795`） | 在 `:787-789` 的阵营循环内一并生成计划 |
| 计划数据 | 挂在 `fac._battlePlan` / `fleet.planRole`（新增字段，与 `_deployTactic` 写入点 `:773`/`:787-789` 同层） | 不新建模块 |
| **计划执行器** | `executeMissionTick`（`:2011`） | **原样复用，不改** |
| 计划 → 目的地 | `_missionDest` 牵引（`:4095`） | **原样复用** |
| **计划原语** | `TacticalCommandSystem.ts:69-109`（`MissionType` / `buildMission`） | **原样复用，不新增类型** |
| 阶段推进 | `battleStage` 判定（`:2341-2345`） | 追加：阶段变化时切 `plan.phaseGoals[stage]` |
| 意图显示 | `TacticalCommandSystem.ts:129-144`（`fleetIntentText`） | 追加 `role` 前缀（如「侧翼 · 攻击 X」）；**脱敏口径见下方"落地现状"** |
| 战略层读计划 | 战略评估块（`:539-589`） | 计划存在时**跳过**独立评估——与 `:506-508` 现存的 mission 优先级同款 |

> **关键**：B **不是新架构**，而是在现成的"计划原语 + 执行器 + 暂停窗口"上加一个**计划生成器**。这是 B 成本低、风险小的根本原因。

> **落地现状（`#71` 回填 · 2026-09-16）**：本表 B-0 的"意图显示"与"前置修复 F1"**均已随 V18-A 落地**（`#57`，独立验证 `#59`）：
> - **F1**：战略层 `:504` 已从 `const fleet = fleets[0];` 改为 `for (const fleet of fleets)`。**注**：V18-B（`#58`）进一步把过滤扩含 player（D1=α），并把 `executeMissionTick` 解算从战役闸下解放（轨无关）——详见 `18` §2.1 / §2.4。
> - **`role` 前缀**：`fleetIntentText` 已显示 `[突击]/[夺取]/[坚守]/[协同]/[补给]`（`PLAN_ROLE_LABEL`，`TacticalCommandSystem.ts:54-61`）。
> - **F-2 脱敏（信息面 · 已落地 `#60`）**：`fleetIntentText` 增 `opts:{team}`（TCS `:156-157`）——**敌方（`team!==1`）浮标剥 `mission.text` 具体目标、仅留 `role` 粗意图 + 观察层文本；己方（`team===1`，含僚舰）保留全文**；调用侧 `Battle3DOverlay.ts:3941` 传 `{ team }`。**与本文 P11 的关系见 §1.1「P11 留痕」。**

#### ③ 开发量级（人日，粗估）

**4–6 人日** = F1 修复 1 + 计划生成器 2–3（约 150–250 行）+ 阶段目标接线 1 + `role` 显示 0.5。**不含** UI 改动。

#### ④ 风险

| 类 | 评级 | 说明 |
|----|:----:|------|
| **平衡** | 低–中 | 计划会**放大 AI 强弱**（有计划的强阵营更强）→ **必须按难度分档**（easy 计划粗 / hard 计划细），否则"变聪明"直接变"变难" |
| **性能** | 低 | 每次开战 1 次 O(F×T)，F≤8、T≈数百格 → 可忽略。**红线：重规划必须事件驱动，不得每帧** |
| **可解释性** | **最低** | 计划能显示在舰队头顶 —— **这是 B 相对 C 的决定性优势** |

#### ⑤ "聪明感"改善预估

**中**。**主要不是"AI 更会打了"，而是"我能看出它想打什么"**。这不是偷换概念——用户说的"过于愚笨 / 不够智能"里，**"看不出意图"会被直接读成"没想法"**（P11）。B 用最低成本提供了"意图"这个新信息通道。

#### ⑥ 真机验证方式

1. **多舰队目标不重叠**：开局 10 秒截图，断言 AI 各舰队 `_missionDest` / `_lastTargetFleetId` **互不相同**。
2. **头顶计划文本**：截图可见每支 AI 舰队头顶是 `role + mission`（而非 6 种通用文本）。
3. **阶段推进改变行为**：进入 `battleStage=3`（`:2344-2345`）前后各截 10 秒，`stance` 分布应有可见变化（如 `siege` 占比上升）。
4. **可复现性**：同种子同地图跑两次，**计划必须一致**（⇒ 计划生成中**不允许 `Math.random()`**）。

### 2.3 方案 C · 战中决策升级（效用评估）

**类型：效用**

#### ① 机制草图

| 步 | 内容 |
|:--:|------|
| **1** | **阈值 → 效用**：`U(action \| state) = Σ wᵢ·fᵢ`。候选动作 = {保持距离, 侧翼, 撤退, 攻坚, 集火}；评估项 = {预期伤害, 承受伤害, 位置价值, 补给风险, 盟友支持, 目标价值} |
| **2** | **浅前推（depth 1–2）**：不做完整博弈树，只做"我动 → 对手最可能反应 → 我的收益"一层 |
| **3** | **战力模型扩展**：`calculateFleetPower`（`:3209`）现仅 `Σ hp×(1+dps×0.1)`，**须补入**补给、士气、阵型、位置、援军 |
| **4** | **目标价值重定义**：从"距离 + 残血"（`score` `:3729`）改为"期望伤害产出"（治 P9） |
| **5** | **去随机化**：`flankAngle`（`:3947`）的 `Math.random()` 改为按敌朝向与地形确定性选择（治 P8） |

#### ② 接入点（file:line）

`:3720-3800`（目标选择 `:3729` + `canEngage` `:3762-3766` + 阵型决策）· `:3947`（`flankAngle` 包抄）/ `:3988-3997`（侧翼落点）· `calculateFleetPower` `:3209`（战力模型）· `:4130-4135`（恐慌响应随机扰动，锚 `dodgeAngle` `:4132`）· `:3947`（`Math.random()` 包抄）

#### ③ 开发量级

**5–8 人日** = 战力模型扩展 1–2 + 效用化目标选择 2–3 + 效用化距离保持 1–2 + 决策日志 1。

#### ④ 风险

| 类 | 评级 | 说明 |
|----|:----:|------|
| **平衡** | **高** | 效用权重每次调整即改平衡，且**难预判**。需敏感性台架——`15` §4 已对同类问题（阵型数值接入）警告过"防圆阵主导策略" |
| **性能** | 低–中 | 每帧全量打分需缓存（建议 0.5s 重算一次，而非每帧） |
| **可解释性** | **高** | 效用分是黑箱 → **直接撞上 `15` §2.4 已登记的"失败不可归因"缺口**。玩家看到 AI 变强却说不出原因，会把"AI 笨"改判为"**AI 作弊**"——**这是 C 最大的单点风险** |
| **与 FIX-3 的交集** | — | C 若预测侧翼/接敌时序，会依赖"朝向瞬变"。`v16_01` U5 已明确登记：接敌时序读敌朝向、且用 `facingAngle` 算角差 → **FIX-3（#49）落地后 C 的预测模型须重新校准**（锚点：`facingAngle`，行号见 `v16_01` 快照，FIX-3 在途故不锁死） |

#### ⑤ "聪明感"改善预估

**高**（但受 ④ 的可解释性风险制约）。

#### ⑥ 真机验证方式

A/B 对局（同地图同编成，效用版 vs 现值）**≥ 20 局**胜率对比 + **决策日志回放**（人工读"这一步它为什么这么选"）+ **敏感性台架**（权重扰动下行为不崩）。

### 2.4 方案 D · B+C 分期组合

**类型：规划 + 效用**

**机制草图**：B 先落地（含 F1）→ 跑 1–2 轮真机反馈 → 再在**计划框架内**做 C：效用函数**只用于"计划内的选择"**（如"侧翼从哪一侧切""这一步是打还是走"），**不替换计划本身**。

**为什么这么分**：B 提供"骨架 + 可读性"，C 提供"骨架内的智慧"。**若先做 C**，会在"多舰队没有舰队级战略"（F1）的地基上堆效用函数 → 效用再准，也只是"每支舰队各自聪明"，**协同问题（P4/P10）原样保留**。

**接入点**：B 全部落点（§2.2 ②）+ C 全部落点（§2.3 ②）

**开发量级**：**10–14 人日**（分两期，可分别验收）

**风险**：中——两期独立验收，风险被摊平；且 B 期已建立"可读性"通道，C 期可以**用同一通道输出决策理由**，把 C 的可解释性风险**降一档**。

**"聪明感"改善预估**：**高**。

**真机验证**：按 §2.2 ⑥ / §2.3 ⑥ 分别验证 + 一期结束时的整体对局观感。

## 3. 回答"要不要"

### 3.1 明确推荐

> **要 —— 推荐 D（先 B 后 C，MVP ＝ B-0）；并明确不做学习型 AI。**

**四条理由**：

| # | 理由 |
|:--:|------|
| **1** | **用户要的是"可感知的规划"，不是"算法先进"。** 原话重点是"**战场初期由 AI 做好规划，然后进入战场**"——这是**叙事 / 可读性诉求**，**B 精确命中，C 不命中** |
| **2** | **B 的性价比最高，且地基已存在。** `Mission` 五类 + `executeMissionTick` + `_missionDest` + `deployPhase` 全是现成的 ⇒ B 是"**接线 + 生成器**"，不是"新架构" |
| **3** | **C 单独做有可解释性反噬。** `15` §2.4 已登记"失败不可归因"是深度瓶颈之一；一个**不可解释的强 AI** 会把玩家的归因从"AI 笨"推向"**AI 作弊**" |
| **4** | **F1 是必须先修的地基**（不论 B 还是 C）。**只修 F1 就能改善"多舰队各打各的"**——性价比高于任何新层 |

### 3.2 MVP 定义（B-0）

| 项 | 内容 |
|----|------|
| **范围** | ① 修 **F1**（`const fleet = fleets[0];` `:504`）→ 战略层覆盖全部舰队 ② 新增 `planFactionBattle()`，按 `role` 为每支 AI 舰队写**既有 `Mission`** ③ `fleetIntentText`（`TacticalCommandSystem.ts:129-144`）显示 `role` |
| **不做** | 阶段目标切换（B-1）· 事件重规划（B-2）· 计划 UI · 难度分档 |
| **验收判据** | ① 开战 10 秒截图：**所有** AI 舰队 `_missionDest` 互不相同 ② 每支 AI 舰队头顶有 `role + mission` 文本 ③ **同种子两次运行计划一致** ④ `tsc` EXIT=0 ⑤ **战斗数值路径未被触碰**（伤害/速度/士气 hunk 为空） |
| **预计** | **2 人日** |
| **失败退路** | 若"头顶计划文本"观感**无改善** → **停止 B-1，转 C**（说明可读性不是用户的痛点所在） |

### 3.3 分期路线

| 期 | 内容 | 依赖 | 人日 |
|:--:|------|:----:|:----:|
| **B-0** | **F1 修复 + 计划生成器 + `role` 显示（MVP）** | 无 | 2 |
| B-1 | 阶段目标（`battleStage` 播报 → 行为）+ 撤退条件进计划 | B-0 | 2–3 |
| B-2 | 事件驱动重规划（3 个触发条件） | B-1 | 1–2 |
| C-1 | `calculateFleetPower` 扩展（补补给/士气/阵型/位置/援军） | B-0 | 1–2 |
| C-2 | 效用化「目标选择 + 距离保持」+ 决策日志 | C-1 | 3–4 |
| C-3 | 浅前推（depth 1–2）+ 敏感性台架 | C-2 | 2–3 |

**先 B 还是先 C：先 B。** 除 §3.1 外，还有一条**工程理由**：

> **C 的一切改动都要挂在"某支舰队想干什么"之上。** `role` 一旦存在，C 的效用函数就有了**边界条件**（"掩护舰不要贪伤害"、"预备队不该追残血"）；否则 C 得**先自己解决"我是谁、我该干什么"**——等于把 B 重做一遍，且做得更贵。

### 3.4 与在途议题的衔接（不冲突）

|----------|---------------|----------|

| **BW-02 幽灵信标回滚 → move 命令 → 三按钮文案**（后续队列） | B 的计划写 `fleet.mission`；玩家 move/信标写 `targetFlare`/`stance`。**两条通道目前不互斥**（`:3706` 信标条件优先级高于一切） | **登记为接口项**：B 落地时明确"计划 vs 信标"优先级（建议同 Q1：玩家显式命令优先） |
