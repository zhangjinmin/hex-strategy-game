# 30 · 战役与战术模拟的统一舰队生成（口径对齐方案）

日期：2026-10-15。用户需求原文：
> 把战役的口径挪过来。现在的战术模式是**每个提督随机生成的舰队**，开场只负责选提督，然后开局，
> 这样也**不知道问题点**。你把战役里面的**每个提督配置阵型、配置部队**都挪过来，做好版面设计，
> 可以适当的简单化，比如**选了提督，默认就带过来他的阵型配置和舰队组成**。
> 关于战役里面这个部分我其实是不满意的，做的很烂、不完善，所以可以顺便在战术模拟里面再完善下，
> 比如**开局提督的棋盘格里面都是没有默认的舰队的**，这个棋盘格其实是 **4X 给提督做部队配置和
> 阵型配置**的，但现在这个棋盘格的功能很难发挥作用了，所以肯定得改。
> 就是把战役里面的**涉及到对战的都挪过来**，这样整个口径就对齐了，**修改一个另外一个正常复用**就可以了，
> 否则测试还得战役再打一轮，但战役部分哪里那么容易开战的，这个测试就太久了。
> **战役的部分唯一的差距就是战后结算的部分**，这个是涉及到实际游戏数值的，这个你也考虑好了怎么弄。

## 2. 目标（用户明确）

1. **口径对齐**：战术模拟与战役**共用同一套**「提督配置 → 舰队 → 单舰」转换；
   **改一处，另一处自动复用**。
2. **提督带配置**：选提督 ⇒ 默认载入他的**部队组成 + 阵型**。
3. **棋盘格可用**：部署阶段成为**4X 式的部队/阵型配置界面**（不是空棋盘）。
4. **测试成本**：**不必进战役、不必等轮次**即可在战术模拟里检验对局。
5. **唯一差异**：**战后结算**（战役回写大地图数值；演习只看战报）。

## 4. L1 · 提督配置（数据模型）

**现状问题**：`admiralsData.deck: string[]`（8 槽卡组）且**全空**。

**方案**：把 `deck` 升级为**结构化配置**（保留 `deck` 兼容旧存档）：

```ts
/** 提督的标准作战配置（战术模拟直接用；战役由大地图 fleet 覆盖） */
export interface AdmiralDoctrineConfig {
  /** 部队配比（兵力数；总兵力由 rank/编制决定） */
  composition: {
    battleships: number; cruisers: number; destroyers: number;
    carriers?: number; fighters?: number; supplies: number;
  };
  /** 默认阵型（formations.ts 的 id） */
  formation: FormationId;
  /** 战法倾向（可选；影响 AI 决策权重） */
  tactics?: { aggression?: number; flank?: boolean; defensive?: boolean };
}
```

**数据来源策略（关键）**：

| 轨道 | 部队组成来源 | 阵型来源 |
|---|---|---|
| **战役** | 大地图 `fleet.composition`（实际编成，战后衰减也写回这里） | `fleet.formation` |
| **战术模拟** | **提督的 `AdmiralDoctrineConfig.composition`**（新增数据） | `AdmiralDoctrineConfig.formation` |

⇒ **提督配置的初始化**（渐进式，避免一次性写 100+ 提督）：
1. **按 `faction`（阵营）+ `rank`（军衔）给一套基准配比**（如帝国=巨舰大炮、同盟=空母放飞）
2. **重点提督手工定制**（莱因哈特/杨威利等）
3. 其余走基准 ⇒ **保证"选谁都不一样"至少体现在阵营/军衔层**

## 5. L2 · 统一生成入口（**根治点**）

**把两套路径合并为一个纯函数**（放 `frontend/src/game/fleetGeneration.ts`）：

```ts
export interface FleetGenInput {
  composition: AdmiralDoctrineConfig['composition'];
  entityBudget: number;              // 军衔 → 编制位
  admiralStats?: { attack: number; defense: number };  // 两轨都传
  difficultyMods?: ShipStatMods;     // 难度（两轨同层；默认恒等）
  /** 仅战役：大地图舰队 id（用于写回） */
  sourceFleetId?: number;
}
export function buildFleetUnits(input: FleetGenInput): UnitSlot[];
```

**硬性约束（写进函数注释 + 台架断言）**：
- **`classType` 一律中文键**（`'战列'/'巡洋'/'驱逐'/'补给'/'空母'/'突击'/'电子'`）
  ⇒ 方向装甲 / 拦截 / 舰种距离带 / 电子特例**必须生效**
- **提督属性必须进单舰**（不再有"演习侧 ≡1"的旁路）
- **`def` / `atkInterval` 按舰种真源**（不硬编码）
- **`ΣHP/ΣATK` 守恒**（与实体数 N 无关，沿用 `shipScaling` 的既有保证）

**验收**：给同一 `FleetGenInput` ⇒ **两轨输出逐字段相等**（台架断言）。

## 6. L3 · 部署阶段（棋盘格）

**用户原话**：棋盘格是 **4X 给提督做部队配置和阵型配置**的，现在发挥不了作用。

**方案（由简入繁，分三期）**：

### 一期（最小可用）
- 开局棋盘格**显示提督的默认配置**：阵型轮廓 + 各舰种在图上的初始摆放
- **可切换阵型**（dropdown 或按阵型按钮）⇒ 棋盘格上阵型预览实时更新
- **可调整舰种数量**（若编制有余量）
- **"确认部署"⇒ 开战**（替代现在的纯 25s 计时）

### 二期
- **分舰队编制**（把部队拆成 2-3 支分队，分别指定阵型/任务）
- 与军议面板（`CouncilWarRoom`）联动：**部署期配置 ⇒ 战中可改任务**

### 三期
- **提督配置的保存/复用**（玩家调好的配置存起来，下次选同一提督自动载入）
- **配置预设库**（几套经典编成，一键套用）

**版面原则（用户要求"适当简单化"）**：
- **默认全部自动带好** ⇒ 玩家**想改才改**（一键开局不受阻）
- 左侧：提督卡（立绘/属性/配置摘要）；中间：棋盘格；右侧：阵型与编成控件

## 7. L4 · 战后结算（**唯一分轨点**）

**用户原话**：战役的唯一差距是战后结算，涉及实际游戏数值。

**方案：统一产出 → 分轨消费**

```ts
/** 战斗结束时的统一产出（两种轨道都生成） */
export interface BattleOutcome {
  winnerTeam: number;
  /** 每个参战舰队的战损（按舰队 id 聚合） */
  fleets: Array<{
    fleetId: number;
    factionId: number;
    admiralId: number;
    survivedUnits: number;
    lostUnits: number;
    /** 按舰种拆分的兵力损失（用于写回大地图编制） */
    lostShipsByType: Record<string, number>;
    finalMorale: number;
    finalSupply: number;
  }>;
  elapsedSec: number;
}
```

**分轨消费**：

| 轨道 | 消费方式 |
|---|---|
| **战役** | `writeBackToCampaign(outcome)` ⇒ 回写大地图的 `fleet.composition`（扣损失）/ `morale` / `supply` / 舰队存活状态；触发战役回合推进 |
| **演习** | `showBattleReport(outcome)` ⇒ **仅展示战报**（战损率、MVP、达成度等），**不写回**任何战役数值 |

⇒ **好处**：战斗内部**完全不感知轨道**；`isCampaign` 仅剩"结算后的去向"一处
（外加战场生成来源、倒计时 UI）—— **正是用户要的"唯一差距"**。

## 8. 执行分期（建议）

| 期 | 内容 | 风险 | 可验证性 |
|---|---|---|---|
| **P1** | **L2 抽统一入口**（先不动数值，保持现行为）+ 台架断言"两轨输出相等" | **零行为变化** | 高（输出逐字段对比） |
| **P2** | **L1 提督配置**（按阵营/军衔基准 + 重点提督定制）+ 演习改读它 | 中（会改变演习观感） | 高（选不同提督 ⇒ 舰队组成不同） |
| **P3** | **统一数值口径**（classType 中文 + 提督属性进单舰 + def 同源） | 中高（改变平衡，需重标定） | 高（战术模拟可验） |
| **P4** | **L3 部署阶段一期**（棋盘格载入默认配置 + 可调阵型） | 中（UI 工作量） | 中（真机） |
| **P5** | **L4 结算分离**（统一 `BattleOutcome` + 分轨消费） | 低 | 高（战役数值写回正确性） |
| **P6** | 顺手修 `deployAdj` 断供（僚舰自主）+ 新增 AI 托管 | 低 | 中 |

**⇒ 顺序理由**：P1 先做（零风险，为后续铺路且立即可验证）⇒ P2/P3 解决"提督同质化"⇒
P4 补棋盘格 ⇒ P5 收口结算 ⇒ P6 补友军行为。
