# 35 · 切片传送入场（家园2 式 hyperspace entry）

> 用户需求（2026-10-16 原话）：
> 「你知道家园2这个游戏吗？也是星际战争的rts游戏，他的入场有个切片的动画，是传送的，
> 就像核磁共振切片一样。现在的战术界面，入场是**一个舰队的所有战舰集中于一个点，然后展开阵型**，
> 我需要你做个入场，就是**入场的时候就是阵型正常展开的**，然后**所有的战舰有个这样的切片传送的过程**，
> 这样比现在的入场要帅的多了」

流程沿用：**多人做 → 反对（红队）→ 测试（审核）→ 总审核（lead）**；
且**视觉类任务必须出真机截图**（用户要求"从截图中理解意图并多版本精修"）。

## 0. 现状诊断（两路侦察，已核实）

### 0.1 「集中于一个点然后展开」的确切机制

| # | 机制 | 位置 |
|---|---|---|
| D1 | 每个战舰容器都建在**同一坐标** `fac.castlePos` | `BattleScene.ts:1684` `add.container(fac.castlePos.x, fac.castlePos.y)` |
| D2 | 阵位是**每帧**算出来的：`targetUnit = fleet.x + formationOffsets(阵型)[slot] × spacing`，再用 `stepShipSlotFollow` 限速挪过去 | `:8056-8107` |
| D3 | **部署暂停期 `update()` 提前 return** ⇒ 追踪循环不跑 ⇒ 全队**冻结堆在一点**，直到玩家按回车 | `:5939-5942`（`isPaused`） |
| D4 | **不存在任何"收拢→展开"的偏移动画** —— 完全是"建在一点 + 逐帧追踪"的副产物 | — |

⇒ **结论**：只要在**建舰时就把 sprite 放到阵位**（复用 D2 的同一个公式），第一帧即"阵型正常展开"，D1 的问题消失。

### 0.2 渲染能力（决定"切片"怎么做）

| 项 | 结论 | 位置 |
|---|---|---|
| Three.js 版本 | `^0.160.0` ⇒ `clippingPlanes` / `localClippingEnabled` 均可用 | `frontend/package.json:17` |
| 舰体材质 | **一艘船 = 1 Mesh(`MeshPhongMaterial`) + 1 LineSegments(`LineBasicMaterial`)**，同在一个 `Group` | `Battle3DOverlay.ts:3234-3245` |
| 材质是否每舰独立 | **是**（几何共享 `__b3dShared`，材质每舰 `new`）⇒ **可按舰施加裁剪，不串扰** | `:3225/3234/3236` |
| `localClippingEnabled` | **全工程未开启**（grep 零命中）⇒ 需补一行 | `:1389` 渲染器构造处 |
| `clippingPlanes` | **零先例**（`syncClipPlanes` 是相机视锥同步，**与材质裁剪无关**） | `:5957` |
| 自定义 shader 先例 | 有（护盾 `battleFx.ts:323` / dots `:978` / CRT `:1414`），但**无 `onBeforeCompile` 先例** | — |
| 线条材质能否裁剪 | `LineBasicMaterial` 是内置材质，**支持** `clippingPlanes`（需实测确认） | — |
| 常驻面片特效 | **舰体当前无任何常驻面片特效**（尾焰/引擎 glow 已随 v88 删除）⇒ **无"与 grow 打架"的现存冲突** | `docs/qa/2026-10-15-v88-remove-flame.md` |

### 0.3 可复用的既有设施

| 设施 | 用途 |
|---|---|
| `battle3dFx` 事件桥（`BattleScene.pushFx3d` → 3D `handleFx`） | 新增 3D 特效的**标准通道** |
| `ShipEntry.meshT` / `MESH_GROW_DUR=0.25s`（`:3955-3968`） | 实体"长出"的逐帧通道 —— **入场进度应复用同一通道** |
| LOD `grow`（`v.grow = sstep(lodLo,lodHi,fleetPx)`，`:3977`） | 0=光点→1=实体；**入场必须与它协调** |
| `config/fleetSplitManeuver.ts`（三幕 `t∈[0,1]` + `smooth01`，只输出视觉偏移） | 本工程做"一次性分段动画"的**推荐范式** |
| `UnitVis` 字段 | `x,y,z,h,seen,px,sx,sy,shipLen,shipW,grow,yaw,fleetPx`（**无 obj/pooled**） |
| `this.ships: Map<string,ShipEntry{group,meshT,baseScale,tier,cmdRing}>` | "已获实体"的表 |
| 单位**每次新建 + 显式 dispose**（非池化） | 入场动画可作用在新建单位上 |

### 0.4 ⚠ 三个必须绕开的坑（侦察发现）

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| P1 | 舰体**仅当 `fleetPx ≥ lodKeep` 才存在**（`:3786-3809`）；远景只有光点 | **远景舰队无体可切** | 入场时段临时强制建实体（或临时抬高该队 keep 门槛） |
| P2 | 实体随缩放**建/销**（`MESH_ADD_PER_FRAME=96` / `MESH_DROP_PER_FRAME=64`） | 若把切片绑到 `addMesh`，**推拉镜头会反复重播** | **进度绑到「入场事件」状态机，绝不绑 `addMesh`** |
| P3 | `meshT` 长出（缩放 0.25→1）与切片平面**叠加** | "又缩又切"，观感浑浊 | **入场期把 `meshT` 直接设满**，只留平面推进 |
| P4 | 光点在 `hasMesh && grow>0.02` 时被抑制（`:4093`） | — | **有利**：切片期不会同时出现"光点 + 半切舰" |

## 1. 目标（可验收）

1. **舰队第一帧就是展开好的阵型**（不再"堆一点再散开"）
2. **每艘战舰有沿轴扫描的"切片传送"过程**（家园2 式逐层实体化）
3. **逐舰错开**，形成"从一侧扫向另一侧"的波次感（不是所有船同时浮现）
4. **扫描位置有一道辉光**（CT 扫描亮面）
5. 不破坏既有表现：LOD 淡入淡出、点/实体切换、现有特效（护盾/激光/命中）**逐位不变**

## 2. 方案（裁剪平面为主 + 扫描面片增强）

### 2.1 核心：`clippingPlanes` 沿轴扫掠

- 构造渲染器时补 `this.renderer.localClippingEnabled = true;`（**局部**裁剪，
  ⚠ **不要**用全局 `renderer.clippingPlanes` —— 会连带切掉星空/地形/后处理 quad）
- 舰体 Group 建立后，收集其 `children` 里的 Mesh/LineSegments **材质引用**，存入 `ShipEntry`（新增字段，如 `sliceMats`）
- 每帧令全队**共享同一个 `THREE.Plane` 实例**：`plane.constant` 沿扫描轴推进
  （共享 → 一次扫整支舰队 ⇒ 家园2 观感；材质每舰独立 ⇒ 不会串扰）
- 入场结束后 `clippingPlanes = []`（**必须清理**，否则后续永久被切）

### 2.2 视觉增强：加法扫描面片

- 一个**独立**的半透明 `MeshBasicMaterial` + `AdditiveBlending` 面片，
  法线与裁剪平面同向、位置逐帧同步 ⇒ 就是"CT 扫描亮面"
- **完全独立对象**（不碰舰体 shader），可通过参数一键关闭

### 2.3 被否决的方案与理由

| 方案 | 否决理由 |
|---|---|
| `onBeforeCompile` 注入 dissolve | 观感上限最高（可做发光扫描线），但**全工程无先例**，需给 Phong 与 Line **分别**注入 + 处理 `customProgramCacheKey`/world varying/`#include` 顺序 ⇒ 改动面最大、回归风险最高。**本轮不做**，列为后续可选增强 |
| 逐单位分批显隐 | 零风险但**没有"单舰内部的 CT 切片感"**（整舰一次出现）⇒ **只达成需求的一半**。保留为**降级兜底**（若裁剪方案在真机出问题，可切到它） |

## 3. 落点（3 处，互相配套）

| # | 落点 | 改什么 |
|---|---|---|
| **L1** | `spawnInitialFleets()`（`:1684` 附近） | 建舰时**直接按阵位**放置 sprite（复用 `formationOffsets(formation, n) × formationSpacing` 的现成公式 + `formFacing` 旋转，与 `:8056-8107` 完全同源）；给每舰打入场时间戳 `_entryT0` / `_entryDelay` |
| **L2** | 逐舰循环（`:8016-8107`） | 按入场进度门控：未到该舰"传送时刻"的舰可全程可见（因为 L1 已让它在阵位上），切片只负责"显现" |
| **L3** | `Battle3DOverlay`：`addMesh()`（`:4030`）收集材质 + `syncShips` 第三遍（`:3955` 附近）推进；或 `tick()`（`:5758`）新增 `updateEntryFx(dt)` | 扫描平面推进 + 扫描面片 + `meshT` 设满 + 入场结束清理 |

**⚠ 关键决策（实现者必须先查清）**：
`Battle3DOverlay.tick()` 的**驱动源**是什么？是否受 `store.isPaused`（部署暂停）影响？
- **若不受影响**（3D 有独立循环）⇒ 入场动画可**在部署期播**（玩家在军议时就能看到舰队切片集结）—— **更帅，优先**
- **若受影响** ⇒ 动画在**开战后**播（按回车 → 切片入场 → 转入机动）

## 7. v1 为什么失败（根因）

**v1 的验收标准错了** —— 只验了"机制生效"（数据上确实有 406~636 舰挂上 `clippingPlanes`），
**没有验"眼睛能看到"**。实际观感为：

| # | v1 的问题 | 后果 |
|---|---|---|
| **V1** | 开场是**默认远景**，而舰体**只在 `fleetPx ≥ lodKeep` 时才存在**（§0.4 的 P1 坑） | ⇒ **远景全是光点阵列、没有模型** ⇒ 裁剪切的是**光点** ⇒ **等于什么都没做** |
| **V2** | 开战即取消暂停（`isPaused = false`） | ⇒ 没有"加载/入场"时间窗，动画与战斗起步混在一起 |
| **V3** | 动画仅 **2.5 s** | ⇒ 太短，来不及被看见 |
| **V4** | 扫描轴 = **世界 Y（水平切面）** | ⇒ 用户要的是**从舰首开始、沿舰体纵轴** |
| **V5** | 全队共享**一个无限平面** | ⇒ 没有"门"的形体；用户要的是**长方体/正方体传送门** |
| **V6** | 无"门"的可见形体（只有裁剪） | ⇒ 就算裁到了也看不出"从门里出来" |

**⇒ v1 需按"可见性优先"重做。**

## 9. v2 关键设计

### 9.1 「门」的几何（N6/N7）
```
门框（矩形截面，法线 = 舰队朝向水平方向）
  ├─ 尺寸：全队投影包围盒的 max(宽, 高) × ENTRY_GATE_PAD(1.25)
  ├─ 位置：从【舰首一侧】开始，沿【舰队朝向】向后推
  └─ 裁剪体 = 5 个无限平面：
       ① 推进面（法线 = 舰队朝向，constant 随进度推进）
       ②~⑤ 上下左右四个侧面 ⇒ 与①合围成"无限长方柱"
     ⇒ 只有落在方柱内的舰体可见 ⇒ 视觉上"舰队从门里钻出来"
```
**一队一门** ⇒ 同队所有舰**共享这 5 个 `THREE.Plane` 实例**（性能好，一次更新全队生效）。

### 9.2 可见的「门」本体（v1 缺的东西）
裁剪本身**不可见** —— 必须再画一个**门框**，否则用户看到的只是"舰体凭空出现"：
- **门框**：矩形线框（加法混合、亮色）+ 内嵌半透明**位面**（量子波/水面感）
- **扫描亮面**：随推进面同步移动的辉光带
- 建议配色：青白（与既有护盾/激光同族），**加法混合**

### 9.3 暂停与时长（N3/N4）
- 开战 ⇒ `entryPhase = true` + `isPaused` **保持 true** + 相机聚焦
- 3D 播 **5 s** 入场（门推进 + 舰体逐段显现）
- 结束后 3D **通知** `BattleScene`（用**正式通道**，不要用 window 全局）
  ⇒ `isPaused = false`、`entryPhase = false`
- ⚠ **与 `ASSEMBLE_MAX_MS`（4 s）的关系**：入场 5 s > 4 s ⇒ 入场期间 `_assemblingSince`
  可能已到期 ⇒ **入场结束时必须重置该计时**，否则解除暂停瞬间舰队直接跳进 `exploring`

### 9.4 相机（N1）
- 开战调 `focusOnPlayerMainFleet({ dist })`，`dist` 取值要保证该队 **`fleetPx ≥ lodKeep`**（有模型）
- ⚠ 聚焦是**一次性**的；之后玩家仍可自由移动相机（不锁定跟随）
- ⚠ 无玩家阵营（无部署暂停分支）⇒ 退回"保持当前机位"

## 14. 球面 Voronoi（自研，不引第三方库）

```
Fibonacci 球均匀撒 N 个种子（N = 120）
  → 对每个种子 p：取 k = 12 个近邻，把近邻投影到 p 的切平面
  → 半平面裁剪（每个近邻给一条中垂线：a·(u·q) + b·(v·q) ≤ 1 − p·q）逐个裁初始方块
  → 2D Voronoi 单元朝质心收缩 gapRatio(0.08) ⇒ 留缝
  → 顶点**归一化投影回球面**（⇒ 每个顶点都在球面上）
  → 三角扇（扇心 = 质心）⇒ BufferGeometry
```
- 实测分布（N=120）：**六边形 66%**、五边形 22%、七边形 12%（与参考图的蜂窝观感一致）
- 覆盖率（Σ球面面积 / 4π）= **0.849** ≈ (1−0.08)² ⇒ 缝隙率与 `gapRatio` 精确对应
- **确定性**：固定 seed 的 `mulberry32` ⇒ 同 seed 两次生成**逐位一致**（含全部动画随机量）
- 几何**只在入场开始时生成一次**（实测 ~6ms），动画期间只改 `position / quaternion / opacity`

## 15. 三层科幻质感（**优先级：色散镶边 > 发光层次 > 瓦片形状**）

| 层 | 实现 | 参数 |
|---|---|---|
| **色散镶边**（最重要） | 每块瓦片叠 **3 层 Mesh**（主色 + 色散 A 红端 + 色散 B 青端），沿**瓦片法线径向**微偏移 `±dispersion×R`，全加法混合 ⇒ 球体轮廓处分离出红/青镶边 | `dispersion = 0.016`（实测 0.03 会拉出"尖刺"且过曝）、A `0xff4d6a` / B `0x3fd0ff`，层不透明度 `[0.38, 0.14, 0.14]` |
| **亮白核心** | 球心 billboard 柔边径向渐变面片（加法混合 ⇒ 无硬边），半径 = `R × 0.95` | 峰值不透明度 0.78，包络 `sphereCoreAmt`（组装 30% 处开始升起 → 完整期满 → 消散前半段褪去） |

## 16. 三阶段时序（总时长**恒等于** `ENTRY_TOTAL_SEC` = 5.0s）

| 阶段 | 区间 | 内容 |
|---|---|---|
| 组装 | `0 → 1.8s` | 每块瓦片从**球外** `R × [1.5, 3.0]` 的随机方向 + **随机初始翻滚** + 透明度 0 → 缓动飞向目标位（`k → 1`）并朝向归位（`spin → 0`）；**逐块随机延迟** `[0, 0.6s]` ⇒ "随机拼起来" |
| 完整 + 舰队显现 | `1.8 → 3.0s` | 全部瓦片就位、不透明；核心满亮、紫辉光满亮；**舰队在此窗口内显现**（见 §17） |
| 消散 | `3.0 → 4.5s` | 反向：瓦片沿**径向向外** `× [1.8, 3.2]` + 随机翻滚 + 淡出；逐块随机延迟 `[0, 0.5s]` |
| 余晖 | `4.5 → 5.0s` | 瓦片已全收（`visible = false`），核心/紫辉光残余淡出 |

阶段时长之和 = 1.8 + 1.2 + 1.5 + 0.5 = **5.0**（台架断言 `sphereTotalSec(cfg) === ENTRY_TOTAL_SEC`）。

## 17. 舰队"在球里面出现"

**改为「逐舰径向错开的缩放淡入」**（不再用 v2 的裁剪平面 —— 球体内部是曲面，平面裁不出"径向显现"）：

- 开战瞬间：舰队先被**吸进球里**（`sphereRevealAmt` 的"吸收段" `0 → 0.35s`，缩放 1 → 0）
- 球体完整期：`1.40s` 起逐舰 `0 → 1` 升起（单舰 0.75s），**逐舰错开跨度 0.55s**，
  延迟按"距球心的归一化距离"给（**球心先亮、舰队由内向外浮现**）
- ★ 最晚一舰 `1.40 + 0.55 + 0.75 = 2.70s < 3.0s`（消散开始）⇒ **显现必定发生在球体内部**（台架断言）
- 复用既有 `entryStates`（进度绑"入场事件"，**推拉镜头不重播**）⇒ 与 v2 的机制同源，只换消费方式

**与 v2 的差异**：v2 = 5 个裁剪平面围成的"无限长方柱"从舰首扫到舰尾（切舰体）；
v3.1 `S` = **完全不切舰体**（`attachEntryClippingTo` / `addMesh` / GLB 换装三处都对 `S` 提前返回），
改由缩放淡入驱动 ⇒ 结束**没有裁剪需要拆除**（红线仍由 `finishEntryGate` 的防御性清理兜底）。
