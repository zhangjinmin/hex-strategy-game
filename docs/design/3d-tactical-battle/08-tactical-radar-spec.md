# 08 · 2D 战术雷达规格

> **Q2 已由用户拍板：加。** 本文件是雷达的完整规格。
> 雷达是缓解 3D 空间可读性风险**最有效的单一措施**——一根杠杆同时压住 R-02（深度误判）、R-06（视野外无感知）、R-11（阵型不可辨）三个 S/A 级风险，且实现成本极低（2D 平面坐标在 `BattleScene` 中已全部存在，只需一个 canvas）。

---

## 1. R-11 是什么，雷达怎么解决它

> team-lead 要求：R-02 和 R-06 已说清楚，**R-11 需要能向用户完整解释**。

### 1.1 R-11 的定义

**R-11 = 阵型在透视下变形，玩家无法一眼辨识双方阵型 → 现有阵型克制规则在玩家侧归零。**

### 1.2 被破坏的东西有多大

游戏里有一套**现成的循环克制规则**（`BattleScene.ts:2695`）：

```js
const beats = { wedge: 'spindle', spindle: 'circle', circle: 'square', square: 'line', line: 'wedge' };
if (beats[mForm] === eForm)      damageMultiplier = 1.3;   // 我克他 → +30%
else if (beats[eForm] === mForm) damageMultiplier = 0.7;   // 他克我 → −30%
```

5 种阵型（雁行 / 单纵 / 纺锤 / 圆阵 / 方阵）构成循环克制链。**这是一个 ±30% 的伤害乘数**，量级上等于一个 2CP 的「集中火力」（+30%），但**阵型切换是免费的**（数字键 `1`–`5`，随时可切）。

所以：**能不能读出对方阵型，直接决定这 ±30% 落在谁头上。** 这是战斗中最划算的单项决策——前提是玩家看得见。

### 1.3 3D 为什么会破坏它

2D 俯视下，雁行阵就是屏幕上的一个 V 字、单纵阵就是一列、圆阵就是一个环。玩家扫一眼就知道双方阵型，**零成本**。

3D 透视下：V 字被纵向压缩、圆阵变成椭圆、方阵变成梯形、单纵阵在低仰角下缩成一团。**玩家在 3D 主视图里看不出对方是什么阵型**，于是：

> 阵型克制系统继续在规则层运行，但玩家**无法参与**这个决策——它从"策略深度"退化成"玩家看不见的随机数"。

### 1.4 为什么"贴地编队轮廓线"不够（我在 `05` R-11 给的缓解 1）

我在 R-11 缓解里给了「贴地编队轮廓线」（在棋盘平面画出阵型的凸包形状）。它有用，但**不足以替代雷达**，三条理由：

1. **它仍然受透视压缩。** 画在棋盘平面上，仰角 27° 时纵向压缩到 `sin(27°) = 0.45` 倍，V 字会变成扁 V，圆阵变成扁椭圆——形状仍然失真，只是比不画好。
2. **它是主动成本。** 要看清某支舰队的阵型，玩家得把相机转过去或拉过去。战斗中同时有 8 支舰队时，逐个查看不现实。
3. **它无法做对比。** 阵型克制是**双方**的关系。玩家需要同时看到"我是什么阵"和"对面是什么阵"才能决策，而贴地轮廓线一次只能看清局部。

### 1.5 雷达的解法

| 雷达提供的 | 为什么是决定性的 |
|-----------|-----------------|
| **2D 正俯视，阵型零变形** | 雷达不受相机角度影响，雁行就是雁行、圆阵就是圆阵，形状 100% 保真 |
| **全局可见** | 220px 内同时显示全部 8 支舰队的阵型，**一眼可做克制对比** |
| **零操作持续可读** | 不需要转相机、不需要拉远近、不需要选中——一直在那里 |
| **敌我同屏** | 直接对照：我是 `wedge`（克 `spindle`），对面是 `spindle` → 冲；对面是 `square` → 按 `5` 切 `line` |

**实现要点**：雷达尺度是 220px 显示 2500px 地图（**1:11.4**），一个编队跨度约 112 世界px ≈ **9.8 雷达px**——画不出真实队形。因此雷达上**画阵型字形图标**（12px 的 `V` / `│` / `◆` / `○` / `▦` 符号）置于舰队标记旁，而不是画实际单位位置。这是关键实现细节，画真实队形会糊成一团。

### 1.6 定量价值（供向用户说明）

| 项 | 数值 |
|----|------|
| 阵型克制的伤害修正 | **+30% / −30%** |
| 切换成本 | **0**（数字键 `1`–`5`，随时可切，无 CP 无冷却） |
| 等价 CP 价值 | 与 2CP 的「集中火力」（+30%）同量级 |
| 3D 化后玩家的获取成本 | **无雷达时：需要逐个转相机查看，战斗中不可行** |
| 有雷达后 | **0 操作，全局持续可读** |

**一句话**：雷达把阵型克制从一个**玩家看不见的隐藏乘数**，变回一个**每时每刻可参与的免费决策**。

## 2. 雷达基本规格

### 2.1 位置与尺寸

| 项 | 规格 |
|----|------|
| 屏幕位置 | **右下角**：`right: 16px`，`bottom: 88px`（略过 GameFooter 与活跃效果条） |
| 尺寸 | **220 × 220 px**（正方形，与棋盘 AABB 等比） |
| UI 缩放联动 | 1.0x = 220 / 1.25x = 275 / 1.5x = 330 |
| 形状 | 正方形 + CRT 风格四角 L 形角标（与整体视觉语言一致） |
| 折叠态 | 折叠为 `220 × 32px` 的标题条（保留「战术雷达」标题 + 展开箭头） |
| 默认 | 展开 |

**为什么是右下角而不是右上角**：命令面板（非模态）占据右上区域（`right:16px, top:88px, width:320px`）。雷达若也在右上会与命令面板**直接重叠**。二者在右侧上下分区：命令面板占上半（top 88 → max-height 660，即到 y≈748），雷达占下半（y 772 → 992），中间留 24px 间隙。

### 2.2 显示层级与遮挡

| 项 | 规格 |
|----|------|
| 渲染层 | **DOM 层（Vue 组件）**，在 3D canvas 之上，**不受 CRT 后处理影响** |
| `z-index` | 低于命令面板，高于 3D canvas 与 W+ 层标记 |
| 背景不透明度 | **0.85**（可透出下方的 3D 画面，保持"全息悬浮板"观感） |
| **是否遮挡 3D 战场** | **会**，遮挡右下角 220×220 px 区域 |
| 遮挡的代价评估 | 低。① 是角落不是中心；② 按 `05` R-01，**画面下缘本就是遮挡最严重、可读性最差的区域**（下缘遮挡纵深 150px vs 中心 10px）；③ **被遮住的那块 3D 画面，在雷达上仍然可见**（雷达显示全图） |
| 缓解手段 | ① 半透明 0.85 ② `M` 键折叠/展开 ③ 设置项可完全关闭 ④ 悬停时提升到 0.95 |

### 3.2 不画什么（及理由）

| 不画 | 理由 |
|------|------|
| **单舰位置** | 64 艘单舰在 220px 上间隔约 2.5px，画出来是一团噪点。**编队级聚合才是雷达的价值**——它提供的是全局态势，不是局部细节 |
| **舰载机** | 同上，且数量动态变化会造成视觉闪烁 |
| **射程** ⭐ team-lead 点名要求结论 | **明确不画。** 8 支舰队各画一个射程圆，在 220px 内必然糊成一团；且射程是**局部交战决策**信息，3D 主视图里用**贴地射程圆**读得准得多（贴地圆与相机角度无关，是正确判据）。**结论：射程归 3D 主视图，不进雷达** |
| **敌人意图线** | 意图是 3D 空间中的施动者→目标关系，压到 2D 雷达上会与阵型字形、视锥梯形互相干扰；且会突破信息密度红线 |
| **伤害数字** | 空间不足，且屏幕外伤害已聚合到边缘指示器（`04` §1.2） |
| **地形细节 / 高度** | 雷达是平面态势图，高度信息无意义 |

## 4. 交互规格

| 输入 | 行为 | 备注 |
|------|------|------|
| **左键点击** | 主相机**平移**到该点（**不改变角度与距离**） | 见 §5.2 与可访问性的冲突处理 |
| **左键拖拽** | 持续平移主相机 | |
| **悬停** | 精简 tooltip：舰队名 / 提督 / 阵型中文名 / 舰数 / HP% / 状态图标（≤3） | 比 3D tooltip 精简 |
| **目标选择态下点击候选目标** | 选中该目标 —— 与点击 3D 战场**完全等价** | 三种选择方式之外的第四条路径，且解决了"目标在屏幕外"的极端情况 |
| **`M` 键** | 折叠 / 展开 | |
| 右键 | **无行为** | 避免与「投放战术信标」及「轨道旋转」冲突 |
| 滚轮 | **不缩放主相机** | 与 3D 滚轮语义冲突；雷达恒定全图 |
| 雷达自身缩放 | **不支持** | 恒定显示全图是它的核心价值（稳定参照系） |

## 5. 与 3D 主视角的联动规则

### 5.1 视锥梯形（"我在看哪里"）

| 项 | 规格 |
|----|------|
| 画法 | 相机视锥与棋盘平面 `y = 0` 求交，得到近/远 × 左/右 4 个交点，连成梯形 |
| 更新 | 每帧 |
| 退化处理 | 若视锥上边缘不与平面相交（相机看向天空，即画面上缘超出地平线），梯形退化为**开放多边形**，需裁剪到棋盘边界内 |
| 样式 | 半透明白色描边（不透明度 0.35）+ 四角小刻度 |
| 作用 | 玩家一眼看出"我现在看的是战场的哪一块" + "还有哪些区域没看到" |

### 5.2 联动规则表

| 触发 | 雷达侧表现 | 3D 主视角侧表现 |
|------|-----------|----------------|
| 3D 中选中舰队 | 对应标记高亮 + 外环加粗 | — |
| 选中目标在屏幕外 | 雷达标记**持续脉冲** | 边缘方向指示器（`04` §1.2） |
| 点击雷达某点 | 标记闪烁一次 | **相机平移到该点**，视锥梯形随之移动 |
| 屏幕外发生受击 | 红色闪烁 800ms | 屏幕边缘方向指示器（同一事件，两个通道） |
| 屏幕外发生损失 | 白色闪烁 800ms | 边缘指示器 + 战斗日志 |
| 进入命令目标选择态 | 候选目标显示 `1`–`9` 编号（与 3D 徽章一致） | 编号徽章 + 脉动轮廓 |
| 相机移动 | 视锥梯形实时更新 | — |

### 5.3 与可访问性档位的冲突处理（重要）

雷达点击会移动相机，这与 `06` §1.1 的「相机完全锁定」档位潜在冲突。处理规则：

| 档位 | 雷达点击跳转 |
|------|:------------:|
| Basic / Standard | ✅ 生效 |
| **Comprehensive（相机完全锁定）** | ❌ **禁用跳转**，只保留高亮与 tooltip |

**理由**：R-13（晕动症）管的是**事件触发的自动镜头运动**；雷达跳转是**玩家主动发起**的直接操作，性质不同。但在"完全锁定"档位下，玩家的意图是"相机绝不移动"，此时必须尊重该意图——**可访问性档位的优先级高于便利功能**。

同理，雷达跳转**不受**「自动镜头运动 = 全部关闭」设置影响（那一项只管事件触发），但**必须遵守** M1–M4 四条硬规则中的 M3（单次上限 2.5s）与 M4（不阻塞其他操作）。

## 6. 性能与实现约束

| 项 | 规格 |
|----|------|
| 实现方式 | 单个 `<canvas>` 2D context（不走 Three.js，不占 WebGL 预算） |
| 重绘频率 | **10 Hz**（100ms）`[PLACEHOLDER]`。高于此值对态势图无意义，且浪费 CPU |
| 数据源 | 直接读 `BattleScene` 中已有的舰队平面坐标（`fleet.x` / `fleet.y`），**无需新增计算** |
| 分辨率 | 设备像素比适配（HiDPI 下 canvas backing store ×2） |
| 与后处理的关系 | DOM 层，完全不受 CRT / Bloom 影响，保证在特效全开时仍清晰可读 |
