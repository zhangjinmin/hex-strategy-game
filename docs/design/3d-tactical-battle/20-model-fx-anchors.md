# 20 · 模型自带 FX 锚点约定（尾焰喷口）

> 结论先行：**别再让程序去猜喷口在哪，也别让你去量喷口多大。**
> 在 Blender 里往喷口里放几个**空物体（Empty）**，命名以 `FX_ENGINE` 开头 —— 你只负责**位置**
> （要的话再给个朝向），**形状与尺寸由程序以该点为原点向四周扫描、撞到内壁为止现场量出来**。
> 圆、方、椭圆、六棱、异形一律不区分：形状就是那条内框线本身。
> 有锚点的模型**优先于**"巡览里手点的标注"，也**优先于**自动探测。

## 为什么改这条路

前几轮的教训（连续被实拍打回）：

| 做法 | 为什么不行 |
|---|---|
| 全舰统一半径的圆盘 | 方尾舰顶着圆盘、光斑大于开口 ⇒ **穿模** |
| 自动探测（尾端面直方图找峰 + 外接矩形/圆盘） | 位置是"统计出来的"，对异形尾（双引擎块、竖框架）**系统性偏**；尺寸只能用外接框近似 ⇒ 四角悬空 |
| 巡览里手点标注 + 描轮廓 | 能救个别舰，但**每艘都要人盯**；且标注是"事后补丁"，不随模型更新 |
| 凹轮廓/内框线（栅格化 + 空腔识别 + 裂缝跟随） | 能贴合结构，但"哪块才是该发光的面板"仍是推断，反复调参 |
| **作者手动给半径**（v27） | 半径要**逐口**量、还要记得改缩放 X。实测事故：同一个模型上两个锚点因为忘了改缩放，半径差 **333 倍**（0.5 舰长 vs 0.0015 舰长）——一个糊住半个舰、一个看不见 |

**建模时多花 3 秒放两个空物体**，上述问题一次性消失。

## 约定（唯一需要记住的东西）

1. **类型**：`Empty`（纯空物体，不要 Mesh）。放在**该放光的位置** —— 喷口**内部**、口沿、或口外一丁点都行。
2. **名字**（大小写不敏感，前缀匹配）：
   - `FX_ENGINE_L` / `FX_ENGINE_R` —— 推荐：左右分明
   - `fx-engine-1` / `FX_ENGINE_2` / `EnginePort_mid` / `ENGPORT_C` 也都认
   - 正则：`/^(fx[_-]?engine|engine[_-]?port|engport)/i`
3. **位置** = 光斑中心（模型局部坐标，随便你把它父子挂在哪一级，程序读的是世界矩阵）。
   放在**喷口内部**也行 —— 程序会从该点朝外逐档找"仍被内壁围住的最大截面"（通常就是口沿那一圈），
   所以不必纠结深度；想更保险就放在口沿附近。
4. **朝向：默认不用管！** 空物体**零旋转**（X/Y/Z 旋转全 0，新建时的默认状态）⇒ 程序自动把
   切平面摆成 ⟂ 舰长轴、朝锚点所在的那一端。**只有**侧向姿控喷口这类"不朝舰尾"的特例才需要手动转：
   把空物体的局部 **+Z（蓝色箭头）指向排焰方向**，转了就完全以你为准。
   - 看不清轴：`Pure Axes（纯轴）`不显示彩色 ⇒ 选中空物体 → `Object Data Properties`（绿色图标）
     → `Viewport Display` → 改成 `Arrows`，就有红/绿/蓝彩色箭头了
   - 常用旋转角（N 面板直接填，欧拉 XYZ）：
     | 想让 +Z 指向 | 旋转 X | 旋转 Y | 旋转 Z |
     |---|---|---|---|
     | −Y（Blender 默认"前"） | **90°** | 0 | 0 |
     | +Y | **−90°** | 0 | 0 |
     | −X | 0 | **−90°** | 0 |
     | +X | 0 | **90°** | 0 |
     | +Z（上） | 0 | 0 | 0 |
     | −Z（下） | **180°** | 0 | 0 |
   - 偷懒法：打开顶部**吸附（磁铁）**→ 模式选 `Face（面）` → 勾 `Align Rotation to Target`，
     然后按 `G` 把空物体拖到喷口面 —— Z 轴自动对齐面法线（指向外）。**方向反了就把某个旋转轴加 180°**。
5. **半径：不用给。** 默认就是"从该点向外扫描到撞墙为止"。
   只有想**强行画圆盘/方片**（例如口部是一圈栅格、不想描那些格子）时才需要给：
   - 缩放 X（按模型原始单位解释，例如模型 1 单位 = 1 米就填米）
   - 自定义属性 `radiusRel = 0.03`（= 3% 舰长）或 `radius = 0.6`（绝对值）
   - ⚠ 采信区间是**舰长的 0.4%~12%**：超出即视为"忘改缩放 X"，忽略掉改走扫描
     （这正是上面那个 333 倍事故的根治）；另外在扫描档下，这个半径只当"**最远找多远**"的搜索上限用。
6. **形状**（可选）：自定义属性 `mode`
   - 不给（默认）或 `scan`：**扫描开口截面**（要什么形状就是什么形状）
   - `outline`：老写法，等价于 `scan`
   - `round`：圆盘（要配合半径用）
   - `rect`：方形/矩形片（方尾舰）
   - `none`：这处**不画**光斑
7. **多个**：想要几处光斑就放几个空物体，尺寸各自独立（都是现场量的，不用你操心）。
   ⚠ 别在**同一个喷口里**放两个 —— 那会得到两片重叠的光。

### 自定义属性怎么加（Blender）

选中空物体 → `Object Properties` → `Custom Properties` → `Add`：

| 名称 | 类型 | 取值 | 作用 |
|---|---|---|---|
| `mode` | String | `scan` / `round` / `rect` / `outline` / `none` | 形状（缺省 = 扫描） |
| `radiusRel` | Float | `0.03` | 半径 = 3% 舰长（仅在 `round`/`rect` 档需要） |
| `radius` | Float | `0.6` | 半径 = 0.6 模型单位（同上） |

## 扫描是怎么算的（一句话 + 四条边界）

以锚点为原点、锚点局部 **+Z 为法线切一刀**，在**切平面内**向 360° 打 96 条射线，取每条射线打到
模型表面的**最近交点**半径 r(θ)，连成闭合多边形 —— 那就是开口的真实截面，直接拿去挤出光斑。

**切哪一刀**：从锚点沿 **+Z（朝外）逐档推进**（0 / 12% / 24% / 38% / 50% × 搜索半径），
取"**仍被内壁完整围住**的**最大**截面" —— 通常就是口沿那一圈。所以你把空物体放在喷口**内部**，
光斑也会自动扩到那个圆框；放到口沿上，量到的就正好是口沿。
（防咬闸，全部满足才推进：**该刀命中率 ≥ 85%**（内壁完整围住，v28c 加）/ **形状闸门**：`p90/med ≤ 1.6`
且逃逸占比 ≤ 3%（v28e 加）/ 不再被围住 / 开始收窄 / 单档增幅 > 1.6 倍 / 总面积 > 第一刀 2.5 倍
⇒ 停，用上一档。挡的是"切平面跑出口外后咬住尾板外缘"、"半开放切面把轮廓撑大"、
与"**形状变尖/出现楔形**"这三类事故。）

> ⚠ **[v28e] 为什么必须要"形状闸门"**：旧闸门只看中位半径。实测某个口外扩一档时
> **中位半径只涨 3.7%**（1.732% → 1.796%），但 `p90/med` 从 **1.25 坏到 1.90**、逃逸占比 1.0% → 4.2%
> ⇒ 旧闸门全部放行，光斑从"正圆贴口"变成"带楔形伸到舰体上"（用户实报的"交叉长条"）。
> **中位数对形状是不敏感的** —— 判"这一刀切得对不对"必须看形状。

**尺寸上限**：锚点喷口的半径 **≥ 舰长 6%** 即触发绝对闸门 ⇒ 整体等比缩回并在控制台点名
（`ANCHOR_PORT_MAX_N`）。34 舰普查实测真实喷口半径 ≤ 5% 舰长；这条闸门是 v27 那类
"缩放 X 留在 1 ⇒ 半径等于整条舰长"事故的最终兜底。

实现：`battleFx.ts → scanPortOpening()`（v28）。

1. **星形域边界**：得到的是"**从锚点看得见的**那圈内壁"。喷口（口内壁一圈）天然满足；
   若是"包裹超过 180° 的月牙形"，凹进去的部分会被弦取代。
2. **朝外扩展是有上限的**：最远走 50% × 搜索半径（搜索半径 = `max(采信半径×3, 6% 舰长)`，夹 25% 舰长）。
   口比这个更深时，量到的是能走到的那一刀 —— 想直接量口沿，把空物体往口沿挪一点。
3. **共面三角形不挡光**：与切平面共面的面（比如点正好压在平尾板的表面上）会被跳过 ——
   否则会描出三角网格的"蜘蛛网"。所以**别把点精确贴在平面上**，往里/往外挪一点点即可。
4. **竖直留了后手**：锚点那一刀完全撞不到墙（点落在口沿上、或掉在口外一点点）⇒ 把切平面沿 −Z
   逐档往里推（−12% / −25% / −45% / −70% × 搜索半径），用第一档能围住的；
   一圈都撞不到（点不在任何腔内）⇒ **不瞎给形状**，退回一个兜底圆盘。
   另有"中位半径 ≤ 舰长 18%"的合理性闸门。
5. **什么样的命中才算"墙"**（[v28e] 逐条实测得出）——
   判据都是"几何上它到底是不是**本腔的内壁**"：

   | 判定 | 内容 | 实测依据 |
   |---|---|---|
   | 掠射不算墙 | `\|cos(命中面法线, 射线)\| < 0.5` ⇒ 当缺口 | 腔内壁 `|cos|` ≥ 0.89；"擦着面滑出去"的远命中中位仅 0.35~0.39 |
   | 不是本腔的墙 | `r > 宽窗(±6 条射线) P40 分位 × 1.6` ⇒ **整条丢掉**（不是夹到上限） | 真墙 1.37~2.43% 舰长，逃逸 3.0~4.4%（相邻喷口外壁） |
   | 共面不算墙 | 与切平面共面的三角形跳过（射线在面内掠过） | 否则点压平板上会描出三角网格 |
   | 缺口怎么补 | 两侧最近有效射线**按角度线性插值** | "取较大者"会撑出 40% 大瓣（v28c）；"填全局中位"会造出**假圆弧 + 径向跳变** = 楔形长条（v28e） |

6. **锚点可以放多个**：每型舰想亮几个口就放几个空物体（同盟战舰现在是 8 个）。
   巡览面板与 `_fx_scan.cjs` 的口径都**与锚点数量无关**，加锚点不必改探针。

## 导出注意

- 空物体在 glTF 里就是"没有网格的节点"，Blender **默认就会导出**（没有单独的 "Empties" 开关）。
- **`Include ▸ Custom Properties` 必须勾** —— 否则 `mode` / `radiusRel` / `radius` 全部丢失
  （这是最常见的一个静默失效点）。
- 若用 `Include ▸ Limit to ▸ Selected Objects`，要**把模型和所有空物体一起选中**，漏选的空物体不会进文件。
- **LOD 文件也要带**：游戏按档位加载 `xxx.lod1/lod2.glb`，若 LOD 里没有空物体，就落回推断（光效与高档不一致）。
  代码侧已做缓解：同一型舰只要**有一个**文件带锚点，其余档位会复用它的锚点；但最稳的还是每个 LOD 都带上。
- 名字里有 `FX_ENGINE` 前缀的**任何节点**都会被采；别给不想发光的物体起这个名。
  `FX_ENGINE-1` / `FX_ENGINE_L` 这类名字都没问题（只看前缀，不看大小写和分隔符）。

## 代码侧（已实现，无需再改）

- 采集：`shipModels.ts` 加载时 `traverse` 找匹配节点，并把锚点过一遍**几何被改写的那串变换**
  （LOD 缩放 → 长轴转 Z → 截面正方化 → 朝向修正 → 居中）⇒ 永不重演"错位"。
  半径单独量测"锚点局部 X 轴长度在最终模型里的长度"，任何线性变换下都精确。
- 解析：`battleFx.ts` 的 `resolveEnginePortsFor` 优先级 =
  **① 模型自带锚点 → ② 巡览手点标注 → ③ `ENGINE_PORT_STYLE` 覆盖 → ④ 自动探测**。
  ①之内：作者明写 `round`/`rect` ⇒ 完全按作者；否则由 `ENGINE_PORT_OPTS*`（巡览面板）选档，
  缺省 = **扫描**。
- 渲染：`buildEnginePortGeo` 按 `q` 先把光斑转到锚点朝向，再平移到锚点位置；
  有轮廓走 **`buildFanPlate`（中心 + 轮廓的扇形挤出）**，轮廓的每个点就是扫描量出来的内框线。
  - ⚠ **不能用 `ExtrudeGeometry`**：它的封盖三角化（earcut）**不产生内部顶点**，所有顶点都落在轮廓上，
    而 `edgeFade` 是**逐顶点**写进顶点色的 ⇒ 径向渐变会塌成"全黑片"（实测中心色和 0.007、光核直接消失）。
    扇形板有中心顶点，渐变才成立。圆口同理走 48 段扇形（旧的 16 段圆柱封盖渐变呈 16 瓣）；方片用 3×3 分段。
  - 两层**白核 + 暖晕**共用**同一套开口尺寸**、各自从内向外用顶点色淡出到黑
    （`edgeFade`：白核 0.55、暖晕 0.0；加色混合下黑 = 不加任何东西）⇒
    **可见能量全部落在开口以内，物理上不可能穿模**，硬多边形边也收成柔光。
    ⚠ 两层的材质**都必须 `vertexColors: true`**，否则顶点色淡出是死代码，暖晕会退回
    "满幅硬边琥珀板"（= 之前那圈穿模的金边）。
- 巡览面板：选中舰 → 「形状来源」三档（**扫描内框** / 外轮廓 / 内框线）+ 缩放；
  下方会显示扫描读数（`🔎 扫描命中 xx% · 中位半径 x.xx% 舰长 · 切割深度 ...`）
  —— 这一刀有没有切到墙、光斑多大，一眼可见。

## 验证

```bash
node frontend/_fx_scan.cjs          # 解析解 + 你的模型；加 survey 参数再跑全舰普查
node frontend/_fx_anchor.cjs        # 锚点采集/变换/朝向（v27 那套）
node frontend/_fx_glow.cjs          # 光斑尺寸 vs 开口（穿模判据）+ 新旧对照渲染
node frontend/_fx_repro.cjs 5173    # 连**正在运行的** dev server 取运行时真值（含巡览截图）
```

`_fx_scan.cjs` 断言（解析解部分**与公式逐点比**，不靠肉眼）：

| 用例 | 判据 |
|---|---|
| 圆管（64 段） | 轮廓点与解析圆的**最大相对误差 < 1.5%**；命中率 = 1 |
| 椭圆（异形） | 轮廓点在解析椭圆上（< 1.5%）；半轴比 = 设定值 |
| 六棱柱（异形 + 实心体） | 轮廓点在解析解（内切/外接）上（< 2%） |
| 圆锥台 | 半径 = 该 z 处的解析半径（< 2%）；**锚点前移 1/4 台高，尺寸跟着变小** |
| 点在几何之外 | 明确判定失败，不瞎给形状 |
| 点压在共面平板上 | 不挡光（不描出三角网格） |

真机部分（你的 `alliance_battleship.glb`，两个锚点半径 0.5 / 0.0015 舰长）：
默认档下两个口都拿到轮廓（≥12 点）、命中率 ≥ 0.5、**尺寸回到同一量级**（旧版差 333 倍）；
并用 three 自带 `Raycaster` **独立复核**扫描半径（自写求交 vs 库求交，最大相对差 < 5%）；
另出 `_fx_scan_shape.svg`（切平面点云 + 扫描轮廓叠画）与近/远景渲染图。

## 还没做

- **共面分区**（按法线做区域生长，把标注点所在的**整块面板**取出来）—— 目前 `convex`/`inner` 两档
  仍走"薄层投影 → 空腔/结构轮廓 → 裂缝跟随"，对"面板边界就是开口边界"的舰型够用，
  对"面板中有一小块凹坑"的舰型仍会取到整块面板的外缘。
- 锚点的**朝向是否要参与形变**（例如光斑随舰体俯仰）：目前只用于"摆正光斑平面"。
- 自动探测路径（无锚点、无标注）不参与扫描：它的取点位置本身就是统计出来的，
  "从统计点向外扫描"会把舰体横截面当成开口。要逐舰精确，请放锚点或在巡览里打点 + 选「扫描内框」。
