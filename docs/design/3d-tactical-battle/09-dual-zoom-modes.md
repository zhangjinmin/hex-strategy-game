# 09 · 双档缩放规格（默认档 / 全局档）

> **Q7 已由用户拍板：双档方案。**
> - **默认档（主用）**：`dMax` = 棋盘填满屏幕，战列舰 25px
> - **全局档（辅助）**：一键拉远到看全战场
> - 两档一键切换
>
> 本文件给出切换交互、全局档信息呈现、可操作性、使用场景，**并对"全局档该多远"提出一个几何层面的修正建议**（§1）。

---

## 1. 先解决一个几何问题：默认档的 `dMax` 已经能看全战场

### 1.1 三档距离的实测换算

按 fov 50°、1920×1080、1 单位 ≈ 15px、棋盘 2500px（= 167 单位）、27° 仰角：

| 距离 | 可见宽度（世界） | 棋盘是否看全 | 战列舰屏幕尺寸 | 屏幕空间占用 |
|:----:|:----------------:|:------------:|:--------------:|:------------:|
| `dMin` = 8 单位 | 13.3 单位 | ❌ | 333 px | — |
| 标准交战 ≈ 55 单位 | 92 单位 | ❌ | 48 px | — |
| **默认档 `dMax` ≈ 100 单位** | **167 单位 = 2500 px** | ✅ **是** | **25 px** | 棋盘占满宽度，垂直约 80% |
| **全局档（用户描述）≈ 379 单位** | 630 单位 = 9450 px | ✅ 是 | **6.6 px** | **棋盘仅占屏幕宽度 26%（500 px）** |

**结论：默认档的 `dMax` 已经等于"看全战场"。全局档（6.6px）比它远 3.8 倍，但看到的还是同一个完整战场——只是小了 3.8 倍。**

这正是我在 `05` §4.1 批评 2D `zoom = 0.2` 时的同一个问题：地图只占屏幕宽度 26%，其余 74% 是空白。

### 1.2 但全局档有一个真实收益（不是纯浪费）

**距离越远，透视越接近正交投影。**

在默认档 `dMax`（100 单位）下，画面边缘仍有明显的近大远小与形状拉伸——同一支舰队的两艘船，在画面左缘和中心的屏幕尺寸可差 20% 以上（取决于它们在画面中的位置）。这对"判断相对位置"是有害的。

拉到 379 单位后，透视失真显著减小，全局档提供的是一张**几何上更准确的平面态势图**。

### 1.3 我的建议：全局档改为「顶视 + 填满屏幕短边」

**同样的"消除透视失真"目标，用顶视可以免费达成，而且不用付 74% 屏幕浪费的代价。**

| 方案 | 仰角 | 相机距离 | 战列舰尺寸 | 屏幕占用 | 透视失真 |
|------|:----:|:--------:|:----------:|:--------:|:--------:|
| **A（用户描述）** | 27° | 379 单位 | **6.6 px** | 棋盘 26% 宽 | 小（靠距离换） |
| **B（建议）** | **90° 顶视** | **179 单位** | **14.3 px** | **棋盘 56% 宽 / 100% 高** | **零**（正交） |

方案 B 的计算：顶视下棋盘无透视压缩，为 2500×2500 px。填满屏幕短边（1080）→ 缩放 0.432 → 棋盘占 1080×1080，**战列舰 33 × 0.432 = 14.3px**，相机距离 ≈ 179 单位。

**B 在两个维度上都优于 A**：战列舰大 2.2 倍（14.3 vs 6.6px，从 L3 兜底档提升到 L2 常规档）、屏幕浪费从 74% 降到 44%、几何保真度更高（正交 vs 近似正交）。

**B 的额外收益**：棋盘左右各留约 420px 空白，**正好容纳左右两侧的 HUD 面板**（BattleLog 在左 260px、命令面板在右 320px），全局档下**战场与 HUD 完全不重叠**——这是 A 做不到的（A 的棋盘只有 500px 宽，居中后两侧虽然也空，但战场本身太小，HUD 相对战场显得过大）。

### 1.4 决策 —— ✅ **Q9 已定案：采纳方案 B（顶视 + 填满屏幕短边）**

用户拍板采纳方案 B。全局档参数锁定：

| 参数 | 值 |
|------|-----|
| 仰角 | **90°（顶视，`polar = 0`）** |
| 相机距离 | **179 单位** |
| 棋盘缩放 | 0.432（2500px → 1080px，填满屏幕短边） |
| 战列舰屏幕尺寸 | **14.3 px**（信息 LOD **L2** 档） |
| 棋盘屏幕占用 | 1080 × 1080（宽 56% / 高 100%） |
| 几何保真 | **正交**，零透视失真 |

**由 Q9 采纳产生的一个连带修正见 §3.4**：14.3px 下**全局档不再强制 billboard**，改用 **LOD1 简化几何**。理由与 draw call 核算均在 §3.4。

**本文件全部内容按方案 B 编写**（§1.1–§1.3 保留 A/B 对比仅作决策留痕）。

## 2. 切换交互

### 2.1 键鼠映射

| 操作 | 输入 | 说明 |
|------|------|------|
| **进入全局档** | **`G`** | `G` 未被任何现有输入占用（已核对：`1`–`5` 阵型 / `Space` 命令面板 / `Tab` 目标循环 / `Enter` / `Esc` / `V` 顶视 / `Home` 复位 / `F` 聚焦 / `WASD` 平移 / `M` 雷达折叠 / `T` 部署指令卡 / `Alt` / `Shift` / `Ctrl`） |
| **退出全局档** | **`G`**（再次）或 **`Home`** 或 **任何相机旋转操作** | 恢复进入前的完整位姿 |
| **滚轮外滚到底** | 默认档滚到 `dMax` 后继续外滚 | **自动进入全局档**（400ms 过渡 + 屏幕角标提示「全局视图」）。玩家不必记住 `G` |
| **滚轮内滚** | 在全局档内 | 退出全局档，回到默认档 `dMax`，继续内滚则正常缩放。**不会被"困"在全局档** |
| 全局档内继续外滚 | — | 无响应（已是最远） |

### 2.2 固定位姿与位姿记忆

| 项 | 规格 |
|----|------|
| 全局档位姿 | **固定**：顶视（polar = 0）+ 距离 179 单位（方案 B）+ 棋盘中心居中 + 方位角沿用进入前的 yaw（保持玩家习惯的"上北下南"） |
| 进入前 | **保存完整位姿**（位置 / 朝向 / 距离 / yaw） |
| 退出时 | **完整恢复**保存的位姿（复用 `06` §1.3 的 M2 规则） |
| 过渡 | 400ms（Standard），`k = 7.7` 指数阻尼。Comprehensive 档位下改为瞬时（0ms） |
| 过渡期间 | 玩家输入立即中断过渡（复用 M1 规则） |

### 2.3 全局档下禁用的相机操作

| 操作 | 全局档下 | 理由 |
|------|:--------:|------|
| 平移 | ❌ **禁用** | 全局档的定义就是"棋盘居中看全"，平移会破坏它 |
| 旋转（轨道） | ❌ **禁用** | 任何旋转操作 = 退出全局档（见 §2.1） |
| 缩放 | ❌ **禁用** | 固定距离；内滚即退出 |
| 跟随（`F` 双击） | ❌ **禁用** | 同上 |
| 雷达点击跳转 | ❌ **禁用** | 全局档下已看全，跳转无意义（雷达本身也自动折叠，见 §3.3） |
| 选中 / 命令 / 阵型 / 信标 / 主炮 | ✅ **保留** | 见 §4 |

## 3. 全局档的信息呈现

### 3.1 核心原则

> **全局档不是"把默认档拉远"，而是一种独立的信息模式。**
> 全局档下每艘船只有 14.3px，**任何"挂在单舰上的"UI 元素都放不下**。信息必须由**编队级聚合元素**承载。
> 但 14.3px 下**舰体剪影本身仍有信息价值**（见 §3.4），因此舰体不降为 billboard。

**⚠️ 关键修正（Q9 采纳后重算）：绑定的约束不是舰船尺寸，是阵型间距。**

全局档缩放 0.432 下：

| 量 | 世界 | 屏幕 |
|----|:----:|:----:|
| 战列舰长度 | 33 px | **14.3 px** |
| 旗舰长度 | 42 px | **18.1 px** |
| 巡洋长度 | 21 px | **9.1 px** |
| 驱逐长度 | 15 px | **6.5 px** |
| **阵型间距（8 艘编队）** | **28 px** | **12.1 px** |

**任何单舰 UI 元素的宽度都必须 < 12.1px 才不重叠**，这与舰船是 14.3px 还是 6.6px 无关。所以即使投影翻倍，**单舰级 UI 元素依然全部放不下**。

### 3.2 显示 / 隐藏清单（Q9 后重新评估，结论：全部维持隐藏）

| 元素 | 全局档 | 屏幕宽度 | vs 12.1px 间距 | 结论 |
|------|:------:|:--------:|:--------------:|------|
| **舰体几何** | **LOD1 简化几何**（~~原定 LOD2 billboard~~，见 §3.4） | — | — | ✅ 保留几何 |
| 阵营标记（▲/◆） | ✅ 显示 | minPx **10** | 10 < 12.1 ✓ | ✅ 勉强够 |
| **阵型字形**（`V`/`│`/`◆`/`○`/`▦`） | ✅ 显示 | 12px，**每队 1 个** | 不涉及间距 | ✅ |
| 编队聚合 HP 条 | ✅ 显示 | minPx 40×5，**每队 1 个** | 不涉及间距 | ✅ |
| 剩余舰数 `n/8` | ✅ 显示 | 每队 1 个 | 不涉及间距 | ✅ |
| 旗舰 ★ 标记 | ✅ 显示 | 每队 1 个 | 不涉及间距 | ✅ |
| 舰队标签（D 层，精简一行） | ✅ 显示 | 每队 1 个 | 不涉及间距 | ✅ |
| 地块归属 / 地形 | ✅ 显示 | — | — | ✅ **全局档优势项** |
| 视野环 | ✅ 显示 | 每队/每阵营 1 个 | 不涉及 | ✅ |
| 选中高亮 | ✅ 显示 | — | — | ✅ |
| 意图线 | ⚠️ 聚合为编队级粗线 | 每对 1 条 | 不涉及 | ✅ |
| **单舰 HP 条** | ❌ **隐藏** | minPx **20×3** | **20 > 12.1** ❌ | ❌ **8 艘船的条会连成一条** |
| **状态图标** | ❌ **隐藏** | minPx 10，但与阵营标记叠加 = **20** | **20 > 12.1** ❌ | ❌ 与阵营标记争位 |
| **蓄力条** | ❌ **隐藏** | minPx **18×3** | **18 > 12.1** ❌ | ❌ |
| **伤害数字** | ❌ **全部隐藏** | 11px 字 | 会盖住 14.3px 的船 | ❌ 见 §3.5 |
| 目标候选编号徽章 | — | — | — | 不出现（全局档下自动切回，见 §4.2） |

**结论：隐藏清单全部维持不变。** 但理由从"尺寸不足"更正为"**单舰元素宽度超过阵型间距 12.1px**"——这个约束在 6.6px 与 14.3px 下同样成立，所以投影翻倍没有解锁任何单舰 UI 元素。

**真正被解锁的不是 UI 元素，而是舰体本身**（见 §3.4）。

### 3.3 雷达的联动

| 项 | 规格 |
|----|------|
| 全局档下雷达 | **自动折叠**为标题条（信息完全重复） |
| 例外 | 若玩家在设置中开启「全局档保留雷达」，则保持展开但淡化至 0.5 不透明度 |
| 恢复 | 退出全局档时自动展开 |

### 3.4 屏幕边缘方向指示器

**全局档下关闭。** 该指示器（`04` §1.2）的存在理由是"战斗发生在视野外"——全局档下没有视野外。

同理，**全局档下不存在"屏幕外事件"**，所有事件都在画面内发生，伤害数字与事件反馈直接走正常通道。

> ⚠️ 但 §3.2 里我把伤害数字列为"全部隐藏"，原因是**尺寸不足**：14.3px 的舰船上方挂一个 11px 的数字，会完全盖住目标。**全局档下的伤害反馈转为**：HP 条 delta 段 + 舰体/标记闪烁 + 战斗日志。这是可接受的取舍——全局档的定位是"看态势"不是"看细节"，精确数值请回到默认档或读日志。

## 4. 全局档的可操作性

### 4.1 操作权限表

| 操作 | 全局档 | 精度评估 | 备注 |
|------|:------:|:--------:|------|
| 选中舰队 | ✅ | 良好 | 点击聚合标记；拾取代理体生效（14.3px 下需要，6.6px 下**必须**依赖代理体） |
| 单选单舰（`Alt`） | ❌ **禁用** | — | L2/L3 档下不存在单舰概念 |
| 切换阵型（`1`–`5`） | ✅ | 完美 | 无空间精度要求 |
| 暂停 / 调速 | ✅ | 完美 | |
| 投放战术信标 | ⚠️ 允许 | **差** | 6.6px 下点位置精度约 ±50 世界px。建议允许但提示"精度受限" |
| 主炮轰炸 | ⚠️ 允许 | **差** | 同上 |
| 查看 tooltip | ✅ | 良好 | 悬停聚合标记，显示精简信息 |
| 下达 CP 命令 | ⚠️ 见 §4.2 | — | **关键规则** |
| 平移 / 旋转 / 缩放 | ❌ 禁用 | — | 见 §2.3 |

### 4.2 关键规则：进入命令目标选择态时自动切回默认档

| 规则 | 内容 |
|------|------|
| 触发 | 在全局档下按 `Space` 打开命令面板，并选中一个 `requiresTarget` 命令 |
| 行为 | **自动切回默认档** + 相机聚焦到玩家舰队 + 400ms 过渡 |
| 理由 | 目标选择需要：① 看清目标的编号徽章（24px 恒定，在 6.6px 的舰船上会完全遮蔽目标）；② 读取悬停 tooltip 判断"该不该打"；③ 判断距离与射程关系。这三件事在全局档下都做不到 |
| 例外 | `requiresTarget: false` 的 7 个命令（紧急抢修 / 紧急回避 / 士气鼓舞 / 魔术师的反击 / 黄金狮子的咆哮 / 红发的守护 / 老将的坚壁）—— **不需要目标，可在全局档直接下达** |
| 提示 | 切换发生时显示一行提示：`已切换到战术视图以选择目标` |

**这条规则同时解决了一个潜在死锁**：若允许在全局档选目标，玩家会遇到"编号徽章比目标还大、点哪支舰队都分不清"的困境。

### 4.3 全局档下的相机可访问性

全局档切换会移动相机，**属于玩家主动发起**，不受「自动镜头运动 = 全部关闭」设置约束。

但必须遵守：
- Comprehensive「相机完全锁定」档位下，**全局档切换仍应可用**（它是玩家主动的显式操作，且锁定档位限制的是旋转/平移，不是档位切换）
- 过渡动画在 Comprehensive 档位下为瞬时（0ms）
- 遵守 M1（任意输入可中断）与 M2（位姿完整恢复）

## 5. 全局档的使用场景

### 5.1 推荐场景

| # | 场景 | 为什么用全局档 |
|:--:|------|----------------|
| 1 | **战斗开场 / 部署完成** | 看清双方初始布阵与地形，做第一波决策 |
| 2 | **8v8 多线战场** | 默认档一次只能看局部，全局档同时看两个方向的战况 |
| 3 | **找不到自己的舰队** | 快速定位"我的第 3 舰队在哪、还剩多少" |
| 4 | **暂停后做战术决策** | 暂停 → `G` → 看全局 → 决策 → `G` 回到原位继续 |
| 5 | **读双方阵型做克制判断** | 全局档 + 阵型字形 = 一眼对比全部 8 支舰队的阵型（R-11 的第二解法，与雷达互补：雷达精度低但常驻，全局档精度高但需按键） |
| 6 | **查看地块归属与地形全貌** | 雷达只画归属不画地形，全局档是唯一能看到地形全貌的视图 |

### 5.2 不推荐场景

| 场景 | 为什么不适合 | 替代 |
|------|-------------|------|
| 交战中的精细操作 | 无 HP/状态/伤害数字，无法判断交战结果 | 默认档 |
| **下达需指定目标的命令** | 见 §4.2，会自动切回 | 默认档 |
| 读取单舰状态 | L2/L3 档下无单舰概念 | 默认档 |
| 长时间停留 | 全局档信息密度低，长时间使用会导致细节失控而不自知 | 雷达（常驻，零操作） |

### 5.3 与雷达的关系：互补，不重复

| 维度 | 雷达 | 全局档 |
|------|------|--------|
| 操作成本 | **零**（常驻右下角） | 一次按键 + 400ms 过渡 |
| 空间精度 | 1 : 11.4 | **1 : 0.77（约 15×）** |
| 地形细节 | ❌ 只画归属 | ✅ 完整 |
| 遮挡 3D 视野 | 220px 角落 | 全屏（会中断对局部战场的观察） |
| 阵型对比 | ✅ | ✅ 精度更高 |
| 定位 | **持续感知** | **主动查看** |

**结论：二者互补。** 雷达负责"任何时候都能扫一眼"，全局档负责"我要认真看一次全局"。

**若只能选一个 → 选雷达。** 零操作成本的价值高于 15× 空间精度——大部分时候玩家只需要知道"哪里有战斗"，不需要精确的米级位置。这也解释了为什么 Q2 通过之后，全局档从"必需品"降级为"增强项"。

## 6. 验收清单

- [ ] `G` 一键进入/退出全局档，过渡 400ms（Standard）/ 瞬时（Comprehensive）
- [ ] 全局档位姿固定（顶视 + 棋盘居中），平移/旋转/缩放全部禁用
- [ ] 任何相机旋转操作会退出全局档并恢复进入前的位姿
- [ ] 滚轮外滚到底自动进入全局档；全局档内滚轮内滚自动退出（不会被困住）
- [ ] **全局档下强制 LOD2/billboard，不渲染舰体细节**
- [ ] 全局档下不出现：单舰 HP 条、状态图标、蓄力条、伤害数字、屏幕边缘指示器
- [ ] 全局档下 5 种阵型字形与实际阵型 100% 一致（R-11 验收项）
