# 06 · 可访问性与晕动症

本文档引用美术侧 `docs/art/3d-tactical-battle/accessibility.md` 的三级分级（Basic / Standard / Comprehensive），并补充 UX 侧负责的参数、联动规则与非颜色编码规格。

**分工**：美术负责"是什么颜色"，UX 负责"不靠颜色怎么读、玩家能关掉什么、数值是多少"。

## 1. 相机运动限制（补充美术规格未覆盖的部分）

| `maxPolarAngle`（最低仰角） | 0.35π ⚠️见 Q1 | **0.35π**（仰角 27°） | 0.30π（仰角 36°） | 美术原值 0.45π（仰角 9°）过掠射 |

### 1.2 自动镜头运动的关闭路径

**要求：任何情况下玩家都能关掉所有非玩家主动发起的相机运动。**

| 层级 | 设置项 | 位置 | 默认 |
|------|--------|------|------|
| L1 总开关 | 「自动镜头运动」：全部关闭 / 仅关键事件 / 全部开启 | 设置 → 辅助功能 → 相机 | **全部关闭** |
| L2 分项开关 | 「一骑讨名场面镜头」「击沉特写」「命令执行推进」「战斗开场巡览」 | 同上（展开） | 全部关闭 |
| L3 紧急中断 | **任意玩家输入立即中断**当前自动运动 | 硬编码，无开关 | 始终生效 |

### 1.3 相机运动的四条硬规则

| # | 规则 |
|---|------|
| **M1** | 任意玩家输入（`WASD` / 方向键 / 鼠标拖拽 / 滚轮 / 任意按键）**立即中断**正在进行的自动镜头运动，不播放缓出 |
| **M2** | 自动运动前后**完整保存并恢复**相机位姿（位置 + 朝向 + 距离）。残留偏移会让玩家产生"我没动过相机啊"的困惑 |
| **M3** | 单次自动运动时长上限 **2.5 s** `[PLACEHOLDER]`，超时强制中断并复位 |
| **M4** | 自动运动期间，玩家的所有操作（选中、命令、暂停）**保持可用**，不得被镜头动画阻塞 |

### 1.4 晕动症的兜底出口

| 出口 | 触发 | 效果 |
|------|------|------|
| **`V` 顶视** | 按住 / 单击 | 瞬时切到正俯视，消除全部透视与遮挡，等价于 2D 可读性 |
| **`Home` 复位** | 单击 | 回到默认角度 + 玩家舰队居中 |
| **相机锁定** | 设置 → 辅助功能 → 相机 → 「完全锁定」 | 禁用旋转，仅保留平移与缩放。**锁定后全部战斗操作仍可完成**（验收项） |
| **键盘平移** | `WASD` / 方向键 | 相比鼠标拖拽，键盘平移的加速度曲线更平缓，不适感更低 |

## 2. 特效强度与 CRT 滑杆的联动

### 2.1 滑块结构（R1 修订：CRT **独立**成滑块，不再由主控衍生）

~~R0 版：一个「特效强度」主控滑块统管所有表现层特效，CRT 是其中一路（`CRT = master × 0.8`）。~~

**美术侧指出该设计违反用户决策原文**（决策 4：「CRT 强度：**可调滑杆**，范围 0–100%，默认 70–80%」）——做成主控衍生量后玩家**无法单独调到 100%**，用户点名的那个滑块等于不存在。且「特效强度」（玩法反馈）与「CRT 强度」（呈现风格）语义不同，存在「满特效 + 无 CRT」「强 CRT + 温和特效」两种合法需求。

**采纳美术侧方案**：两条独立滑块 + 主控作为预设驱动器。

| 滑块 | 范围 | 默认 | 说明 |
|------|------|:----:|------|
| **特效强度**（主控） | 0–100% | 70% | 拖动时同时设下面两条；玩家仍可**单独微调**任一条 |
| **CRT 强度** | **0–100%** | **75%** | 独立可调，可到 100% |
| （高级展开）Bloom / 色差 / 粒子 | 0–100% | 跟随联动 | 可覆盖联动值 |

> **UX 侧的唯一附加条件**：必须有 **「全部归零」一键预设按钮**（同时把特效主控、CRT、Bloom、色差、粒子全部置 0）。理由见 §2.2 —— "归零后完全可玩"是可访问性的验收硬项，不能要求玩家逐个滑块拖一遍。美术侧表示若裁定单主控只需加该按钮；**现改为独立滑块方案后，该按钮仍然是必需项。**

**各特效随主控的联动规则**（非线性，因为不同特效对可读性的损害程度不同）：

```
CRT_intensity   = 独立滑块（默认 75）；主控拖动时 = master * 0.8
bloom_intensity = master^1.2
aberration      = master <= 0.30 ? 0 : (master - 0.30) / 0.70   // 低强度时优先砍色差
particle        = master^0.8
screen_shake    = master >= 0.80 ? 1 : 0                // 硬开关
flash           = master >= 0.30 ? 1 : 0                // 硬开关
```

| 主控值 | CRT（跟随联动时） | Bloom | 色差 | 粒子 | 屏幕震动 | 屏幕闪光 | 自动镜头 |
|:------:|:-----------------:|:-----:|:----:|:----:|:--------:|:--------:|:--------:|
| **100%** | 80% | 100% | 100% | 100% | 有（≤2px） | 有 | 关（默认） |
| **70%（推荐默认）** | 70% | 80% | 30% | 90% | 无 | 有 | 关 |
| **50%** | 50% | 50% | **0%** | 60% | 无 | 有 | 关 |
| **30%** | 30% | 20% | **0%** | 30% | 无 | 无 | 关 |
| **0%** | **0%（后处理链 bypass）** | 0% | 0% | 0% | 无 | 无 | 关 |

**为什么色差先归零**：色差（chromatic aberration）对**文字与小尺寸线框**的损害远大于扫描线与噪点。玩家抱怨"3D 看起来糊"，主因通常是色差，不是扫描线。美术侧已采纳该优先级（**色差 > 噪点 > 扫描线 > 暗角**）并把色差改为**延迟启动**：`0.004 × clamp((s − 30%)/70%, 0, 1)`，`s ≤ 30%` 恒为 0。

### 2.2 主控归零的硬要求

**主控 = 0% 时，游戏必须完全可玩。** 这不是"降级可用"，是"完全可玩"。具体要求：

| 要求 | 实现方式 |
|------|----------|
| 全部信息仍可读 | 阵营（形状 + 轮廓 + 接地投影形状）、HP（分段条 + 数字）、状态（形状图标）、意图（线型 + 箭头）、命令效果（8 种形状） |
| 舰船仍可辨认 | 主控 = 0 时，半透明舰船**自动切换为不透明实体** `alpha = 1.0`（去掉半透明叠加问题，同时解决 R-03） |
| **⚠️ 亮度必须同步回 1.0**（美术侧补充，已采纳） | `alpha → 1.0` 时实体层亮度必须同步从 `×0.35` 回到 `×1.0`。**否则不透明舰船会变成实心暗块沉入 `0x02040a` 背景，比半透明更不可读——"关掉特效"反而让画面更看不清。** 耦合表见美术 `materials-and-lighting.md §3.4` |
| **接地投影豁免归零** | 投影是唯一的深度锚点（R-02/R-09/R-17 的解法底座），**不透明度不随滑杆归零**；美术侧设定为 0% 档反而提到轮廓 0.95 / 填充 0.35 |
| 命中/被击中仍可感知 | HP 条 delta 段 + 屏幕边缘方向指示器 + 战斗日志 + 音频 |
| 命令反馈仍完整 | 活跃效果条（纯 DOM）+ 状态光环（几何体，非 bloom）+ 日志 |
| 无任何运动不适 | 无相机抖动、无屏幕震动、无自动镜头、无闪光 |
| 无后处理开销 | 后处理链整体 bypass（对低端集显也是性能收益） |

### 2.3 设置项清单（UX 侧要求实现的入口）

| 设置项 | 选项 | 默认 |
|--------|------|------|
| 特效强度（主控） | 0–100% 滑块 | 70% |
| 特效强度 · 高级（展开） | CRT / Bloom / 色差 / 粒子 独立滑块（各自可覆盖联动值） | 跟随联动 |
| 相机运动 | 默认限制 / 严格锁定（仅平移缩放）/ 自定义 | 默认限制 |
| 自动镜头运动 | 全部关闭 / 仅关键事件 / 全部开启 | 全部关闭 |
| 信息密度 | 精简 / 标准 / 完整 | 标准 |
| UI 文字缩放 | 1.0x / 1.25x / 1.5x | 1.0x |
| 色盲模式 | 关闭 / 红绿色盲 / 蓝黄色盲 / 全色盲 | 关闭（可设自动检测） |
| 高对比 UI | 开 / 关 | 关 |
| 战斗事件字幕 | 开 / 关（音效文字化， Comprehensive 要求） | 关 |
| 命令执行后保持暂停 | 开 / 关 | 关 |

## 3. 色盲友好：非颜色冗余编码规格

**原则：任何信息不得仅靠颜色传递。** 这不是"给色盲用户的额外照顾"——在 `0x02040a` 极暗背景 + 半透明舰体 + bloom + 色差的组合下，颜色是所有人的弱通道。

### 3.1 敌我识别（三方冗余）

| 通道 | 同盟 | 帝国 | 来源 |
|------|------|------|------|
| 颜色 | 青绿 `0x2dd4bf` | 紫 `0xc084fc` | 美术 |
| **舰体轮廓** | 方正、棱角分明 | 修长、前倾、带弧线 | 美术 |
| **接地投影形状** | 圆角矩形 | 尖椭圆 | 美术 |
| **编队标记形状（UX 新增）** | **▲ 三角** | **◆ 菱形** | UX |

> UX 新增"编队标记形状"这一层，因为在 L3 聚合档（远处/小尺寸）下，舰体轮廓与接地投影都退化到不可辨，只有标记还留着。

### 3.2 舰种识别（6 类，形状编码）

| 舰种 | 图标（单色可辨） | 说明 |
|------|-----------------|------|
| 战列舰 | **实心方块 ■** | 最大体积 + 实心 |
| 巡洋舰 | **实心三角 ▲** | 中等 |
| 驱逐舰 | **实心斜线 / 小箭头 ➤** | 最小 |
| 航母 | **空心方块 + 内含横线 ▣** | 中空表示"载机" |
| 补给舰 | **十字 ✚** | 与 `heal` 效果形状一致的语义 |
| 工兵舰 | **六边形 ⬡** | 与 `shield` 效果形状呼应 |

舰种图标在 L0/L1 下显示为舰船上方的小徽标，L2/L3 下不显示（改由编队 tooltip 提供）。

### 3.3 HP（不靠颜色渐变）

| 规则 | 内容 |
|------|------|
| **分段刻度** | HP 条分为 **10 段**，段间有 1px 间隔。剩余段数 = HP 百分比的十位数。**不靠颜色渐变**传达数值 |
| **色相仅表达危险档位** | 100–60% 常色 / 60–30% 警示色 / <30% 危险色 + **闪烁** |
| **<30% 必须有非颜色信号** | 闪烁（2Hz）+ HP 条外框加粗。**闪烁频率是可感知的非颜色通道** |
| **精确数值** | 悬停/选中时在 D 层显示 `3,420 / 8,000` |
| **delta 段** | 受伤时显示白色残影段（代表刚失去的量），200ms 收缩消失 |

### 3.4 命令效果（8 种形状编码）

见 `03` §4.2。每种 `effect.type` 有独立形状（▲×3 / 六边形球壳 / 双层反向环 / ▼ / »» / ★ / ✚ / 残影+冲击环）。

### 3.5 敌人意图（线型编码，非颜色）

| 意图类型 | 线型 | 箭头 |
|----------|------|------|
| 威胁我方 | **实线** | 单箭头，指向我方 |
| 敌方内部交战 | **虚线** | 双向箭头 |
| 目标情报不足（fuzzy） | 点线 | 末端 `?` |

### 3.6 选中状态（形状编码）

| 状态 | 编码 | 来源 |
|------|------|------|
| 选中我方 | **绿色 L 形括号 ⌐ ¬** | 美术 |
| 选中敌方 | **红色 X 形括号** | 美术 |
| 悬停（未选中） | 细描边 + tooltip | UX |
| 命令目标候选 | **编号徽章 ①②③** + 脉动轮廓 | UX |
| 命令目标已锁定 | **靶心锁定环**（接地投影上） | UX |

### 3.7 伤害数字（不靠金色）

| 类型 | 编码 |
|------|------|
| 普通伤害 | 白字 11px，常规字重 |
| **暴击** | 白字 **16px + 加粗 + 外描边 + 前缀 `!`**。金色只作为辅助通道 |
| 治疗 | 字前缀 `+`，绿色辅助 |
| 免疫/无效 | 显示 `免疫` 二字（不是显示 `0`） |

## 4. 其余可访问性要求

| 项 | 要求 | 优先级 |
|----|------|--------|
| **键盘可达** | 仅使用键盘可完成一场战斗，含：**选中目标（`Tab` + `Enter`）、下达全部 11 个命令、切换阵型（`1`–`5`）、暂停、复位相机**、撤退 | P1（美术 Comprehensive 档验收项） |
| **UI 文字缩放** | 1.0x / 1.25x / 1.5x，作用于全部 D 层文字（伤害数字、编队标签、日志、tooltip） | P1 |
| **高对比 UI** | HUD 面板背景不透明度 ≥ 0.9，文字对比度 ≥ 7:1 | P2 |
| **战斗事件字幕** | 关键音效文字化（如 `[爆炸]` `[警报：旗舰受损]`），显示在屏幕底部 | P2 |
| **悬停朗读 / screen reader** | 编队 tooltip 内容可被读屏软件读取 | P2 |
| **按键重映射** | 全部相机与命令键位可重映射 | P2 |
| **单手操作模式** | 常用操作可映射到键盘左侧区域 | P2 |

## 5. 验收清单

- [ ] 主控特效滑杆 = 0% 时，游戏完全可玩（§2.2 六条逐条验证）
- [ ] 主控 = 0% 时，半透明舰船自动变为不透明
- [ ] 相机"完全锁定"档位下，玩家仍能完成全部战斗操作
- [ ] 灰度截图下，仍能分辨：敌我、6 种舰种、HP 档位、8 种命令效果、意图类型
- [ ] 仅有音频/仅有视觉（关闭另一通道）时，六类关键事件仍各有至少一个可用通道（见 `04` §3 自检表）
- [ ] 全部自动镜头运动关闭后，战斗中相机不会因任何事件移动
- [ ] 自动镜头运动进行中，任意输入能立即中断并恢复原位姿
- [ ] 仅使用键盘可完成一场战斗（含目标选择）
- [ ] UI 文字缩放 1.5x 下，所有 D 层文字不溢出、不重叠
- [ ] 红绿色盲 / 蓝黄色盲 / 全色盲三档模式下，敌我识别正确率 100%

## 6. 与美术规格的已知冲突（提交裁决）

| # | 议题 | 美术 R0 / UX R0 | **R1 结论** | 状态 |
|---|------|-----------------|-------------|------|
| C-1 | Basic 档 `maxPolarAngle` | 美术 `π×0.45`（仰角 9°）<br>UX 建议 `π×0.35`（仰角 27°） | **三档统一 `π×0.35`** | ✅ **美术已采纳**（`ship-assets.md §3.1`）<br>补强论据：9° 中心仰角在 fov 50° 下画面下缘有效仰角为 **−16°**，**直接违反用户决策「禁止看底部」**，不只是可读性问题 |
| C-2 | Basic 档战斗事件相机抖动 | 美术：开启<br>UX：关闭 | **三档统一关闭**。开启时上限：振幅 ≤2px / 时长 ≤120ms / 单次事件最多 1 次 / 可关 / 不得伴随相机位移 | ✅ **美术已采纳**（`accessibility.md §7.1`） |
| C-3 | 相机阻尼的表达方式 | 美术：逐帧 lerp 0.08/0.12/0.20<br>UX：指数阻尼 `k` | **`k = 5.0 / 7.7 / 13.4`**，不再用逐帧 lerp | ✅ **美术已采纳**，换算已由双方独立复核（60fps 下 1−exp(−k/60) = 0.0800/0.1202/0.2000） |
