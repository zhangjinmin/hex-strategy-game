## 1. 真实目标重定义（第一性原理）

用户给出的是**实现路径清单**，真实目标需从结果倒推：

| 用户表述（路径） | 真实目标（结果） |
|---|---|
| 去掉导弹 | 武器表现可信、克制（已完成 ✅） |
| 飞行"诡异的很"、运输舰侧着飞 | **运动可信**：朝向与位移一致、有质量感、机动有预见性 |
| 六方向惯性/加速度、提前量 | **机动有深度**：布阵与拦截是"驾驶"而非"平移"，操作有技术含量 |
| 立体军阵、真正的 3D 作战 | **空间有层次**：3D 不再是 2D 的皮，高度是战术维度 |
| 每舰 = 战术集群，各有 AI | **规模感 + 分层指挥**：上百集群的宏大调度，宏观意图由下级自主细化 |
| 对战逻辑粗暴、缺乏应变 | **决策有深度**：分支判断、形势应变、协同（集火/包抄/撤整）可见 |

关键澄清——**"战术集群"是组织学概念，不是多智能体系统**：

- "军长指挥上百个连长"的正确读法 = **分层决策权**。连长（集群）的自主权是**有限菜单**内的选择权，不是自由意志。
- 集群 AI 的权限清单（下放）：目标选择、开火时机、微机动（占位/避让/保持阵位）、受损应变。
- 保留给玩家/舰队层（不下放）：阵型、航向大机动、任务分兵/归队——已有 `CommandAuthority` 六级权威 + `TacticalCommandSystem` 意图体系（奉令/临机/交战/整补）直接复用，**不重建**。
- 由此，"每舰 = 战术集群"在本项目中落地为：**每舰 = 一个带本地决策循环的战术单位**，舰队级下发"交战计划"（约束 + 优先级），舰级在约束内自主执行。概念无需新建实体层级。

## 3. 现状诊断（证据链）

### 3.1 移动/飞行现状

| 层 | 机制 | 参数 | 性质 |
|---|---|---|---|
| 舰队级 | 位移预算 + 速度 lerp，`thrustDir = facingSmooth`，推力对齐衰减 | `FLEET_ACCEL = 0.055`（τ≈0.27s），`THRUST_IDLE = 0.45` | **伪惯性**：速度大小有惯性，方向没有独立动量；掉头≈停船原地转 |
| 单位级 | `moveTowardsAtSpeed` 直线追阵位槽 | `UNIT_FORMATION_SPEED = 0.9`，`UNIT_VIS_TURN_RATE = 0.16`（≈9.2°/帧@dt=1） | **几何平移**：无加速度、无提前量、无避碰；舰首只是跟随位移航迹的显示限速 |
| 后勤舰 | `moveAuxShips` 按 `aux.heading` 限速转向 + 对齐门推进 | `AUX_SPEED = 0.7` | 2D 侧已沿舰首推进（无侧滑） |

### 3.2 侧飞案例的结构性教训（已修，但教训要制度化）

根因链（v60 已修复，作为架构教训保留）：

```
BattleScene.ts:6794   if (isSupplyUnit(u)) return;        // 阵型循环跳过运输舰
        ↓ 运输舰永不生成 visHeading
Battle3DOverlay.ts:3766  visHeading 缺失 → 回退 fleet.facingSmooth
        ↓ 3D 模型舰首 = 舰队朝向，位移 = aux.heading
用户实报「明明在转向，却边转向边侧着飞」
```

修复：`BattleScene.ts:7303` 在 aux 同步循环补 `(aux.unit as any).visHeading = aux.heading;`。

**制度化结论**：朝向/运动必须"单一真源、全量生成"。任何"某类单位跳过真源字段生成 + 显示层回退默认值"的组合都是潜伏侧飞 bug。目标架构中，`visHeading` 类字段的生成收口为一个全量函数，禁止按单位类型跳过；显示层回退只允许存在于"首帧未初始化"窗口。

### 3.3 射击/选靶现状

已有的深度（好底子，保留）：
- `fireGate`（接战/受击/射程门，aiDirector 纯函数）
- `authGateOk` 六级权威火控门（none / return_fire_only / attack_target_only / free），`BattleScene.ts:6915-6928`
- 受击必还击（v55，`pickTarget` 复仇加权 + 滞回，`BattleScene.ts:5717-5740`）
- 射界过滤 `isTargetWithinFireArc`、地形射程修正 `getTerrainRangeMul`

**断点（"粗暴"的直接来源）**：两条选靶路径并存——

| 路径 | 位置 | 行为 |
|---|---|---|
| A：机动/还击目标 | `BattleScene.ts:5740` `pickTarget(cands, prevTargetId)` | 评分 + 滞回 + 复仇加权（有深度） |
| B：开火具体选舰 | `BattleScene.ts:6956` `inRangeUnits[Math.floor(Math.random() * ...)]` | **均匀随机**。无威胁评估、无集火、无残血/高价值优先 |

即：**"打不打、打谁家"有深度，"打哪一艘"是掷骰子**。玩家观感上的"缺乏应变"主要来自 B——三艘巡洋各打各的随机目标，永远凑不出集火秒杀；受损旗舰不会被补刀；高威胁炮舰不会被优先压制。

## 6. 目标架构

### 6.1 战术集群（舰级本地决策循环）

```
玩家（方面军宏观调度 / 意图 / 直接指令）
   ↓ CommandAuthority 六级权威 + TacticalCommandSystem 意图标签
舰队级（编队、航向大机动、任务、火力协调 → 生成"交航计划"）
   ↓ 交战计划 = { 集火优先级表, 距离带约束, 阵位槽, 交战规则 }
舰级 clusterAI（每舰 = 战术集群，纯函数本地循环）
   ├─ 攻防选择: 选目标（威胁评分，含集火表加权）
   ├─ 机动判断: 微机动（占位、避让、保持阵位、受损脱离）
   └─ 开火时机: 射距带 + 射界 + 冷却
```

- 新模块 `clusterAI.ts`（纯函数，零实例状态；滞回量存单位字段）。**严禁**在 BattleScene 埋散落阈值（v29 铁律）。
- 集群协作的最小实现 = **舰队级集火表**（`fireCoordinator`：按威胁评分排序生成目标优先级，舰级选靶时对表内目标加权）。比"集群间协商协议"便宜一个量级，且直接命中"缺乏应变"观感。
- 复用不重建：权威/意图/分兵/撤退/阵型互克全部沿用现有真源。

### 6.2 六方向惯性 / 加速度 / 提前量

**六方向定义（H1）**：六角格 6 个轴向 `e_0..e_5`。舰船速度为轴向量合成：

- `v = Σ s_i · e_i`（连续合成，六角轴向作基底），加速度受限：`|dv/dt| ≤ a_max`，转向另有角速率上限 `ω_max`。
- 由此**提前量成为必然**：改向/变速需要时间 ⇒ 布阵按"到槽时间"提前转向，交战按"汇合点"前置追踪。
- 拦截几何：`P_lead = P_target + v_target · t_close`，其中 `t_close` 由相对速度迭代 1~2 步收敛（纯追踪→前置追踪切换）。
- 分层保留：舰队级伪惯性（`FLEET_ACCEL`）**保留**为"大群质量感"；新增的加速度向量在**舰级**生效（集群级惯性）。两层叠加即"大船迟缓、小船灵巧"的天然手感分层。
- 拖刀（撤退）例外：位移方向允许 ≠ 舰首（现有 `retreatDoctrine` 语义保留），这是唯一合法"侧飞"。

**量化验收（继承 v40-v48 判据铁律）**：

| 判据 | 阈值 | 测法 |
|---|---|---|
| 摇头 | `sign(Δθ)` 翻转次数 = 0（稳态段） | 台架逐帧采样，禁止"绕心累计转角"（零判别力） |
| 侧滑角 | 位移方向与舰首夹角 < 15°（拖刀除外） | 逐帧中位数 + P95 |
| 到位超调 | 阵位槽到位后漂移 < 0.3 槽宽 | 到位判定后 3s 窗口 |
| 提前量有效性 | 拦截场景截获时间 < 纯追踪基线 20% | 对照实验台架 |

### 6.3 立体军阵

- **两步走**（H2）：
  - P3a：z 分层槽位——按战术角色分高度带（前卫低、主力中、指挥/航母高，具体编成走 `formations.ts` 扩展），3D 阵型几何 = 2D 槽位 + z 分层；z 参与**视觉判定**（模型遮挡关系、俯仰角）。
  - P3b：z 参与**战术判定**——俯仰射界锥、高度差命中修正、"上方压制"加成（数值走 `aiDirector` 理想交战距体系）。
- 3D 层定位不变：`Battle3DOverlay` 仍是唯一视觉真源，Phaser 画布在指挥制下隐藏但不可删。z 数据进 `tilesList/unit` 数据层字段，**不在渲染层编造**。

| 分支判断粗 | 形势分级（优势/均势/劣势）→ 集群行为参数包 | `aiDirector` 评分权重按形势分级切换 |

## 7. 反方与反常识审查

1. **若失败，最可能失败在哪？** 双真源复发。2D 判定层与 3D 投影层各有朝向/位置时（如侧飞案例），任何新运动学都会放大撕裂感。**对策**：运动学升级时把"位置/朝向/速度"三字段的真源归属写进 ADR（28 号文档补节），显示层只读不写。
2. **20/80？** 集火表 + 威胁评分选舰（预计 < 200 行 + 台架）解决"缺乏应变"观感的大半；运动学只做"舰级加速度向量 + 前置追踪"即可拿到"提前量"手感，**不需要**全六自由度。这两件事先做，立体军阵与形势分级可以靠后。
3. **激进方案？** 全 6DOF + 飞机式机动（路线 D）确实"数倍更真"，但太空歌剧的舰队战观感是"风帆线列"而非"战斗机格斗"（银英原作即此）；6DOF 会把操作复杂度推给玩家且与六角格判定层冲突。**若未来要做战机小队战**，6DOF 局部启用（战机独立运动层），舰队仍走六方向。
4. **从零设计还会这样吗？** 不会。会先定"判定平面（六角格）+ 呈现体积（3D）"的分离契约，再写运动学；现状的耦合是历史沉积。但推倒重来在零测试保护下不可承受——B 路线本质是"按从零设计的目标架构，分段替换现有实现"。
5. **高手未普及的做法？** "AI 集群不直接互相协商，而是订阅同一个作战计划"（共享黑板模式）。本方案的集火表即此——省掉协商协议的复杂度，协同效果等价于"军长下达火力分配"，恰好符合用户"军长-连长"心智模型。
