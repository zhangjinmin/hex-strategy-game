# 05 · 3D 化引入的可读性风险清单

判据：本清单只列 **3D 视角相比 2D 俯视新引入**的问题。2D 时代就存在的缺陷（如 `emergency_repair` 描述与实现不符）不在本清单，记录在 `README.md §3.1`。

严重度定义：

| 级别 | 定义 |
|:----:|------|
| **S** | 直接导致玩家误判并做出错误决策，或根本无法完成操作 |
| **A** | 显著增加认知负荷，高负载战斗（8v8 / 3x 速度）下失控 |
| **B** | 可感知的体验退化，玩家可通过操作习惯补偿 |
| **C** | 边缘情况，影响有限 |

「必须解决」= 不解决则不能进入 playtest。

## 2. 详细条目

### R-01 · 前排舰船遮挡后排 — **S / 必须解决**

**为什么 2D 不存在**：2D 俯视是正交投影且所有物体共面，不存在深度遮挡。

**3D 具体表现（含遮挡纵深计算）**

单位换算基准（美术 `ship-assets.md` §5.0）：**1 世界单位 ≈ 15 px**；常规舰悬空 0.67 单位、舰高 0.35；旗舰悬空 1.73 单位、舰高 ≈0.45。

遮挡纵深：**Δ = (S_顶高 − T_悬空) / tan(θ_eff)**，其中 `θ_eff` = **有效仰角** = 相机中心仰角 ± 半视场角（**屏幕下缘最低**）。按 fov = 50° 计：

| 中心仰角 | 屏幕下缘 `θ_eff` | 常规舰挡常规舰 | 旗舰挡常规舰 |
|:--------:|:----------------:|:--------------:|:------------:|
| **27°**（`0.35π`，已采纳） | 2° | 10.0 单位 = **150 px** | 43.2 单位 = **649 px** |
| 27°（屏幕中心处） | 27° | 0.69 单位 = 10 px | 2.96 单位 = 44 px |
| **9°**（美术 R0 原值 `0.45π`） | **−16°** | 33 px（中心处） | 143 px（中心处） |

两条结论：

1. **遮挡不是均匀分布的，它集中在画面下缘。** 中心处遮挡纵深仅 10px（小于阵型间距 28px），但下缘可达 150px ≈ 3–4 个舰位；旗舰在下缘可挡住其后 649px 内的一切。因此缓解措施必须按**画面下缘**的最坏情况设计，不能按中心仰角设计。
2. **9° 中心仰角在 fov 50° 下，画面下缘的有效仰角是 −16°，即相机在画面下缘看向棋盘平面以下。** 这不只损害可读性，它直接**违反用户决策「禁止看底部」**。这是 `maxPolarAngle` 必须收到 `0.35π` 的独立论据（与晕动症无关）。美术侧已在 R1 采纳。

**缓解方案**：
1. **收紧仰角下限**至 `maxPolarAngle = 0.35π`（仰角 27°）——见 Q1。
2. **被遮挡轮廓透视（X-ray silhouette）**：舰船被其他几何体遮挡时，以 `depthTest=false` 的简化轮廓描边显示，`alpha = 0.35` `[PLACEHOLDER]`，仅勾外形不填充。可在设置中关闭。
3. **决策标记强制前置**：HP 条、状态图标、阵营标记、编号徽章全部走 W+ 层 `depthTest=false`，永远绘制在最上层。`renderOrder` 分层：玩家舰队 > 敌方舰队 > 地形。
4. **`V` 键一键顶视**：瞬时消除全部遮挡。

**验收判据**：8v8 战斗中，任意时刻玩家都回答得出"场上有几支舰队、各自 HP 档位"。

### R-02 · 深度感知错误导致误判距离与射程 — **S / 必须解决**

**为什么 2D 不存在**：2D 俯视的屏幕距离 = 世界距离（只差一个常数 zoom 系数）。玩家用尺子量屏幕就能得到准确距离。

**3D 具体表现**：透视投影下，屏幕上相等的两段距离对应完全不同的世界距离。以「棋盘填满屏幕」的最大拉远档为参照（此时战列舰投影 ≈25px，见 §4 定标），同样 200px 的屏幕间隔，在画面下缘对应约 90px 世界距离，在画面上缘对应约 260px 世界距离——**相差近 3 倍**。玩家会系统性高估远处目标的距离、低估近处目标的距离。射程判断、拦截预判、集火时机全部建立在距离判断上，误判直接等价于决策错误。

**缓解方案**：
1. **接地投影是唯一深度锚点**：每艘舰船必须在棋盘平面上有实心椭圆接地投影（美术已定）。玩家的深度判断应建立在"投影在棋盘上的哪个格子"，而不是"舰体在屏幕上的哪个位置"。
2. **垂直连线**：舰体中心到接地投影之间画细垂线，仰角越低线越长——这本身就是深度线索。
3. **射程用贴地圆表达，不用屏幕距离**：射程环画在棋盘平面上（W+ 层贴地圆），玩家读的是**贴地圆之间的交叠关系**，这是与相机角度无关的正确判据。
4. **悬停显示规则距离，不显示视觉距离**：tooltip 中的距离以**格（hex）**或**世界单位**显示，与战斗规则的计算口径一致（现有规则用 `Phaser.Math.Distance.Between` 的像素距离）。
5. **棋盘网格本身就是标尺**：六边形棱柱网格提供了全局深度参照，不得因性能预算砍掉。

**验收判据**：让玩家在 3D 下目测"这两支舰队是否在彼此射程内"，与规则层实际判定比对，正确率目标 ≥ 85% `[PLACEHOLDER]`。

### R-03 · 半透明舰船叠加，信息糊成一片 — **S / 必须解决**

**为什么 2D 不存在**：2D 舰船是 11×33 的贴图精灵，不透明，且阵型间距 28px 保证不重叠。

**3D 具体表现**：决策 2「半透明实体 + 线框叠加」引入 alpha 混合。多艘半透明舰船在屏幕上重叠时，颜色累加趋近白/灰，阵营色失效、线框纠缠、HP 条与状态图标叠在一起。8v8（64 艘）在混战中心必然发生。

**缓解方案**：
1. **alpha 下限 0.55** `[PLACEHOLDER]`：半透明实体层的不透明度不得低于此值。低于此值，两层叠加后阵营色即不可辨。线框边缘保持 `alpha = 1.0`。
   > **亮度必须随 alpha 同步联动（美术侧补充，已采纳）**：特效滑杆归零、舰船切到 `alpha = 1.0` 时，实体层亮度必须同步从 `×0.35` 回到 `×1.0`。否则不透明舰船会变成**实心暗块沉入 `0x02040a` 背景**，比半透明更不可读。美术侧已在 `materials-and-lighting.md §3.4` 做成耦合表。**这是一条容易漏掉的反向失效——"关掉特效"反而让画面更看不清。**
2. **阵型间距按舰体尺寸重算**：2D 的 `spacing = 28px` 是为 11×33 的贴图设计的。3D 舰体尺寸不同（战列舰 2.2 单位 = 33px），必须重算，判据是「**任意缩放下，同编队相邻舰船的屏幕投影不得重叠**」。
3. **信息层上移出舰体重叠区**：HP 条、状态图标一律绘制在舰体**上方偏移**位置（不在舰体包围盒内），且 `depthTest=false`。
4. **半透明物体排序**：按相机距离从远到近绘制，关闭 `depthWrite`（Three.js 半透明排序问题）。
5. **LOD 聚合**：当同屏舰船数 > 32 或单舰投影 < 24px 时，强制降级到 **L3 编队聚合标记**（见 §4 重定标后的阈值），从根本上消除叠加。

**验收判据**：8v8 混战中心截图，灰度化后仍能数出舰船数量。

### R-04 · 相机角度变化后信息锚点漂移 — **A / 必须解决**

**为什么 2D 不存在**：2D 的 HP 条/伤害数字直接画在世界坐标 → 屏幕坐标的线性映射上，无透视、无抖动。

**3D 具体表现**：D 层（DOM）元素每帧重算投影，舰船的阵型呼吸浮动（`BattleScene.ts` 中的 `breatheX/Y` 正弦）会被放大成高频抖动；相机转动时标签会瞬间跳位；标签可能飘出屏幕或飘到屏幕外对象的错误方向。

**缓解方案**：
1. **指数阻尼平滑**：`screenPos += (target - screenPos) * (1 - exp(-25 * dt))`，`k = 25.0` `[PLACEHOLDER]`。
2. **四种边界处理**（见 `01` §5）：正常显示 / 相机背后→隐藏 / 视口外→钳制到边缘+箭头 / 视口内被遮挡→半透明虚线边框。
3. **深度排序**：D 层元素 `z-index` 按投影深度排序（战略层 `ThreeStrategicMap.ts` 已有实现可复用）。
4. **聚合显示**：两支舰队的屏幕距离 < 40px 时，标签合并为一个（`第2舰队 +1`），避免标签堆叠。

### R-05 · 透视缩放导致远处信息不可读 — **S / 必须解决**

**缓解方案**：屏幕恒定尺寸补偿（公式与参数见 `01` §3）+ 四级信息 LOD（`01` §4）+ L3 编队聚合标记永不消失。

**验收判据**：在最大缩放档（全图可见）下，玩家仍能读出场上有几支舰队、各剩多少血。

### R-06 · 战斗发生在视野外，玩家无感知 — **S / 必须解决**

**为什么 2D 不存在**：2D 初始 zoom 0.3–0.8，整个战场始终在屏幕内。不存在"看不见的战斗"。

**3D 具体表现**：3D 相机的视锥只覆盖战场的一部分。玩家聚焦局部战场时，另一侧的遭遇战、己方舰队被集火、旗舰沉没，全部在屏幕外发生。玩家会突然发现"我的舰队怎么没了"。

**缓解方案**：
1. **屏幕边缘方向指示器**（见 `04` §1.2）：玩家单位受伤/损失时，按来源方位在屏幕边缘显示弧形提示。
2. **战术雷达（强烈建议，Q2）**：右上角 2D 俯视小地图。这是**唯一能同时解决 R-02 / R-06 / R-11 的措施**，且实现成本极低——2D 版本的所有平面坐标已经存在，只需 canvas 绘制。内容包括：
   - 所有已知（非 `fuzzy`）舰队的位置与阵营
   - 玩家视野范围（视野环）
   - **当前相机视锥在棋盘平面上的投影梯形**（玩家一眼看出"我在看哪里"）
   - 屏幕外事件的高亮闪烁
   - 支持点击 → 相机飞向该位置
3. **事件聚合到边缘与日志**：屏幕外伤害不生成世界空间数字，聚合到边缘指示器；完整数值只在战斗日志。

**验收判据**：玩家舰队被屏幕外敌人攻击后，玩家在 0.5s 内能说出"哪支舰队在挨打、从哪个方向"。

### R-08 · CRT 后处理糊掉细线框与文字 — **A / 必须解决**

**为什么 2D 更轻**：2D 的线框是 1px 直线，边缘锐利；3D 的线框经过抗锯齿 + 透视缩放后本就更细更淡，再叠加上 bloom + 色差 + 噪点，直接消失。

**缓解方案**：
1. **文字全部走 DOM 层**，在 CRT shader **之外**合成。这一条解决了绝大部分问题。
2. **世界层标记也需在后处理之外**：编号徽章、HP 条、状态图标建议渲染到一个独立的正交覆盖层（W+ 层），与主 3D 场景合成后再施加后处理时**排除**该层。若工程上实现成本高，则退而求其次：后处理强度 > 50% 时自动对这些标记做 1px 描边补偿。
3. **色差在低强度时优先关闭**：色差（chromatic aberration）是糊字的主因，扫描线次之。规则：**滑杆 ≤ 30% 时，色差权重线性归零**。
4. **bloom 阈值提高**：避免细线框过曝成一团。bloom 不得作用于 D 层与 W+ 层。
5. **滑杆 = 0% 时后处理链整体 bypass**（硬要求）。

### R-09 · 低仰角下接地投影与舰体重叠 — **A / 建议解决**

**表现**：仰角低于 ~20° 时，接地投影在屏幕上被压缩成一条线并与舰体重叠，失去"深度锚点"作用（直接削弱 R-02 的解法）。

**缓解**：
1. **严禁改用几何抬升解决 z-fighting。** 我 R0 版写的「投影抬升至平面上方 2 单位」是错的：按 1 单位 ≈ 15px，2 单位 = **30px**，高于旗舰悬空高度 26px，投影会浮到舰船上方。正确解法是 **`polygonOffset`**（GPU 深度偏移，与单位、距离都无关，投影严丝合缝贴地）。——本条同样修正 R-15。
2. **垂线连接**：舰体中心到接地投影之间的细垂线同时充当深度线索（R-02 缓解 2）。
3. **收紧仰角下限**：`maxPolarAngle = 0.35π` 已在美术 R1 采纳，本项随之从 A 降为 **B 级**。

### R-11 · 阵型在透视下变形，无法一眼辨识 — **A / 必须解决**（**Q2 已拍板加雷达，本项的主要解法已确定**）

**为什么 2D 一目了然**：2D 俯视下，雁行阵就是屏幕上的一个 V 字、单纵阵就是一列、圆阵就是一个环。玩家扫一眼就知道双方阵型，进而预判阵型克制

（现有规则 `BattleScene.ts:2695`：`beats = { wedge: 'spindle', spindle: 'circle', circle: 'square', square: 'line', line: 'wedge' }`，命中 `×1.3` / 被克 `×0.7`，且**阵型切换零成本**——数字键 `1`–`5`，无 CP 无冷却）。

**3D 表现**：透视下 V 字被压扁成一条斜线，圆阵变成椭圆，方阵变成梯形。玩家失去阵型判断 → 失去对克制关系的预判 → 现有规则中阵型克制的策略深度**在玩家侧归零**。

> **本项影响的量级**：阵型克制是 **±30% 伤害修正**，与 2CP 的「集中火力」（+30%）同量级，但**切换免费**。所以"能不能读出对方阵型"直接决定这 ±30% 落在谁头上——这是战斗中最划算的单项决策，前提是要看得见。

**缓解**：
1. **★ 战术雷达（Q2 已拍板，本项的主解法）** —— 雷达是 2D 正俯视，**阵型形状零变形**；且全局可见，能一眼对比全部 8 支舰队的阵型做克制判断；**零操作持续可读**。实现要点：雷达尺度 1:11.4，编队跨度仅约 9.8px，**画阵型字形图标**（`V` / `│` / `◆` / `○` / `▦`）而不是画真实队形。**完整规格见 `08-tactical-radar-spec.md` §1。**
2. **贴地编队轮廓线**：在棋盘平面上连接同编队各舰接地投影的凸包，画出阵型形状（W+ 层，2–3px，阵营色）。
   > 注意它的局限（不足以替代雷达）：① 画在棋盘平面上**仍受透视压缩**，仰角 27° 时纵向压缩到 `sin(27°) = 0.45` 倍，V 字变扁 V；② 要看清需转/拉相机，是**主动成本**；③ **无法做对比**——阵型克制是双方关系，需要同屏对照。
3. **编队标签显示阵型中文名**：雁行 / 单纵 / 纺锤 / 圆阵 / 方阵。
4. **阵型切换动画**：贴地轮廓线 0.4s 重绘过渡 + 标签文字变化 + 战斗日志一行。

### R-14 · 点击拾取困难 — **S / 必须解决**（R1 重定标：风险主体不是"远处舰船"，是**舰载机**）

**R0 版的判据错了。** 我按"远距离下舰船投影 3–8px"设计，但按 1 单位 ≈ 15px 重算（§4 定标），**战列舰在可达缩放范围内的投影是 25px（全图档）～333px（最近档），全程大于 24px 最小可点直径**。战列舰/巡洋/驱逐的拾取没有实质困难。

**真正的风险是舰载机。** 美术 `ship-assets.md §5.6`：Fighter 尺寸 0.4 × 0.30 × 0.06 单位 = **6 × 4.5 × 0.9 px**（2D 基准）。换算到屏幕：

| 缩放档 | 战列舰屏幕尺寸 | **舰载机屏幕尺寸** | 是否达到 24px 最小可点直径 |
|--------|:--------------:|:------------------:|:--------------------------:|
| 全图档（棋盘填满屏幕） | 25 px | **4.6 px** | ❌ |
| 标准交战档 | 48 px | **8.7 px** | ❌ |
| 最近档（`minDistance` = 8 单位） | 333 px | 61 px | ✅ |

舰载机由航母持续释放（`BattleScene.ts` 的 `carrierFighters`），数量多、个体极小，**在任何常规缩放下都点不中**。

**缓解方案（按优先级）**：
1. **舰载机不参与单体拾取，归属到母舰编队。** 点击任意舰载机（或其 24px 邻域）→ 选中其所属母舰的编队。依据是规则而非便利：命令的 `targetType` 全是 `enemy_fleet`，**不存在作用于单舰（更不用说单机）的玩家指令**；2D 版本舰船也完全不可选中。这条把 R-14 从"补偿缺陷"变成"规则对齐"。
2. **拾取代理体兜底**：`02` §3 的四层递进拾取仍然保留，作为未来扩容（更大地图/更小窗口/新增单位）的兜底，不是主解法。
3. **`dMax` 硬约束（结构性解法）**：**3D 不应复刻 2D 的 `zoom = 0.2` 最小缩放。** 2D 在 zoom 0.2 下地图只占屏幕宽度的 26%，战列舰缩到 6.6px——这是 2D 遗留的屏幕空间浪费。3D 的 `dMax` 应定义为「**棋盘完整填满屏幕短边**」，此时战列舰 ≈25px，`≥ MIN_PX` 直径 24px，**拾取问题在构造上被排除**。
4. **`Tab` 循环器**：键盘等价路径，同时满足可访问性验收项。

### R-15 · 棋盘网格莫尔纹与 z-fighting — **C / 不必须**

**缓解**：
1. **z-fighting 用 `polygonOffset`，不用几何抬升。** R0 版写的「网格线与平面间留 0.5 单位偏移」同样错误：0.5 单位 = 7.5px，在远处会被透视放大成可见的悬浮层。与 R-09 同理，几何抬升解决不了深度冲突，只有 GPU 深度偏移能。
2. **摩尔纹来自线条密度，不是亮度。** 远处按距离**降线数**（LOD 简化几何）而非降亮度——这一点很重要，因为美术侧一度提出的"远处线框按距离淡出"与 **R-17「边缘光不随距离衰减」直接冲突**，已由美术侧撤回改为降线数方案。
3. 不使用高对比细密网格。

### R-16 · 事件相机抢夺控制权 — **A / 建议解决**

**表现**：一骑讨（双方舰队距离 < 95px）触发 `setZoom(1.5)` 持续 2500ms + 台词。2D 下这只是"放大看看"，因为放大后全场仍在屏内、方位不变。3D 下相机移动会让玩家**丢失空间定向**（"我现在在看哪里""我刚才在关注的那支舰队呢"）。

**缓解（Q4）**：默认改为不移动相机 —— 时间减速 0.5x + 台词卡 + 双方旗舰双高亮 + 雷达闪烁。若保留相机运动：必须可关闭 + 任意输入立即中断 + 结束后完整恢复原位姿 + 单次上限 2.5s。

### R-17 · 暗背景下低对比舰船难以分辨 — **A / 必须解决**

**表现**：背景 `0x02040a` 极暗，半透明舰船在暗背景下对比度不足，尤其深色阵营色（帝国紫 `0xc084fc` 在低 alpha 下会沉入背景）。

**缓解**：
1. **舰体边缘光强度不随距离衰减**（或衰减下限 0.6 `[PLACEHOLDER]`），保证远处舰船仍有可辨轮廓。
2. **接地投影提供暗底衬托**：投影参数采纳美术 R1 修订 —— **轮廓 0.85 + 填充 0.25**（我 R0 要求的是实心 alpha ≥ 0.8，美术指出实心亮盘在 CRT 风格下喧宾夺主、且亮度 0.55 逼近 Bloom 阈值 0.62）。**承载形状识别的是 0.85 的轮廓线**，填充只负责暗底衬托，因此该折中可接受。
   - 附带硬条件：**轮廓强度豁免于特效滑杆**（美术已写入 `materials-and-lighting.md`，0% 档反而提到轮廓 0.95 / 填充 0.35）。
   - **验收判据**：灰度截图下，接地投影形状必须仍能一眼区分「圆角矩形（同盟）/ 尖椭圆（帝国）」。若实测不足，美术预留了填充上调至 0.40 的通道，不建议更高。
3. **不要依赖 bloom 提高可辨度** —— bloom 会在特效归零时消失，且加剧 R-03。
4. **注意反向失效**：`alpha → 1.0` 时亮度必须同步回 `×1.0`（见 R-03 缓解 1），否则"关掉特效"会让舰船变成更难辨认的暗块。

## 4. 缩放范围定标（R1 新增，本文件所有尺寸数值的基准）

**为什么需要这一节**：我 R0 版的信息 LOD 阈值（`01` §4：L0 ≥32px / L1 16–32px / L2 8–16px / L3 <8px）是按"2D `zoom = 0.2` 时战列舰 6.6px"推的。按 1 单位 ≈ 15px 重算后，**若 3D 的 `dMax` 定义为"棋盘填满屏幕"，则 L2 / L3 两档永远不可达**，整张 LOD 表失效。这里重新定标。

### 4.1 可达的舰船屏幕尺寸范围

按 fov = 50°、1920×1080、1 单位 ≈ 15px：

| 缩放档 | 相机距离 | 可见宽度 | **战列舰屏幕尺寸** | 备注 |
|--------|:--------:|:--------:|:------------------:|------|
| 最近（`minDistance` = 8 单位，美术 C2 硬约束） | 8 单位 | 13.3 单位 = 199 px | **333 px** | |
| 标准交战 | ~55 单位 | 92 单位 | **48 px** | |
| 默认档 `dMax`（棋盘填满屏幕宽度） | ~100 单位 | 167 单位 = 2500 px | **25 px** | **已能看全战场** |
| **全局档 · 方案 B（建议）** | 顶视，179 单位 | 棋盘 1080×1080 | **14.3 px** | 棋盘占屏高 100% / 屏宽 56% |
| **全局档 · 方案 A（用户描述）** | 27°，379 单位 | 630 单位 = 9450 px | **6.6 px** | 棋盘仅占屏宽 **26%** |

**默认档的可达区间：25 px ～ 333 px。** L2 / L3 原阈值（<16px / <8px）在此区间外，必须上调。

**启用全局档后，可达区间下延到 6.6px（方案 A）或 14.3px（方案 B）**——这正是 L2 / L3 两档重新变得有意义的原因。**完整双档规格见 `09-dual-zoom-modes.md`。**

> ⚠️ **几何提示**：默认档 `dMax`（100 单位）**已经能看全战场**。全局档比它远 3.8 倍但看到的是同一个完整战场，只是更小。全局档的真实价值不是"看得更全"，而是**"距离越远透视越接近正交，位置关系更准确"**——而这个收益用**顶视**可以免费拿到（方案 B），不必付 74% 屏幕浪费的代价。详见 `09` §1。

### 4.2 重定标后的信息 LOD 阈值

| LOD | 新的屏幕投影高度判据 | 显示内容 |
|:---:|---------------------|----------|
| **L0** 全信息 | ≥ 48 px | 舰体全细节 + 舰种图标 + 单舰 HP 条 + 状态图标（≤3）+ 蓄力条 +（旗舰）舰名 |
| **L1** 标准 | 24 – 48 px | 舰体 + 阵营标记 + 单舰 HP 条（简化：无分段）+ 状态图标（≤2） |
| **L2** 全图档 | 12 – 24 px | 阵营标记 + **编队聚合 HP 条** |
| **L3** 聚合兜底 | < 12 px | **编队聚合标记**（▲ / ◆ + 聚合 HP 条 + 舰数 `n/8`） |

**L2 是常规游玩必然到达的档位**（默认档 `dMax` 的 25px 落在 L1/L2 边界；窗口更小时进 L2；**启用全局档方案 B 后 14.3px 稳定落在 L2**）。
**L3 是兜底档**：默认档下不触发，但在**全局档方案 A（6.6px）**、未来扩容、小窗口、以及**舰载机**（全图档 4.6px，见 R-14）四种情况下会触发。

### 4.3 与美术渲染 LOD 的映射（消除两套命名体系）

美术 `ship-assets.md §4.4` 已给出映射，但**美术的距离阈值与我重定标后的屏幕尺寸判据不自洽**，需要同步修正：

| 美术渲染 LOD | 美术 R1 距离阈值 | 该距离下战列舰屏幕尺寸 | **UX 建议修正后阈值** | 对应信息 LOD |
|:------------:|:----------------:|:----------------------:|:---------------------:|:------------:|
| LOD0 完整几何 | < 8 单位 | > 333 px | **< 55 单位（> 48 px）** | L0 |
| LOD1 简化几何 | 8 – 20 单位 | 133 – 333 px | **55 – 111 单位（24 – 48 px）** | L1 / L2 |
| LOD2 billboard | > 20 单位 | < 133 px | **> 111 单位（< 24 px）** | L3 |

**问题**：美术 R1 的 LOD2 阈值是 `> 20 单位`，即战列舰在 **133 px** 时就退化成 billboard —— 此时它比全图档（25px）还大 5 倍，是全屏最容易看清的时候。按此实现，玩家一拉远就看到满屏贴图图标。

**建议**：阈值统一由**屏幕投影高度**驱动（而非世界距离），美术 LOD2 的触发线上移到 `< 24 px`。同时也解决了美术自己标注的"切换建议按距离或像素判定，避免抖动"——**两者应统一为像素判据**，避免两套判据给出不同结果。

滞回区间：阈值上下各留 15% 滞回（如 24px → 20.4px / 27.6px），防相机连续缩放时抖动 `[PLACEHOLDER]`。

### 4.4 Q7 已定案：双档方案（默认档 + 全局档）

用户拍板**双档**而非单选：

| 档位 | 定义 | 战列舰 | 用途 |
|------|------|:------:|------|
| **默认档（主用）** | `dMax` = 棋盘填满屏幕 | 25 px | 常规游玩 |
| **全局档（辅助）** | 一键拉远看全战场 | 6.6 px（A）/ 14.3 px（B 建议） | 主动查看全局态势 |

**完整规格见 `09-dual-zoom-modes.md`**（切换交互、固定位姿、全局档信息呈现降级、可操作权限、使用场景、与雷达的互补关系）。

我在 `09` §1 提出的修正建议：**全局档改用「顶视 + 填满屏幕短边」（方案 B）**，战列舰从 6.6px 提升到 14.3px（L3 → L2）、屏幕浪费从 74% 降到 44%、几何保真度从"近似正交"变成"正交"。若用户坚持保留斜视 3D 观感的方案 A，则 §3 的全部降级规则按 L3 档启用。

> 注：本文件 R0 版的"dMax 应取棋盘填满而非复刻 2D zoom 0.2"论证仍然成立，且已被采纳为**默认档**。全局档是在此之上的增强，不是回退。Q2 雷达通过之后，全局档的定位从"必需品"降为"增强项"——雷达零操作成本，全局档精度更高，二者互补（见 `09` §5.3）。

**代价是全局态势感知范围缩小 —— 这必须由战术雷达（Q2）补偿。** 若 Q2 不通过，`dMax` 需要放宽到 2D 等效（战列舰 ~7px），则 L2/L3 重新成为主用档，且 R-14 的拾取问题会回到严重状态。**Q2 与本节定标强耦合，建议一并裁决。**
