## 一、核心结论（先看这个）

**你要的"运输舰前出补给"在当前代码里根本不存在。**

当前补给是**纯地块连通性驱动**，与"运输舰"这个舰种没有任何关系。

### 证据链

1. **补给判定 = 地块 BFS 连通性**（`BattleScene.ts:788-820` `updateSupplyNetwork`）
   - 从己方 `castle`/`planet` 出发做 BFS，把同 team 地块标记 `connected`
2. **舰队能否补给 = 旗舰站在哪个格子上**（`BattleScene.ts:835-880` `processSupplyAndCapture`）
   ```js
   const currentTile = this.tilesDict[`${fQ},${fR}`];   // 旗舰所在格
   if (currentTile && currentTile.ownerId !== 0 && currentTile.connected) {
       const tileFac = this.factionMap.get(currentTile.ownerId);
       if (tileFac && tileFac.team === myTeam) inSupply = true;   // 格子连通 = 有补给
   }
   ```
3. **`supply` 舰种在战斗中零逻辑**：全仓 grep `classType === '补给'/'supply'` 在战斗层**无任何命中**
   → 运输舰进了战场也只是一个普通低攻单位，**不会给友军补给**
4. **断粮惩罚是"直接扣血"**，不是你要的"先掉士气再掉生命"
   ```js
   if (u.supply <= 0) { u.hp -= u.maxHp * 0.02; }   // :874
   ```
5. **士气**：战斗层无独立士气字段（`morale` 只在 CP 效果的伤害加成里出现一次，`BattleScene.ts:3163`）
   → "先掉士气"没有承载字段

## 二、补给机制：现状 vs 你的设计

| 维度 | 你的设计 | 当前实现 | 差距 |
|---|---|---|---|
| 补给源 | 地图边缘己方补给基地 | 己方 `castle`/`planet` 地块 | 概念接近 |
| 补给方式 | **AUX 运输舰飞到前线舰队** | **站在连通地块上自动回补** | **完全不同** |
| 补给速度 | 运输舰有速度、需飞行时间 | 每帧 +5（无延迟） | 无运输延迟 |
| 中继 | 星球可作中继扩大范围 | 地块 BFS 自动传导 | 机制不同但效果类似 |
| 断链 | 打掉运输舰/中继 → 断补给 | 地块失守 → 断补给 | 可实现 |
| 断粮惩罚 | **先掉士气，再掉生命** | **直接扣 2% 最大生命/秒** | 缺士气环节 |

### 关键判断

- 你的设计（运输舰前出）是**单位驱动**；当前是**地块驱动**
- 地块驱动在**六边形战棋**下是自洽的（沿格子铺补给线）；但你要的是**银英 4EX 式指挥制纯宇宙**，没有格子 → 地块驱动无处依附
- **所以：补给机制必须随指挥制一起改造为"单位驱动"**，否则指挥制下补给要么永远满、要么永远空

## 四、章程（方案）

### 4.1 补给机制改造：地块驱动 → 单位驱动

**核心模型：补给链图**
```
己方补给基地（地图边缘）
   ↓ 半径 R_base
星球中继（随机散落少量）
   ↓ 半径 R_relay
AUX 运输舰（可移动）
   ↓ 半径 R_aux
前线舰队
```

**判定规则**
- 舰队补给度由**到最近补给源的距离**决定，而非地块
- 补给源优先级：运输舰 > 星球中继 > 基地（就近取）
- 运输舰**自身需回基地/中继补货**（有载货量，卸完要回去）

**运输舰行为**
- 有航速（现 `speed: 0.6`）、有补给速度（每秒回补量）、有载货量
- 状态机：`idle → 前往前线 → 补给中 → 返航补货`
- 可被击沉（现 HP 900，皮薄）

**断粮惩罚（按你的要求改）**
```
阶段1: 补给度 < 30  → 士气下降（新增 morale 字段）
阶段2: 士气归零     → 战力衰减（伤害/机动降低）
阶段3: 补给度 = 0   → 才开始扣结构生命
```

### P2 运输舰补给行为（已实施）

新建独立模块 `frontend/src/game/SupplyChainSystem.ts`（173 行，纯计算不碰渲染）：

- 运输舰**不脱离舰队**（单位是 sprite 跟随制，无独立移动），改用**阵型外前出偏移**
  朝目标友军方向偏移 46 单位，视觉上表现为"运输舰前出"
- 状态机：`idle → forward（前出）→ supplying（补给中）→ returning（返航补货）`
- 载货量 100，补给输出 1.2/帧；返航到补给源附近以 2 倍速补货
- 自动 AI：优先补给补给度 < 70 的友军（评分减 400 优先级）
- 运输舰被击沉 → 该链路断裂（unit.hp <= 0 不再计入）

关键参数初值（可调）：
| 参数 | 值 | 说明 |
|---|---|---|
| SUPPLY_SOURCE_RADIUS | 420 | 基地/星球直接补给半径 |
| SUPPLY_AUX_RADIUS | 260 | 运输舰补给半径 |
| AUX_FORWARD_OFFSET | 46 | 前出偏移距离 |
| AUX_CAPACITY | 100 | 载货量 |
| AUX_SUPPLY_RATE | 1.2 | 补给输出/帧 |

### P3 斩链判定（已实施）

原判定 `enemyConnected <= 8`（地块连通数）在指挥制下永远不成立 → 改为：
- 敌方**过半舰队断补给**（断链比例 ≥ 0.5）
- **或**敌方运输舰全灭（且曾经有过运输舰）
- 原地块条件保留（六边形模式仍有效），两者取或

  - **舰队状态环**：链内=绿环，**断链=红环 + 外层警示红圈**

### 已实施细节（2026-09-06）

**P0 士气系统**
- 战术层 fleet 加 `morale` 字段（模拟 100 / 战役取 `fleetData.morale ?? 100`）
  （注：`StrategicFleet` 本就有 morale 字段，此前战术层未接）
- 断粮三段式（`:867-887`）：
  - 补给充足 → 士气 +1/帧（回升）

  - 伤害 `moraleDmgMult = 0.6 + 0.4 × (morale/100)`（士气 0 → 伤害 60%）
